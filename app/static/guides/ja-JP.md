# Yeufonic ガイド

このガイドはアプリの**使い方**についてです。インストールと、使い始める前に必要なことはすべて
[README](https://github.com/yeufonic/yeufonic#readme) にあります。

このアプリは YuE2 で曲を作ります。YuE2 は 2 段階で動くモデルです。まず**楽譜プラン**――
メロディ、コード、セクションをテキストで――を書き、次にそのプランをオーディオに**レンダリング**します。以下のほとんどすべてはこの分担から来ています。プランは数秒で済み、読んだり編集したり捨てたりできます。レンダリングには数分かかります。だからアプリは先にプランを見せてくれます。

---

## 最初の曲 {#your-first-song}

1. 左パネル上部の<strong>+ 曲</strong>をクリックします。エディターのウィンドウが開きます。
2. <strong>スタイルを書きます。</strong>タグの羅列ではなく、ひとつの文で：*「warm indie rock, expressive female lead, jangly
   guitars, 96 BPM」*。結果をいちばん大きく左右するのがこれです。
3. **歌詞を加える**か、**歌詞を書く**をクリックして、説明から Gemma に下書きさせます。
4. **楽譜プランを書く**をクリックします。ウィンドウが閉じ、テイクが左パネルに表示されます。ボタンの横の**プランができたらすぐにレンダリング**が最初のとおりチェックされていれば、プランはそのままレンダリングに進みます。

何かがレンダリングされる前にプランを読みたいときは、先に**プランができたらすぐにレンダリング**のチェックを外します。するとテイクはプランの段階で止まります。開いて、その**楽譜**ページで**新しいプランを書く**を押せば、気に入らないメロディを数秒でもう一度振り直せます。**この楽譜をレンダリング**でレンダリングします。まだオーディオのないテイクは補完されます。すでにオーディオのあるテイクは、その隣に新しいテイクとしてレンダリングされるので、レンダリングが残したいテイクを上書きすることはありません。

テイクは右側のライブラリに表示され、下部のバーで再生されます。

### テイクパネルとエディター {#the-take-panel-and-the-editor}

**左パネル**には、最後にクリックしたテイクが読み取り専用で表示されます。スタイル、サウンドの設定、歌詞の最初の数行、そして楽譜としての調、テンポ、長さ、各セクションのコードです。上部の<strong>+ 曲</strong>、**+ カバー**、**+ インスト**は新しいものを始めます。そのテイクの種類のボタンが強調表示されます。パネルの横の山形の矢印でパネルを畳むとテイク一覧が横幅いっぱいに広がり、もう一度押すと元に戻ります。単独のキーはパネルに表示されたテイクに作用します（M でマスタリングラック、E でエディターなど）。[キーボードショートカット](#hot-keys)を参照してください。

テイクを作ったり変えたりするのは**エディターウィンドウ**です。パネルにあるそのメインボタンは、その場に合った操作を表示します。*編集してもう一度レンダリング*、またはプランが待っているときは*プランを確認してレンダリング*です。カードの**楽譜**ボタンと**もう一度**ボタンでも開きますし、カードのダブルクリックでも開きます。エディターには 3 つの列（曲、歌詞、サウンド）がすべて並び、楽譜は専用のタブにあります。

**閉じる**、× ボタン、または Esc でウィンドウを閉じても、書いた内容は残ります。

右上の**閉じる**の次にあるボタンを押すと、ウィンドウがブラウザーのウィンドウいっぱいに広がり、もう一度押すと通常の大きさに戻ります。ウィンドウは前回閉じたときの状態で開きます。いっぱいに広げると、歌詞の列が高さ全体を使います。歌詞欄（すでに言葉が入っているとき）と構成が空いたスペースに広がり、プレーヤーは列の下端に残ります。

ウィンドウの最上段には、テイクカードの小さなボタンが大きくなって並んでいます。もう一度歌う、バリエーション、もっと試す、中身、取り出す、ノーマライズ、移動で、それぞれカード上と同じ位置にあります。ノーマライズはテイクがノーマライズされている間は緑色で、そのときクリックするとレンダリング時のレベルに戻ります。中身はテイクがほかのテイクを含んでいる間は点灯し、クリックするとウィンドウを閉じてテイクの下にそれらを表示します。

### 録音した声 {#a-recorded-voice}

テイクは、誰かの歌の録音から学習したボイスで歌わせることができます。あなた自身の声でも、コーパスの歌い手の声でもかまいません。テイクはいつもどおりレンダリングされ、そのあとボーカルを分離して、そのボイスで歌い直し、残りの音の上にミックスし直します。ボイスはメニューの <strong>ボイス</strong> ページで作成・管理します。オプションの音声サービス（README の「Recorded voices」）が必要で、それがないと声の欄は表示されません。

#### ボイスを作る {#making-a-voice}

<strong>新しいボイス</strong> は、自分の録音からボイスを作るか、コーパスの曲で学習したボイスを作ります。録音から作るボイスは空の状態から始まり、そのページに録音を集めます。

- <strong>録音…</strong> はレコーダーを開きます。残したテイクは、歌ったとおりのままボイスに渡り、オートチューンはかかりません。
- <strong>アップロード…</strong> は音声ファイルを受け付けます。
- <strong>ライブラリから…</strong> は、カバー用に録ったボーカルなど、すでにある録音を加えます。それぞれに試聴用のプレーヤーがあり、コピーではなくリンクで加わります。

各録音には、声だけのもの（<strong>ボーカルのみ</strong>。ここで録音したものにはチェックが付きます）か、先に分離される曲かが示されます。ページは歌の量を数えます。音域全体で 10 分ほどあれば十分で、短い録音でも聞き分けられるボイスになります。そのうえで <strong>学習</strong> を押します。

学習は GPU の順番を待ち、進み具合をジョブ表示とログに示します。<strong>再学習</strong> は、いまの録音、またはコーパスの曲でもう一度学習します。<strong>学習した内容</strong> には、各曲の分離したボーカルと学習に使った抜粋が残り、聞き返せます。設定 → <em>ボイスの学習</em> で、ボイスが学ぶ歌の量と学習回数を決めます。

#### ボイスの設定 {#settings-for-a-voice}

これらはボイスのページで決める既定値です。テイクごとに別の設定も持てます（下記）。

| 設定 | 何をするか |
|---|---|
| <strong>オクターブ</strong> | ボイスを 1 オクターブ単位で上げ下げします。テイクと音域がかけ離れた歌い手向けです。 |
| <strong>ボーカルの音量</strong>、<strong>楽器の音量</strong> | リミックスのバランスです。 |
| <strong>似せ具合</strong> | 歌い手自身の音にどれだけ寄せるか。高いほど似ますが、加工した感じも出やすくなります。100% では言葉を失うことがあり、歌い手が歌うのを聞いたことのない言葉が崩れて出ることがあります。エディターはそう表示します。 |
| <strong>フォルマント</strong> | 音程はそのままに声の大きさを変えます。<em>深く</em> は大きく、<em>明るく</em> は小さく聞こえます。 |
| <strong>ブレンド</strong> | ボーカルのうちボイスが歌う割合。残りは元になった生成ボーカルです。 |
| <strong>ルーム</strong> | 変換したボーカルの下に短い残響を加え（<em>ドライ</em>、<em>控えめ</em>、<em>多め</em>）、ミックスになじませます。 |
| <strong>明るさ</strong> | <em>自動</em> は高域を生成ボーカルに合わせて持ち上げます。<em>オフ</em> は変換したままにします。 |
| <strong>息と子音</strong> | それらに生成ボーカル自身の音をどれだけ残すか。<em>残す</em> ははっきりしますが元の名残があり、<em>変換</em> は裂けることがあります。 |
| <strong>ダイナミクス</strong> | フレーズごとの音量を、生成されたままのテイクに合わせるか、ボイス自身の抑揚に合わせるか。 |

#### テイクでボイスを使う {#using-a-voice-in-a-take}

エディターの <strong>録音した声</strong> でボイスを選びます。その横の <strong>設定</strong> を開くと、上の設定をこのテイクだけに変えられます。テイクはその設定を保ち、ボイスの既定値と違うときはボタンに <em>個別の設定</em> と表示されます。

#### 使う前にボイスを聞く {#hearing-a-voice-before-you-use-it}

その設定の中の <strong>聞く</strong> は、ボイスが短いループ（<em>男性の歌</em> か <em>女性の歌</em>）をいまの設定で繰り返し歌うのを流すので、設定を変えるたびにその場で聞けます。<strong>新しい声として保存…</strong> は、聞いたものを同じモデルを使う独立したボイスとして残します。

<strong>自分のループ。</strong> 2 つのループはアプリに付いています。自分のものも加えられます。

1. 1 人の声だけが歌う 15〜30 秒を探すか録音します。伴奏、残響、ハモリのないドライなものにします。
2. FLAC、WAV、MP3、M4A、OGG、Opus のいずれかで、リストに出したい名前で保存します。
3. ライブラリの <em>voice-loops</em> フォルダーに置きます。Docker では `data/voice-loops`、Windows ではインストール先の `data` フォルダーの中です（`settings.ini` の `data_dir` で別のライブラリフォルダーを指定している場合はそちら）。
4. <strong>設定</strong> を開き直すと、ファイル名で表示されます。

#### ボイスを共有・インポートする {#sharing-and-importing-voices}

- <strong>声をダウンロード</strong> は、学習済みのボイスを zip に保存して人に渡せるようにします。
- <strong>声をインポート…</strong> はボイスを追加します。その zip でも、ほかで作った RVC モデル（その zip、または .pth と .index を一緒に選択）でもかまいません。インデックスなしでインポートしたボイスには、あとから <strong>インデックスを追加…</strong> で追加できます。「似せ具合」はこれを参照します。
- <strong>既製のボイス</strong>（他の人が学習させた RVC モデル）は、[voice-models.com](https://voice-models.com/) などのサイトで入手できます。<strong>声をインポート…</strong> はダウンロードした zip をそのまま受け付けます。
- テイクのレシピにはボイスとそのテイクでの設定が記録され、インポートすると、このインストールに同じ名前のボイスがあればそれを使います。

#### きれいなボイスにするには {#getting-a-clean-voice}

結果は分離した伴奏の上に変換したボーカルを重ねたものなので、モデル自身が歌ったボーカルほど自然にはなじみません。

- ボイスは歌い手と一緒に、録音のリバーブや音作りも学習します。そのため、リードボーカルがはっきりしたクリーンでドライな歌のほうが、ミックス済みの曲を集めたコーパスよりきれいなボイスになります。
- 1 曲や短い録音でも聞き分けられるボイスになりますが、歌うのを聞いたことのない言葉はぼやけることがあります。
- 既製のボイスによくあるように、はるかに多くの歌で、はるかに多くのパス数で学習したボイスは、「似せ具合」が高くても言葉を保ちます。

### 詳細設定 {#advanced-settings}

エディターのヘッダーにある**詳細**ボタンは、このテイクだけの設定を開きます。ほとんどの曲では必要ありません。設定はテイクと一緒に保存されるので、*編集してもう一度レンダリング*は前回のままの設定を見つけます。どれかの設定が既定値と違うとボタンが点灯し、**既定値に戻す**ですべて元に戻ります。

プランに作用するものと、レンダリングと最終ファイルに作用するものがあります。

- **拡散ステップ**（16–64、既定 32）：オーディオデコーダーが進むステップ数。ステップが多いほどレンダリングに時間がかかります。
- **スタイルに従う**（0–100、既定 1.0）：音楽がスタイルと歌詞にどれだけ忠実に従うか。楽譜を音に変える段階のガイダンス（CFG）です。1.0 より上では近づき、下では離れていきます。小さな値では違いはわずかで、レンダリングは少し長くなります。エンジンが受け付ける値なら何でも入力できますが、ガイダンスを非常に強くすると、忠実になるよりも耳障りになりがちです。エンジンが対応しているときに表示されます。yue2.cpp、または最新版の ComfyUI エンジンです（古い Docker エンジンでは再ビルドすると使えます）。
- <strong>避ける：</strong>遠ざけたい言葉。たとえば「drums」や「rap vocals」。スタイルに「avoid: …」として加えられます。プランナーへのヒントであって保証ではありません。レンダラーにはネガティブプロンプトがありません。
- <strong>キー固定：</strong>プランナーが書いたあと、プランをこの調に移します。プランナーはスタイルに書かれた調を無視するので、これは楽譜そのものに対して行われます。すべての音符とコードが同じ音程だけ移され、調号が書き直されます。短調のプランは短調のままで、主音だけが動きます。旋法のプランや途中で転調するプランなど、アプリが確実に読み取れないものはプランナーの調のままになり、ログにそう記されます。
- **テンポ固定**（BPM）：プランをこのテンポに固定します。スタイルやプランナー自身の楽譜にあるテンポはすべてこれに置き換えられ、レンダリングもそれに従います。
- **楽譜トークン上限**（既定 8192）：プランナーが書ける上限。低くすると短い曲のプランが間延びしにくくなります。
- **コード持続の上限**（小節、既定 8）：プランナーが同じルート音にとどまれる小節数の上限。それを過ぎると変えなければなりません。
- **調外ハーモニーのボーナス**（0–10、既定 0）：プランナーを借用和音や主調の外のルート音へ押し出す強さ。この 2 つはプランナーの選択に作用するので、耳ではっきりわかる違いよりもプランのコードの違いとして現れます。楽譜ウィンドウで比べてください。
- **声を指示に合わせる**（歌詞欄の下のチェックボックス。歌詞に `[male voice]` のような声の指示があるときに表示されます。新しいテイクではオン）：指示のある各行のメロディを、指示が示す声の歌う音域へオクターブ単位で移します。[歌詞](#the-words)を参照してください。
- **この構成に正確に従う**（歌詞欄の下のチェックボックス。詳細設定にはありません。曲のみ。既定はオフ）：歌詞に書かれたセクションを、その順番どおりに、過不足なくプランに書きます。オフのときはプランナーが自分で曲の形を決め、イントロ、アウトロ、間奏を加えたり、セクションを省いたりすることがよくあります。それでも、リストの終わりより前にプランが終わることはあります。
- **セクションごとに違う始まり方**（ハーモニーに従う、常に、しない）：セクションが前のセクションと同じコードで始まってよいかどうか。*ハーモニーに従う*は「カラフル」以上でオン、それ未満でオフにします。*常に*と*しない*は、どのレベルでもこのテイクについて決めるので、ルールのあるプランとないプランを比べられます。
- <strong>目標ラウドネス：</strong>テイクをノーマライズする目標レベル。ノーマライズがオンのときだけ使われます。
- **終わりのフェード**（秒、既定 3）：テイクが長さの上限で切られるときのフェードの長さ。

### スタイル欄に何を書くか {#what-to-put-in-the-style-box}

YuE2 はこれを録音の説明として読むので、録音を描写してください。言語、ジャンル、声、楽器、雰囲気、テンポ、プロダクションを、だいたいこの順番でひとつの文にします。ばらばらのタグの羅列はうまく働きませんし、`[Verse]` のようなセクションの印は歌詞に書くもので、ここには書きません。

下にある**ボーカル**のチップはスタイルに書き込んでくれます。女性、男性、デュエットと、ブレシーやしゃがれ声のような声質です。入力の近道なので、結果は手で直せます。

### 歌詞の下書き {#drafting-the-lyrics}

<strong>構成。</strong> 歌詞欄の上には、まだ言葉が入っていないあいだ、インストと同じように組み立てる <strong>構成</strong> があります。並べ替え、削除、追加ができるセクションのリストです（イントロ、ヴァース、プリコーラス、コーラス、ブリッジ、間奏、アウトロ）。

- <strong>ひな形から…</strong> はよくある形で埋めます。各形のツールチップに向いている曲が書かれています。
- <strong>間奏</strong> は楽器だけの部分です。作詞役はそのタグを独立した行に置き、プランナーは楽器パートで演奏します。
- <strong>歌詞欄にセクションを入れる</strong> は、手で書き込めるようにタグを空のセクションとして入れます。
- 欄に言葉が入ると、歌われるのは歌詞になり、構成は脇に退きます。

歌詞欄の横の <strong>歌詞を書く</strong> は、曲のテーマを尋ね、組み立てたセクションに言葉を書きます。

- <strong>ヴァースやコーラスの行数</strong> で各セクションの長さを決めます。プランナーは言葉の量に見合った長さの音楽を書くので、行が多いほど曲は長くなります。
- 上のスタイルが雰囲気を決めます。
- 同じエンジン上の Gemma が下書きを書き、タイトルを付けていなければタイトル付きで欄に入ります。設定で構成した [外部 LLM](#external-llm) に書かせることもできます。
- 下書きが始まるとウィンドウは閉じ、進み具合は歌詞欄の横に出ます。

歌詞エディターのボタンでも、これらのセクションや声の指示（+ 男性、+ 女性、+ 両方）を追加できます。

<strong>行の響き</strong> は、作詞役が目指すリズムと韻を決めます。<em>自然</em>（既定）から <em>短く切れよく</em>、<em>長く流れるように</em> まであります。それぞれの内容は [言葉](#the-words) にあります。

これは最初の下書きです。行は拍に乗り韻も踏みますが、モデルはありがちなイメージに頼りがちで、ある行がすでに誰かのものかどうかは確かめていません。プランを作る前に読んで、自分のものにしてください。

## プロンプトから曲を書く：すべてのオプション {#writing-a-song-from-a-prompt-every-option}

**+ 曲**には今では多くのオプションがあります。必須のものはありません。スタイルと少しの歌詞があれば十分です。
[最初の曲](#your-first-song)のとおりです。この章では、エディターが表示する順番に、
3 つの列（曲、歌詞、サウンド）のすべてを見ていき、そのあとプランができてからすることを扱います。最後によくある望み、たとえば曲を長くしたい、コーラスをヴァースと違う響きにしたい、といったものの表があります。

### 曲 {#the-song}

- <strong>タイトル。</strong>任意。空欄なら歌詞の 1 行目が使われます。
- <strong>スタイル。</strong>リスト **スタイルを選ぶ…** には afrobeats から zydeco まで 200 の出発点がアルファベット順に並んでいます。ひとつ選ぶとスタイル欄が完全な説明で埋まり、あとで編集できます。その下のチップは、曲のクイックスタート 10 種です：warm indie rock、soulful jazz-pop、synthwave、acoustic ballad、heavy rock、modern pop、
  country、hip hop、smooth R&B、dance pop。[スタイル欄に何を書くか](#what-to-put-in-the-style-box)を参照してください。
- <strong>自分のスタイルを保存する。</strong>リストの横の**保存**は、スタイル欄の内容を付けた名前で保存します。リストの最初の項目 **保存済みスタイル** で保存したものが開きます。横のごみ箱で削除でき、リストの検索では 200 と一緒に見つかります。使用済みの名前で保存するとそのスタイルを置き換えます。スタイル LoRA のトリガーワードは保存されず、スタイルを使うときに選択中の LoRA に合わせて改めて入ります。
- <strong>スタイルの中のテンポはヒントにすぎません。</strong>プランナーはたいてい自分のテンポを選びます。テンポを固定するには詳細設定の**テンポ固定**を使います。
- <strong>ボーカル。</strong>チップが声（女性、男性、デュエットと声質）をスタイルに書き込みます。
- <strong>スタイル LoRA。</strong>サウンドの列の下にあります。[スタイル LoRA](#style-loras)を参照してください。

### 歌詞 {#the-words}

<strong>構成。</strong>歌詞欄の上には、まだ言葉が入っていないあいだ、セクションのリストがあります。曲がたどる順番です。各行は別のセクションに替えたり、上下に動かしたり（ドラッグも可）、削除したりでき、リストの下のチップでセクションを加えます。セクションはイントロ、ヴァース、プレコーラス、コーラス、ブリッジ、間奏、アウトロです。**間奏**は楽器だけのパッセージで、言葉はなく、プランナーが楽器の声部で演奏します。（`solo` はプランナーが知っているセクションではありません。ソロがほしいときは間奏を使います。）

<strong>ひな形から…</strong>はよくある形でリストを埋めます。選択肢にマウスを重ねると、何に向いているかが表示されます。

| 形 | セクション | 向いている曲 |
|---|---|---|
| ヴァース、コーラス、ブリッジ | ヴァース、コーラス、ヴァース、コーラス、ブリッジ、コーラス | 王道の曲：ポップ、ロック、カントリー |
| 短め | ヴァース、コーラス、ヴァース、コーラス | フォーク、パンク、初期のロックンロール |
| イントロとアウトロ | イントロ、ヴァース、コーラス、ヴァース、コーラス、アウトロ | バラード、ソフトロック、シンガーソングライター |
| 物語 | ヴァース、ヴァース、コーラス、ヴァース、コーラス、アウトロ | 物語の曲、フォーク、カントリー |
| プレコーラス付きポップ | ヴァース、プレコーラス、コーラス、ヴァース、プレコーラス、コーラス、ブリッジ、コーラス | 現代のポップ、ダンスポップ、ポップロック |
| サビ始まり | コーラス、ヴァース、コーラス、ヴァース、コーラス、ブリッジ、コーラス | ストリーミング時代のポップ、インディーポップ |
| 短くシンプル | ヴァース、コーラス、ヴァース、コーラス、コーラス | パンク、ガレージロック、ロカビリー |
| ヒップホップ | イントロ、ヴァース、コーラス、ヴァース、コーラス、ヴァース、アウトロ | ラップ、ヒップホップ、トラップ、R&B |
| ダブルブリッジ | ヴァース、コーラス、ヴァース、コーラス、ブリッジ、ブリッジ、コーラス、コーラス | パワーバラード、プログレッシブロック、シンフォニックロック |
| 間奏入り | ヴァース、コーラス、間奏、ヴァース、コーラス、ブリッジ、コーラス | ロック、ポップロック、インディー |
| 全部入り | イントロ、ヴァース、プレコーラス、コーラス、間奏、ヴァース、プレコーラス、コーラス、アウトロ | ポップ、ダンスポップ |

<strong>セクションの数。</strong>歌詞が何を求めても、プランナーはふつう 8〜10 のセクションを書きます。そのため
10 を超えるリストは圧縮され、捨てられたセクションの言葉は歌われません。リストがそれほど長くなるとビルダーが警告します。セクションを増やしても曲は長くならず、ひとつひとつが短くなるだけです。
[曲を長くする](#making-the-song-longer)を参照してください。

**歌詞欄にセクションを入れる**はセクションを空のタグとして入れるので、その下に手で書けます。欄に言葉が入ると歌詞が歌われ、ビルダーは脇に退きます。

<strong>歌詞を書く。</strong>曲が何についてのものかを説明すると、組み立てたセクションにモデルが言葉を書きます。尋ねるのは次の 3 つです。

- **ヴァースやコーラスの行数**（4、6、8。既定は 6）。セクションの行が多いほど曲は長くなります。プランナーは言葉の量とほぼ同じだけ音楽を書くからです。イントロ、ブリッジ、アウトロは 2〜4 行にとどまり、間奏には行がありません。
- <strong>行の響き。</strong>リストには各行が狙う音節数が表示されます。以前の作詞者はほとんどいつも同じ
  8 音節の韻を踏む行を書いていましたが、これでそれが変わります。

| 選択肢 | 狙い | 得られるもの |
|---|---|---|
| 自然（既定） | 3-13 音節 | 短い行と長い行の混在、韻は少し、決まった拍子はなし |
| 規則的な韻 | 6-10 音節 | 2 行ずつ韻を踏む同じ長さの行：伝統的な形で、以前の作詞者の書き方 |
| 語りのリズム | 5-14 音節 | 話し言葉やラップのように口語的でリズミカル、行の中の韻あり |
| ゆるい韻 | 4-13 音節 | 韻を踏む行、近い韻の行、踏まない行があり、長さもまちまち |
| 短く鋭く | 3-6 音節 | 短い行と繰り返されるフレーズ |
| 長く流れるように | 10-14 音節 | 思考のように流れる長い行 |

  最後の選択は記憶されます。これらは目標であって保証ではありません。言語モデルは両端（短く鋭く、長く流れるように）ではぴったり従い、中間ではもっとゆるやかです。
- **依頼内容**そのものを自分の言葉で書き、上のスタイルが雰囲気を決めます。依頼内容はテイクと一緒に保存されるので、テイクを開いて**歌詞を書く**を押すと、何についての曲を頼んだかが表示され、変えて書き直せます。

下書きは歌詞欄に届き、始まるとウィンドウは閉じます。これは最初の下書きです。読んで、自分のものにしてください。

**この構成に正確に従う**（歌詞欄の下のチェックボックス、既定はオフ）。プランナーは歌詞のセクションタグを目安として受け取り、放っておくと自分なりの形を書きます。イントロやアウトロを加えたり、ブリッジを間奏とヴァースに替えたり、長いリストを圧縮したりすることがよくあります。これをオンにすると、プランは歌詞に書かれたセクションをその順番どおりに、過不足なく書きます。書いていないイントロやアウトロを加えることはできません。音楽をどうするか、各セクションがいつ始まるかは、引き続きプランナーが決めます。曲にのみ適用されます。

<strong>どの行を誰が歌うか：声の指示。</strong>声の名前を角括弧で囲んだ 1 行は、次の指示か次のセクションまで、続く行を誰が歌うかを示します。

```
[Verse 1]
[male voice]
The ferry leaves at half past nine
I watch the harbour lights go by
[female voice]
I wait beside the ticket line

[Chorus]
[both voices]
Carry me over, carry me home
```

指示は `[male voice]`、`[female voice]`、`[both voices]` のように、それぞれ角かっこで囲んで 1 行に書きます。

- 拡大した歌詞エディターのヘッダーには、カーソル位置に挿入する <strong>+ 男性</strong>、<strong>+ 女性</strong>、<strong>+ 両方</strong> のボタンがあります。
- これらは機能を試したときの書き方で、`voice` の代わりの `vocal`（`[female vocal]`）や、両方を表す `[male and female voices]` も使えます。
- カンマのあとに自分の言葉を足せます（例：`[female voice, soft and close]`）。誰が歌うかは変わりません。
- 指示のないセクションはプランナーに任されます。
- ほかで書かれた歌詞が無視されないよう、別の書き方も読み取ります。`[man]`、`[woman]`、`[duet]`、`[Verse 2 - female vocal]` のようにセクションのタグに入った指示、丸かっこの指示 `(female voice)` などです。丸かっこの言葉はふつうバックコーラスで、歌われることがあるので、角かっこのほうが安全です。

<strong>指示だけで声が決まるわけではありません。</strong> 誰が歌うかは主にメロディの高さで決まります。同じ行も 1 オクターブ上なら女性が歌い、プランナーは誰が指示されていても、ヴァースを 2 つのオクターブにまたがって書き、4 行ほどごとに切り替えがちです。

- <strong>声を指示に合わせる</strong>（歌詞に指示があると歌詞欄の下に出るチェックボックス。新しいテイクではオン）は指示を守ります。プランを書くとき、指示のある部分のメロディを、その声が歌う高さまでオクターブ単位で動かします。男性なら低く、女性なら高くです。プランのほかの部分は変わりません。
- これはレンダリングのたびにやり直されるので、言葉や楽譜を変えても追従します。
- 楽譜ページの <strong>声を指示に合わせる</strong> は、チェックなしで作ったテイク向けに、欄の楽譜に同じことを 1 回行います。楽譜を保存してレンダリングしてください。

知っておきたいことが 3 つあります。

- <strong>誰がどの行を歌うかは、まだ運に左右されます。</strong>メロディが正しい位置にあれば、ほとんどの行は指示された声に行きますが、レンダリングがある行をもう一方の声に渡すこともあります。別のシードでレンダリングし直すか、**もっと試す**を使ってください。
- **両方**は行を女性の歌う位置に置き、2 人目の声はレンダリングに任せます。レンダリングはコーラスにもう 1 人を加えることがよくあります。デュエットを作るというより頼むもので、2 人目の声がどれだけ聞こえるかはレンダリングごとに違います。歌詞を損なわずに 1 行に 2 人の歌い手を書く方法は、まだありません。
- このチェックボックスができる前に作ったテイクは楽譜がそのままです。チェックを入れるか、**声を指示に合わせる**を使って合わせてください。

<strong>手で書く。</strong>展開ボタンで大きなエディターが開き、イントロ、ヴァース、プレコーラス、コーラス、ブリッジ、間奏、アウトロ、インストのボタンがあります。セクションは `[Verse]` のような 1 行と、そのあとに続く行です。下に行のないタグ、たとえば `[Interlude]` は、楽器だけのパッセージです。

### サウンド {#the-sound}

- **ハーモニー**（スライダー）：コードの大胆さ。新しい曲は**多彩**から始まり、解釈は**ワイド**です。私たち自身のテストではこの組み合わせが音楽的にいちばん面白いバージョンを生んだので、よい出発点です。どちらでも好みに合わせて動かしてください。既存のテイクは作られたときの設定を保ちます。放っておくとプランナーは
  4 つのコードのループを書いてすべてのセクションで使いがちで、レベルが上がるごとにそこから少しずつ離れます。レベルは積み重なっていきます。

  | レベル | コードに何をするか | 選ぶとき |
  |---|---|---|
  | おなじみ | 何もしない：YuE2 のコード。曲全体でループひとつのことが多い | プランナーの最初の案が気に入っている、またはいちばんシンプルな伴奏がほしい |
  | 多彩 | 直前に使ったコードをそのまま繰り返すのを抑え、色を変える（F の次に Fmaj7）が、調の中にとどまる | ループが単調に聞こえるが、曲は正統派のままにしたい |
  | カラフル | 同じことをもっと強く：ヴァースとコーラスが分かれ、コードが豊かになる。セクションは前のセクションと同じコードで始まれないので、コーラスがヴァースと同じ始まり方をしなくなる | コーラスを繰り返しではなく盛り上がりにしたい。最初の一歩に最適 |
  | 冒険的 | 書き方だけでなく、最近使った*ルート音*そのものを抑えるので、ハーモニーは移ろい、調の外からコードを借りる | 動きと驚きがほしく、変に聞こえるコードに気を配れる |
  | 調の外 | 大胆で、調の外のコードに引き寄せられる | 実験。いくつかのプランは捨てるつもりで |

  「カラフル」以上では、コードの選び方がセクションごとにより違ってきます。1 曲の中の異なるコードが増え、繰り返さない 4 小節のパターンが増え、ヴァースの始まりをなぞるコーラスが減ります。プランはふつうの曲のままなので、よりワイルドなプランの多様さに頼る前に、ハーモニーを 1、2 段上げてみる価値があります。**詳細**では、**セクションごとに違う始まり方**を*常に*か*しない*にして、コーラスのルールがあるプランとないプランを試せます。既定の*ハーモニーに従う*は「カラフル」以上で有効です。トラップやアンビエントのようなスタイルはもともとループで成り立っていることが多いので、ポップやロックより変化は小さめです。測定結果は[ハーモニー](#harmony)を参照してください。
- <strong>プランの多様さ。</strong>プランナーがほかのすべてをどれだけ自由に書くか。[プランの多様さ](#plan-variety)を参照してください。
- <strong>解釈。</strong>レンダリングで音符がどう演奏されるか。[解釈](#interpretation)を参照してください。
- <strong>長さの上限。</strong>曲が終わってよいいちばん遅い時点。[長さ](#length)を参照してください。
- **モード。** *フル*はプランのコードを保ち、*メロディ*は伴奏を自由にします。曲の場合の*楽譜なし*は、プランをまったく書きません。[楽譜なしの曲](#a-song-with-no-score)を参照してください。
- **シード**と**このシードを保つ**。[シードと、テイクの再現](#seed-and-reproducing-a-take)を参照してください。
- **プロダクション仕上げ**と**音量をノーマライズ。**[プロダクションの仕上げ](#production-polish)を参照してください。
- ウィンドウ下部のボタンの横にある**プランができたらすぐにレンダリング**は、プランとレンダリングを途中で止まらずに行います。最初はチェックされていて、エディターは選択を覚えます。先にプランを読むにはチェックを外します。
- **詳細**（ヘッダーのボタン）：拡散ステップ数、スタイルに従う、避ける、調の固定、テンポの固定、最長の楽譜、コードの維持上限、調の外のハーモニーのボーナス、セクションの始まりを変える、目標ラウドネス、終わりのフェード。
  [詳細設定](#advanced-settings)を参照してください。
- <strong>マスタリング</strong>（その左のボタン。テイクに音があるとき）は、エディターの上に、そのテイク用のマスタリングラックを開きます。ラックがテイクの音を変えているあいだ、ボタンは緑になります。ラックのモジュールは順に次のとおりです。

  1. 1073 風 EQ
  2. パラメトリックイコライザー
  3. コンプレッサー
  4. ステレオイメージャー
  5. <strong>3D 空間</strong>（下記）
  6. リミッター

  各モジュールはバーの左の矢印でたためて、どれをたたんだかはテイクが覚えています。

  <strong>パラメトリックイコライザー。</strong> 7 つのバンドはそれぞれグラフ上の点です。

  - 点を左右にドラッグすると周波数、上下にドラッグするとゲインが変わります。
  - 点の上でホイールを回すと幅が変わり、ダブルクリックすると元に戻ります。
  - グラフの下の帯で、選んだバンドの種類（ローカット、ローシェルフ、ベル、ノッチ、ハイシェルフ、ハイカット）とオン／オフを決めます。
  - <strong>フラット</strong> は全バンドを 0 dB に戻し、グラフの隅のボタンは表示するデシベルの範囲を変えます。

  <strong>キー操作。</strong> ラックを開いているあいだ、スペースでテイクの再生と一時停止、矢印キーで移動と音量の調整ができます（メインページと同じ）。Escape でラックを閉じ、もう一度押すとエディターを閉じます。

- <strong>3D 空間</strong> はイメージャーとリミッターのあいだにあるモジュールで、ヘッドホン向けにテイクを自分の周りに配置します。方法は 2 つあります。

  | 元 | 設定するもの |
  |---|---|
  | <strong>ミックス</strong> | 前に 2 つ（<strong>幅</strong>）、後ろに 2 つ（<strong>後方</strong>）の仮想スピーカー。<strong>サラウンド</strong> はミックスの広がりと空気感をどれだけ後ろから鳴らすかを決めます。スピーカーは円の上でドラッグもできます。<strong>高さ</strong> は全体を持ち上げ、<strong>ルーム</strong> は短い残響を加えます。 |
  | <strong>ステム</strong> | テイクの各ステムを個別に配置します。円の下で 1 つ選び、円の周りをドラッグして置き、ホイールで広げます。ステムがないときは <strong>ステムを作る</strong> でステムウィンドウが開きます。 |

  <strong>前方</strong>、<strong>ワイド</strong>、<strong>周囲</strong> はまとめて設定します。聞こえる音はヘッドホン用で、テイク自身のファイルには入りません。残すには次のようにします。

  - ヘッドホンの下の <strong>ダウンロード</strong> で WAV として保存します。
  - 5.1 スピーカーの下の <strong>FLAC</strong> と <strong>AC-3</strong> で、サラウンドスピーカー用にテイクを保存します（ステムからの場合、各ステムは置いた位置の両側のスピーカーに振られます）。
  - 空間がオンのあいだは、テイクの保存ウィンドウにも同じダウンロードが出ます。

### 曲を長くする {#making-the-song-longer}

曲の長さはプランで決まり、レンダリングはプランの長さに従います。長さを動かすのは次のことです。

| 得たいもの | すること |
|---|---|
| もっと長い曲 | 各セクションの行を増やす（**ヴァースやコーラスの行数**：6 か 8） |
| もっとゆっくりで長い曲 | 詳細設定で**テンポ固定**を設定する。同じプランでも BPM が低いほど長くなる |
| セクションを増やして長い曲 | うまくいかない：プランのセクションは 8〜10 ほどなので、増やしても短くなるか圧縮されるだけ |
| プランが許すより長く | 新しいプランを書く。同じ歌詞でも実行ごとに長さは大きく変わる |
| 歌詞の終わりで終わる曲 | 切られてしまうときだけ長さの上限を上げる。上限は天井であって目標ではない |

### プランができたら {#after-the-plan}

- **この楽譜をレンダリング**は、開いているテイクにすでにオーディオがあれば必ず新しいテイクを作るので、比べたいテイクをレンダリングが上書きすることはありません。まだオーディオのないテイクは補完されます。
- **このメロディを残す**（テイクの歌詞を変えたあと）：テイクの楽譜を新しい歌詞で、新しいテイクとして歌います。メロディはセクションや音符を増やせないので、歌詞のセクションがメロディより多いとき、または音節が音符よりずっと多いか少ないとき（短い行用のメロディに長い行、長い行用のメロディに短い行）は、チェックボックスが自動的に外れ、新しいプランが書かれ、その理由を示す 1 行が表示されます。[同じメロディ、新しい歌詞](#same-tune-new-words)を参照してください。
- <strong>ライブラリの絞り込み。</strong>フィルターの横の**曲**、**カバー**、**インスト**の切り替えで、開いているスペースのその種類だけを表示します。複数選ぶことも、何も選ばずにすべての種類を表示することもできます。

## プランを読んで直す {#reading-and-fixing-the-plan}

プランは **ABC 記譜法**で書かれています。音楽をプレーンテキストで表し、五線の上の音符の代わりに文字を使います。
Chris Walshaw が 90 年代初めに、フォークのメロディを電子メールで送るために考案し、そのまま定着しました。

読めなくてもかまいません。アプリは同じプランを、エディターの下に**コード譜**と本物の**五線譜**として表示し、**広げる**で全体を大きく開きます。それでも、テキストこそ YuE2 が書いてレンダリングの元にしたものなので、読み方を知っておく価値があります。

### プランの読み方 {#reading-a-plan}

プランはヘッダーで始まります。1 行に 1 文字とコロンです。

```
X:1
M:4/4
L:1/32
Q:1/4=120
V: Vocal clef=treble name="Vocal Melody"
V: Ins   clef=treble name="Ins Melody"
K:D#m
```

| 行 | 意味 |
|---|---|
| `X:1` | 曲番号。ABC ファイルはすべてこれで始まる |
| `M:4/4` | 拍子——1 小節に 4 拍 |
| `L:1/32` | 単位の長さ：文字ひとつが 32 分音符ひとつ分 |
| `Q:1/4=120` | テンポ——4 分音符が毎分 120 拍 |
| `V:` | 声部を宣言する。YuE2 は 2 つ書く：歌のラインと楽器のライン |
| `K:D#m` | 調。嬰ニ短調。`K:` は常にヘッダーの最後 |

そのあとが音楽そのものです。

```
% intro
V: Vocal
z24z4"D#m"z4|"D#m"z32|
V: Ins
Z|d16a16-|a16g8a8|
```

- **音符は文字です。**`d16` は 16 単位の長さの D。小文字は大文字より 1 オクターブ高く鳴り、
  `'` や `,` でさらに移ります。
- **`-` は音符を次の音符につなぎ**、ひとつの音として鳴らします。
- **`z` は休符**で、音符と同じように長さを持ちます。大文字の `Z` は 1 小節全体の休符です。
- **コードは二重引用符の中**、たとえば `"D#m"` に書き、始まる音符の前に置きます。**検索と置換**で編集するのはこれです。
- **`|` は小節線**、**`%` はコメントの始まり**——セクションはこうして印を付けます：
  `% intro`、`% verse`、`% chorus`。

つまりこの断片は、嬰ニ短調、4 分の 4 拍子、毎分 120 拍で、イントロのあいだ歌声はコードを持ったまま休み、楽器はつないだ D と A、続いて G と A を弾く、という意味です。

実際的な帰結が 2 つあります。**コードの編集は安全です**。音符がわかりにくく見えても、触るのは引用符の中だけで、ほかはそのままにしておけます。そして**プランを編集すると、レンダリングは編集した内容を使います**。だから、よいものが出るまで振り直すより、プランを直すほうが早いことがよくあります。

### 聴いてみる {#hearing-it}

**譜面**タブの五線譜の上にプレーヤーがあります。**再生**を押すと、欄にあるとおりのプラン（編集も含めて）を聴けるので、迷っているメロディにレンダリングを使う前に耳で判断できます。演奏中の音符が順に強調表示され、テンポのつまみはプレビューだけを変え、楽譜は変えません。再生を始めると再生バーで鳴っていたものは止まります。2 つ同時に鳴っても誰の役にも立たないからです。ウィンドウを閉じる——またはコードや歌詞に切り替える——と、これも止まるので、止めるボタンが手元にないまま鳴り続けることはありません。

<strong>楽器</strong> は、すべてをピアノで弾く代わりに、スタイルが挙げる楽器で各声部を演奏します。

- <em>electric guitar, drums</em> とあるスタイルなら、ギターで鳴り、コードは別のギターが弾き、下にベースが入ります。歌のラインは声で代わりに鳴らし、インストのメロディは声にしません。
- ドラムを挙げるスタイルにはドラムパートも付き、楽譜自身の拍子に合わせて書かれます（ロックならバックビート、ダンスなら四つ打ち、ジャズならライド、バラードならもっとまばらに）。楽譜には休めるセクションがないので、最初から最後まで鳴ります。
- プレーヤーの横の行に何が選ばれたかが出て、チェックを外すと、本来聞こえるピアノに戻ります。

これはスタイルの読み取りで、レンダリングの読み取りではありません。実際の演奏は YuE2 が決め、楽譜にないパートも加えるので、テイクの音そのものではなく、ふさわしい音色で弾いたプランとして受け取ってください。

<strong>MIDI をダウンロード</strong> は DAW 用に楽譜を保存します。

- 各パートはそれぞれのチャンネルの独立したトラックで、プレビューが使った楽器がそのチャンネルに設定されます。歌のライン、楽器のライン、<strong>コード</strong> のチェックを外さない限りコードネームをコードパートとして（横にベース付き。和声が音符で書かれる唯一の場所です）、スタイルが求めればチャンネル 10 にドラムが入ります。
- 楽器は General MIDI のプログラム番号なので、DAW は自分の音で鳴らします。テンポと拍子もファイルに入っています。
- 途中で拍子が変わるプランは、始まりの拍子で書かれます（記録されるのはそれだけです）。音符はそれぞれの長さを保ちます。

五線の音符をクリックすると、その音符を書いた ABC にカーソルが移ります。

<strong>音域の外。</strong> これらの楽器が弾ける範囲より上や下の音がある楽譜は、収まるまでオクターブ単位でずらして演奏し、プレーヤーの横の行にどれだけずらしたかが出ます。五線、MIDI ファイル、楽譜そのものは変わりません。楽器はすべて同じ音域ではなく、ベースはピアノよりずっと低くまで出るので、楽譜をずらしたときにこの行が出ます。音符のない楽譜は弾くものがないので、そう表示します。

<strong>音源。</strong> プレーヤーには音符のサンプルが必要で、これはアプリに含まれていません。楽器ごとに約 7 MB あり、その楽器を使うプレビューを初めて再生したときに提供元から取得してライブラリに保存するので、以後はオフラインで動きます。<strong>再生</strong> はいまの楽譜に必要なものを取得してから始め、<strong>音を取得</strong> は再生せずに同じものを取得します。前もって用意しておきたい人向けです。

### ピアノロール {#the-piano-roll}

楽譜ウィンドウで**ピアノロール**をクリックすると、視覚的な MIDI エディターが開きます。生の ABC 文字を編集する代わりに、音の高さと時間のインタラクティブなグリッドの上で、メロディを直接見て形作れます。

エディターは楽譜の両方の声部を同時に表示します——**Vocal**（空色のメインの歌メロディ）と **Ins**（暖かい琥珀色の楽器の伴奏）。両方の声部は常に完全に有効で、表示され、選択でき、編集できます。左上の**描画**ボタンで、クリックして追加する新しい音符をどちらの声部に割り当てるかを選びます。

#### 音符の編集 {#editing-notes}

- <strong>音符を加える：</strong>グリッドの空いたセルをクリックすると、その高さと時間に音符ができます。音符はすぐに鳴るので、音程を確かめられます。
- <strong>音符を選ぶ：</strong>音符をクリックすると選択されます。<kbd>Shift</kbd> か <kbd>Ctrl</kbd>/<kbd>Cmd</kbd> を押しながらクリックすると、歌と楽器のパートにまたがって複数選べます。空いた場所で**選択枠**をドラッグすると、全声部のフレーズやパッセージを選べます。<kbd>Ctrl</kbd>+<kbd>A</kbd>（macOS では <kbd>Cmd</kbd>+<kbd>A</kbd>）を押すか**すべて選択**をクリックすると、楽譜のすべての音符を選びます。再生カーソルから曲の終わりまでの音符をすべて選ぶには、<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>A</kbd> か <kbd>Alt</kbd>+<kbd>A</kbd> を押します（またはツールバーの<strong>カーソルから ▶</strong>をクリックします）。
- <strong>音符を動かす：</strong>選んだ音符を横にドラッグすると前後に、縦にドラッグすると音の高さが移ります。複数の音符——歌、楽器、またはその両方——を選んでいるときは、相対的なタイミング、メロディ、歌詞を保ったまま一緒に動きます。
- <strong>長さ：</strong>音符の右端をドラッグすると長くも短くもできます。**スナップ**の選択（1/16、1/8、1/4 音符）で、移動とサイズ変更をきれいな音楽的な区切りに揃えます。
- <strong>音符を消す：</strong>音符をダブルクリックすると消えます。または 1 つ以上選んで <kbd>Delete</kbd> か <kbd>Backspace</kbd> を押します。
- <strong>元に戻す・やり直す：</strong>音符の編集、移動、サイズ変更、追加、削除はすべて履歴に残ります。<kbd>Ctrl</kbd>+<kbd>Z</kbd>（<kbd>Cmd</kbd>+<kbd>Z</kbd>）で元に戻し、<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> か <kbd>Ctrl</kbd>+<kbd>Y</kbd> でやり直します。
- <strong>鍵盤を聴く：</strong>左のピアノ鍵盤のキーをクリックすると、その高さの音が鳴ります。
- <strong>最大化：</strong>上部バーの**最大化**をクリックすると、ピアノロールがブラウザーのウィンドウの横幅いっぱいに広がります。

#### タイムライン、セクション、コード {#timeline-sections-and-chords}

上のルーラーに沿って、タイムラインが小節番号とセクションの境目を表示します。
- <strong>セクションの名前を変える：</strong>セクションの印（`intro`、`verse`、`chorus` など）をクリックすると、名前を編集したり割り当て直したりできます。
- <strong>コードを編集する：</strong>小節ルーラーのすぐ下に、曲のコード進行を示すコードトラックがあります。既存のコードをクリックすると名前を変えられ（たとえば `C` を `Am7` や `G/B` に）、空の小節をクリックすると新しいコードを置けます。
- <strong>空の小節にハーモニーを付ける（空白を埋める）：</strong>ツールバーの**空白を埋める**をクリックすると、楽器の伴奏の空いた小節を、コード進行から作った音符で埋めます。
- **空の小節を取り除く（空白を詰める）：** **空白を詰める**をクリックすると、両方の声部で空いていて無音の小節を取り除き、後ろの音符とコードを左に詰めて、アレンジの不要な隙間をなくします。

#### 歌詞とカラオケ表示 {#lyrics-and-karaoke-tracking}

ピアノロールの下部では、専用の歌詞トラックが各音節を歌メロディに合わせます。
- **フレーズに合わせる：** **歌詞を割り当て**をクリックすると、歌詞を歌メロディに割り振ります。メロディのフレーズのあいだの自然な息継ぎと休符を見つけ、歌詞の各行をそのフレーズに割り当てるので、言葉が休符を越えて次の小節にはみ出すことはありません。複数音節の単語は音符にきれいに分けられます。
- <strong>音節を編集する：</strong>歌詞のラベルをクリックする（または歌の音符を選んで <kbd>L</kbd> を押す）と、その文字を編集できます。音節をスペースかハイフンで区切って入力すると（たとえば `Hel- lo world`）、続く歌の音符に自動的に割り振られます。
- <strong>マウスを重ねて強調：</strong>歌詞のラベルにマウスを重ねるとグリッドの対応する音符が強調され、歌の音符に重ねると下のラベルが強調されます。
- <strong>カラオケのボール：</strong>再生中は、アニメーションのボールが歌われている音符の上を跳ね、今の音節とグリッドの音符がリアルタイムで光ります。

#### 再生とハーモニーの伴奏 {#playback-and-harmony-accompaniment}

<kbd>Space</kbd> を押すか<strong>▶ 再生</strong>をクリックすると、カーソルの位置から再生を始めます。再生線がグリッドを走り、小節、拍、経過時間のカウンターを更新します。

- <strong>聞こえるクリック（メトロノーム）：</strong>再生には既定でクリック音が入り、各小節の 1 拍目はアクセントの付いたウッドブロック、ほかの拍はやわらかいクリックです。<kbd>C</kbd> か <kbd>M</kbd> を押す（またはトランスポートバーの**クリック**をクリックする）と、いつでもメトロノームのオンとオフを切り替えられます。
- <strong>コードのハーモニー伴奏：</strong>再生では、楽譜のコード進行から暖かいポリフォニックなコードのパッドを直接合成します。歌や楽器のトラックが休んでいるところでも、ハーモニーの空間は音楽的で暖かいままで、死んだような無音にはなりません。<kbd>H</kbd> を押す（またはトランスポートバーの**コード**をクリックする）と、コード伴奏のオンとオフを切り替えます。
- **小節単位で移動：**<kbd>左矢印</kbd> と <kbd>右矢印</kbd> で 1 小節ずつ前後に動き、<kbd>Home</kbd> でまっすぐ先頭に戻ります。

### ハーモニー {#harmony}

放っておくと、YuE2 は 4 つのコードのループを書いてそこにとどまりがちです。**ハーモニー**スライダーは、曲の構成を壊さずに、直前に使ったコードから引き離します。

| レベル | 得られるもの |
|---|---|
| おなじみ | YuE2 のコード。曲全体でループひとつのことが多い |
| 多彩 | 同じコードの繰り返しを避ける。調の中にとどまる |
| カラフル | ヴァースとコーラスが別のコード進行になり、コードが豊かになる。セクションは前と同じ始まり方をできない |
| 冒険的 | ハーモニーを動かし続け、調の外からコードを借りる |
| 調の外 | 大胆で、調からさらに離れる |

**新しいプランを書く**はスライダーの今の位置を使うので、同じ歌詞のまま、もっと大胆なコードで振り直して比べられます。

これは推測ではなく測定したものです——歌詞ひとつ、スタイル 2 つ、それぞれシード 3 つ：

| | おなじみ | 多彩 | カラフル | 冒険的 | 調の外 |
|---|---|---|---|---|---|
| 1 曲の中の異なるコードの数 | 4.7 | 6.3 | 8.7 | 9.0 | 10.3 |
| 調の外のコードがある小節 | 0% | 0% | 0% | 13% | 24% |
| 繰り返さない 4 小節のパターン | 29% | 38% | 50% | 63% | 64% |

どのレベルのどのプランも、正しいセクションとコードを保ちました。代わりにスタイルの文章で大胆なハーモニーを頼んでも——「jazz harmony」「borrowed chords」——測定できる効果はまったくありませんでした。

### プランの多様さ {#plan-variety}

*詳細*の**プランの多様さ**は、プランナーがどれだけ自由に書くかを決めます。ハーモニーがコードに作用するのに対し、こちらはすべてに作用します。メロディ、構成、長さです。

- <strong>穏やか：</strong>いちばん安定。コードは少なく、メロディはあまりさまよいません。
- <strong>標準：</strong>既定値です。
- <strong>快活：</strong>コードと展開が少し増えます。
- <strong>大胆：</strong>より豊かなハーモニー。コードの語彙はふだんの約 3 倍ですが、メロディは同じ種類だとはっきりわかるままです。
- <strong>風変わり：</strong>落ち着きがありません。コードは変わり続け、メロディはセクションごとに音域を跳び移ります。奇妙で風変わりな曲に。
- <strong>ワイルド：</strong>いちばん落ち着きがなく、途中で調が変わることもあります。

### 楽譜なしの曲 {#a-song-with-no-score}

**モード**の 3 つ目の選択肢**楽譜なし**は、プランをまったく使わずに歌詞を歌います。YuE2 は歌いながらメロディとコードを書き、元の YuE と同じです。曲は**楽譜なしで歌う**ですぐにレンダリングされます。プランのある曲とはかなり違って聞こえることがよくあります。

プランを導くものがここでは作用する対象を持たないので、これを選ぶと**ハーモニー**、**プランの多様さ**、**このメロディを残す**、**この構成に正確に従う**はグレー表示になり、読んだり編集したりする楽譜もありません。長さは上限の範囲で YuE2 が決めます。調の固定とテンポの固定は、スタイルの中の言葉としてしか届きません。もう一度歌う、バリエーション、もっと試す、新しい歌詞はすべて使え、どれも楽譜なしで歌い直されます。**新しいプランを書く**でテイクに楽譜が付き、モードは*フル*に戻ります。これはプロンプトからの曲だけのものです。カバーは録音の楽譜そのもので、インストは声を締め出すために楽譜が必要だからです。どちらのエンジンでも使えます。

## レンダリング {#rendering}

### 解釈 {#interpretation}

楽譜が音符を決めます。**解釈**は、それをどう演奏するかを決めます。

| 解釈 | 聞こえるもの |
|---|---|
| 標準 | YuE2 のふだんの読み方 |
| タイト | より引き締まって洗練されている |
| ルーズ | より荒々しく自然発生的 |
| 落ち着いた | 音型を繰り返してグルーヴにとどまってよい |
| 落ち着きのない | パートを動かし続け、繰り返しを避ける |
| ワイド | ありきたりでない音を探す |

### バリエーション {#variations}

カードのきらめきボタンは、**同じ楽譜と同じシード**をほかの解釈でレンダリングします。変わるのは解釈だけなので、それぞれの違いとして聞こえるのは解釈そのものです——サイコロの振り直しではありません。それぞれが独立したテイクで、タイトルは
*Night drive · Loose* となり、元になったテイクの中に保存されます（「ライブラリ」の**テイクの中のテイク**を参照）。ウィンドウには独自の長さの上限があり、エディターの上限から始まり、これらのテイクにだけ適用されます。

### もっと試す {#try-more}

カードのサイコロボタンは、**同じ楽譜と同じ歌詞をもう一度、いくつかの新しいテイクとして**レンダリングし、一緒に聴けるようにします。バリエーションは解釈だけを変えてシードを保ちますが、こちらは出目を変えます。

- <strong>新しいシード：</strong>それぞれに新しいシード。ほかはすべて同じです。
- <strong>プランナーの強さ：</strong>プランナー部分を持つスタイル LoRA を使ったテイクで、同じシードのままほかのプランナーの強さを使います（自分の値は除きます）。プランナーは声だけでなく演奏そのものを変えるので、別のシードのように働きます。

新しいテイクのタイトルは *Night drive · try 1* や *Night drive · planner 0.60* となり、元になったテイクの中に保存されます。そのテイクのパネルが開き、できあがるたびに表示されます。互いに聴き比べるには、パネルを開いたまま**すべて選択**を押し、次に**比較**を押します。ウィンドウには独自の長さの上限があり、テイクの上限から始まります。

### シードと、テイクの再現 {#seed-and-reproducing-a-take}

各テイクはシードと、形作ったすべての設定を記録します。カードがそれらを示し、カードをクリックするとテイクパネルに表示され、エディターで開くとすべてが読み込み直されます。**もう一度**はシードも含めてまったく同じ内容でエディターを開くので、気に入ったテイクを再現したり、もう少しで気に入りそうだったテイクの設定を 1 つずつ変えたりできます。

エディターのメニューでは、解釈にマウスを重ねると、それが何をするかが表示されます。

**このシードを保つ**にチェックを入れると、レンダリングのあいだ同じシードを保ちます。外すと、レンダリングのたびに新しいシードが引かれます。

レンダリングはエディターに表示されているものを使います。スタイル、スタイル LoRA とその強さ、長さの上限、モード、解釈、シードです。テイク自身の楽譜をレンダリングし直すときも同じです。

### 同じメロディ、新しい歌詞 {#same-tune-new-words}

プランナーは音符を 1 つ書く前に歌詞全体を読むので、同じシードが同じプランになるのは同じ歌詞のときだけです。1 行変えると次のプランは新しいメロディになります。別の旋律、多くの場合別の調とテンポで、声もそれに合わせて変わります。

気に入ったメロディを残すには：

1. テイクを開いて歌詞を変えます。歌詞の下にチェックの入った <strong>このメロディを残す</strong> が現れ、メインボタンが <strong>新しい歌詞で歌う</strong> に変わります。
2. ほかに変えたいもの（スタイル、LoRA とその強さ、長さの上限、解釈）を先に変えます。声をできるだけ近く保つには、シードにチェックを入れたままにします。
3. <strong>新しい歌詞で歌う</strong> を押します。テイクの楽譜が新しい歌詞で歌われ、元のテイクの横に新しいテイクとしてできます。元のテイクはそのまま残ります。

代わりに、その歌詞のための新しいプランと新しいメロディを書くには、<strong>このメロディを残す</strong> のチェックを外します。

元の行と音節数がそろった新しい歌詞が、いちばんメロディに合います。合わないときは、<strong>このメロディを残す</strong> が理由を示す行とともに自動で外れ、歌詞のための新しいプランが書かれます。それでもメロディを歌わせたいときは、チェックを入れ直してください。歌詞が合わないのは次の場合です。

- <strong>セクションが多い、またはメロディの音符よりはるかに音節が多い：</strong> 短い行向けのメロディに長い行を載せると、繰り返されたり抜けたりします。
- <strong>音節がはるかに少ない：</strong> 長い行向けのメロディに短い行を載せると音符が余り、歌い手はそこを自分の言葉で埋めます。

### プロダクションの仕上げ {#production-polish}

**プロダクション仕上げ**は Mothersuperior の Realaudio デコーダー LoRA を適用します。素の YuE2 は中域がこもって聞こえることがよくありますが、これで楽器と声がよりきれいに分かれます。既定はオンです。

### 長さ {#length}

長さの上限は固い天井であって、目標ではありません。曲がいつ終わるかは YuE2 が決め、たいていは自分で終わります。上限は、終わらない曲を止めるだけです。上限は 360 秒から、または設定の**新しいテイクの長さの上限**の値から始まります。そのあと、長い曲が切られないよう音楽に場所を空けます。

- **プロンプトからの曲やインスト**では、プランが書かれたとき、プランのほうが長ければ上限が上がります。プランの長さに 10 秒ほどの余裕を足した値までです。下がることはありません。
- **録音**を選んでいるとき（カバーやインスト）は、上限は録音の楽譜に従い、同じように切り上げられます。

自分で入力した上限はそのまま残り、プランがそれより長いと楽譜ページがそう表示します。

曲が本来どおりに終わらないとき：

- <strong>上限よりずっと長いプラン</strong>（3 分の 1 以上超え、かつ 8 分超）は曲として扱われず、書き直されます。
- <strong>楽譜を過ぎても続くレンダリング</strong> は上限まで鳴り続け、最後の数秒で切れずにフェードアウトし、上限まで行ったことがカードに表示されます。
- <strong>楽譜の最後のセクションが始まる前に終わるレンダリング</strong>（さらにまれ）は、完了とする前に新しいシードでもう一度レンダリングされます。それも早く終わった場合は、最後のセクションの前で止まったとカードに表示されます。<strong>レンダリング</strong> をもう一度押すと再挑戦できます。

## 録音のカバーを作る {#covering-a-recording}

1. オーディオファイルをドロップします。2 GB まで使えます。保存は一度だけで、ハッシュを取るので、同じファイルが二度保存されることはありません。動画ファイル（MP4、MOV、MKV、WebM など）も使えます。音だけが FLAC として残ります。
2. **採譜**を押します。SheetSage2 がメロディとコードを楽譜欄に書き込みます。結果は録音ごとにキャッシュされるので、同じ曲の 2 つ目のカバーではこの手順を飛ばします。
3. 聞き間違えたところを直します。
4. 歌詞を加え、スタイルを選び、**カバーを作成**を押します。

カバーは原曲のメロディとコードに従い、それ以外はすべてスタイルが決めます。それがコピーではなくカバーである理由です。

### 自分のメロディを録音する {#recording-a-tune-of-your-own}

> [!NOTE]
> メロディがどれだけうまく検出されるかは録音しだいで、それをもとに作ったプランも外れたり
> さまよったりすることがあります。新しいプランを書くか、メロディを録り直してください。

**カバー**モードでは、**メロディを録音**でレコーダーが開きます。何を録音するかを**入力**で選びます。

- <strong>声：</strong>マイクに向かって歌うかハミングします。**オートチューン**で録音を調と音階に合わせられます。録音のボタンで、補正したものと元のものを切り替えて、何をしたかを聴き比べられます。
- <strong>楽器：</strong>楽器でメロディを弾きます。たとえばオーディオインターフェースにつないだギターです。
  **1 音ずつ**弾いてください。弾いたラインが歌われるメロディになり、かき鳴らしたコードからは歌うメロディは生まれません。**デバイス**でインターフェースを、**チャンネル**で楽器をつないだ側を選びます（インターフェースの入力 1 はふつう**左**です）。楽器の音が小さいときは**入力ゲイン**を上げ、メーターが CLIP に入らないようにします。オートチューンはありません。楽器はもともと音程が合っているからです。Yeufonic はこれらの選択をこのブラウザーで覚えます。

メトロノーム、カウントイン、ヘッドホンでのモニターはどちらでも同じです。**カバーに使う**は録音を録音として保存し、リストでは **MIC** か **INST** と表示されます。ほかの録音と同じように採譜してください。録音したメロディはメロディとしてだけ採譜されます。単独のメロディから推測したコードは、そのメロディで作った曲のすべてのコーラスに残ってしまうからです（これより前に採譜した録音は、もう一度採譜するまでコードを保ちます）。メロディは 10〜30 秒あれば十分すぎるほどです。楽器の録音には聞き取る言葉がないので、**歌詞を抽出**はありません。代わりに**歌詞を書く**を使ってください。

<strong>自分の声が遅れて聞こえる？</strong>ブラウザーは、歌ったり弾いたりした音とヘッドホンで聞こえる音のあいだに、わずかな遅れを加えます。オーディオインターフェースにダイレクトモニタリング（遅延ゼロ）があれば、それを使い、レコーダーの**モニター**をオフにしてください。インターフェースから直接、しかも一度だけ自分の音が聞こえます。ヘッドホンは有線のものを使ってください。Bluetooth は独自の遅れを加えます。

#### 曲全体に広げる {#expand-to-full-song}

録音したメロディは、たいてい数小節しかありません。**フルサイズの曲に広げる**は YuE2 に、あなたのメロディを含む曲全体をプランさせます。プランはメロディの調、拍子、テンポで書かれ、すべてのコーラス（選べばすべてのヴァース）にあなたのメロディが入り、曲の残りはその周りに書かれます。そのあと、あなたの録音のカバーとしてレンダリングされます。

- <strong>歌うのは：</strong>男性か女性。メロディはオクターブ単位で、その声が歌う位置へ移されます。メロディがどのオクターブに書かれているかで、誰が歌うかが決まるからです。スタイルに歌い手が書かれていなければ、声が加えられます。
- <strong>コード：</strong>メロディだけだと、採譜から戻ってきたときにコードがないことがよくあります。その場合 Yeufonic は、メロディ自身の音符からコードを付け、プランナーがたどるハーモニーを用意します。録音の楽譜にあなたが書いたコードはそのまま残ります。
- **あなたのメロディ**は、エディターがそこから作ったテイクを表示しているときでも、常に録音の楽譜です。
- <strong>曲の構成：</strong>歌詞欄が空のときに使われます。欄に言葉があれば、そのセクションが構成になり、メロディを置く **[Chorus]**（または **[Verse]**）が必要です。
- <strong>歌詞：</strong>ハミングは歌詞なしでもプランできます。楽器で弾いたメロディを歌わせるには歌詞が必要なので、先に書いてください。**歌詞を書く**が下書きします。

### MIDI ファイルとカバー {#midi-files-and-covers}

> [!NOTE]
> MIDI ファイルは、オリジナルのメロディから、ひと味違う、ときに風変わりなテイクを作るためのものです。

録音したオーディオファイルのほかに、標準 MIDI ファイル（`.mid`、`.midi`）を**カバー**モードに直接ドロップしたりアップロードしたりできます。

MIDI ファイルをアップロードすると：
- <strong>楽譜の自動採譜：</strong>Yeufonic はトラックとチャンネルを解析して、メインの歌メロディ、伴奏、コード進行を見つけ、ABC 記譜法に採譜してピアノロールに直接読み込みます。低い音域のシンセリードやシーケンスされた歌メロディは、自然に歌えるオクターブへ自動的に移調されます。
- <strong>埋め込まれた歌詞：</strong>MIDI シーケンスに埋め込まれた歌詞やテキストのイベントが取り出され、メロディの音節に合わせられます。
- <strong>小節の区切り：</strong>MIDI ファイルには自分の小節線がなく、最初の言葉が強拍の*前*の拍にあるものもあります。Yeufonic はドラムとベースを読んで本当の小節線を見つけ、ファイルがそうした弱起で始まる場合は、最初の言葉を独立した短い小節に入れて、コードと小節の印が曲の実際の位置に来るようにします。ドラムとベースのパターンがはっきりしないファイルは、そのままにします。
- <strong>貼り付けた歌詞：</strong>貼り付けた言葉は、メロディ全体に一度に合わせられます。1 つの音符に 1 音節で、余った音符は直前の音節を伸ばします。行はメロディが休むところで終わり、フレーズが始まるところで始まるので、歌詞の見出しより長い、または短いセクションがあっても、残りがずれることはなくなりました。言葉がメロディに乗り切らないほど多いときは、最後の数行が省かれます。
- <strong>SoundFont での全体試聴：</strong>プレーヤーは **FluidSynth** と General MIDI の SoundFont（`.sf2`）で、MIDI のアレンジを高音質のオーディオに合成します。出力はピークでノーマライズされるので、小さな音のマルチトラック MIDI 録音も、歪まずに存在感とはっきりした音で聞こえます。
- **SoundFont を選ぶ：** **設定**で、使いたい `.sf2` SoundFont バンク（*Arachno SoundFont 1.0* や *JNS-GM 2.0* など）を選べます。`data/models/soundfonts/sf2/` に置いたほかの `.sf2` ファイルは自動的に見つかります。
- **ピアノロールで調整：** **ピアノロール**を開いて、音符を確かめたり変えたり、どのトラックをメインの歌メロディにするか選んだり、伴奏の隙間を**空白を埋める**でハーモニー付けしたり、貼り付けたばかりの歌詞を**歌詞を割り当て**で合わせたりできます。

### コーパスの曲をカバーする {#covering-a-song-from-a-corpus}

コーパスの解析で、カバーに必要なことはもう済んでいます。楽譜、曲の中で聞き取った言葉、分離した声です。そのため、あなたの録音の下に、リストは**あなたのコーパスから**を表示します。コーパスごとに畳まれ、各曲の調とテンポが並び、大きなコーパスには絞り込み欄があります。曲を選ぶとすぐに、楽譜と歌詞を持ったあなたの録音のひとつになり、何も再実行されません。言葉は楽譜のセクションの下に、**歌詞を抽出**と同じやり方で並べられます。ただしコーパスで確認済みなら、あなたが残したとおりの形で届きます。言葉は歌詞欄に入り、別の録音から来た言葉を置き換えます。そこであなたが入力したり編集したりした言葉は、そう指示したときだけ置き換えられます。スタイル欄には、その曲がコーパスで学習されたときのスタイルが入ります。それで学習した LoRA の下に並ぶ、その曲のチップと同じものです。

ディスクが許せばファイルはコピーではなくリンクされるので、余分な場所を取らず、コーパスを削除しても残ります。*score: melody only* や *score: first 4 min* と印の付いた曲もあります。解析中に完全な採譜に失敗したもので、学習にはそれで足ります。コード付きの完全な楽譜にするには**採譜**を押します。

<strong>LoRA と組み合わせる。</strong>コーパスの曲がいちばん役立つのはここです。同じ作品から作った曲と LoRA、あるいは違う作品から作ったものです。
1. **カバー**モードで録音のリストを開き、**あなたのコーパスから**から曲を選びます。その楽譜がメロディとコードを決め、歌詞は欄に入っています。
2. **スタイル LoRA**を選びます。そのコーパス自身の LoRA なら、その歌い手が自分の曲をカバーし、原曲にいちばん近くなります。別のコーパスの LoRA なら、そちらのスタイルと声でカバーします。
3. 強さはほかのカバーと同じように設定します。録音がすでにメロディを決めているので、**サウンド**は
   **0.50** 前後に保ち、LoRA の声と音をもっと出したいときに上げます。
4. スタイル欄にはすでにその曲自身のスタイルが入っていて、LoRA を選ぶとそのトリガーワードが先頭に付きます。これで曲のジャンルと雰囲気が保たれます。別のチップや絞り込みのタグを使えば、別の方向に持っていけます。テンポと調は、スタイルに何が書いてあっても楽譜から来ます。
5. **カバーを作成**を押します。そのあと**バリエーション**でほかの解釈にレンダリングし、**もう一度歌う**で同じ楽譜に別の声を付けられます。どのテイクでも同じです。

### 歌詞を取り出す {#extracting-the-lyrics}

<em>採譜</em> の横の <strong>歌詞を抽出</strong> は、録音が歌っている内容を書き出します。声を分離して聞き取り、楽譜のセクションの下に行を並べます。楽譜の採譜が数秒で済むのに対してこちらは数分かかるので、採譜のたびにではなく、求めたときに行います。

- <strong>どこで動くか。</strong> エンジンに Demucs と Whisper があれば GPU で、なければ CPU で、声を分離して言葉を聞き取ります（設定の <strong>ステムと歌詞に GPU を使う</strong>）。バーにはいま 2 つの段階のどちらかが出ます。GPU と CPU の Whisper は、どちらも正確ではないため、同じボーカルに同じ言葉を書くとは限りません。リードの上にバックコーラスが重なるような難しいボーカルでは、言葉の 5 分の 1 ほど違うこともあります。
- <strong>やり直すとき。</strong> 分離したボーカルは残るので、同じ録音から再び抽出すると聞き取りから始まり、待ち時間の大半が省けます。
- <strong>言葉は録音と一緒に保存されます。</strong> もう一度 <strong>歌詞を抽出</strong> を押すとすぐ欄に戻り、抽出し直すかどうかを尋ねられます。設定で方法を変えたあとはやり直す価値があります。別の録音を選ぶと同じようにその言葉が入り、言葉のない録音を選ぶと前の言葉は消えます。入力や編集した言葉は、置き換えに同意しない限り残ります。

書き起こしではなく、よい下書きだと考えてください。2 曲の実際の歌詞と比べると、Whisper の誤りは一方で <strong>言葉の 1.5%</strong>、もう一方で <strong>25%</strong> でした。後者は最後のコーラスでリードとバックコーラスが重なる曲です。ボーカル全体を聞きます。以前は声の検出器が無音と判断した部分を飛ばしていましたが、歌のボーカルではそれが曲の大半でした。下書きを読み、聞き間違いを直してください。声が重なるところは特に注意が必要です。

<strong>外部 LLM に聞かせる。</strong> [外部 LLM](#external-llm) をプロバイダーにしている場合、設定の <em>録音からの歌詞</em> に選択肢があります。<strong>外部 LLM</strong> にすると、分離したボーカルがモデルに送られて言葉を聞き取り、各行がいつ歌われるかは引き続き Whisper が決めます。

- 音声を受け付けるモデル（Gemini など）が必要です。同じ 2 曲で Gemini は <strong>1.5% と 23%</strong> だったので、両者は近い結果です。Whisper が苦戦する曲で両方を試してください。
- モデルの返答が歌詞らしく見えれば、Whisper の言葉とかなり違っていてもその言葉を使います。ミックスに埋もれたボーカルは Whisper がいちばん苦手とするところで、モデルはそうではありません。
- モデルが音声を拒んだり、控えめに返したり（行を短く切る、歌詞サイトを案内するなど。知っている曲に対してモデルがそうすることがあります）、ほとんど何も返さなかったりした場合は、代わりに Whisper の版になります。
- 終わったときのメッセージに、どちらが言葉を聞き取ったかが出ます。
- このとき、ボーカルはあなたのマシンの外へ送られます。Whisper ならボーカルはここに留まります。

<strong>コーパスの曲では両方の版が残ります。</strong> 両方あるとき、曲のレビュー欄には各版と単語数を並べた <strong>言葉の出どころ</strong> が表示され、既定では外部モデルの版が使われます。もう一方を選ぶと、その言葉が欄に入ります。ある版を初めて選んだときにその言葉が下書きされ、外部モデルでセクションが付けられます。以後は各版が自分の言葉、編集、<strong>確認済み</strong> のチェックを持つので、切り替えはすぐで、モデルを呼びません。Whisper 自身の行では、同じ言葉が 8 回を超えて続く場合（何百回も書いた伸ばした「la」など）、8 回に切り詰められます。

## インスト {#instrumentals}

3 つ目のモードは、声のない曲を書きます。歌詞の代わりに**構成**を受け取ります。

| 構成 | YuE2 が受け取るもの | 誰が決めるか |
|---|---|---|
| YuE2 に任せる | `[instrumental]` | YuE2 がセクションとその長さを選ぶ |
| セクション | `[intro] [verse] [chorus] …` | セクションはあなたが、長さは YuE2 が選ぶ |
| 時間指定のセクション | `[intro 0:00-0:15] …` | どちらもあなたが選ぶ |

**+** のチップでセクションを加え、矢印で並べ替え、時間指定モードでは各セクションに長さを与えます。
<strong>YuE2 に送信：</strong>には、モデルが受け取るものがそのまま表示されます。構成は目安です。YuE2 はセクションの名前を変えたり、間奏を加えたり、指定した時間を超えたりすることがあるので、長さの上限が固い天井です。

### 録音からのインスト {#an-instrumental-from-a-recording}

エディター上部の<strong>録音から（任意）</strong>は、カバーと同じように録音をひとつ使います。その採譜が楽譜になるのでプランを書く必要はなく、レンダリングはインスト用の LoRA でそのメロディとコードを演奏します。

セクションも楽譜から来ます。楽譜のセクションごとにひとつで、LoRA が知っている名前が付きます（<em>間奏</em> はブリッジになります）。レンダリングは構成の各セクションを楽譜のセクションと組み合わせるので、構成ビルダーはそれらに場所を譲ります。

<strong>曲を並べ替える。</strong> 変更するたびに楽譜が書き換えられます（楽譜ウィンドウに表示されます）。

- セクションを別の場所へドラッグするか、矢印で動かします。
- セクションの直後にその <strong>コピー</strong> を加えます。
- <strong>✕</strong> でセクションを取り除きます。
- <strong>元のセクションに戻す</strong> は、別の楽譜を読み込むまで、元のセクションに戻します。

<strong>再生を追う。</strong> エディターでテイクが再生されているあいだ、いまのセクションが点灯し、セクションをダブルクリックするとそこへ移ります。時間は楽譜の小節とテンポから来ており、レンダリングはテイクの前半と、最後までレンダリングされたテイクではそれによく沿います。楽譜よりかなり早く終わるレンダリングは楽譜にある音楽より少なく演奏しているので、曲が進むにつれてリストが音とずれることがあります。リストの下の行がそう示し、どれだけずれたかも示します。

<strong>歌詞と長さ。</strong> カバーでは歌詞の下に同じリストが出て、歌詞は順番にセクションへ割り当てられるので、それに合わせて変えてください。セクションを足したり、取ったり、並べ替えたりすると、何が必要かをリストが示します。リストは合計時間と長さの上限も並べて示し、長い曲が切れてしまうときは上限を上げるよう提案します。<strong>インストを作成</strong> を押すとレンダリングします。

構成から書いたインストにも楽譜があり、プランができたあとはそのセクションも同じように並びます。構成のビルダーはまだ書かれていないプランへの依頼なので、リストに場所を譲ります。セクションを並べ替えて**この楽譜をレンダリング**を押すと、レンダリングのセクションタグは編集した楽譜に従います。すでにオーディオのあるテイクは、何を変えても隣に新しいテイクとしてレンダリングされるので、元のテイクは自分のものを保ちます。**新しいプランを書く**（楽譜の下）は、引き続きテイクを書いたときの構成から別のメロディを求めます。

<strong>歌のある曲でも使えます。</strong>その楽譜では歌のメロディが歌のパートにあり、そのままでは歌われてしまうので、メロディは楽器に渡されます。楽器が鳴っていないところでは歌の音符が楽器に移り、歌のパートにはコードだけが残ります。エディターはそのことを録音の下に表示します。曲の場合、多くはこちらのほうがよい選択です。声がないと採譜はヴァースとコーラスの違いを見失いがちで、曲全体をひとつのコードループとして聞いてしまうからです。LoRA はこれをインストとしてアレンジするので、ギターが増えるなど、独自のパートが加わると考えてください。

リストで**録音なし：楽譜プランを書く**を選ぶと、プランを書く方法に戻ります。

### インストが歌ってしまうとき {#when-an-instrumental-sings}

ときどき、モデルがインストに声を忍び込ませることがあります。これはモデルのくせで、あなたの設定の間違いではありません。レンダリングの前に、プランが歌の声部に音符を置いていれば、ダイアログが新しいプラン、新しいシード、またはそのままレンダリングを提案します。できあがったテイクは確認されないので、聴いてみてください。

### 曲の楽譜からインストを作る {#an-instrumental-from-a-song-s-score}

エディターの楽譜ページで、曲かカバーの楽譜の下（曲では**この楽譜をレンダリング**の横）にある**インストを作る**は、同じ楽譜からインストを新しいテイクとして作ります。元のテイクはそのままです。歌のメロディは楽器に移り、モデルには歌詞の代わりに楽譜のセクションタグだけが送られ、インスト用の LoRA が使われ、スタイルからは声を描写するタグ（「soft male vocal」）が除かれます。「このメロディを、声なしで」を手に入れる方法はこれです。曲の楽譜の Vocal パートを手で空にするだけでは足りません。曲のレンダリングは、受け取った言葉を歌い続けるからです。

## 声 {#voices}

**ボーカル**のチップは、スタイルに書き込むことで、曲全体の歌い手の性別と声質を決めます。

デュエットや、ヴァースとコーラスで歌い手を変えたいときは、歌詞に声の指示を入れて**声を指示に合わせる**にチェックを入れます。「プロンプトから曲を書く」の[歌詞](#the-words)を参照してください。カバーの歌詞でも使えます。

## コーパスと LoRA の学習 {#corpora-and-training-a-lora}

**コーパス**は曲のフォルダーで、スタイル LoRA の学習セットとして用意したものです。ふつうは 1 組のアーティスト、1 つのジャンル、または似たアーティスト数組です。メニューから**コーパス**を開きます。既定でオンです。アプリに `TRAINING_ENABLED=0` を設定するか、
`WITH_TRAINER=0` でビルドしたエンジンを使うと、この機能はなくなります。

<strong>学習に必要なもの。</strong> 学習はアプリがすることの中でいちばん重い処理です。

- <strong>推奨のフル品質モデル（BF16）</strong> には、少なくとも約 12.5 GB の GPU メモリが必要です（3½ 分の切り出しの場合。長く切り出すほど増えます）。その大半は曲を準備するあいだに使われます。そのため 16 GB のカードと 32 GB のシステム RAM が実用上の最低ラインです。ComfyUI は YuE2 の重み全体とデータセットのキャッシュをホストメモリに置きます（WSL2 では `.wslconfig` に `memory=32GB` を設定します）。
- <strong>省メモリモデル（INT8）</strong> なら 8 GB のカードでも学習できます。
- <strong>学習できないカード</strong> でも、ほかで学習した LoRA は使えます（<strong>LoRA をインストール</strong>）。
- GPU やシステムの空きメモリが少ないと学習ウィンドウが警告するので、先に GPU を使うほかのものはすべて閉じてください。

<strong>手順：</strong>

1. <strong>新しいコーパス。</strong> 名前と <strong>トリガーワード</strong> を付け、声が男性か女性か（ボーカルのない曲なら <strong>なし</strong>。下記参照）を選び、全曲に共通する音を書き、曲の入ったフォルダーを開きます。学習する権利があることを確認し、<strong>フォルダーをスキャン</strong> を押します。フォルダーは読み取るだけです。

   <strong>ボーカルのないコーパス。</strong> ダンスや電子音楽など、曲がインストのときは <strong>声</strong> を <strong>なし</strong> にします。

   - アプリはボーカルを分離せず、言葉も聞き取らないので、シンセの上に言葉がでっち上げられることはありません。
   - 各曲の歌詞は楽譜にあるセクションのタグ（なければ `[instrumental]`）になり、キャプションからはボーカルの部分が省かれ、歌詞のレビューはありません。<strong>セクション</strong> 欄は編集でき、編集は残ります。
   - 各曲の音は、インストールされていればローカルモデルが説明します。外部モデルにはタイトルしか手がかりがないためです。
   - こうして学習した LoRA はプランのボーカルパートに音符を書くことがあり、そうなるとレンダリングが歌ったりハミングしたりします。プランの「歌うかもしれない」の警告がそれを示します。
   - 分析済みのコーパスの声を変えると、歌詞もそれに合わせて変わります。
2. <strong>曲を選ぶ。</strong> 外したい曲のチェックを外します。
   - 曲を準備するとき、アプリはフル録音の自分用のコピーを内部のコーパス保存領域に置くので、元のフォルダーが後で空になったり移動したりしてもコーパスはそのまま残ります。
   - 25 分を超える録音は、1 ファイルにまとまったアルバムやコンサート全体である可能性が高いため外されます。横に `.cue` シートがあれば、<strong>トラックに分ける</strong> で曲ごとに切り分け、それがコーパスでの位置を引き継ぎます。トラックはアプリ自身のフォルダーに置かれ、あなたのフォルダーは変わりません。
   - 15 分のトラックなど、学習器の GPU の限度より長い曲は、書き出しのときに音楽的なセクションの境目で安全に切ってフェードします。
3. <strong>分析。</strong> 各曲のボーカルを分離し、キー、テンポ、セクションを求め、セクションのタグ付きで歌詞を下書きします。
   - 設定で外部 LLM を指定していれば、聞き取った言葉からセクションを付けます。言葉が戻ってくるところをコーラス、間（ま）を新しいセクションとします。送るのは行とそのタイミングだけで、言葉やその順番は変えません。外部 LLM がない場合や、答えにすべての行が含まれない場合は、音楽の分析からタグを付けます。
   - 曲のレビューの保存の横にある <strong>下書きし直す</strong> は、以前に下書きした曲について、曲を聞き直さずに同じ方法でセクションを付け直し、欄の内容を置き換えます。
   - ボタンの下の行に実行中の処理が出て、進行中の分析はメイン画面のジョブカードとキューにも出ます。<strong>停止</strong> で終わります。終わった手順は残るので、<strong>分析</strong> は止まったところから続けます。
   - <strong>再分析。</strong> すべての曲を分析すると、ボタンは <strong>分析済み ✓</strong> になります。クリックすると、最新のプロンプトと LLM の設定で全曲のスタイル提案を分析し直すかを尋ねます（コーパスの名前を変えたりプロバイダーを替えたりしたあとに便利です）。<strong>分析済み ✓</strong> を Shift クリックすると、ゼロからの完全な再分析（ステム分離、キー、テンポ、採譜、スタイルのやり直し）を選べます。曲ごとに、レビューの <strong>再分析</strong> でスタイルだけやり直すこともできます。
4. <strong>レビュー。</strong> 曲を開いて歌詞を確認し、<strong>確認済み</strong> にチェックを入れます。ほかと違う曲は、その音を書き添えます。スタイルのキャプションに、学習器が読む内容が出ます。
5. <strong>学習セットを書き出す。</strong> 各曲の音声、歌詞、キャプションを書き出します。ボタンの下の行に進み具合が出ます。
   - 学習器が使うのは曲の一部だけで、その長さはアプリがグラフィックカードの空きメモリから決めます（16 GB のカードで約 5½ 分。ログウィンドウに選んだ長さが出ます）。
   - それより長い曲は、その範囲内の最後のセクションの終わりで切ってフェードし、まだ歌われている言葉だけを残します。行には「最初の 3:12 を学習」と出ます。
   - 学習でメモリが足りなくなったら、環境設定 `TRAIN_MAX_MINUTES` を 3.5 などの小さい値にしてください（README 参照）。
6. <strong>LoRA を学習。</strong> 時間がかかり、終わるまで GPU はアプリから使えません。
   - 進み具合はボタンの下とメイン画面に出て、そこで止められます。学習中はページ上部のコーパスのバッジが脈打ちます。
   - 学習し直すとき、前回の LoRA は日付付きの名前で <strong>以前の実行</strong> に残すか削除するかを選べます。

### 早く終わってしまった実行 {#a-run-that-ends-early}

実行は最後の手順の前に終わることがあります。<strong>停止</strong>、クラッシュ、GPU のメモリ不足などです。そのときはボタンの下の行に、いつ、なぜ、どの手順のあとだったかが出ます。たいてい作業の大半は残っています。学習器は途中で 50 ステップごとにチェックポイントを保存し、プランナーの損失でここまでで最良のもののコピーも残しているためです。

- <strong>保存されたもので仕上げる</strong> は、それらのファイルから、完了した実行と同じことをします。最良のコピー、なければ最後のチェックポイントが、コーパスの名前とトリガーワードを持つ LoRA になり、チェックポイントはスタイル LoRA のリストでその下にたたまれます。数秒で済み、GPU は使いません。
- 実行の最後のほうのステップは LoRA をいちばん変えないので、こうして仕上げたものはたいてい完全な実行に近くなります。耳で比べたいときは、<strong>チェックポイント</strong> で各ステップで 1 曲ずつレンダリングできます。
- 代わりに実行全体を学習し直すには、<strong>LoRA を学習</strong> を押します。

### すべて実行 {#run-all}

3 つのボタンの横の <strong>すべて実行</strong> は、分析、書き出し、学習を順に行います。待っていたくないコーパス向けで、大きなコーパスの分析には何時間もかかります。最初に以前の LoRA をどうするかを尋ね、そのあとはページを閉じても続きます。

- 分析するのはまだ必要なものだけです。分析に失敗した曲は学習セットから外され、ボタンの下に名前が出ます。誰も確認していない歌詞は下書きのまま使われます。
- 学習の前に、すでにエンジンを使っている処理を待ちます。
- <strong>停止</strong> はその場で止め、終わった分は残します。書き出し中に止めた場合は、先に学習セットを仕上げます。
- アプリを再起動すると止まり、もう一度 <strong>すべて実行</strong> を押すと続きから再開します。

### GPU のメモリが足りなくなったとき {#running-out-of-gpu-memory}

GPU のメモリが足りなくなったジョブはそう表示し、試すことを示します。GPU を使うほかのプログラムを閉じる、長さの上限を下げる、学習なら最も長い曲を外す、などです。エンジンがクラッシュして再起動した場合、実行中だったジョブは失われ、そのことも表示されます。

### 学習した LoRA {#the-trained-lora}

学習が終わると、LoRA はトリガーワード付きで <strong>スタイル LoRA</strong> のリストに現れます。

- <strong>学習した曲。</strong> 選ぶと、学習した曲ごとのチップがスタイル欄の下に出て、クリックするとその曲のスタイルが欄に入ります。曲が 12 を超えると、フィルター欄と、コーパスで繰り返し出てくるタグ（ジャンル、雰囲気、楽器）の列で絞り込めます。2 つのタグをクリックすると両方を持つ曲が見つかります。リストは <strong>すべて表示</strong> を押すまで最初の 12 曲を示します。
- <strong>最初の強さ：</strong> 下の <strong>プランナーとサウンドのバランス</strong> を参照してください。
- <strong>共有する：</strong> コーパスのページの <strong>LoRA をダウンロード</strong>、またはセレクターの下の <strong>ダウンロード</strong> を押します。下の <strong>LoRA を共有する</strong> を参照してください。
- <strong>他の人の LoRA：</strong> <strong>新しいコーパス</strong> の横の <strong>LoRA を読み込む</strong> を押し、その zip を選びます。
- <strong>書き出したセットでほかで学習した LoRA：</strong> <strong>LoRA をインストール</strong> を押してファイルを選びます。このコーパスのトリガーワード付きで、スタイル LoRA のリストに加わります。

**コーパスを削除する**と、アプリが作った曲のコピー、分離した声、歌詞、楽譜が消えます。指定したフォルダーと、そこから作った LoRA には手を付けません。

## スタイル LoRA {#style-loras}

LoRA は、モデルをある音へ傾ける小さなファイルです。`models/loras/` に置いて、セレクターの下の**再スキャン**を押すか、**インストール**を使うと、**スタイル LoRA**のリストに現れます。

スタイル LoRA には 2 つの部分があり得て、セレクターはファイルがどれを持っているかを表示します。

- **プランナー**は演奏される内容を形作ります——楽譜プラン（形式、ハーモニー、フレージング）と、そのあとレンダリングがその楽譜から書く音楽です。両方の段階で働きます。
- **サウンド**はオーディオを形作ります——音色とプロダクションです。

ファイルが使えない強さはグレー表示になり、このエンジンがまったく読み込めないファイルは、レンダリングの中で黙って失敗するのではなく、その旨が表示されます。

### スタイル LoRA の入手先 {#where-to-find-style-loras}

いちばん早いのはインストールのときです。インストーラーのコンポーネントページで**スタイル LoRA**にチェックを入れます（Docker なら
`sh scripts/fetch-models.sh --loras` を実行します）。作者から 39 個のスタイル LoRA、合計 3.8 GB がダウンロードされ、それぞれにトリガーワードと推奨の強さを示す説明が付きます。下のセット、atomtanstudio の 2 つ（dream pop
と old school hip-hop）、そして楽譜だけを形作る ntc-ai の 16 個のコンセプトスライダーです（サウンドは何もせず、トリガーワードも不要です）。これらは手を加えずに
[pshields/yue2-style-loras](https://huggingface.co/pshields/yue2-style-loras) に集められていて、その README は各作者を明記し、元のページにリンクしています。同じ名前の LoRA がすでにフォルダーにあれば、そのままにします。

Hugging Face にはほかにもあります。そこに集められているセットを、各作者のページで紹介します。

- [Militant reggae](https://huggingface.co/becausereasons/yue2-mltnt-militant-reggae)
- [Chanson française](https://huggingface.co/becausereasons/yue2-chnsn-chanson-francaise)
- [Canzone italiana](https://huggingface.co/becausereasons/yue2-cnzn-canzone-italiana)
- [Bulgarian voices](https://huggingface.co/becausereasons/yue2-blgr-bulgarian-voices)
- [Qawwali, sufi and tabla](https://huggingface.co/becausereasons/yue2-qwwl-qawwali-sufi-tabla)
- [J-pop](https://huggingface.co/storagejuju/yue2-jpop-t4-lora)、サウンド部分だけを持つ単独の LoRA

加えるには、リポジトリの **Files** タブからその `.safetensors` ファイルをダウンロードして `models/loras/` に置き、**再スキャン**を押すか、**インストール**を押してファイルを選びます。リポジトリのページには各 LoRA のトリガーワードと推奨の強さが書いてあります。ファイルの横の `.txt` に書いておけば（下の**説明**を参照）、セレクターがそれを表示し、トリガーワードをスタイルの先頭に入れてくれます。ほかから入手した LoRA は、このエンジンが読み込めない形式で保存されていることがあります。セレクターはその旨を表示し、害はありません。

各 LoRA には作者のライセンスが付いていて、これらのセットでは CC BY-NC 4.0 とされています。個人的で非商用の利用で、YuE2 の重みそのものと同じです。LoRA を使う前、またはそれが生み出したものを共有する前に、そのページでライセンスを読んでください。

### プランナーとサウンドのバランス {#balancing-planner-and-sound}

- <strong>まとまりのあるコーパス：</strong>1 枚のアルバムや統一されたアコースティックな音（たとえば 60 年代のフォークロック）で学習した LoRA は、より高い強さに耐え、ふつうは**プランナー ~0.85 / サウンド ~0.80** あたりです。
- <strong>多様なコーパス：</strong>学習用コーパスが複数のジャンル、プロダクションのスタイル、時代（たとえばアコースティックフォーク、ロック、シンセポップ）にまたがる場合、サウンドの重みが高いと音がぶつかり合うことがあります。**プランナー 0.70 / サウンド 0.70** あたりまでなら、アーティストのメロディのフレージングと声の個性を保ったまま、音はきれいなままです。
- <strong>カバー：</strong>録音がメロディを決めるので、LoRA が形作るものは少なく、サウンド部分がより強く押されます。サウンドは **0.50** 前後に保ってください。
- <strong>プランの多様さ：</strong>コーパスから学習した LoRA では、**穏やか**か**標準**がいちばんそれらしい結果になります。**穏やか**はスタイル LoRA と短いスタイルの組み合わせでループに陥ることがあり、そのときプランは何分も続き、長いイントロが繰り返されたり、何も歌われなかったりします。スタイルをもっと詳しく（ジャンル、楽器、雰囲気）書くか、**標準**を使ってください。そうしたプランや曲よりずっと長いプランは、新しいシードで一度だけ書き直され、2 回目も同じならヒント付きでテイクが失敗します。
- <strong>よいテイクを見つける：</strong>LoRA の個性は、強さと同じくらい出目にも左右されます。
  0.3 から 0.6 くらいでは**サウンド**は声をあまり変えないので、上げる必要はありません。**プランナー**は声だけでなく演奏そのものを変えるので、ある曲にぴったりの値が、別の曲ではいちばん弱いこともあります。シードと同じように扱ってください。いくつか（たとえば 0.6、0.8、1.0）と、**もう一度歌う**でいくつかのシードを試し、気に入ったテイクを残します。
- <strong>強さを保存：</strong>ある LoRA に合う組み合わせが見つかったら、セレクターの下の**強さを保存**を押します。以後その LoRA を選ぶとその値から始まり、共有するときにも一緒に付いていきます。

### トリガーワード {#trigger-words}

ほとんどのスタイル LoRA は、トリガーワードで**始まる**説明で学習されていて、それがないとほとんど働きません。アプリがこれを引き受けます。LoRA を選ぶとそのトリガーがスタイルの先頭に入り、別の LoRA に替えると置き換えられ、なしを選ぶと取り除かれ、消されていればレンダリングが元に戻します。スタイル欄に言葉が現れるのが見えます——編集も移動もできます。

### 説明 {#descriptions}

リストはセットごとにまとめられています。見出しをクリックすると開いたり畳んだりでき、セレクターはどれを開いたままにしたかを覚え、今の選択を含むグループはいつも一緒に開きます。

項目にマウスを重ねると、それが何か（作者自身の言葉で）と推奨の強さを読めます。これらの説明は LoRA の横にあるテキストファイルから来ています。

```
CHNSN Rive Gauche
Trigger: chnsn
Step 200, the decoder-loss minimum. The more supple of the two: acoustic
narrative, yé-yé, female leads, waltz meters.
```

1 行目が名前になり、`Trigger:` の行がトリガーワードになり、残りが説明です。自分の LoRA も、横に `.txt` を書けば説明が付きます。同じフォルダーの `families.txt` はグループに見出しを付けます。1 行に 1 つの `prefix = label` です。

### コーパスから学習した LoRA {#loras-trained-from-a-corpus}

自分のコーパスのひとつから学習した LoRA は、ふつうのスタイル LoRA です。ほかの LoRA と一緒にこのリストにトリガーワード付きで現れ、同じ 2 つの強さが使えます。

### チェックポイントを試す {#trying-the-checkpoints}

学習の実行は 50 ステップごとにチェックポイントを保存します。それぞれが、学習のその時点での LoRA です。どれもほぼ同じくらいの出来ですが、学習したものの重み付けがそれぞれ違うので、LoRA が学習したスタイルと特徴的な音を保ちながら、それぞれに好みの違いがあります。

<strong>どこにあるか。</strong> セレクターでその LoRA の下に置かれます。LoRA の名前の横の <strong>▸ 9 ステップ</strong> で開きます（容量を節約するために、設定で代わりに削除させることもできます）。LoRA を削除したチェックポイントは <strong>学習のチェックポイント</strong> の下に残ります。

<strong>いくつか片付ける。</strong> コーパスの <strong>編集</strong> を押すと、そこの <strong>学習のチェックポイント</strong> に、今回と以前の各実行のチェックポイントがサイズ付きで並びます。消すものにチェックを入れて <strong>削除</strong> を押します。完成した LoRA はここには出ず、それ自身の <strong>LoRA を削除</strong> があります。

<strong>並べて聞く：</strong>

1. LoRA を選び、1 つのテイクのときと同じようにエディターを準備します。
2. <strong>LoRA を削除</strong> の横の <strong>チェックポイント</strong> を押します（チェックポイントのない LoRA ではグレーになります）。
3. 欲しいステップにチェックを入れ、必要ならこれらのテイクの長さの上限を決めて、<strong>レンダリング</strong> を押します。

エディター自身の操作が各チェックポイントで 1 回ずつ、すべて同じシードで実行され、各テイクにはステップ名が付きます（<em>Night drive · step 250</em>、<em>Night drive · full</em>）。これらはエディターで開いているテイクの中に、新しい曲の場合はそのうち最後のものの中に置かれます（ライブラリの <strong>テイクの中のテイク</strong> を参照）。エディターは閉じ、テイクが作られているライブラリに戻ります。曲やインストはプランを書いてから、そのままレンダリングに進みます。

曲やインストでは、LoRA は音を形作るだけでなくメロディも書くので、同じシードでも同じ曲にはなりません。各チェックポイントが自分のメロディと構成を書きます。シードはモデルがありそうだと考えるものの中から選び、各チェックポイントは最初の音符から少しずつ考え方が違うので、プランは数小節で分かれていきます。残るのは音です。音だけを比べたいときは、**楽譜**でプランを読み込み、各チェックポイントで順に**この楽譜をレンダリング**を押してください。

新しいファイルは、エンジンが `models/loras/` を見直したときに現れます。オプションを読み込み直すときにそうします。

### LoRA の共有 {#sharing-a-lora}

LoRA を選んでセレクターの下の**ダウンロード**を押すと、LoRA とそのメモが入った zip が手に入ります。コーパスから学習した LoRA では、メモに学習したスタイルが含まれるので、チップも一緒に付いていきます。

送られてきたものを加えるには、**インストール**を押して、その zip か単独の `.safetensors` ファイルを選びます。`models/loras` の**インストール済み**という見出しの下に、名前、トリガーワード、チップ付きで入ります。**LoRA を削除**は選んだ LoRA とそのメモ、グループの行を取り除きます。**再スキャン**は、手でファイルを加えたあとにフォルダーを読み直します。

## ステム {#stems}

どのテイクでも**ステム**を押します。モデルを選び、欲しいパート——ボーカル、ドラム、ベース、その他、モデルによってはギターとピアノ——にチェックを入れて実行します。

エンジンに Demucs があれば分離は **GPU** で行い、エンジンのキューのジョブになります。進行中のレンダリングを待ってから素早く進み、そのうしろにキューされたレンダリングは順番を待ちます。これより前にビルドしたエンジン、学習中の LoRA（GPU を占有します）、設定で**ステムと歌詞に GPU を使う**を「いいえ」にしている場合、または `STEMS_ON_GPU=0` では **CPU** のままです。CPU は遅いですが、レンダリングを遅らせることはありません。*精密*はよりよい分離のために 4 つのモデルを続けて実行し、およそ 4 倍の時間がかかります。

カラオケ用のトラックには**ボーカルと楽器**を選びます。曲を 2 つに分けます。ボーカルと、**楽器**——それ以外すべてをひとつのステムにしたもの——です。**ボーカル**のチェックを外すと楽器だけを残します。これは
4 つのステムと同じ分離をもう一度足し合わせたものなので、かかる時間も同じで、同じくらいきれいに聞こえます。*精密*版がいちばんボーカルを残しません。

ステムは `data/stems/<title>-<id>/` に入り、カードのチップから再生でき、1 つずつ、または
zip でダウンロードできます。削除するまで残ります。

## 止める、削除する、やり直す {#stopping-deleting-and-starting-again}

エンジンが何をしているかは、上部バーの名前の横に表示されます。ジョブと経過時間、進み具合を示す下端の線、うしろで待っているジョブの数が入ったピルです。ジョブが始まったり終わったりしても、ページのほかの部分は何も変わりません。クリックするとジョブカードが開きます。段階、**停止**、そして**次**（待っているジョブ）で、それぞれに**キャンセル**があります。

キュー中や進行中のテイクはカードに**キャンセル**を表示し、ジョブカードの**停止**はエンジンが取り組んでいるものを止めます。ジョブカード、その**次**のリスト、ページ下部のプレーヤーにあるテイクのタイトルをクリックすると、そのテイクに移ります。そのスペースに移り、それを隠している検索やフィルターは解除されます。テイクを削除するとそのジョブが止まり、ステムも消えます。録音の横の**削除**はファイルとそのステムを消します。そこから作ったカバーはオーディオと楽譜を保ちますが、レンダリングし直すことはできません。

テイクパネルの<strong>+ 曲</strong>、**+ カバー**、**+ インスト**、またはエディターのタイトルの横の**新しい曲**は、表示中のテイクからやり直します。タイトル、歌詞、楽譜を消し、既定値から始めます。空のスタイル（LoRA を選んでいればそのトリガーワード付き）、ふだんの長さの上限、ハーモニー「多彩」、標準のプランの多様さ、解釈「ワイド」、プロダクションの仕上げはオン、ノーマライズはオフ、そして新しい固定されていないシードです。選んでいる LoRA と録音は選ばれたままです。表示中のテイクはエディターから切り離されるので、「レンダリング」が誤ってそれに作用することはありません。

入力したのに使わなかった言葉は捨てられません。バーが元に戻すことを提案します。

## ライブラリ {#the-library}

### スペース {#spaces}

テイクは <strong>スペース</strong> に入っています。曲ごと、アルバムごと、またはスケッチ用のスペースです。テイクの上のスペース名がいま表示しているスペースで、作ったものはすべてそこに入ります。

- <strong>スペースを選ぶ：</strong> 名前をクリックするとスペースの一覧が出ます。名前を入力して探すか、矢印キーと Enter で選びます。最近使った 5 つが先頭に、そのあとにすべてのスペースが、それぞれのテイク数付きで並びます。
- <strong>新しいスペース</strong>、<strong>このスペースの名前を変更</strong>、<strong>テイクをインポート</strong>、<strong>このスペースを削除</strong> は一覧の下にあります。スペースを削除してもテイクは消えず、Default に移ります。
- <strong>テイクを移す：</strong> カードのフォルダーボタンで、そのテイクを中に含むテイクごと別のスペースへ移します。
- 録音はすべてのスペースで共有されるので、1 つの録音を複数のスペースでカバーできます。

### テイクの中のテイク {#takes-inside-a-take}

**バリエーション**、**もっと試す**、**チェックポイント**は、どれも 1 曲から複数のテイクを作ります。それらは元になったテイクの**中に**保存されるので、スペースには曲が並び、曲ごとのすべてのレンダリングは並びません。
Checkpoints はエディターで押します。そこにテイクが開いていればその中に入り、まだテイクのない新しい曲なら、最後にチェックしたチェックポイントのテイク（完成した LoRA が含まれていればそれ）がほかのテイクを含みます。

- テイクが、完成したもの、または作成中のテイクを含んでいるとき、カード上部の小さなボタンの中に**中身ボタン**が現れ、**オレンジ色に点灯**します。マウスを重ねると、いくつ完成していて、いくつ残っているかが読めます。カード自体もほかよりはっきり明るくなり（ライトテーマでは暖かい色合い）、中にテイクを持つテイクがリストの中で目立ちます。（隣のマスタリングラックのボタンも、テイクがマスタリングされていると同じように緑色に点灯します。）
- **クリックすると**カードの下にパネルが開き、中のテイクがそれぞれのカードで並びます。テイクは完成するとそこに現れ、作成中は、それが属するテイクだけが表示されます。もう一度ボタンを押すか、**閉じる**で閉じます。
- <strong>テイクの中のテイクも、ふつうのテイクです。</strong>再生、スター、保存、ステムへの分離、名前の変更ができ、ダブルクリックでその曲と楽譜を開きます。
- <strong>1 階層だけ。</strong>テイクの中のテイクはテイクを含まないので、そのカードにはバリエーションももっと試すもなく、それがエディターで開いているあいだは**チェックポイント**がグレー表示になります。**取り出す**（箱から出る矢印）でスペースのリストの独立したテイクにすると、できるようになります。
- <strong>リストの道具はパネルに従います。</strong>パネルが開いているあいだ、**すべて選択**、**スター**、種類のボタン、**比較**、**削除**、プレーヤーの前へ・次へは、パネルのテイクに作用します。パネルが開いているテイクは、フィルターがどうであれページに残ります。
- <strong>中で鳴っているものは外から見えます。</strong>パネルのテイクのひとつを再生中にパネルを閉じると、それを含むテイクの再生ボタンが金色に光り、音がどこから来ているかがわかります。緑色は、そのテイク自体が鳴っていることを引き続き示します。
- **検索ではほかのテイクと同じように見つかります**。どこにあってもです。検索中は、見つかったものがシンプルなカードで表示され、別のテイクの中にあるテイクはどのテイクの中にあるかを示します。
- <strong>テイクを削除すると、中のテイクも削除されます。</strong>警告に数が表示されます。残したいものは先に取り出してください。

この機能ができる前に作ったテイクは、そのままの場所に、リストの中で並んでいます。

### カード {#cards}

各カードは、それを形作った設定を示します——ハーモニー、解釈、録音した声、プランの多様さ、LoRA とその強さ、シード、レンダリングしたエンジン、作成からの時間——なので、カードはそのテイクを作ったレシピとして読めます。タイトルは常に 1 行に収まり、長いときは … で終わります。カードのタイトル、設定、スタイルにマウスを重ねると全文が読めます。

<strong>保存</strong> は、テイクをどの形式でダウンロードするかを尋ねます。前回保存した形式から始まり、初回は何も選ばれていません。

- <strong>FLAC、WAV、MP3：</strong> 音声です。
- <strong>動画</strong>（画像のあるテイク）：カードの画像を映す曲の MP4 です（H.264 映像、192 kbps の AAC 音声）。WhatsApp などのメッセージアプリは、音声ファイルを書類として送るのに対し、これは動画として送って再生します。
- 横の <strong>テイク</strong>：テイクのレシピで、歌詞、スタイル、楽譜、シードと設定、LoRA の名前、マスタリングラックの設定を収めた小さなファイル（`<title>.yeufonic.json`）です。音声は入りません。形式も選ぶと両方が 1 つの zip になり、選んだ形式をもう一度押すとレシピだけを保存します。ファイルにはあなたのインストールの情報（パス、ID、キー）は入らないので、保管したり、ほかの Yeufonic ユーザーと共有したりできます。
- マスタリングラックがオンなら、どの形式もマスタリング後の音になります。

スペースの一覧にある <strong>テイクをインポート</strong> は、そのようなファイルから、表示中のスペースに新しいテイクを作ります。ライブラリにファイルをドロップしても同じです。テイクにはレンダリングできる状態のプランが入っているので、先に確認したり変えたりできます。

- どちらのエンジンでもレンダリングできます。同じエンジンなら同じ楽譜とシードでとてもよく似たテイクになり、別のエンジンでは違うものになります。
- 名前の挙がった LoRA がここにインストールされていなければ、インポート時にその名前を示すので、レンダリング前にインストールするか別のものを選べます。
- カバーの録音はファイルに入らないので、共有されたカバーはカバーの楽譜と歌詞を持つ曲として入り、録音に属していた設定（テンポの固定、ハーモニー、声の指示、長さの上限）は残りません。そこから新しいプランを作ると、プロンプトからの曲と同じように始まります。

<strong>テイクを検索</strong> は、入力したすべての言葉がタイトル、スタイル、歌詞、LoRA 名のどこかにあるテイクを、大文字小文字を区別せずに探します。表示中のスペースの中を探し、入力すると横に出る <strong>すべてのスペース</strong> ではすべてのスペースを探します。別のスペースのカードにはどのスペースかが示されます。× または Escape で消えます。欄はページを開くたびに空で始まり、何か見つかった最近の検索を候補に出します。クリックするか、矢印キーと Enter で選びます。

<strong>表示するものと表示のしかた：</strong>

| 操作 | 何をするか |
|---|---|
| <strong>曲</strong>、<strong>カバー</strong>、<strong>インスト</strong> | その種類のテイクを表示します。1 つ以上を点灯させるか、どれも点灯させなければすべての種類を表示します。 |
| <strong>スター</strong> | スター付きのテイクだけを表示します。もう一度クリックするとすべて表示します。 |
| レイアウトのアイコン | プロンプトがより多く見える広い <strong>ゆったり</strong> のカードか、狭い <strong>コンパクト</strong> のカード。ウィンドウの <strong>幅いっぱい</strong> か中央の列。すべてのテイクを見出し行まで <strong>たたむ</strong>。使用中のものは緑に点灯します。アイコンにマウスを重ねると、クリックで何が起きるかが読めます。 |

テイクをたたんでいるあいだ、カード右上のボタンはそのカードだけを開き、カードの外のどこかをクリックすると再びたたまれます。ステムのあるたたまれたカードには <strong>ステム</strong> のラベルが出て、同じようにそのカードを開きます。

<strong>テイクを選ぶ。</strong> テイクにチェックを入れると、種類とレイアウトの代わりに、それらでできることが列に出ます。選んだ数、<strong>比較</strong>、<strong>削除</strong>、チェックを外す <strong>完了</strong> です。列の端の <strong>すべて選択</strong> は、表示中のすべてのテイクにチェックを入れます。

### テイクごとの画像 {#a-picture-for-each-take}

新しいテイクには、それぞれ曲の画像が付きます。

- <strong>表示される場所：</strong> テイクのカードの背後にうっすらと、選んだときはテイクパネルの上部に、エディターで開いているときはエディターの背後に表示されます。
- <strong>作られるタイミング：</strong> この PC で描く場合は、曲を作っていないときまで待つので、プランやレンダリングを遅らせることはなく、曲ができてから少しして現れます。外部 LLM が描く場合は、テイクのレンダリング中に作られます。
- <strong>作り方</strong> は 2 段階です。テイクのタイトル、スタイル、最初の言葉を画像の <strong>説明</strong> にし、画像モデルがそれを白地に <strong>描き</strong>、白を抜いて透明な背景の画像にします。
- <strong>別のテイクの中で作られたテイク</strong>（さらに試す、バリエーション、チェックポイント）は、自分の画像を持たず、入っている先のテイクの画像を表示します。
- 画像モデルは実在のバンドや人物を描かないので、説明から名前は省かれます。画像そのものの文字は控えめに保たれ、カードの文字と競いません。

#### 2 つの描き方：この PC の FLUX.2 klein、または外部 LLM {#two-ways-to-draw-flux-2-klein-on-this-pc-or-an-external-llm}

画像には、絵を描けるものが必要です。それは 2 つあり、片方、両方、どちらもなし、のいずれでもかまいません。

| | この PC の FLUX.2 klein | 外部 LLM の画像モデル |
|---|---|---|
| 何か | エンジンの中で YuE2 と並んで動く小さな画像モデル | プロバイダー自身の画像モデル。Gemini のものなど |
| 費用 | 無料。ディスクを約 8 GB 使う | 画像 1 枚ごとにプロバイダーへのリクエストになり、課金されることがある |
| PC の外に出るもの | 何も出ない。説明はこの PC の Gemma が書くか、テイク自体から作る | テイクのタイトル、スタイル、最初の言葉、そして説明 |
| いつ動くか | 曲を作っていないときに GPU で。曲のあとで、決して邪魔をしない | レンダリングと並行して、その実行中に |
| 設定するもの | インストール時のオプション | 設定の外部 LLM。画像モデルを提供するプロバイダーが必要 |

**この PC で描くには、FLUX.2 klein をインストールします。**

- <strong>Windows：</strong>インストーラーのコンポーネントページで **FLUX.2 [klein]** にチェックを入れます。自分で選ばない限りチェックは入っていません。インストール済みのアプリは更新のときに同じページが出ます。またはリリースページからインストーラーを実行し直します。チェックはそのあと記憶され、更新で二度ダウンロードされることはありません。ファイルは 3 つで、合計約 8 GB です。
- **Docker：**`sh scripts/fetch-models.sh --pictures` を実行すると、3 つのファイルが `models/`
  （`diffusion_models`、`text_encoders`、`vae`）に置かれ、それぞれが検証されます。そのあと
  `docker compose restart app` でアプリを再起動して、ファイルを見つけさせます。

<strong>FLUX.2 klein 9B、グラフィックカードに余裕があれば。</strong>klein にはより大きなサイズがあり、より高品質なモデルで、細部や手と顔をよりよく描きます。ビデオメモリの多いグラフィックカードだけを想定しています。
Yeufonic はこれを決してダウンロードしません。ファイルは Hugging Face でアクセス申請が必要で、Black Forest Labs の**非商用ライセンス**の下にあるからです。ただし、所定の場所に置けば使われます。

- <strong>ディスク：</strong>ふつうの組み合わせ、FP8 モデルとその FP8 テキストエンコーダーで約 18 GB（FP4 エンコーダーなら
  16 GB）、4B のファイルの横に置きます。4B の VAE（`flux2-vae.safetensors`）が必要なので、先に 4B をインストールしてください。
- <strong>ビデオメモリ：</strong>16 GB のカードで動きますが、描いているあいだはほぼすべてを使い、空きメモリはほぼゼロになります。画像は曲を作っていないときまで待つので曲が遅くなることはありませんが、同時にグラフィックカードを使うほかのプログラムは苦労することがあります。メモリが少なくても動きますが、エンジンがモデルを出し入れするので遅くなります。その場合は 4B のほうがよい選択です。

1. <strong>モデル。</strong>Hugging Face にサインインし、
   [black-forest-labs/FLUX.2-klein-9b-fp8](https://huggingface.co/black-forest-labs/FLUX.2-klein-9b-fp8)
   でライセンスに同意して、`flux-2-klein-9b-fp8.safetensors`（9.4 GB）をダウンロードします。またはフル精度の
   `flux-2-klein-9b.safetensors` を [black-forest-labs/FLUX.2-klein-9B](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B) から入手します。
   Mac 用で、およそ 2 倍の大きさで、2 倍のメモリが必要です。これは `diffusion_models` フォルダーに入れます。
2. <strong>そのテキストエンコーダー。</strong>サインイン不要の
   [Comfy-Org/Flux-2-Klein-9B](https://huggingface.co/Comfy-Org/Flux-2-Klein-9B/tree/main/split_files/text_encoders)
   から次のいずれかをダウンロードし、`text_encoders` フォルダーに入れます。
   `qwen_3_8b_fp8mixed.safetensors`（8.7 GB、NVIDIA カードでのふつうの選択）、`qwen_3_8b_fp4mixed.safetensors`
   （6.8 GB、いちばん小さい）、`qwen_3_8b.safetensors`（16.4 GB、フル精度、Mac 用）。
   **yue2.cpp エンジンでは**、画像サーバーがこれらのエンコーダーを読めません。代わりに
   [unsloth/Qwen3-8B-GGUF](https://huggingface.co/unsloth/Qwen3-8B-GGUF) から `Qwen3-8B-Q4_K_M.gguf`
   （5.0 GB）を入手し（`-Q8_0.gguf`、8.7 GB でも動きます）、同じフォルダーに入れます。
3. **フォルダーの場所：** **Docker** では Yeufonic フォルダーの `models/`、**Windows** ではインストールフォルダーの `engine\ComfyUI\models`、**Mac** ではインストールフォルダーの
   `engine/ComfyUI/models/` です。
4. <strong>アプリに見つけさせて、選びます。</strong>Yeufonic を再起動し（Docker なら `docker compose restart app`）、設定で**テイクの画像：モデル**を *FLUX.2 klein 9B* にします。そうするまでは 4B が描きます。
   9B を選んでいてもここで描けないときは、設定がそう表示します。*4B* を選べば、何も取り除かずに元に戻せます。エディターの画像のメモに、どれが描いたかが表示されます（*drawn by FLUX.2 klein 9B on this PC*）。

モデルとエンコーダーはこの名前でしか見つからないので、ダウンロードしたときのファイル名のままにしておいてください。

<strong>FLUX 3 klein、文字入れと 12 GB 以上のカード向け。</strong>Black Forest Labs の FLUX 3 Image Klein は、シーン全体の説明から描きます。Gemma や外部 LLM が書く画像プロンプトはまさにそれなので、文字もうまく書け、**テイクの画像：画像に曲名**と相性がよいです。9B と同じく、Yeufonic はこれを決してダウンロードしません。ファイルは
Hugging Face でアクセス申請が必要で、**FLUX Kommunity License** の下にあります（非商用の利用と、ライセンスの収益の基準を下回る人による描いたものの商用利用。同意する前に読んでください）。ファイルを所定の場所に置けば、選べるようになります。

- <strong>ディスク：</strong>int8 の組み合わせで約 11 GB、4B のファイルの横に置きます。4B の VAE（`flux2-vae.safetensors`）を使うので、先に 4B をインストールしてください。
- <strong>ビデオメモリ：</strong>描いているあいだ約 11 GB。FLUX.2 klein の何倍ものステップを踏むので、1 枚ごとに時間がかかります。
- <strong>エンジン：</strong>今のところ ComfyUI エンジンだけです。yue2.cpp エンジンでは提供されません。

1. **Hugging Face にサインイン**し、
   [black-forest-labs/flux-3-image-klein-comfy](https://huggingface.co/black-forest-labs/flux-3-image-klein-comfy) でライセンスに同意します。
2. **モデル**を `diffusion_models` フォルダーに入れます。`flux3-image-klein-int8-convrot.safetensors`（5.8 GB、NVIDIA カードでのふつうの選択）、`flux3-image-klein-nvfp4.safetensors`（5.3 GB、RTX 50 カード用）、
   `flux3-image-klein-bf16.safetensors`（11.1 GB、フル精度、Mac 用）のいずれかです。
3. **そのテキストエンコーダー**を `text_encoders` フォルダーに入れます。`qwen3vl_4b_int8_convrot.safetensors`（4.9 GB）か
   `qwen3vl_4b_bf16.safetensors`（8.9 GB、Mac 用）です。
4. <strong>アプリに見つけさせて、選びます。</strong>Yeufonic を再起動し（Docker なら `docker compose restart app`）、設定で**テイクの画像：モデル**を *FLUX 3 klein* にします。エディターの画像のメモには *drawn by
   FLUX 3 klein on this PC* と表示されます。

フォルダーは 9B と同じで、ファイルもこの名前でしか見つかりません。

<strong>FIBO 2.0、写真の質感と 16 GB のカードのために。</strong>Bria の FIBO 2.0 は、画像の手本であるレコードジャケットの本物の写真に最も近く描きます。細部がより鮮明で、自然な被写界深度、フィルムの色を持ち、説明が求めるものもより多く描きます。Yeufonic はこれも決してダウンロードしません。<strong>ライセンスは CC BY-NC 4.0 で、非商用に限られます。</strong>FLUX 3 のライセンスは、収益の上限を下回る人が描いたものを商用に使うことを認めますが、FIBO では、販売する曲のジャケットを含め、どんな商用利用にも Bria との契約が必要です。使う前にライセンスを読んでください。

- <strong>ディスク：</strong>約 10.4 GB。モデルとその turbo アドオンです。FLUX 3 のテキストエンコーダーと 4B の VAE を読むので、FLUX 3 がインストールされていればほかに必要なものはありません。
- <strong>ビデオメモリ：</strong>描いている間は約 12.5 GB なので、16 GB のカードが必要です。小さいカードでは一部を退避させるため、ずっと遅くなります。
- <strong>時間：</strong>turbo アドオンがあれば、FLUX 3 とほぼ同じです。なければ FIBO は自分の設定で描き、約 8 倍かかります。
- <strong>ジャケット：</strong>FIBO が描くとき、写真のまわりの縁には細い暗い線がありません。FIBO はそれを太い帯にし、タイトルを枠で囲んでいたからです。
- <strong>エンジン：</strong>ComfyUI エンジンのみです。

1. <strong>モデル</strong>を [Comfy-Org/Fibo-2.0](https://huggingface.co/Comfy-Org/Fibo-2.0)（サインイン不要）から `diffusion_models` フォルダーに入れます。`fibo2_dev_int8_convrot.safetensors`（8.4 GB、NVIDIA カードでの通常の選択）か `fibo2_dev_bf16.safetensors`（16.5 GB、フル精度、Mac 用）です。
2. <strong>その turbo アドオン</strong>を同じページから `loras` フォルダーに入れます。`fibo_2.0_turbo_lora_avg_rank_270_bf16.safetensors`（2 GB）です。スタイル LoRA ではなく、スタイル LoRA としては表示されません。
3. <strong>そのテキストエンコーダー</strong>を、FLUX 3 がインストールされていなければ、同じページから `text_encoders` フォルダーに入れます。`qwen3vl_4b_int8_convrot.safetensors`（4.9 GB）か `qwen3vl_4b_bf16.safetensors`（8.9 GB、Mac 用）です。
4. <strong>アプリに見つけさせて、選びます。</strong>Yeufonic を再起動し（Docker なら `docker compose restart app`）、設定で<strong>テイクの画像：モデル</strong>を *FIBO 2.0* にします。エディターの画像のメモには *drawn by FIBO 2.0 on this PC* と表示されます。

<strong>外部 LLM で描くには、</strong>設定を開いて**歌詞とスタイルタグを書く LLM**を
[外部 LLM](#external-llm) にし、歌詞のときと同じように **API URL**、**API キー**、**モデル**を入れます。プロバイダーには画像モデルが必要です。Gemini にはあり（別のものを指定しない限り `gemini-3.1-flash-image` を使います）、OpenAI 互換のプロバイダーには `gpt-image-1` を求めます。アプリはバックグラウンドでプロバイダーにモデルの一覧を尋ねます。起動時、これらの設定が変わったとき、そして数時間ごとです。一覧に画像モデルがあるときだけ、そこで描きます。

どちらもないとき、設定の**テイクの画像**には**画像なし：既定の背景**と表示され、入手方法を示す 1 行が付き、作成の選択肢は選べません。どちらかを設定すれば有効になり、それ以降に作るテイクには画像が作られます。

#### 設定での画像の管理 {#managing-pictures-in-settings}

| 設定 | 何をするか |
|---|---|
| **テイクの画像** | *新しいテイクごとに作る*（描けるものがあるときの既定）、または*頼んだときだけ*。後者では、テイクの四角かエディターの「画像」ボタンで作るまで、テイクは既定の背景のままです。下の設定は、どちらの方法で作った画像にも効きます。ここで描けるものが何もないあいだは*画像なし*です。 |
| **テイクの画像：描くもの** | *klein がインストールされていればこの PC、なければ外部 LLM*（既定）、*この PC（下のモデル）*、*外部 LLM の画像モデル*。この PC でどの klein が描くか（FLUX.2 klein 4B か 9B、または FLUX 3 klein）は **モデル**で選びます。FIBO 2.0 もここで選びます。 |
| **テイクの画像：モデル** | *FLUX.2 klein 4B*（既定）、*FLUX.2 klein 9B*、*FLUX 3 klein*、*9B のファイルがあれば 9B、なければ 4B*。この PC で描く画像だけに使います。9B と FLUX 3 は決して自動ではインストールされません。上の [FLUX.2 klein 9B と FLUX 3 klein](#two-ways-to-draw-flux-2-klein-on-this-pc-or-an-external-llm) を参照してください。指定したものがなければ別のものが描き、設定がどれかを表示します。*FIBO 2.0* も手動で追加し、非商用に限られます。上を参照してください。 |
| **テイクの画像：説明するもの** | 誰が画像プロンプトを書くか。テイクのタイトル、下のアートスタイル、テイクのスタイルと歌詞（最大 50 行）から書きます。*ローカルの Gemma があればそれ、なければテイク自体*（既定）。誰が描くかに関係ありません。*ローカルの Gemma*：この PC で書きます。歌詞の下書きのオプションが必要です。*テイク自体から*：LLM を使わず、テイクのタイトル、スタイル、最初の言葉から説明を作ります。いちばん速く、何も送りません。または*外部 LLM*。画像 1 枚につき 1 リクエストです。使えないとき、またはそのセッションでローカル LLM に切り替えたときは、Gemma がインストールされていれば代わりに書きます。 |
| **テイクの画像：アートスタイル** | 画像がどう見えるべきか。画像プロンプトを書く LLM に渡します（テイクが自分で説明するときはグレー表示）。既定は 70 年代と 80 年代のアルバムジャケット風の、抽象的でシュールなデザインで、文字も人物もありません。空にすると既定に戻ります。 |
| **テイクの画像：自分のプロンプト** | 各画像のプロンプトの最初に入る言葉。たとえば *salt marsh, overcast* で、512 文字までです。LLM が書いたプロンプトがそのあとに続きます。空（既定）：なし。LLM が画像プロンプトを書くときだけ使います（テイクが自分で説明するときはグレー表示）。 |
| **テイクの画像：画像に曲名** | *いいえ*（既定）または*はい*：曲のタイトルをジャケットに太字で入れます。入力したとおりの大文字小文字で、アーティスト名であっても入れます（画像自体はそれでも名前なしで説明されます）。たいていは、70 年代の多くのジャケットのように、途切れた白い縁の内側の細い暗い線で囲まれ、タイトルは上か下の広めの帯の中央に置かれます。5 枚に 1 枚ほどは縁がなく、タイトルは画像の上、隅か上下の中央に、画像から取った落ち着いた色で置かれ、LLM にはその部分を空けておくよう頼みます。これらはすべて画像ごとにランダムに選ばれます。FLUX.2 klein は綴りを間違えることがあります。LLM が画像プロンプトを書くときだけ使います。 |
| **テイクの画像：画像モデル** | プロバイダーのどのモデルで描くか。外部 LLM が描く画像だけに使います（**描画**で選びます。そうでなければグレー表示）。空ならプロバイダーのふつうのモデルで、ほとんどの場合それで十分です。 |

つまり FLUX.2 klein をインストールし、設定を既定のままにすれば、画像はすべてこの PC で作られます。外部 LLM が歌詞を書いている場合でもです。歌詞の下書きがインストールされていれば Gemma が各画像プロンプトを書き、なければ説明は LLM を使わずテイク自体から作られ、時間はかかりません。プロバイダーに描かせるには*外部 LLM の画像モデル*を選び、いちばん速い画像には**説明**を*テイク自体から*に、または*外部 LLM*（画像 1 枚につき 1 リクエスト）にします。

#### エディターでのテイクの画像 {#a-take-s-picture-in-the-editor}

エディターウィンドウの最上段、ほかのテイクのボタンの横にある <strong>画像</strong> アイコンは、画像と 2 つの選択肢を表示します。

- <strong>新しい画像を作る</strong> は、バックグラウンドで作り直します。
- <strong>既定の背景を使う</strong> は画像を取り除きます。求めない限り、そのテイクの画像は二度と作られません。

そこで画像をクリックすると、ウィンドウに収まる限り大きく全体を表示します。どこかをクリックするか Escape で閉じ、エディターは元のままです。全体表示の下にも同じ 2 つの選択肢があります。そこで <strong>新しい画像を作る</strong> を選ぶと、新しい画像ができるまで今の画像が表示されたままになり、ボタンのあいだに進行状況が出て、できあがると新しい画像に切り替わります。

テイクのカードでは、左上の四角にマウスを重ねると画像が表示されます。画像のないテイクでは、この PC で画像を作れる場合、代わりにそこに <strong>新しい画像を作る</strong> が出ます。

### テイクを比べる {#comparing-takes}

2〜6 個のテイクにチェックを入れて <strong>比較</strong> を押します（2 つにチェックを入れると「すべて選択」の横に現れ、まだレンダリング中のテイクを待ちます）。テイクは 1 つのウィンドウに重なり、再生位置を共有します。

- <strong>1</strong>〜<strong>6</strong> を押すか、テイクをクリックして切り替えます。再生中でも一時停止中でも、曲の同じ位置から続きます。
- <strong>スペース</strong> で再生と一時停止、矢印キーで 5 秒ずつ移動します。
- スターで好きなほうに印を付けます。
- <strong>ラウドネスをそろえる</strong> は、大きいテイクを最も小さいテイクに合わせて下げます。大きいほうが良く聞こえがちだからです。
- <strong>名前を隠す</strong> はテイクをシャッフルしてテイク A、B、C と呼び、ブラインドで聴けるようにします。

### プレーヤー {#the-player}

波形をクリックまたはドラッグして移動します。前へと次へは、表示されている順にカードをたどります。

| キー | 何をするか |
|---|---|
| スペース | 再生または一時停止 |
| 左、右 | 5 秒戻る、または進む |
| Shift+左、Shift+右 | 前または次のテイク。プレイリストの表示では、プレイリストの前または次の曲 |
| 上、下 | 音量 |

システムのメディアキーも使えます。テイク自身のキーは[キーボードショートカット](#hot-keys)にあります。

### オーディオビジュアライザーと同期歌詞 {#the-audio-visualizer-and-synced-lyrics}

トランスポートバーの**ビジュアライザー**を押す（またはトラック再生中に **V** を押す）と、ビジュアライザーのステージが全画面で開きます。

ステージは、再生と同期したリアルタイムのオーディオビジュアライゼーションを表示します。

- <strong>ビジュアライザーのモード：</strong>上部バーで 11 種類から選べます。
  - <em>Yeufonic：</em>ロゴそのものが呼吸します——タイルは低音で光ってビートで膨らみ、音叉の両腕はそれぞれ半分のスペクトルを示すメーターで、緑の点はビートで光ります。
  - <em>ウェーブリボン：</em>音に反応して漂う 2 本のハーモニックなリボン。
  - <em>オーロラ：</em>中域と高域に反応して揺れる、幻想的なオーロラのカーテン。
  - <em>宇宙の星雲：</em>星空と星間粒子の星雲が、リズムに合わせて回転し脈打ちます。
  - <em>万華鏡：</em>テンポに合わせて脈打つ放射状の幾何学的対称模様。
  - <em>ネオングリッド：</em>レトロフューチャーなシンセウェーブのワイヤーフレームの平面が遠近法で広がり、ベースラインに合わせてうねります。
  - <em>リキッドディストーション：</em>ハーモニックな波でゆがむ流体の表面。
  - <em>パーティクルの群れ：</em>重力に引かれた粒子の群れが、打楽器のアクセントで散ります。
  - <em>Hi-Fi スペクトラムバー：</em>漂いながら落ちるピーク付きのマルチバンド・スペクトラムアナライザー。
  - <em>アートワーク：</em>テイクの画像を大きく、タイトルを下に、音楽に合わせて動く自分自身のぼかしたコピーの上に表示します。画像のないテイクでは、画像ができるまで Yeufonic のシーンを表示します。
  - <em>なし：</em>テイクの画像だけを、暗い背景の上に静止したまま表示します。画像がなければ Yeufonic のマークです。何も動かないので、ほかのシーンが重いコンピューター向けです。
- <strong>シーンの背後：</strong>アートワーク、Yeufonic、マンダラ、グリッド、リキッド、バーの各シーンは、テイクに画像があれば、音楽に合わせてゆっくり動くその画像の上で再生されます。その上で、画像の色を使って何かを動かすこともできます。*呼吸*（画像だけ）、中心から回転する*光線*、ビートで広がる*波紋*、*色の漂い*、*奥行き*（画像のコピーがさらに逆回転し合う）、*スペクトルの光輪*です。各シーンは自分のもので始まり（アートワークの背後は色の漂い、マンダラは光輪、グリッドは光線、リキッドは波紋、Yeufonic とバーは画像だけ）、**B** で切り替えると、シーンが選択を覚えます。
- <strong>波形：</strong>Yeufonic とアートワークのシーンの下では、テイクの波形が曲のどこまで再生したかを示します。クリックするとそこへ飛びます。
- <strong>アートワークとレコードの動き：</strong>テイクのジャケットを Hipgnosis 風に、ポインターに合わせて傾き回転するインタラクティブな 3D のスリーブに入れて表示します。リアルなアナログレコードが 33⅓ 回転で回り、ベースの打音でスリーブから滑り出て、ホログラフィックな光沢と、リズムに反応する衝撃波の輪を伴います。**アートワーク**ボタンでモードを切り替えます。*スリーブ*、*オーラ*（ぼかした背景）、*オフ*です。
- <strong>新しい画像：</strong>各シーンの右上の画像ボタンは、この PC で画像を作れる場合、再生中のテイクの新しい画像を作ります。作っているあいだは脈打ち、できあがると新しい画像に替わります。
- **画面上の歌詞：** **L** を押すか**歌詞**をクリックすると、独立したスクロールできる歌詞パネルを表示または非表示にします。上部のバーをつかんでドラッグすればどかせます。置いた場所にとどまり、バーをダブルクリックすると元の位置に戻ります。
- <strong>ミニプレーヤーのリボン：</strong>フルのビジュアライザーを閉じているあいだは、反応する二重波形のミニビジュアライザーが下部のトランスポートバーの中で再生されます。**設定 → 外観**でオンとオフを切り替えます。

### プレイリストとお気に入り {#playlists-liked-songs}

上部バーの**プレイリスト**をクリックすると、プレイリストの表示に切り替わります。

- <strong>2 列のレイアウト：</strong>左の列には、固定のシステムプレイリスト**お気に入り**と並んであなたのプレイリストが、曲の総数付きで並びます。メインの列には、選んでいるプレイリストのヘッダー（高解像度のカバー、タイトル、説明、曲の総数と長さ）とトラックの表が表示されます。
- <strong>お気に入りの自動同期：</strong>ライブラリでスターを付けたテイクは、どのスペースのものでも自動的にお気に入りのプレイリストに現れます。スターを外すとそこから消えます。
- **プレイリストに加える：** **P** を押すか、どのカードでも**プレイリスト**アイコンをクリックすると、プレイリストの選択が開き、プレイリストへの所属をチェックで切り替えたり、新しいものを作ったりできます。**Esc** で閉じます。
- <strong>並べ替えと検索：</strong>列の見出し（**タイトル**、**長さ**、**追加日**）をクリックすると、方向の表示付きで並べ替え、もう一度クリックで逆順にします。トラックは検索欄で絞り込めます。
- <strong>ライブラリのスペースへ移動：</strong>トラックの表で曲のタイトルをクリックすると、すぐにライブラリの表示に切り替わり、そのテイクがあるスペースを開いてカードを強調します。
- <strong>プレイリストでのショートカット：</strong>プレイリストの表示では、思わぬ変更を防ぐため、テイク専用のショートカットは無視されます。ただし再生中または読み込み中のトラックに作用する **M**（マスタリングラック）と、ふだんのトランスポートの操作（**スペース**、矢印キー、**?**、**L**）は使えます。
- <strong>連続再生とシャッフル：</strong>プレイリストのヘッダーの**再生**で 1 曲目から聴くか、**シャッフル**でランダムな順に聴きます。曲が終わるたびに、自動的にプレイリストの次のトラックへ進みます。

### キーボードショートカット {#hot-keys}

メインページでは、単独のキーは**選んだテイク**、つまり左パネルのテイクに作用します。カードをクリックすると選べます。各キーはそのボタンと同じことをするので、削除するキーは先に確認し、キーの求めることができないテイク（たとえば楽譜のないテイクでのバリエーション）では、ステータスバーに理由を示す 1 行が残ります。

| キー | 何をするか |
|---|---|
| スペース | 再生または一時停止 |
| 左、右 | 5 秒戻る、または進む |
| Shift+左、Shift+右 | 前または次のテイク。プレイリストの表示では、プレイリストの前または次の曲 |
| 上、下 | 音量 |
| M | テイクのマスタリングラックを開く。もう一度で閉じる |
| E | テイクをエディターで開く |
| I | テイクの詳細：作るのに使ったすべてを言葉で、**コピー**付きで |
| N | テイクをノーマライズする。ノーマライズ済みなら元に戻す |
| V | 再生中はビジュアライザーを開閉、停止中はバリエーション |
| T | もっと試す |
| S | テイクにスターを付ける、または外す |
| P | テイクをプレイリストに加える |
| D | 確認してからテイクを削除する。ごみ箱ボタンと同じ |
| L | ログ。ビジュアライザーを開いているときは歌詞を表示 |

エディターウィンドウでは、そのウィンドウのプレーヤーが表示されているとき——どの段階でも、マスタリングラックを上に開いているときも——スペースと矢印キーがそのプレーヤーを操作し、そこで開いているテイクに作用します。欄に入力しているあいだは決して働かず、文字のキーはメインページだけのものです。ピアノロールには専用のキーがあります。[ピアノロール](#the-piano-roll)を参照してください。

## 設定 {#settings}

左上の **Yeufonic** をクリックします。設定はサーバーに保存されるので、どのブラウザーでも引き継がれ、再ビルドしても残ります。ステムとテイクの保存に使う出力オーディオの形式、分離モデル、ステムを書き出す場所、学習のチェックポイントを残すかどうか、インストが歌わないことをどう確かめるか、などです。

### ストレージ {#storage}

**設定 → ストレージ**は、Yeufonic のディスク容量がどこに使われているかを示し、その一部を取り戻せます。コーパスの学習は、もう必要のないファイルを多く残します。曲の解析中にエンジン用に作ったコピー、学習セット（各曲をロスレスの FLAC に書き直したもので、元より大きい）、そして途中で保存したチェックポイントです。ウィンドウはそれぞれを、大きさ、**それが何か**、**取り除くとどうなるか**とともに並べ、最後の確認のあと、チェックを入れたものだけを取り除きます。**損失のない項目にチェック**は、必要になればそのまま作り直されるコピーにチェックを入れます。

今後解析する曲は、分離した声を FLAC で保存し、同じ音をおよそ半分の容量で持ちます。ウィンドウは**すでにある WAV の声を変換**できます。それぞれを変換し、まったく同じ音にデコードできることを確かめてから、WAV を取り除きます。バックグラウンドで動き、止めることもできます。

学習のチェックポイントは、取り除く前にもう一度見る価値があります。それぞれがスタイル LoRA のリストの項目で、新しいテイクに選べるものなので、コーパスのチェックポイントを取り除くと、それらの項目はリストから永久に消えます。完成した LoRA は残り、引き続き使えます。コーパスの学習セットは違います。取り除いても LoRA とチェックポイントはリストに残り、必要になるのはそのコーパスを学習し直すときだけです。

あなたのテイク、曲、完成した LoRA、モデルが取り除く対象に出ることは決してありません。学習中、書き出し中、解析中のコーパスに属するものはすべてグレー表示になり、終わるまで触れません。

その下の**自動で片付ける**で、Yeufonic が自動で取り除くものを選びます。各曲の解析が終わったときの作業用コピー（既定でオン）、LoRA の学習が終わったときの学習セット（既定でオフ。その場合コーパスはもう一度学習する前に**書き出し**が必要になります）、そして学習のチェックポイント（既定では残します）です。

Docker のイメージとビルドキャッシュは Yeufonic の外にあり、ここでは扱いません。`docker system df` で確認できます。

### YuE2 モデル {#the-yue2-model}

YuE2 には 2 つのサイズがあり、1 つのインストールにはどちらか 1 つがあります。おすすめの**フル品質**か、ビデオメモリの少ないグラフィックカード向けの小さなコピーである**省メモリ**です。同じメニューの**このアプリについて**で、どちらを使っているかがわかります。これは Yeufonic のインストール時に選ぶもので、ここでは選びません。

- **Windows では**、インストーラーを実行し直します。コンポーネントページに両方のサイズがあり、ダウンロード済みのものにチェックが入っています。切り替えると初回にもう一方をダウンロードし、両方を残すので、元に戻すときは何もダウンロードしません。
- **Docker では**、`sh scripts/fetch-models.sh` でフル品質を、
  `sh scripts/fetch-models.sh --int8` で省メモリをダウンロードします。`models/checkpoints` に両方のファイルがあると、
  `.env` に `YUE2_CHECKPOINT=int8` がない限り、アプリはフル品質を使います。

レンダリングがとても遅い、またはエンジンの GPU メモリが足りなくなるときは、省メモリを試してください。LoRA の学習はどちらのサイズのモデルでもできます。**省メモリ (int8) モデルでの学習**の設定でどちらを使うかを選びます。オフではフル品質のモデルで学習し、オンではアプリがレンダリングに使うモデルで学習します。省メモリのモデルだけがインストールされているときは、最初からオンです。GitHub の README には *Choosing a model size* という節があり、それぞれに何を期待できるかが書いてあります。

Yeufonic は ComfyUI の代わりに **yue2.cpp** エンジンも使えます。メモリの少ないグラフィックカード向けで、セットアップのときに選びます。Windows インストーラーのコンポーネントページで、または Docker で
`sh scripts/fetch-models.sh --cpp` を使います。**このアプリについて**でどのエンジンが動いているか、テイクのカードでどのエンジンがレンダリングしたかがわかります。曲、カバー、インストを作り、録音を採譜し、スタイル LoRA も使えます。Gemma がその横で歌詞を下書きし画像を説明でき（Docker では `--gemma`）、FLUX.2 klein が画像を描けます（`--pictures`）。学習には ComfyUI
エンジンが必要で、yue2.cpp ではコーパスと学習は提供されません。GitHub の
[Choosing an engine](https://github.com/yeufonic/yeufonic/blob/main/docs/ENGINES.md) のページに、すべての一覧と切り替え方があります。

**新しいバージョンを確認**は、ここで唯一、自分からインターネットを使うものです。4 時間ごとにアプリが yeufonic.com に新しいバージョンが出ていないか尋ね、右上のバージョン番号の横にピルで知らせます。そのピルからインストーラーが、Docker のコピーならそれを更新する 2 つのコマンドが手に入ります。送るのは 1 回のリクエストだけで、ほかに何もコンピューターの外には出ません。**確認しない**でオフにできます。メニューの**アップデートを確認**は、これがオンかどうかにかかわらずその場で尋ね、メニューで答えます。今のバージョンと、それが最新かどうかです。

新しいバージョンがあると、メニューに **x.y.z を入手** が出ます。Windows のインストールではインストーラーをダウンロードし、Docker のコピーでは 2 つのコマンドをクリップボードに入れます。

<strong>テーマ</strong> はアプリの見た目を決めます。すぐに切り替わり、ブラウザーごとに記憶されるので、ページはそのテーマで開きます。

| テーマ | 見た目 |
|---|---|
| <strong>ダーク</strong> | アプリ本来の暗い見た目です。 |
| <strong>ライト</strong> | 明るいパネル。マスタリングラックのパネルはヘアラインのシルバーになり、ノブ、メーターの窓、ディスプレイはハードウェアらしい暗い見た目を保ちます。 |
| <strong>コンピューターに合わせる</strong> | システムのライト／ダークに従い、それに合わせて切り替わります。 |
| <strong>スタジオ</strong> | 琥珀色の入った温かみのあるダークです。 |
| <strong>ハイコントラスト</strong> | 白黒で、輪郭がはっきりしています。 |

ログウィンドウはどのテーマでもターミナルのように暗いままで、マスタリングラックもテーマに従います。

テーマの下の**背景色**は、テイクの背後のページを選んだ色で染めます。**色合い**にチェックを入れ、**色相**を色相環に沿って動かし、**強さ**を淡いベールから濃い色まで調整します。ドラッグしているあいだページは変わり、離すと選択が保存されます。テイクのカード、パネル、ウィンドウはそれぞれの色を保ち、ハイコントラストのテーマは黒のままです。

### 外部 LLM {#external-llm}

Yeufonic は、ローカルの Gemma モデルの代わりに外部 LLM を使って、歌詞の下書き、録音の採譜、曲のセクションの印付け、コーパスのスタイルの解析ができます。

外部 LLM を使うと、はっきりした利点が 2 つあります。
- <strong>GPU メモリの節約：</strong>Gemma 4 モデルを GPU の VRAM に読み込まずに済み（約 8 GB のビデオメモリを節約）、グラフィックカードを YuE2 のプランとオーディオのレンダリングに丸ごと使えます。
- <strong>より豊かな下書きと解析：</strong>大規模なクラウドモデルは、より細やかな歌詞を下書きし、コーパスに詳しいスタイルタグを付けることがよくあります。

<strong>おすすめのプロバイダー：</strong>使えるなら、API に課金のない外部 LLM プロバイダーを選ぶことをおすすめします——**Google Gemini** がよい例です。Gemini API（Google AI Studio 経由）には課金なしの十分な無料枠があり、標準の OpenAI 互換エンドポイント（`https://generativelanguage.googleapis.com/v1beta/openai/`）に対応し、録音の採譜のためにオーディオを直接受け付けます。

従量課金やトークン課金の API（OpenAI や Anthropic の有料プランなど）を使う場合、何十曲もあるコーパス全体を解析したり、多くのテイクの説明を作ったりすると、API のクレジットをすぐに使い切ったり、支出の上限に達したりすることがあります。外部 API がクォータやレート制限のエラー（HTTP 429）を返すと、Yeufonic は警告を表示し、そのセッションの残りをローカルモデルに切り替えられるようにするので、ほかのジョブは途切れずに続きます。課金のないプロバイダーなら、思わぬ費用を避けられます。

**設定方法：**
1. **Yeufonic → 設定 → 外部 LLM と歌詞**を開きます。
2. **歌詞とスタイルタグを書く LLM**を<strong>外部 LLM（OpenAI 互換 API）</strong>にします。
3. プロバイダーの **API URL**、**API キー**、**モデル**を入力します（たとえば、モデル `gemini-2.5-flash` か `gemini-1.5-flash` と、Google Gemini の OpenAI 互換のベース URL `https://generativelanguage.googleapis.com/v1beta/openai/`）。
4. **LLM 接続をテスト**をクリックして、資格情報を確かめます。
5. 選んだモデルがオーディオ入力に対応していれば（Gemini など）、**録音から歌詞を取る**を**外部 LLM**にして、分離した声を聞かせることもできます。

## AI エージェントから Yeufonic を使う（MCP） {#using-yeufonic-from-an-ai-agent-mcp}

Yeufonic は **MCP サーバー**として動けます。同じコンピューター上の AI エージェント、たとえば Claude Code や Cursor が、あなたの代わりに使えるようになります。曲、カバー、インストを頼み、完成を待ち、再生し、別のやり方で試し、画像を付け、プレイリストに入れ、ライブラリを整理する——すべて自分の言葉で（「EDM スペースに 1 分の EDM インストを作って再生して」）。エージェントはページと同じことを同じ経路で行うので、それが始めたテイクはライブラリのふつうのテイクです。

### 設定方法 {#setting-it-up}

1. <strong>オンにします。</strong>設定を開き、**MCP サーバー**を**オン**にします。リクエストひとつで GPU の作業が始まりうるので、既定はオフです。
2. <strong>エージェントを接続します。</strong>アプリのアドレスの末尾に `/mcp` を付けたものです。Yeufonic を開いているアドレス、たとえば
   `http://localhost:8090/mcp` です。Claude Code では：

   ```
   claude mcp add --transport http yeufonic http://localhost:8090/mcp
   ```

   ほかのクライアントも同じアドレスを HTTP サーバーとして受け付けます。設定ファイルを読むクライアントは、ふつう
   `{"mcpServers": {"yeufonic": {"url": "http://localhost:8090/mcp"}}}` のようなものを求めます。サインインもキーも不要です。
3. <strong>頼みます。</strong>どのフォルダーからでもエージェントを起動し、したいことを伝えます。

<strong>どのアドレス？</strong>Yeufonic を開いているアドレスの末尾に `/mcp` を付けたものです。
- **Docker：**`http://localhost:8090/mcp`。
- <strong>Windows のインストール：</strong>アプリのポートは `settings.ini` にあります（`app_port`。変えていなければ 8090 で、たとえば
  Docker のコピーと並べて動かすために変えることがあります）。`app_port = 8091` なら `http://localhost:8091/mcp` です。
- <strong>エージェントが WSL、アプリが Windows：</strong>これでは接続できません。Windows のアプリは Windows 自身のループバックアドレスだけで待ち受けていて、WSL からは届きません（WSL の中の Docker は大丈夫です。それも WSL の中にあるからです）。エージェントを Windows から実行する（PowerShell やエージェントの Windows 版）か、WSL のミラーモードのネットワークをオンにしてください（`.wslconfig` の `[wsl2]` に `networkingMode=mirrored`、そのあと `wsl --shutdown`）。そうすると両側で `localhost` が同じになります。

エージェントがサーバーに**認証が必要**と言う場合、ほとんどは設定がまだオフのままだからです。オンにしてからエージェントを接続し直してください（Claude Code では `/mcp`）。Yeufonic を再起動したあとも、接続が切れるので接続し直してください。

### 頼めること {#what-you-can-ask-for}

| 頼むこと | 起きること |

| 「夜行列車についての歌詞を、語りかける口調で書いて」 | アプリ自身の**歌詞を書く**を、その曲の形、セクションごとの行数、口調とともに使う。エージェントが自分で歌詞を書くこともできる |

| 「再生して」 | テイクをブラウザーで開き、そこで再生する |
| 「それにスターを付けて」「Sunrise という名前にして」「Folk スペースに移して」 | テイクにスターを付ける、名前を変える、移動する |
| 「新しいシードでレンダリングし直して」「それを止めて」 | テイクをレンダリングし直すか、進行中のものを取り消す |

| 「もう一度歌って」「全部の解釈で試して」 | **もう一度歌う**（同じ楽譜に新しい声）または**バリエーション**（同じ楽譜とシードを、それぞれのやり方で演奏）。バリエーションはもっと試すと同じくテイクの中に保存される |
| 「そのメロディをこの歌詞で歌って」 | **新しい歌詞**：同じメロディ、調、テンポに別の歌詞で、新しいテイクとして |
| 「それをインストにして」 | 同じ楽譜で、メロディを楽器にして歌なしで、新しいテイクとして |

| 「*Night Ferry.yeufonic.json* を Drafts にインポートしてレンダリングして」 | テイクファイルから新しいテイクを作り、プランを持たせ、頼んだときにレンダリングします。ファイルにある LoRA のうちインストールされていないもの、カバーが曲として入ってきたことを伝えます |
| 「ドリームポップのスタイルでもう一度インポートして、楽譜とシードは同じで」 | インポートの前にレシピを変えるので、指定したところだけが変わります |

| 「そのテイクを削除して」 | 何が消えるかを見せ、先に確認する。下を参照 |

テイクを作るには数分かかります。エージェントは作り始めて待ち、進み具合を伝えるので、そのあいだに次のことを頼めます。

### こんなふうに進みます：例 {#how-it-can-work-an-example}

アイデアからプレイリストまでのひとつの会話です。あなたが話し、エージェントが道具を選び（真ん中の列は何が起きているかを見せるためだけのものです）、返ってきたものを伝えます。

| あなたの言葉 | エージェント | 得られるもの |
|---|---|---|
| 「灯台守の最後の夜についての歌詞を、フォーク風、物語の形で書いて。それから Coast という新しいスペースで、それを使って曲を作って。」 | `write_lyrics`、`create_space`、`make_song`、そのあと完成まで `wait_for_take` | *The Last Light* という歌詞が表示され、Coast というスペースができ、そこでプランとレンダリングを済ませた曲が、途中の進み具合とともに手に入る |
| 「再生して。」 | `get_take`、そのあとその `listen_url` を開く | ブラウザーで再生される |
| 「いいメロディだね。もっとゆるく落ち着きなく、それと歌なしのをひとつ。」 | ゆるい解釈と落ち着きのない解釈で `make_variations`、`instrumental_from_take` | 曲の中に 2 つのテイク、その隣にインスト |
| 「何ができたか見せて。」 | Coast で `list_takes`、曲には `inside` も付けて | それぞれに短い ID が付いた一覧。タイトルの代わりに「3f9a」と言える |
| 「3f9a を取り出して、スターを付けて、画像も付けて。」 | `take_out`、`star_take`、`make_picture` | ゆるいテイクが独立し、スター付き（つまりお気に入りにも入る）で、画像へのリンク付き |
| 「それとインストを Coast demos というプレイリストに入れて。」 | `create_playlist`、`add_to_playlist` | その 2 つが入ったプレイリスト |
| 「スタイルを Coastal folk として保存して。」 | `save_style` | アプリのスタイルメニューに **Coastal folk** が入り、次回すぐ使える |
| 「今度はデュエット。この歌詞で、[male voice] と [female voice] の指示付き、各セクションは書いたとおりに。」 | `follow_structure` 付きで `make_song`（セクションが変わるので新しいプラン） | あなたのセクションを順番どおりにプランした新しい曲。指示のある各行は、その声が歌う位置に移されている |

エージェントがしたことはすべて、ページでしたのと同じようにライブラリに入っています。どのテイクもエディターで開け、マスタリングでき、そこから続けられます。ある手順ができないとき、エージェントはアプリ自身から理由を受け取り（「this take is an instrumental already」「nothing here can draw a
picture」）、それを伝えるので、ページと同じ答えが聞けます。

### できることすべて {#everything-it-can-do}

これらの名前を覚える必要はありません。自分の言葉で頼めば、エージェントが選びます。ここに並べているのは、何があるかを見られるように、そしてどれを使ってほしいかをエージェントに伝えられるようにするためです。

| 道具 | 何をするか |
|---|---|

| `wait_for_take` | 作成中のテイクを（1 回につき約 1 分まで）待ち、終わったかどうかを伝える |
| `make_instrumental` | スタイルからインストをプランしてレンダリングする。指定すれば長さ、スペース、スタイル LoRA を、渡せばセクションを使う |
| `make_song` | 曲でも同じ。歌詞から作る |
| `make_cover` | ライブラリの録音からカバーを作る。その楽譜と、別のものを渡さなければその言葉を使う |
| `try_more` | 既存のテイクから、新しいシードでテイクをいくつか追加する |
| `sing_again` | 同じ楽譜を新しいシードで歌い直す：新しい声で、新しいテイクとして |
| `make_variations` | 同じ楽譜とシードを、指定した各解釈で（またはすべてで）。テイクの中に保存される |
| `new_words` | 同じ楽譜を別の歌詞で歌う。新しいテイクとして |
| `instrumental_from_take` | 同じ楽譜をインストにする。新しいテイクとして |
| `replan_take` | オーディオのないテイクに新しいプラン。ハーモニー、プランの多様さ、調、テンポを変えることもできる |
| `take_out` | 別のテイクの中に保存されたテイクを独立させる |
| `write_lyrics` | 依頼から歌詞を書く。曲の形と口調付きで、ページの「歌詞を書く」と同じ書き方 |
| `render_take` | プランしたテイクをレンダリングするか、完成したものをレンダリングし直す（頼めば新しいシードで） |
| `cancel_take` | キュー中や進行中のテイクを止める |
| `make_stems`、`get_stems` | テイクをパートに分け、各パートと全体の zip へのリンク付きで一覧にする |
| `list_recordings`、`transcribe_recording` | ライブラリの録音と、それぞれに楽譜があるかを表示する。楽譜のないものを採譜する |
| `list_style_loras` | インストール済みのスタイル LoRA を、トリガーワードと一緒に保存された強さ付きで |
| `list_voices` | 録音した声と、それぞれが使えるかどうか、既定の設定。`make_song`、`make_cover`、`render_take` は名前で声を指定でき、そのテイクだけの設定も渡せる。`get_take` はテイクを歌った声を示す |
| `list_spaces`、`move_take`、`create_space` | スペースとその中身。テイクを別のスペースへ移す。新しいスペースを作る |

| `star_take`、`rename_take` | テイクにスターを付ける、外す。タイトルを変える |
| `delete_take` | テイクを見せて同意を得てから、永久に削除する |

| `import_take` | レシピから新しいテイクを作り、指定があればそのスペースに入れ、レンダリングできる状態にします。インストールされていない LoRA と、カバーが曲として入ってきたことを伝えます |
| `status` | エンジンが準備できているか、何が動いていて何が待っているか、LoRA を学習中か。動いているエンジン（ComfyUI か yue2.cpp）も伝えます |

### 使い方のアイデア {#ideas-for-using-it}

- **アイデアをまとめて出してから選ぶ。**「EDM スペースに、スタイルの違う 1 分の EDM インストを 5 つ作って。」1 つずつ始め、それぞれが終わるたびに知らせます。聴いてから「2 つ目と 4 つ目にスターを付けて、残りは削除して」と言えます。
- **ひとつのアイデアを磨く。**「夢のようなシンセのスタイルでインストを作って再生して」、続いて「同じのをドラム多めで」、さらに「2 つ目みたいなのをあと 4 つ」。エージェントはどのテイクがどれかを覚えているので、順番や、あなたがそれについて言ったことで呼べます。
- **クリックせずにカバー。**「*そのデモ*を採譜して、フォーク、シンセウェーブ、ジャズの 3 つのカバーを作って。」録音に楽譜がなければ先に採譜し、指定したスペースにカバーを作ります。
- **LoRA を使う。**「スタイル LoRA を一覧にして、それからジャズのでインストを作って。」トリガーワードと保存した強さは自動で扱われます。手でやると間違えやすいところです。
- <strong>歌詞はエージェントが書くか、アプリが書くか。</strong>エージェントは自分で歌詞を書けます。「夜行列車についての歌詞を書いて、それでフォーク風の曲を作って。」Yeufonic が見るのは完成した歌詞だけです。アプリの作詞を頼むこともできます。「Yeufonic の作詞者を使って、ヒップホップの形、語りかける口調で」と言えば、ページの**歌詞を書く**と同じように書いて、曲のために返します。
- **同じメロディ、別の歌詞。**「2 番のヴァースをこの歌詞にして、もう一度歌って」：`new_words` はメロディ、調、テンポを保ちます。歌詞から新しい曲を作ると、新しいメロディが書かれます。
- **設定を比べる。**「同じ曲を 2 回、同じシードで、ハーモニーを『おなじみ』と『冒険的』で作って」、続いて「よいほうを全部の解釈で」。設定は名前で頼めるので、小さなテストを 1 文で組めます。
- **聴いてからプレイリストを作る。**「今週スターを付けたテイクを全部 Week 43 というプレイリストに入れて」、または「Road trip からインストを外して」。お気に入りはスター付きのテイクなので、スターとお気に入りはいつも同じリストです。
- **まとめてステム。**「最新の 5 つのテイクをボーカルと楽器に分けて、リンクをちょうだい。」1 つずつ順に、
  GPU が実行中のレンダリングのうしろにキューされます。
- **ライブラリの整理。**「同じタイトルのテイクを探して、どれがいちばん新しいか教えて、古いのは削除して」、または「今日作ったものを全部 Drafts というスペースに移して」。ID で作業し、削除の前に確認します。
- <strong>長い作業の前に確認。</strong>長いレンダリングやまとまった作業をキューに入れる前に「Yeufonic は忙しい？」と聞けば、学習のうしろに並ばずに済みます。
- <strong>もっと大きな作業の一部に。</strong>エージェントが呼べる道具なので、もっと大きなことの一部になれます。動画用のトラックを作って添える文章を書く、プレイリストほどの数のテイクを作って一覧どおりに名前を付ける、などです。

エージェントはテイクを聞けないので、どう聞こえるかは判断できません。聴くのはあなたで、重い作業はエージェントがします。エンジンを飛ばす近道でもありません。GPU は今でも一度に 1 つのジョブしか実行しないので、大量に頼めば長いキューになります。
- <strong>テイクを共有する。</strong>「スターを付けたテイクをレシピと一緒に FLAC の zip で保存して」で、ほかの人が聴いて作り直せるファイルができます。相手は自分のエージェントに「このテイクファイルをインポートしてレンダリングして」と頼みます。あるいは「ジャズの LoRA でもう一度インポートして、楽譜とシードは同じで」と頼めば、同じプランを別の形で聴けます。

### 知っておきたいこと {#things-to-know}

- **テイクはタイトルが同じことがある**ので、エージェントはテイクの **ID** で作業し、テイクを一覧にするときは短い ID（`short_id` の列）を表示します。
  ID の先頭 4 文字以上でテイクを指せます。そう始まるテイクが 1 つだけならです。2 つあれば、そう伝えてもっと求めます。
- <strong>削除は 2 度確認します。</strong>エージェントはまず、同じタイトルのほかのテイクも含めて何を削除するかを見せ、あなたが「はい」と言ったときだけ削除します。スター付きのテイクは、はっきりそう言う必要があります。削除したテイクは、オーディオごと元に戻せません。
- **スペースとスタイル LoRA は名前で指定します**。番号ではありません。「EDM スペースに」「ジャズの LoRA で」。何にも合わない名前には、あるものの一覧が返り、何も作られません。LoRA のトリガーワードは自動でスタイルに加わります。LoRA はそれなしではほとんど働かないからです。
- <strong>新しいテイクはページと同じところから始まります。</strong>ハーモニーは「多彩」、解釈は「ワイド」で、ほかを指定すればそれになります。ハーモニーのノードがないエンジンでは「おなじみ」から始まります。そこではハーモニーをそれ以上上げられないからです。
- <strong>画像と歌詞は順番を待ちます。</strong>この PC で描いたり説明したりする画像は曲を作っていないときまで待ち、この PC で書く歌詞はほかの GPU の作業と一緒にキューに並ぶので、エージェントは「まだ作っています」と言って、あとで見直すことがあります。
- **インストは常に時間指定の構成でプランされます**。頼んだ長さから計算されます（何も言わなければ約 2 分半）。時間がないと、プランナーは使えないほど長いプランを書くからです。自分のセクションを指定すれば、そのまま使われます。
- <strong>この PC でだけ。</strong>ページと同じホスト名とオリジンの確認がかかり、サインインはないので、使わないときは設定をオフにし、信頼できないネットワークにポートを公開しないでください。

## システムログ {#system-logs}

アプリは重要な操作——楽譜のプラン、レンダリング、オーディオの採譜、ステムの分離、LoRA の学習——ごとに、`INFO`、`WARN`、`ERROR` の接頭辞付きで、ひとつにまとめたリアルタイムのログを書きます。

- <strong>ブラウザー内のコンソール：</strong>上部バーの**ログ**ボタンをクリックする（または **L** を押す）と、ドラッグもサイズ変更もできるフローティングのコンソールが開きます。ページを妨げずに開いたままなので、テイクをキューに入れながら生成をリアルタイムで追えます。
- <strong>別ウィンドウ：</strong>コンソールのヘッダーの<strong>↗ 切り離す</strong>をクリックする（または直接 `/logs` に行く）と、ログ専用のウィンドウが開きます。
- <strong>ターミナルで：</strong>ログはホストの `data/logs/yeufonic.log` に自動でローテーションされ、そこでリアルタイムに追えます。
  ```bash
  tail -f data/logs/yeufonic.log
  ```

## エンジン自身のページ {#the-engine-s-own-page}

エンジンは ComfyUI で（このインストールが yue2.cpp を使っている場合は別で、そのページは簡単なテストベンチです）、その画面にアクセスできます。Docker では <http://localhost:8189>、
Windows のインストールでは <http://localhost:8188>（`settings.ini` の `engine_port`）です。応答するのはこのマシンだけで、サインインはありません。

- <strong>アプリと同じエンジン、同じ GPU です。</strong>そこで実行したジョブは、アプリのキューに外部からのものとして現れ、アプリ自身のジョブはそれを待ちます。
- **その履歴には、アプリが送ったすべてのグラフが表示されます**。プラン、レンダリング、採譜で、エンジンが受け取ったとおりの設定がすべて入っています。テイクが何から作られたかを正確に見るにはよい場所です。

## うまくいかないとき {#when-something-is-wrong}

<strong>ヘッダーにエンジンがないと表示される。</strong>アプリはエンジンなしでも動き、そう表示します。レンダリングは待ちます。エンジンのコンテナーが動いているか確かめてください。

<strong>曲が終わらない。</strong>たいていはプランナーの強さが高すぎます。LoRA のプランナーを 0.5 に下げてください。長さの上限で、いずれにしても止まります。

<strong>LoRA が何もしていないようだ。</strong>トリガーワードがスタイルにあるか、そして上げた強さがファイルに本当にあるものか確かめてください——セレクターはもう一方をグレー表示にします。

<strong>テイクに「弱いレンダリング」と表示される。</strong>最初から最後まで、ふつうよりずっと小さい音で出てきたものです。そうしたテイクの中には単に小さいだけのものもあれば、薄く聞こえたり歪んだりするものもあります。表示をクリックするとノーマライズされ、ふつうの音量に上がって*ノーマライズ済み*と印が付きます。それでもよくなければ、別のシードを試し、その LoRA のサウンドを 0.5 以下にしてください。いちばん起きやすいのは、ここで学習したスタイル LoRA を通したカバーです。

<strong>音量をノーマライズ。</strong>エディターでチェックを入れると、チェックが入っているあいだに作ったテイクは、完成時にふつうの音量に合わせられ、*ノーマライズ済み*と印が付きます。チェックなしで作ったテイクは、あとからカード上部のスピーカーボタンでノーマライズできます。レンダリングされたままのファイルは横に残り、*ノーマライズ済み*をクリックするとそれに戻ります。どれだけ大きくするかは、設定の*ノーマライズ先*で決めます。チェックがなければ、テイクはレンダリングされたときのレベルを保ちます。

<strong>インストが歌ってしまった。</strong>上の*インストが歌ってしまうとき*を参照してください。モデルのくせで、新しいシードでたいてい直ります。

<strong>テイクがレンダリングし直せない。</strong>録音が削除されたのかもしれません。カバーはオーディオと楽譜を保ちますが、もう存在しない録音からレンダリングし直すことはできません。

<strong>何も鳴らないのに波形は動いている。</strong>音量のつまみと、ステムが選ばれていないかを確かめてください——プレーヤーは最後にクリックしたものに従います。
