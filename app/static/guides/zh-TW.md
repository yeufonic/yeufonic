# Yeufonic 使用指南

本指南講的是如何**使用**這個應用。安裝方法，以及開始使用前需要準備的一切，都在
[README](https://github.com/yeufonic/yeufonic#readme) 裡。

這個應用用 YuE2 來寫歌。YuE2 分兩步工作：先寫一份**樂譜方案**——旋律、和絃和段落，以文字形式——然後把這份方案**渲染**成音訊。下面幾乎所有內容都源於這種兩步分工。一份方案只要幾秒鐘，可以閱讀、編輯，也可以丟掉；一次渲染則要幾分鐘。所以應用會先讓你看方案。

---

## 你的第一首歌 {#your-first-song}

1. 點選左側面板頂部的<strong>+ 歌曲</strong>。編輯器視窗隨即開啟。
2. <strong>寫一個風格。</strong>一句話，而不是一串標籤：*「warm indie rock, expressive female lead, jangly
   guitars, 96 BPM」*。它對結果的影響最大。
3. **加上歌詞**，或者點選**寫歌詞**，讓 Gemma 根據描述起草。
4. 點選**寫樂譜方案**。視窗關閉，版本出現在左側面板中。按鈕旁的**方案就緒後立即渲染**預設是勾選的，此時方案會直接進入渲染。

想在渲染之前先讀方案，就先取消勾選**方案就緒後立即渲染**。這樣版本會停在方案這一步：開啟它，在它的**樂譜**頁面裡，**寫新方案**只需幾秒鐘就能為一段你不喜歡的旋律重新擲一次骰子，**渲染此樂譜**則會渲染它。還沒有音訊的版本會被補全；已經有音訊的版本則會作為一個新版本渲染在它旁邊，所以渲染永遠不會覆蓋你想保留的版本。

版本出現在右側的庫裡，並在底部的播放欄中播放。

### 版本面板與編輯器 {#the-take-panel-and-the-editor}

**左側面板**顯示你最後點選的那個版本，只供閱讀：它的風格、聲音設定、歌詞的前幾行，以及樂譜的調性、速度、時長和每個段落的和絃。頂部的<strong>+ 歌曲</strong>、**+ 翻唱**和<strong>+ 純音樂</strong>用來開始新的創作；與該版本型別相同的那個按鈕會高亮。面板旁的箭頭可以把它收起，讓版本列表佔滿寬度，再點一次又會展開。單個按鍵作用於面板顯示的版本（M 開啟母帶處理架，E 開啟編輯器，等等）：參見[鍵盤快捷鍵](#hot-keys)。

建立和修改版本都在**編輯器視窗**中進行。面板中它的主按鈕會顯示當前合適的操作：*編輯並重新渲染*，或者在有方案等待時顯示*檢查方案並渲染*。卡片上的**樂譜**和**再來**按鈕也能開啟它，雙擊卡片也一樣。編輯器有三欄（歌曲、歌詞和聲音），一覽無餘，樂譜則在單獨的標籤頁裡。

用**關閉**、叉號或 Esc 關閉視窗時，你寫下的內容都會保留。

右上角**關閉**之後的那個按鈕會讓視窗占滿整個瀏覽器視窗，再點一次則恢復常規大小。視窗會按你上次離開時的樣子開啟。佔滿視窗時，歌詞欄會佔據整個高度：歌詞框（已有文字時）和結構會擴充套件到多出的空間裡，播放器則留在這一欄的底部。

視窗頂部一行放著版本卡片上那些小按鈕的放大版：再唱一次、變奏、再試幾個、內部、取出、標準化和移動，各自位於卡片上相應的位置。版本處於標準化狀態時，標準化按鈕顯示為綠色，此時點選會把它恢復到渲染時的電平；版本內含其他版本時，內部按鈕會亮起，點選會關閉視窗，在該版本下方顯示它們。

### 錄製的音色 {#a-recorded-voice}

一個版本可以用從某人演唱的 **錄音** 訓練出的音色來演唱：可以是你自己的，也可以是語料庫歌手的。在編輯器的 *錄製的音色* 欄中選擇，
或用一段演唱的音訊檔案透過 **建立音色…** 訓練一個。幾分鐘就夠了，帶伴奏的錄音會先分離。每個語料庫卡片上也有 **建立音色…** 按鈕，
可以用語料庫的歌曲訓練音色。只有選用的音色服務在執行時才會顯示此欄（見 README 的「Recorded voices」）。

訓練會在 GPU 上排隊，可能需要一小時，清單會顯示進度。使用音色的版本照常渲染，然後分離出人聲，用該音色重新演唱，再混回其餘
部分，之後才測量響度。

**八度** 把音色整體升高或降低一個八度。離歌手音域太遠的音色聽起來不對，只有整八度移動才能讓人聲保持在伴奏的調上。這個值
儲存在音色上。**重新產生** 重新訓練音色：語料庫音色會用語料庫現在的歌曲訓練。

結果是在分離出的伴奏上疊加轉換後的人聲，所以不如模型自己唱出的人聲那樣渾然一體。錄音越乾淨（無損而不是 MP3），音色就越
乾淨。版本的配方會記下它的音色名稱，匯入時如果本機有同名音色，就會使用它。

**下載音色** 把訓練好的音色存成 zip，可以分享給別人；**匯入音色…** 用來加入音色：可以是那個 zip，也可以是別處的 RVC 模型（.pth，或帶索引的 zip）。訓練使用多少演唱在設定的 *錄製的音色：演唱分鐘數* 中設定，它會在語料庫的歌曲之間平均分配，大約十分鐘就夠了。

**人聲音量** 設定轉換後的人聲相對於渲染人聲在混音中的音量，範圍 −3 到 +6 dB，同樣儲存在音色上。

### 高階設定 {#advanced-settings}

編輯器標題欄中的**高階**按鈕會開啟只針對這個版本的設定。大多數歌曲都用不到它們。這些設定隨版本一起儲存，所以*編輯並重新渲染*會按你離開時的樣子找到它們。只要有任何設定偏離預設值，按鈕就會亮起，**恢復預設**則會把它們全部恢復。

有些作用於方案，有些作用於渲染和最終檔案：

- **擴散步數**（16–64，預設 32）：音訊解碼器走多少步。步數越多，渲染越久。
- **遵循風格**（0–100，預設 1.0）：音樂對風格和歌詞的遵循程度，也就是把樂譜變成聲音那一階段的引導強度（CFG）。高於 1.0 會更貼近它們；低於則會偏離。數值較小時差別很細微，渲染會稍慢一些。可以輸入引擎接受的任何數值：非常高的引導往往聽起來更刺耳，而不是更貼切。引擎支援時才會顯示：yue2.cpp，或最新版本的
  ComfyUI 引擎（舊的 Docker 引擎需要重新建置才能獲得）。
- <strong>避免：</strong>想要避開的詞，例如「drums」或「rap vocals」。它們會以「avoid: …」的形式加到風格里。這只是給規劃器的提示，並非保證：渲染器沒有負面提示詞。
- <strong>鎖定調性：</strong>規劃器寫完方案後，方案會被移到這個調上。規劃器會忽略風格里寫的調，所以這一步直接在樂譜上完成：每個音符和每個和絃都移動相同的音程，調號也會重寫。小調方案依然是小調，只有主音會移動。應用無法確定讀懂的方案，比如調式音樂或中途轉調的方案，會保留規劃器的調，日誌中會說明。
- **鎖定速度**（BPM）：方案會固定在這個速度上，它會取代風格里或規劃器自己樂譜裡的任何速度，渲染也會跟隨它。
- **樂譜 token 上限**（預設 8192）：規劃器最多能寫多少。上限越低，短歌的方案就越不會拖長。
- **和絃停留上限**（小節，預設 8）：規劃器在同一個根音上最多停留多少小節，之後必須換和絃。
- **調外和聲獎勵**（0–10，預設 0）：把規劃器推向借用和絃以及主調之外根音的力度。這兩項作用於規劃器的選擇，所以更多體現為方案和絃上的差異，而不是明顯的聽感差異。可以在樂譜視窗中比較。
- **聲部遵循提示**（歌詞框下方的核取方塊，當歌詞中有像
  `[male voice]` 這樣的人聲提示時出現；新版本預設勾選）：每一行被標註的旋律都會按八度移動到提示所指那個人聲的演唱區域。參見[歌詞](#the-words)。
- **嚴格遵循此結構**（歌詞框下方的核取方塊，不在「高階」裡；僅限歌曲；預設關閉）：方案嚴格按歌詞裡寫的段落，按順序寫，不多不少。關閉時，規劃器會自己安排歌曲的形式，常常加入前奏、尾奏或間奏，或者漏掉某個段落。即便開啟，方案也仍可能在列表結束前就結束。
- **段落開頭各不相同**（跟隨和聲、總是、從不）：一個段落能否用與上一段相同的和絃開頭。*跟隨和聲*在「多彩」及以上開啟，以下關閉；*總是*和*從不*則在任何級別都為這個版本做決定，方便比較有無這條規則的兩份方案。
- <strong>目標響度：</strong>版本標準化的目標電平。只在開啟標準化時生效。
- **結尾淡出**（秒，預設 3）：版本在時長上限處被截斷時，淡出的長度。

### 風格框裡寫什麼 {#what-to-put-in-the-style-box}

YuE2 把它當作一段錄音的描述來讀，所以請描述一段錄音。語言、流派、人聲、樂器、氛圍、速度和製作，大致按這個順序，寫成一句話。零散的標籤列表效果較差，而像 `[Verse]` 這樣的段落標記屬於歌詞，不該寫在這裡。

下方的**人聲**標籤會替你寫進風格：女聲、男聲或二重唱，再加一種特質，比如氣聲或沙啞。它們只是輸入的捷徑，結果你也可以手動修改。

### 起草歌詞 {#drafting-the-lyrics}

<strong>結構。</strong>在歌詞框上方，只要框裡還沒有文字，歌曲就有一個可以搭建的**結構**，和純音樂一樣：一個可以重新排序、刪除和擴充的段落列表（前奏、主歌、預副歌、副歌、橋段、間奏、尾奏）。**從…開始**會用一種常見形式填滿它，每種形式的懸浮說明會告訴你它適合什麼。**間奏**是一段純器樂：作者會把它的標籤單獨放一行，規劃器則用器樂聲部來演奏它。**把段落放入歌詞框**會把這些標籤作為空段落插入，方便你在下面手寫。框裡一旦有了文字，唱的就是歌詞，結構則會讓到一旁。

歌詞框旁的**寫歌詞**會問你這首歌講什麼，然後為你搭好的段落寫詞。**主歌或副歌的行數**決定每段有多長：一個段落裡的行越多，歌就越長，因為規劃器寫出的音樂大致和詞一樣多。上面的風格決定氛圍。Gemma 在同一個引擎裡起草，如果你沒給標題，草稿會帶著標題來到框裡；也可以改由[外部 LLM](#external-llm) 來寫，在設定中配置。草稿一開始，視窗就會關閉，進度顯示在歌詞框旁。歌詞編輯器的按鈕也能新增上述任何段落，以及人聲提示（+ 男聲、+ 女聲、+ 合唱）。

**歌詞的讀感**決定作者追求的節奏和押韻。*自然*（預設）混合長短句，帶少量押韻。*規整押韻*是傳統寫法，每兩行押韻、行長相同，也是這個選項出現之前作者的寫法。*口語節奏*像說話或說唱；*鬆散押韻*只讓部分行押韻；*短促有力*和*綿長流暢*則決定行的長短。

這只是初稿。各行有節奏、也押韻，但模型會傾向於用熟悉的意象，也沒有任何東西檢查某一行是否已經屬於別人。在規劃之前，讀一遍，把它變成你自己的。

## 從提示詞寫一首歌：所有選項 {#writing-a-song-from-a-prompt-every-option}

**+ 歌曲**如今有很多選項。沒有哪個是必需的：一個風格加一點歌詞就夠了，就像
[你的第一首歌](#your-first-song)那樣。本章按編輯器顯示的順序逐一介紹它們，即三欄（歌曲、歌詞和聲音），然後講有了方案之後做什麼。最後有一張常見需求表，比如讓歌更長，或讓副歌聽起來和主歌不同。

### 歌曲 {#the-song}

- <strong>標題。</strong>可選。留空時使用歌詞的第一行。
- <strong>風格。</strong>列表 **選擇風格…** 裡有 200 個起點，從 afrobeats 到 zydeco，按字母順序排列。選擇其中一個，會用完整的描述填滿風格框，之後可以再編輯。下方的標籤是十個快速起步的歌曲風格：warm indie rock、soulful jazz-pop、synthwave、acoustic ballad、heavy rock、modern pop、
  country、hip hop、smooth R&B 和 dance pop。參見[風格框裡寫什麼](#what-to-put-in-the-style-box)。
- <strong>儲存你自己的風格。</strong>列表旁的**儲存**會把風格框裡的內容以你取的名字儲存。列表的第一項**儲存的風格**會開啟你儲存的風格；旁邊的垃圾桶可以刪除，列表的搜尋會把它們和那 200 個一起找出來。用已有的名字儲存會替換那個風格。風格 LoRA 的觸發詞不會被儲存，使用該風格時會為當前選中的 LoRA 重新填上。
- <strong>風格里的速度只是提示。</strong>規劃器通常會選自己的速度。要固定速度，請用「高階」裡的**鎖定速度**。
- <strong>人聲。</strong>這些標籤會替你把人聲（女聲、男聲、二重唱及一種特質）寫進風格。
- <strong>風格 LoRA。</strong>位於聲音欄底部。參見[風格 LoRA](#style-loras)。

### 歌詞 {#the-words}

<strong>結構。</strong>在歌詞框上方，只要框裡還沒有文字，就會有一個段落列表：歌曲將要遵循的順序。每一行都可以換成另一個段落、上下移動（或拖動）或刪除，列表下方的標籤可以新增段落。段落有前奏、主歌、預副歌、副歌、橋段、間奏和尾奏。**間奏**是一段純器樂：它沒有歌詞，規劃器用器樂聲部來演奏。（`solo` 不是規劃器認識的段落；要獨奏，就用間奏。）

**從…開始**會用一種常見形式填滿列表。把滑鼠懸停在某個選項上，可以看到它適合什麼：

| 形式 | 段落 | 適合 |
|---|---|---|
| 主歌、副歌、橋段 | 主歌、副歌、主歌、副歌、橋段、副歌 | 經典歌曲：流行、搖滾、鄉村 |
| 短小 | 主歌、副歌、主歌、副歌 | 民謠、朋克、早期搖滾樂 |
| 前奏與尾奏 | 前奏、主歌、副歌、主歌、副歌、尾奏 | 抒情歌、軟搖滾、創作歌手 |
| 敘事 | 主歌、主歌、副歌、主歌、副歌、尾奏 | 敘事歌曲、民謠、鄉村 |
| 帶預副歌的流行 | 主歌、預副歌、副歌、主歌、預副歌、副歌、橋段、副歌 | 現代流行、舞曲流行、流行搖滾 |
| 鉤子先行 | 副歌、主歌、副歌、主歌、副歌、橋段、副歌 | 流媒體時代的流行、獨立流行 |
| 短而簡單 | 主歌、副歌、主歌、副歌、副歌 | 朋克、車庫搖滾、鄉村搖滾 |
| 嘻哈 | 前奏、主歌、副歌、主歌、副歌、主歌、尾奏 | 說唱、嘻哈、陷阱、R&B |
| 雙橋段 | 主歌、副歌、主歌、副歌、橋段、橋段、副歌、副歌 | 力量抒情、前衛與交響搖滾 |
| 間奏 | 主歌、副歌、間奏、主歌、副歌、橋段、副歌 | 搖滾、流行搖滾、獨立 |
| 全部部分 | 前奏、主歌、預副歌、副歌、間奏、主歌、預副歌、副歌、尾奏 | 流行、舞曲流行 |

<strong>段落數量。</strong>無論歌詞要求什麼，規劃器通常寫 8 到 10 個段落，所以超過
10 個的列表會被壓縮，被丟掉的段落裡的詞不會被唱出來。列表這麼長時，搭建器會提醒你。加段落並不會讓歌變長；每個段落只會變短。參見
[讓歌曲更長](#making-the-song-longer)。

**把段落放入歌詞框**會把段落作為空標籤插入，方便你在下面手寫。框裡一旦有了文字，唱的就是歌詞，搭建器則會讓到一旁。

<strong>寫歌詞。</strong>描述這首歌講什麼，模型就會為你搭好的段落寫詞。它會問三件事：

- **主歌或副歌的行數**（4、6 或 8；預設 6）。一個段落裡的行越多，歌就越長，因為規劃器寫出的音樂大致和詞一樣多。前奏、橋段或尾奏保持 2 到 4 行，間奏則沒有歌詞。
- <strong>歌詞的讀感。</strong>列表顯示每一行追求的音節數。舊的作者幾乎總是寫出同樣的八音節押韻句，而這個選項改變了這一點：

| 選項 | 追求 | 你會得到 |
|---|---|---|
| 自然（預設） | 3-13 個音節 | 長短句混合，少量押韻，沒有固定節拍 |
| 規整押韻 | 6-10 個音節 | 行長相同、兩兩押韻：傳統形式，也是作者以前的寫法 |
| 口語節奏 | 5-14 個音節 | 口語化且富有節奏，像說話或說唱，帶內韻 |
| 鬆散押韻 | 4-13 個音節 | 有的押韻，有的近似押韻，有的不押，行長不一 |
| 短促有力 | 3-6 個音節 | 短句和重複的短語 |
| 綿長流暢 | 10-14 個音節 | 如思緒般流淌的長句 |

  最後一次的選擇會被記住。這些是目標而非保證：語言模型在兩端（短促有力、綿長流暢）貼得很緊，在中間檔則較為寬鬆。
- **委託內容**本身，用你自己的話寫，以及上面的風格，它決定氛圍。委託內容會隨版本一起儲存，所以開啟一個版本再點**寫歌詞**，就能看到當初要求寫什麼，可以修改後重寫。

草稿會進入歌詞框，草稿一開始，視窗就會關閉。這只是初稿：讀一遍，把它變成你自己的。

**嚴格遵循此結構**（歌詞框下方的核取方塊，預設關閉）。規劃器把歌詞中的段落標籤當作參考，自行寫出自己的形式：常常加入前奏和尾奏，把橋段換成間奏和一段主歌，或壓縮一個很長的列表。開啟它後，方案會嚴格按歌詞裡寫的段落、按那個順序來寫，不多不少。它不能加入你沒寫的前奏或尾奏。音樂怎麼寫、每個段落何時開始，仍由規劃器決定。僅適用於歌曲。

<strong>誰唱哪一行：人聲提示。</strong>單獨一行、用方括號寫出某個人聲，表示接下來各行由誰來唱，直到下一個提示或下一個段落：

```
[Verse 1]
[male voice]
The ferry leaves at half past nine
I watch the harbour lights go by
[female voice]
I wait beside the ticket line

[Chorus]
[both voices]
Carry me over, carry me home
```

把 `[male voice]`、`[female voice]` 或 `[both voices]` 這樣的提示寫成單獨一行，用方括號括起來。展開後的歌詞編輯器標題欄裡有<strong>+ 男聲</strong>、**+ 女聲**和<strong>+ 合唱</strong>按鈕，可以把它們插入到游標處。這些是這個功能測試過的寫法，另外也支援用 `vocal` 代替 `voice`（`[female vocal]`），以及用
`[male and female voices]` 表示兩人。逗號後可以加你自己的詞，例如
`[female voice, soft and close]`；它們不會改變由誰演唱。沒有提示的段落交給規劃器決定。

其他寫法也能識別，這樣別處寫的歌詞不會被忽略：`[man]`、`[woman]`、`[duet]`、寫在段落標籤裡的提示（如 `[Verse 2 - female vocal]`），以及圓括號裡的提示 `(female voice)`。方括號是最穩妥的習慣：圓括號裡的詞往往是和聲，可能會被唱出來。

光靠提示並不能決定人聲。由誰來唱主要取決於旋律寫得有多高：同一行高一個八度就會由女聲來唱，而且無論怎麼提示，規劃器都喜歡把一段主歌寫在兩個八度上，大約每四行切換一次。**聲部遵循提示**（歌詞框下方的核取方塊，歌詞中有提示時出現；新版本預設勾選）會遵從提示：寫方案時，每一段被標註的旋律都會按整八度移到那個人聲演唱的位置，男聲偏低，女聲偏高。方案的其他部分都不會改變。每次渲染前都會重做一遍，所以會跟隨歌詞或樂譜的修改。在樂譜頁面裡，**聲部對應提示**會對框中的樂譜做一次同樣的處理，適用於沒勾選這個核取方塊時做的版本；儲存樂譜再渲染即可。

有三點值得了解：

- <strong>誰唱哪一行仍有幾分運氣。</strong>旋律到位後，大多數行會交給被提示的人聲，但渲染仍可能把某一行交給另一個人聲。換一個種子重新渲染，或者使用**再試幾個**。
- **合唱**會把這一行放在女聲演唱的位置，第二個人聲則交給渲染，渲染常常會在副歌里加進一個。它是在請求二重唱，而不是製造二重唱：你能聽到多少第二人聲，每次渲染都不一樣。目前還沒有辦法在不損害歌詞的前提下把兩位歌手寫進同一行。
- 在這個核取方塊出現之前做的版本，樂譜保持原樣；勾選它，或使用**聲部對應提示**來調整。

**手寫。**「展開」按鈕會開啟全尺寸編輯器，帶有前奏、主歌、預副歌、副歌、橋段、間奏、尾奏和純音樂按鈕。一個段落是像 `[Verse]` 這樣的一行，後面跟著它的各行；下面沒有歌詞的標籤，如 `[Interlude]`，就是一段純器樂。

### 聲音 {#the-sound}

- **和聲**（滑塊）：和絃有多大膽。新歌從**多樣**開始，演繹設在**寬廣**：在我們自己的測試裡，這一組合給出了音樂上最有意思的版本，所以是個不錯的起點。可以隨意調整其中任何一個。已有的版本保留它們當時的設定。規劃器自己往往會寫一個四和絃的迴圈，並在每個段落裡使用它，而每升一級都會讓它離這種寫法更遠一點。各級別層層疊加：

  | 級別 | 對和絃做什麼 | 什麼時候選 |
  |---|---|---|
  | 熟悉 | 什麼都不做：YuE2 的和絃，常常整首歌只有一個迴圈 | 你喜歡規劃器的第一想法，或想要最簡單的伴奏 |
  | 多樣 | 不鼓勵原樣重複剛用過的和絃，所以會給它們換色（先 F，再 Fmaj7），但仍留在調內 | 迴圈聽起來太單調，而你希望歌曲保持常規 |
  | 多彩 | 同上，力度更強：主歌和副歌分開，和絃更豐富。段落也不能用與上一段相同的和絃開頭，所以副歌不再像主歌那樣開始 | 你希望副歌是一次推進，而不是重複。不錯的第一步 |
  | 冒險 | 不鼓勵最近用過的*根音*，而不只是寫法，所以和聲必須遊走，並從調外借用和絃 | 你想要動感和驚喜，並願意留意聽起來奇怪的和絃 |
  | 調外 | 大膽，偏向調外和絃 | 實驗。做好扔掉一些方案的準備 |

  從「多彩」開始，各段落之間的和絃選擇差異更大：一首歌裡有更多不同的和絃、更多不重複的四小節型，以及更少照搬主歌開頭的副歌。方案仍然是一首正常的歌，所以在求助更狂野的方案多樣性之前，值得先把和聲往上調一兩級試試。在**高階**裡，**段落開頭各不相同**可以設為*總是*或*從不*，用來測試有無副歌規則的方案；預設的*跟隨和聲*在「多彩」及以上生效。陷阱或氛圍這類風格本質上往往建立在迴圈上，所以變化會比流行或搖滾小。測量資料參見[和聲](#harmony)。
- <strong>方案多樣性。</strong>規劃器在其他所有方面寫得有多自由。參見[方案多樣性](#plan-variety)。
- <strong>演繹。</strong>渲染時音符如何被演奏。參見[演繹](#interpretation)。
- <strong>時長上限。</strong>歌曲最晚可以在何時結束。參見[時長](#length)。
- **模式。** *完整*保留方案的和絃；*旋律*讓伴奏自由發揮。*無樂譜*（僅限歌曲）完全不寫方案：參見[沒有樂譜的歌](#a-song-with-no-score)。
- **種子**和**保留此種子**。參見[種子，以及重現一個版本](#seed-and-reproducing-a-take)。
- **製作潤色**和<strong>響度標準化。</strong>參見[製作潤色](#production-polish)。
- 視窗底部按鈕旁的**方案就緒後立即渲染**會一口氣完成方案和渲染，中間不停。預設勾選，編輯器會記住你的選擇。取消勾選可以先讀方案。
- **高階**（標題欄按鈕）：擴散步數、遵循風格、避免、鎖定調性、鎖定速度、最長樂譜、和絃停留上限、調外和聲加成、段落以不同方式開頭、目標響度和結尾淡出。參見
  [高階設定](#advanced-settings)。
- **母帶**（它左邊的按鈕，版本有聲音時出現）會在編輯器上方開啟母帶處理架，作用於其中的版本。處理架依次是 1073 風格均衡器、參量均衡器、壓縮器、立體聲擴充套件器和限幅器。在參量均衡器的圖上，七個頻段各是一個點：左右拖動調頻率，上下拖動調增益，在點上滾動滾輪調寬度，雙擊可復位。圖下方的條帶設定所選頻段的型別（低切、低架、鐘形、陷波、高架、高切），並開啟或關閉它，**平直**把每個頻段恢復到 0 dB，圖角上的按鈕則改變圖上顯示的分貝範圍。母帶處理架改變版本的聲音時，按鈕顯示為綠色。處理架開啟時，空格鍵播放和暫停版本，方向鍵在其中移動並調節音量，與主頁面相同。Esc 關閉處理架，再按一次關閉編輯器。

### 讓歌曲更長 {#making-the-song-longer}

歌曲的長度由方案決定，渲染會跟隨方案的長度。能改變它的是這些：

| 想要… | 這樣做 |
|---|---|
| 更長的歌 | 給每個段落更多行（**主歌或副歌的行數**：6 或 8） |
| 更慢、更長的歌 | 在「高階」裡設定**鎖定速度**。同一份方案 BPM 越低，時長越長 |
| 透過加段落讓歌更長 | 行不通：一份方案大約有 8 到 10 個段落，多出來的只會變短或被壓縮 |
| 比方案允許的更多 | 寫一份新方案；同樣的歌詞每次執行，時長差別很大 |
| 歌詞結束時歌也結束 | 只在歌被截斷時才提高時長上限；上限是天花板，不是目標 |

### 有了方案之後 {#after-the-plan}

- 只要開啟的版本已有音訊，**渲染此樂譜**就會新建一個版本，所以渲染永遠不會覆蓋你想拿來比較的版本。還沒有音訊的版本會被補全。
- **保留此旋律**（修改了某個版本的歌詞之後）：用新歌詞演唱該版本的樂譜，作為新版本。旋律不能增加段落或音符，所以如果你的歌詞段落比旋律多，或音節比它的音符多得多或少得多（長句配給為短句寫的旋律，或短句配給為長句寫的旋律），這個核取方塊會自動取消勾選，並寫一份新方案，附上一行說明原因。參見[同一旋律，新的歌詞](#same-tune-new-words)。
- <strong>篩選庫。</strong>篩選器旁的**歌曲**、**翻唱**和**純音樂**開關只顯示開啟的空間裡這些型別；可以選多個，或都不選以顯示所有型別。

## 閱讀和修改方案 {#reading-and-fixing-the-plan}

方案用 **ABC 記譜法**寫成：音樂以純文字表示，用字母代替五線譜上的音符。
Chris Walshaw 在九十年代初發明瞭它，用來透過電子郵件傳送民謠旋律，此後便流傳下來。

你不必會讀它。應用會在編輯器下方把同一份方案顯示為**和絃譜**和真正的**五線譜記譜**，**展開**會把它們全尺寸開啟。但文字才是 YuE2
寫下並據以渲染的東西，所以值得學會在其中找路。

### 閱讀方案 {#reading-a-plan}

方案以一個標頭開始，每行一個字母加一個冒號：

```
X:1
M:4/4
L:1/32
Q:1/4=120
V: Vocal clef=treble name="Vocal Melody"
V: Ins   clef=treble name="Ins Melody"
K:D#m
```

| 行 | 含義 |
|---|---|
| `X:1` | 曲目編號。每個 ABC 檔案都以它開頭 |
| `M:4/4` | 拍號——每小節四拍 |
| `L:1/32` | 單位時值：單獨一個字母持續一個三十二分音符 |
| `Q:1/4=120` | 速度——每分鐘 120 個四分音符 |
| `V:` | 宣告一個聲部。YuE2 寫兩個：一個人聲線，一個器樂線 |
| `K:D#m` | 調性，升 D 小調。`K:` 總是在標頭的最後 |

然後是音樂本身：

```
% intro
V: Vocal
z24z4"D#m"z4|"D#m"z32|
V: Ins
Z|d16a16-|a16g8a8|
```

- **音符是字母。**`d16` 是一個持續 16 個單位的 D。小寫字母比大寫字母高一個八度，
  `'` 或 `,` 會把它們移得更遠。
- **`-` 把一個音符連到下一個**，讓它們聽起來像一個音。
- **`z` 是休止符**，和音符一樣有時值。大寫的 `Z` 是整小節休止。
- **和絃寫在雙引號裡**，如 `"D#m"`，放在它開始的那個音符前面。**查詢和替換**編輯的就是它們。
- **`|` 是小節線**，**`%` 開始一條註釋**——段落就是這樣標出的：
  `% intro`、`% verse`、`% chorus`。

所以這一段說的是：升 D 小調，四四拍，每分鐘 120 拍，前奏期間人聲不唱、只承載和絃，樂器則奏出連起來的 D 和 A，然後是 G 和 A。

兩個實際的結論。**改和絃是安全的**，即使音符看起來晦澀——它們只是引號裡的部分，其餘都可以保持原樣。而且**如果你修改了方案，渲染會使用你改過的內容**，所以修好一份方案往往比反覆重擲直到出現一份好的更快。

### 試聽 {#hearing-it}

**五線譜**標籤頁的五線譜上方有一個播放器。點選**播放**，就能聽到框中現有的方案（包括你的修改），在為一段拿不準的旋律花掉一次渲染之前，先用耳朵判斷它。播放的音符會隨之高亮，它的速度控制只改變試聽，不改變樂譜。開始播放會停止播放欄正在播放的內容，因為同時放兩樣東西對誰都沒有幫助；關閉視窗——或切換到和絃或歌詞——也會停止它，這樣就不會有東西在沒有控制按鈕可用時繼續播放。

**樂器**用風格里提到的樂器演奏每個聲部，而不是全部用鋼琴：寫著 *electric guitar, drums* 的風格會用吉他來聽，和絃由另一把吉他彈，下面還有貝斯；演唱的線條會換成人聲，純音樂的旋律則不會。提到鼓的風格還會得到一個鼓聲部，按樂譜本身的拍號寫成——搖滾用反拍，舞曲用四踩，爵士用叮叮鑔，抒情歌則更簡約——並且從頭到尾都在演奏，因為樂譜裡沒有讓它停下的段落。播放器旁的那一行會說明選了什麼，取消勾選則回到你原本會聽到的鋼琴。這是對風格的解讀，而不是對渲染的解讀：YuE2 決定真正的演奏，還會加上樂譜裡從來沒有的聲部，所以把它當作用合適的音色演奏的方案，而不是版本最終的聲音。

**下載 MIDI**把樂譜儲存給 DAW 用。每個聲部都是單獨的一軌，在各自的通道上，並把試聽所用的樂器分配給該通道：人聲線、器樂線，以及（除非你取消勾選**和絃**）作為和絃聲部、旁邊帶著貝斯的和絃符號（這是和聲唯一被寫成音符的地方），風格要求時還有第 10 通道上的鼓。樂器使用 General MIDI 音色編號，所以你的 DAW 會用自己的音色來演奏它們，速度和拍號也寫在檔案裡。中途換拍號的方案會按它開頭的拍號寫入——只記錄這一個——而音符保留各自的時值。在五線譜上點選一個音符，游標會跳到寫下它的 ABC 處。

如果樂譜裡有音符高於或低於這些樂器能演奏的範圍，就會按整八度移動後再演奏，直到合適為止，播放器旁的那一行會說明移了多少；五線譜、MIDI 檔案和樂譜本身都不變。樂器的音域各不相同——貝斯遠遠低於鋼琴——所以樂譜被移動時才會出現這一行。還沒有音符的樂譜沒有東西可以演奏，並會如實說明。

播放器需要音符取樣，它們不隨應用附帶：每種樂器大約 7 MB，第一次在試聽中用到時從來源下載，並儲存在庫裡，所以之後可以離線使用。**播放**會下載當前樂譜所需的內容然後開始播放，**獲取音色**則只下載同樣的內容而不播放，適合想提前準備好的人。

### 鋼琴捲簾 {#the-piano-roll}

在樂譜視窗中點選**鋼琴捲簾**，開啟視覺化 MIDI 編輯器。你不必編輯原始的 ABC 字母，而是直接在一個互動式的音高—時間網格上檢視和塑造旋律。

編輯器同時顯示樂譜的兩個聲部——**Vocal**（天藍色的主唱旋律）和 **Ins**（暖琥珀色的器樂伴奏）。兩個聲部始終完全可用，可見、可選、可編輯。左上角的**繪製**按鈕決定點選新增的新音符屬於哪個聲部。

#### 編輯音符 {#editing-notes}

- <strong>新增音符：</strong>點選網格中的空格，在該音高和時間處建立一個音符。音符會立即發聲，讓你聽到音高。
- <strong>選擇音符：</strong>點選一個音符即可選中。按住 <kbd>Shift</kbd> 或 <kbd>Ctrl</kbd>/<kbd>Cmd</kbd> 點選，可在人聲和器樂聲部中選中多個音符。在空白區域拖出一個**選框**，可選中所有聲部中的一個樂句或段落。按 <kbd>Ctrl</kbd>+<kbd>A</kbd>（macOS 上為 <kbd>Cmd</kbd>+<kbd>A</kbd>）或點選**全選**選中樂譜中的所有音符。要選中從播放游標到歌曲結尾的所有音符，按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>A</kbd> 或 <kbd>Alt</kbd>+<kbd>A</kbd>（或點選工具欄中的**從游標起 ▶**）。
- <strong>移動音符：</strong>橫向拖動選中的音符可提前或推後，縱向拖動可移調。選中多個音符時——無論是人聲、器樂還是兩者——它們會一起移動，保持相對時間、旋律和歌詞不變。
- <strong>時值：</strong>拖動音符的右邊緣可加長或縮短它。**吸附**選擇器（1/16、1/8 或 1/4 音符）讓移動和調整大小對齊到整齊的音樂細分。
- <strong>刪除音符：</strong>雙擊音符將其刪除，或選中一個或多個後按 <kbd>Delete</kbd> 或 <kbd>Backspace</kbd>。
- <strong>撤銷和重做：</strong>每一次對音符的編輯、移動、調整大小、新增和刪除都會記入歷史。按 <kbd>Ctrl</kbd>+<kbd>Z</kbd>（<kbd>Cmd</kbd>+<kbd>Z</kbd>）撤銷，按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> 或 <kbd>Ctrl</kbd>+<kbd>Y</kbd> 重做。
- <strong>試聽琴鍵：</strong>點選左側鋼琴鍵盤上的琴鍵，聽它的音高。
- <strong>最大化：</strong>點選頂部欄中的**最大化**，讓鋼琴捲簾撐滿瀏覽器視窗的整個寬度。

#### 時間線、段落與和絃 {#timeline-sections-and-chords}

沿著頂部標尺，時間線顯示小節號和段落邊界：
- <strong>重新命名段落：</strong>點選段落標記（`intro`、`verse`、`chorus` 等）可編輯名稱或重新指定。
- <strong>編輯和絃：</strong>就在小節標尺下方，和絃軌顯示歌曲的和聲進行。點選已有和絃可重新命名（例如把 `C` 改成 `Am7` 或 `G/B`），點選空小節可放置新和絃。
- <strong>為空小節配和聲（填補空白）：</strong>點選工具欄中的**填補空白**，用根據和絃進行生成的音符填滿器樂伴奏中的空小節。
- <strong>刪除空小節（壓縮空白）：</strong>點選**壓縮空白**刪除兩個聲部中都空著、無聲的小節，把後面的音符和和絃向左移動，消除編曲中多餘的空隙。

#### 歌詞與卡拉 OK 跟隨 {#lyrics-and-karaoke-tracking}

鋼琴捲簾底部有一條專門的歌詞軌，把每個音節對齊到人聲旋律上：
- <strong>按樂句對齊：</strong>點選**匹配歌詞**把歌詞分配到人聲旋律上。對齊會識別旋律樂句之間自然的換氣和休止，把每行歌詞分給它的樂句，而不會讓詞越過休止溢位到後面的小節。多音節的詞會被幹淨地拆分到各個音符上。
- <strong>編輯音節：</strong>點選歌詞標籤（或選中一個人聲音符後按 <kbd>L</kbd>）編輯其文字。如果輸入用空格或連字元分隔的音節（例如 `Hel- lo world`），它們會自動分配到連續的人聲音符上。
- <strong>懸停高亮：</strong>滑鼠懸停在歌詞標籤上會高亮網格中對應的音符，懸停在人聲音符上則會高亮下方的標籤。
- <strong>卡拉 OK 小球：</strong>播放時，一個動畫小球會在每個正在演唱的音符上跳動，當前音節和網格中的音符會即時發光。

#### 播放與和聲伴奏 {#playback-and-harmony-accompaniment}

按 <kbd>Space</kbd> 或點選<strong>▶ 播放</strong>從游標處開始播放。播放線掃過網格，同時更新小節、拍和已播放時間。

- <strong>可聽節拍聲（節拍器）：</strong>播放預設帶有可聽的節拍聲，每小節第一拍是加重的木魚聲，其餘拍則是較輕的咔嗒聲。隨時按 <kbd>C</kbd> 或 <kbd>M</kbd>（或點選走帶欄中的**節拍器**）開關節拍器。
- <strong>和絃和聲伴奏：</strong>播放會直接根據樂譜的和絃進行合成溫暖的複音和絃鋪底。即使人聲或器樂軌靜默，和聲空間仍保持音樂性和溫暖，而不會陷入死寂。按 <kbd>H</kbd>（或點選走帶欄中的**和絃**）開關和絃伴奏。
- <strong>逐小節移動：</strong>按 <kbd>左方向鍵</kbd> 和 <kbd>右方向鍵</kbd> 逐小節後退和前進，或按 <kbd>Home</kbd> 直接回到開頭。

### 和聲 {#harmony}

YuE2 自己往往會寫一個四和絃迴圈並一直停在那裡。**和聲**滑塊會把它從剛用過的和絃上拉開，同時不破壞歌曲的結構。

| 級別 | 你會得到 |
|---|---|
| 熟悉 | YuE2 的和絃。常常整首歌只有一個迴圈 |
| 多樣 | 避免重複同樣的和絃。留在調內 |
| 多彩 | 主歌和副歌得到不同的和絃進行，和絃更豐富。段落不能以上一段的方式開頭 |
| 冒險 | 讓和聲保持流動，並從調外借用和絃 |
| 調外 | 大膽，離調更遠 |

**寫新方案**使用滑塊的當前位置，所以你可以用同樣的歌詞和更大膽的和絃重擲一次，再比較。

這是測量出來的，而不是假設的——一份歌詞、兩種風格、每種三個種子：

| | 熟悉 | 多樣 | 多彩 | 冒險 | 調外 |
|---|---|---|---|---|---|
| 一首歌中不同和絃的數量 | 4.7 | 6.3 | 8.7 | 9.0 | 10.3 |
| 含調外和絃的小節 | 0% | 0% | 0% | 13% | 24% |
| 不重複的四小節型 | 29% | 38% | 50% | 63% | 64% |

每個級別的每份方案都保留了有效的段落與和絃。改為在風格文字里要求大膽的和聲——「jazz harmony」、「borrowed chords」——沒有任何可測量的效果。

### 方案多樣性 {#plan-variety}

在*高階*裡，**方案多樣性**決定規劃器寫得有多自由。和聲作用於和絃，而它作用於一切：旋律、結構和長度。

- <strong>平靜：</strong>最穩定。和絃少，旋律不跑遠。
- <strong>常規：</strong>預設值。
- <strong>活潑：</strong>多一些和絃和轉折。
- <strong>大膽：</strong>更豐富的和聲，大約是常規和絃詞彙的三倍，而旋律依然明顯是同一型別。
- <strong>古怪：</strong>躁動不安。和絃不停變化，旋律在一個段落和下一個段落之間跳換音區。適合奇特、古怪的歌。
- <strong>狂野：</strong>最躁動的一檔，還可能在中途轉調。

### 沒有樂譜的歌 {#a-song-with-no-score}

**無樂譜**是**模式**的第三個選項，它完全不寫方案就演唱歌詞：YuE2 一邊唱一邊寫旋律和和絃，就像原來的 YuE 那樣，歌曲會透過**無樂譜演唱**直接渲染。它聽起來常常和有方案的歌截然不同。

引導方案的那些設定在這裡無從作用，所以選中它時，**和聲**、**方案多樣性**、**保留此旋律**和**嚴格遵循此結構**都會變灰，也沒有可以閱讀或編輯的樂譜。在上限以內，長度由 YuE2
決定。鎖定調性和鎖定速度只能以風格里的文字傳達給它。再唱一次、變奏、再試幾個和新歌詞都可以用，每次都會在沒有樂譜的情況下重新演唱。**寫新方案**會給這個版本一份樂譜，模式也會回到*完整*。它只適用於從提示詞寫的歌：翻唱就是其錄音的樂譜，純音樂則需要樂譜來把人聲擋在外面。兩種引擎都支援。

## 渲染 {#rendering}

### 演繹 {#interpretation}

樂譜決定音符。**演繹**決定它們怎麼被演奏。

| 演繹 | 你會聽到 |
|---|---|
| 標準 | YuE2 通常的詮釋 |
| 緊湊 | 更收斂、更精緻 |
| 鬆弛 | 更粗獷、更隨性 |
| 沉穩 | 可以重複一個音型、停留在律動裡 |
| 躁動 | 讓各聲部保持流動，避免重複 |
| 寬廣 | 尋找不那麼常見的聲音 |

### 變奏 {#variations}

卡片上的閃光按鈕會用其他演繹渲染**同一份樂譜和同一個種子**。因為只有演繹在變，你在它們之間聽到的就是演繹本身——而不是又一次擲骰子。每一個都是獨立的版本，標題為
*Night drive · Loose*，儲存在它所來自的版本里面（參見「庫」中的**版本里的版本**）。視窗有自己的時長上限，初始值取自編輯器的上限，只作用於這些版本。

### 再試幾個 {#try-more}

卡片上的骰子按鈕會把**同一份樂譜和同一份歌詞再渲染成幾個新版本**，方便放在一起聽。變奏只改變演繹、保留種子；這個則改變擲出的結果：

- <strong>新種子：</strong>每個都用新種子，其餘一切不變。
- <strong>規劃器強度：</strong>對於用了帶規劃器半部分的風格 LoRA 的版本，使用同一個種子和其他規劃器強度（跳過它自己的那個）。規劃器改變的是演奏本身，而不只是人聲，所以效果就像換了一個種子。

新版本的標題為 *Night drive · try 1* 或 *Night drive · planner 0.60*，儲存在它們所來自的版本里面，該版本的面板會開啟，隨著它們完成而逐個顯示。要把它們互相比較，在面板開啟時點選**全選**，再點選**對比**。視窗有自己的時長上限，初始值取自該版本的上限。

### 種子，以及重現一個版本 {#seed-and-reproducing-a-take}

每個版本都會記錄它的種子和塑造它的每一項設定。卡片上會列出它們，點選卡片會在版本面板中顯示它們，在編輯器中開啟則會把一切重新載入。**再來**會用完全相同的內容（包括種子）開啟編輯器，用來重現一個你喜歡的版本，或在一個差點讓你滿意的版本上一次只改一項設定。

在編輯器的選單裡，把滑鼠懸停在某個演繹上可以看到它的作用。

勾選**保留此種子**可在多次渲染之間保持同一個種子；不勾選時，每次渲染都會抽一個新的。

渲染使用編輯器所顯示的內容：風格、風格 LoRA 及其強度、時長上限、模式、演繹和種子，即使是重新渲染某個版本自己的樂譜也一樣。

### 同一旋律，新的歌詞 {#same-tune-new-words}

規劃器在寫下第一個音符之前會讀完全部歌詞，所以同一個種子只有在歌詞相同時才會給出相同的方案。改動一行，下一份方案就是一段新旋律：不同的曲調，常常還有不同的調性和速度，人聲也會隨之改變。

要保留一段你喜歡的旋律，開啟該版本並修改它的歌詞。歌詞下方會出現**保留此旋律**，已勾選，主按鈕也會變成**用新歌詞演唱**。先改好你想改的其他一切：風格、LoRA 及其強度、時長上限、演繹。然後該版本的樂譜會用新歌詞演唱，作為原版本旁邊的新版本，原版本保持不變。保持種子勾選，讓人聲儘可能接近。取消勾選**保留此旋律**，則會改為為歌詞寫一份新方案和一段新旋律。新歌詞如果保持舊歌詞各行的音節數，與旋律最貼合。如果不是——段落更多，或音節比旋律的音符多得多（長句配給為短句寫的旋律：歌詞會被重複或丟失），或少得多（短句配給為長句寫的旋律：歌手會用自己的詞填滿多餘的音符）——**保留此旋律**會自動取消勾選，並附一行說明原因，同時為歌詞寫一份新方案。重新勾選它，就仍然會唱這段旋律。

### 製作潤色 {#production-polish}

**製作潤色**會應用 Mothersuperior 的 Realaudio 解碼器 LoRA。原版 YuE2 的中頻常常聽起來發悶；它能把樂器和人聲分得更乾淨。預設開啟。

### 時長 {#length}

時長上限是硬性的天花板，而不是目標。歌曲何時結束由 YuE2 決定，通常它會自己結束；上限只會叫停不肯結束的那首。它從 360 秒開始，或者從設定中**新版本的時長上限**的值開始。之後它會為音樂騰出空間，免得長歌被截斷：

- 對於**從提示詞寫的歌或純音樂**，寫方案時如果方案更長，上限就會提高：提高到方案的時長，再留大約十秒餘量。它從不會被降低。
- 選擇了**錄音**時（用於翻唱或純音樂），上限跟隨錄音的樂譜，同樣向上取整。

你自己輸入的上限會保持原樣，樂譜頁面會在方案比它長時提醒你。比上限長得多的方案（超出三分之一以上，且長於八分鐘）根本不會被當作一首歌，會被重寫。偶爾渲染不會在樂譜結尾停下，而是一直跑到上限；這樣的版本會在最後幾秒淡出而不是戛然而止，它的卡片會說明它碰到了上限。更少見的是，渲染在樂譜最後一段開始之前就結束了。這時應用會先用一個新種子重新渲染，再認定它完成；如果那一次也太短，卡片會說明它在最後一段之前停了下來：再點一次**渲染**重試。

## 翻唱一段錄音 {#covering-a-recording}

1. 拖入一個音訊檔案，最大 2 GB。它只儲存一次並計算雜湊，所以同一個檔案永遠不會儲存兩次。影片檔案（MP4、MOV、MKV、WebM 等）也可以：只保留它的聲音，存為 FLAC。
2. 點選**轉錄**。SheetSage2 會把旋律和和絃寫進樂譜框。結果會按錄音快取，所以再翻唱同一首歌時會跳過這一步。
3. 修正它聽錯的地方。
4. 加上歌詞，選一個風格，點選**建立翻唱**。

翻唱遵循原曲的旋律和和絃，其餘一切由風格決定，這正是它成為翻唱而不是複製的原因。

### 錄一段你自己的旋律 {#recording-a-tune-of-your-own}

> [!NOTE]
> 旋律能被識別得多好取決於錄音，圍繞它建立的方案仍可能失手或
> 跑偏：寫一份新方案，或者重錄這段旋律。

在**翻唱**模式下，**錄製旋律**會開啟錄音器。在**輸入**中選擇你要錄的內容：

- <strong>人聲：</strong>對著麥克風唱或哼。**自動調音**可以把錄音校準到某個調和音階；錄音上的按鈕可以在校準版和原版之間切換，讓你聽到它做了什麼。
- <strong>樂器：</strong>用樂器演奏旋律，例如接入音訊介面的吉他。**一次一個音**地彈：你彈的線條會成為被演唱的旋律，掃出的和絃則不會產生可以演唱的旋律。在**裝置**中選擇介面，在**通道**中選擇樂器接入的那一側（介面的輸入 1 通常是**左**）。樂器較輕時調高**輸入增益**，同時別讓電平表進入 CLIP。這裡不提供自動修音：樂器本來就是準的。Yeufonic 會在這個瀏覽器裡記住這些選擇。

節拍器、倒數和耳機監聽對兩者都一樣。**用於翻唱**會把這段錄音儲存為錄音，在列表中標為 **MIC** 或 **INST**。像任何錄音一樣轉寫它；錄下的旋律只會被轉寫為旋律，因為從單獨一段旋律猜出的和絃會卡在用它做出的歌的每一段副歌裡（在此之前轉寫過的錄音會保留它的和絃，直到重新轉寫）。十到三十秒的旋律就綽綽有餘。樂器錄音不提供**提取歌詞**，因為裡面沒有可聽的詞：請用**寫歌詞**。

<strong>聽到自己有延遲？</strong>瀏覽器會在你唱或彈的聲音與你在耳機裡聽到的聲音之間加入一點延遲。如果你的音訊介面有直接監聽（零延遲），請使用它，並關閉錄音器的**監聽**，這樣你會直接從介面聽到自己，而且只聽到一遍。請用有線耳機：藍芽會加入它自己的延遲。

#### 擴充套件成整首歌 {#expand-to-full-song}

錄下的旋律通常只有幾小節長。**擴充套件為完整歌曲**會讓 YuE2 規劃一整首歌，把你的旋律放在裡面：方案採用你旋律的調性、拍號和速度，每段副歌（如果你選擇，也可以是每段主歌）都包含你的旋律，歌曲的其餘部分則圍繞它來寫。然後它會作為你錄音的翻唱進行渲染。

- <strong>演唱者：</strong>男聲或女聲。你的旋律會按整八度移到那個人聲演唱的位置，因為旋律寫在哪個八度決定了由誰來唱。如果風格沒有提到歌手，就會把人聲加進去。
- <strong>和絃：</strong>單獨的旋律從轉寫器回來時常常沒有和絃。這時 Yeufonic 會根據它自己的音符給它配和絃，讓規劃器有和聲可依。你寫進錄音樂譜裡的和絃會被保留。
- **你的旋律**始終是錄音的樂譜，即使編輯器正在顯示一個由它做出的版本。
- <strong>歌曲結構：</strong>歌詞框為空時使用。框裡有文字時，文字中的段落就是結構，並且需要一個 **[Chorus]**（或一個 **[Verse]**）來放你的旋律。
- <strong>歌詞：</strong>哼唱可以不帶歌詞來規劃。用樂器演奏的旋律需要歌詞才能被唱出來，所以先寫歌詞：**寫歌詞**會替你起草。

### MIDI 檔案與翻唱 {#midi-files-and-covers}

> [!NOTE]
> MIDI 檔案用於為原創旋律生成不同的、常常很古怪的版本。

除了錄製的音訊檔案，你還可以在**翻唱**模式下直接拖入或上傳標準 MIDI 檔案（`.mid`、`.midi`）。

上傳 MIDI 檔案時：
- <strong>自動轉寫樂譜：</strong>Yeufonic 會分析各軌和各通道，找出主唱旋律、伴奏和和絃進行，把它們轉寫為 ABC 記譜，並直接載入鋼琴捲簾。較低音區中的合成器主音或音序人聲旋律會自動移調到適合演唱的自然八度。
- <strong>內嵌歌詞：</strong>MIDI 序列中內嵌的歌詞或文字事件會被提取出來，並對齊到旋律的音節上。
- <strong>小節落在哪裡：</strong>MIDI 檔案沒有自己的小節線，有些檔案的第一個詞落在強拍*之前*的那一拍上。Yeufonic 會讀取鼓和貝斯來找到真正的小節線，當檔案以這樣的弱起開頭時，會把開頭的幾個詞放進一個單獨的短小節裡，讓和絃和小節標記落在歌曲實際的位置上。沒有清晰鼓與貝斯型的檔案則保持原樣。
- <strong>貼上的歌詞：</strong>你貼上的詞會一次性對齊到整段旋律上，每個音符一個音節，多出的音符延續前一個音節。各行在旋律休止處結束、在樂句開始處開始，所以比歌詞標題更長或更短的段落不會再把後面的內容擠偏。如果詞比旋律能承載的更多，最後幾行會被捨去。
- <strong>用 SoundFont 完整試聽：</strong>播放器使用 **FluidSynth** 和 General MIDI SoundFont（`.sf2`）把 MIDI 編曲合成為高傳真音訊。輸出會做峰值標準化，讓音量較小的多軌 MIDI 錄音聽起來飽滿清晰而不失真。
- <strong>選擇 SoundFont：</strong>在**設定**中，可以選擇你偏好的當前 `.sf2` SoundFont 音色庫（如 *Arachno SoundFont 1.0* 或 *JNS-GM 2.0*）。放進 `data/models/soundfonts/sf2/` 的其他 `.sf2` 檔案會被自動識別。
- <strong>在鋼琴捲簾中微調：</strong>開啟**鋼琴捲簾**檢查或修改音符，選擇哪一軌作為主唱旋律，用**填補空白**為伴奏中的空隙配和聲，或用**匹配歌詞**對齊剛貼上的歌詞。

### 翻唱語料庫中的歌 {#covering-a-song-from-a-corpus}

語料庫的分析已經完成了翻唱所需的工作：樂譜、在歌中聽到的詞，以及分離出的人聲。所以在你的錄音下方，列表提供了**來自你的語料庫**，按語料庫摺疊，顯示每首歌的調性和速度，大的語料庫還有篩選框。選一首歌，它立刻就會變成你的錄音之一，帶著它的樂譜和歌詞，什麼都不用重新執行。詞會被放到樂譜的段落下面，方式與**提取歌詞**相同，除非你已經在語料庫裡審閱過它們，那樣它們會以你留下的樣子出現。它們會進入歌詞框，替換來自另一段錄音的詞；你在那裡輸入或編輯過的詞，只有在你同意時才會被替換。風格框會得到這首歌在語料庫中學習時所用的風格，也就是用它訓練的 LoRA 下它那個標籤的風格。

磁碟允許時，檔案會被連結而不是複製，所以不再佔用額外空間，並且在語料庫被刪除後仍會保留。有些歌標著 *score: melody only* 或 *score: first 4 min*：它們的完整轉寫在分析時失敗了，不過這對訓練來說已經足夠。點選**轉錄**可得到帶和絃的完整樂譜。

<strong>配合 LoRA。</strong>語料庫裡的歌在這裡最有用：一首歌和一個 LoRA 出自同一批作品，或出自不同的作品。
1. 在**翻唱**模式下，開啟錄音列表，在**來自你的語料庫**中選擇這首歌。它的樂譜決定旋律和和絃，它的歌詞就在框裡。
2. 選一個**風格 LoRA**。語料庫自己的 LoRA 會讓它的歌手翻唱自己的歌，最接近原曲。另一個語料庫的 LoRA 則會用那種風格和那種人聲來翻唱。
3. 像任何翻唱一樣設定強度：錄音已經決定了旋律，所以把**音色**保持在 **0.50** 左右，想要更多 LoRA 的人聲和音色就調高它。
4. 風格框裡已經是這首歌自己的風格，選擇 LoRA 會把它的觸發詞放在最前面。這樣能保留這首歌的流派和氛圍；換一個標籤，或用篩選框的標籤，就能把它帶到別處。速度和調性來自樂譜，不管風格怎麼寫。
5. 點選**建立翻唱**。之後**變奏**會用其他演繹來渲染它，**再唱一次**則會在同一份樂譜上換一種人聲，和任何版本一樣。

### 提取歌詞 {#extracting-the-lyrics}

*轉寫*旁邊的**提取歌詞**會寫下錄音裡唱的內容：它會分離出人聲、聆聽它，並把各行放到樂譜的段落下。它需要你主動請求，而不是在每次轉寫時都執行，因為它要花上幾分鐘，而轉寫樂譜只要幾秒。引擎有 Demucs 和 Whisper 時，人聲的分離和聽詞都在 GPU 上進行，否則在 CPU 上（設定，**用 GPU 處理分軌和歌詞**），進度條會說明正處在兩步中的哪一步。GPU 上的 Whisper
和 CPU 上的 Whisper 對同一段人聲寫出的詞並不總是一樣，因為兩者都不精確：難聽清的人聲，比如疊在主唱上的和聲，詞的差異可能在任一方向達到五分之一。分離出的人聲會被保留，所以再次提取同一段錄音時會直接跳到聆聽這一步，省去大部分等待。

詞會隨錄音一起儲存。再點一次**提取歌詞**，它們會直接回到框裡，並詢問你是否要重新提取——在設定中更改了方法之後，這樣做是值得的。選擇另一段錄音也會同樣取來它的詞，而沒有詞的錄音會清空上一段的詞。你輸入或編輯過的詞會保留，除非你同意替換。

請期待一份不錯的草稿，而不是一份逐字稿。與兩首歌的真實歌詞相比，Whisper
在一首裡錯了 **1.5% 的詞**，在另一首裡錯了 **25%**，後者在最後一段副歌中主唱和和聲互相重疊。它會聆聽整段人聲：以前它會跳過它的語音檢測器當作靜音的部分，而在歌唱人聲裡，那是歌曲的大部分。讀一遍草稿，修正它聽錯的地方，尤其是人聲重疊的地方。

<strong>讓外部 LLM 來聽。</strong>如果你的提供商是[外部 LLM](#external-llm)，設定中會在*從錄音獲取歌詞*裡提供一個選項。把它設為**外部 LLM**，分離出的人聲就會發給模型去聽詞，而 Whisper 仍負責算出每一行在何時被唱出。在同樣兩首歌上，Gemini
得到 **1.5% 和 23%**，所以兩者相差不大；在 Whisper 吃力的歌上可以兩者都試試。這需要一個接受音訊的模型，比如 Gemini。當模型的回答看起來像歌詞時，就會使用它的詞，即使與 Whisper 的詞相差很多：埋在混音裡的人聲正是 Whisper
最吃力、而模型並不吃力的地方。如果模型拒絕音訊、有所保留（縮短各行，或像模型對它認出的歌可能做的那樣，把你引到歌詞網站）或幾乎什麼都沒返回，你會得到 Whisper 的版本。結束時的訊息會說明是哪一個聽出了這些詞。為此人聲會離開你的電腦；Whisper 則把它留在這裡。

對於語料庫裡的歌，**兩個版本都會儲存**。兩者都存在時，這首歌的審閱面板會顯示**詞來自**，列出每個版本及其詞數，預設使用外部模型的版本。選擇另一個，它的詞就會進入框裡。第一次選中某個版本時，它的詞會被整理成草稿，這一步會用外部模型標出它的段落；之後每個版本都保留自己的詞、編輯和**已檢查**核取方塊，所以在它們之間切換是即時的，也不會呼叫模型。在 Whisper 的各行中，任何連續重複超過八次的詞，比如它寫了幾百遍的一個拖長的「la」，都會被削減到八次。

## 純音樂 {#instrumentals}

第三種模式寫沒有人聲的作品。它接受的不是歌詞，而是一個**結構**：

| 結構 | YuE2 收到什麼 | 由誰決定 |
|---|---|---|
| 讓 YuE2 決定 | `[instrumental]` | YuE2 選擇段落及其長度 |
| 段落 | `[intro] [verse] [chorus] …` | 你選擇段落，YuE2 決定長度 |
| 定時段落 | `[intro 0:00-0:15] …` | 兩者都由你選擇 |

用 **+** 標籤新增段落，用箭頭重新排序，在定時模式下給每段設定時長。<strong>傳送給 YuE2：</strong>會準確顯示模型收到的內容。結構只是參考：YuE2 可能會給某個段落改名、加一段間奏，或超出你給的時間，所以時長上限才是硬性的天花板。

### 來自錄音的純音樂 {#an-instrumental-from-a-recording}

編輯器頂部的<strong>來自錄音（可選）</strong>會取用你的一段錄音，就像翻唱那樣。它的轉寫就是樂譜，所以不需要寫方案，渲染會用器樂 LoRA 演奏它的旋律和和絃。

段落也來自樂譜：樂譜的每個段落對應一個，名稱是 LoRA 認識的那些。*間奏*會變成橋段。渲染會把結構中的每個段落與樂譜中的一個段落配對，所以搭建器會給它們讓位。要重新排列這首歌，可以把段落拖到別處或用箭頭移動，在它後面緊接著加一個**副本**，或用 **✕** 刪除它：每次改動都會重寫樂譜（樂譜視窗會顯示出來），**恢復原來的段落**則會把它恢復，直到載入另一份樂譜。版本在編輯器中播放時，當前所在的段落會亮起，雙擊某個段落會跳到那裡。時間取自樂譜的小節和速度，渲染在版本開頭以及整段渲染的版本中都會緊緊跟隨它們。比樂譜結束得早很多的渲染，演奏的音樂少於樂譜所含的內容，所以隨著歌曲推進，列表可能會與音訊錯開；列表下方的一行會說明這一點以及錯開多少。翻唱會在歌詞下方顯示同樣的列表，它的歌詞會按順序與各段落配對，所以請相應調整：新增、刪除或重排段落後，列表會說明它需要什麼。它還會顯示總時長與時長上限的對比，並在更長的歌會被截斷時提議提高上限。點選**建立純音樂**進行渲染。

從結構寫出的純音樂也有樂譜，規劃完成後，它的段落會以同樣方式列出。結構搭建器是對一份尚未寫出的方案的委託，所以它會給列表讓位。重新排列段落後點選**渲染此樂譜**：渲染的段落標籤會跟隨編輯後的樂譜。已有音訊的版本會被渲染為旁邊的新版本，無論你改了什麼，所以原版本會保留它自己的。**寫新方案**（在樂譜下方）仍會根據寫出這個版本時所用的結構，請求一段不同的旋律。

<strong>帶人聲的歌也可以。</strong>它的樂譜把演唱的旋律寫在人聲聲部裡，那樣會被唱出來，所以旋律會交給一件樂器：在沒有樂器演奏的地方，演唱的音符會移到樂器上，人聲聲部只保留它的和絃。編輯器會在錄音下方說明這一點。對一首歌來說，這往往是更好的選擇：沒有人聲時，轉寫器容易丟失主歌和副歌之間的區別，把整首歌聽成一個和絃迴圈。LoRA
會把它編成純音樂，所以會有它自己的聲部，比如多出來的吉他。

在列表中選擇**無錄音：寫樂譜方案**，就會回到寫方案。

### 純音樂唱了起來 {#when-an-instrumental-sings}

模型偶爾會在純音樂裡塞進人聲。這是模型的毛病，不是你設錯了什麼。渲染前，如果方案在人聲聲部放了音符，會彈出一個對話方塊，提供新方案、新種子，或照樣渲染。已完成的版本不會被檢查：請聽一聽。

### 用歌曲的樂譜做純音樂 {#an-instrumental-from-a-song-s-score}

在編輯器的樂譜頁面裡，歌曲或翻唱的樂譜下方（歌曲則在**渲染此樂譜**旁邊）的**生成純音樂**，會把同一份樂譜做成純音樂，放進一個新版本：原版本保持不變。演唱的旋律會移到一件樂器上，發給模型的只是樂譜的段落標籤而不是歌詞，會使用器樂 LoRA，風格里描述人聲的標籤（「soft male vocal」）也會被去掉。這就是得到「這段旋律，不帶人聲」的辦法。手動清空歌曲樂譜中的 Vocal 聲部是不夠的：歌曲的渲染仍會唱它收到的詞。

## 人聲 {#voices}

**人聲**標籤透過寫入風格來設定歌手的性別和特質，作用於整首歌。

要做二重唱，或者主歌一位歌手、副歌另一位，就在歌詞里加上人聲提示並勾選**聲部遵循提示**：參見「從提示詞寫一首歌」中的[歌詞](#the-words)。它也適用於翻唱的歌詞。

## 語料庫與訓練 LoRA {#corpora-and-training-a-lora}

**語料庫**是一個歌曲資料夾，被整理成風格 LoRA 的訓練集：通常是一位藝人、一種流派，或幾位相近的藝人。從選單中開啟**語料庫**。它預設開啟；為應用設定 `TRAINING_ENABLED=0`，或用
`WITH_TRAINER=0` 建置引擎，就會去掉它。

訓練是應用要做的最吃資源的事：使用推薦的全品質模型（BF16）時，
16 GB 的顯示卡和 32 GB 的系統記憶體（在 WSL2 中，在 `.wslconfig` 裡設定 `memory=32GB`）是實際的最低要求。
8 GB 的顯示卡也許可以用低顯示記憶體模型（INT8）來訓練。

1. <strong>新建語料庫。</strong>給它一個名字和一個**觸發詞**，說明人聲是男聲還是女聲（沒有人聲的歌選**無**：見下文），描述所有歌曲共有的聲音，並開啟存放它們的資料夾。確認你有權用它們訓練，然後點選**掃描資料夾**。資料夾只會被讀取。<strong>沒有人聲的語料庫。</strong>當歌曲是純音樂時，比如舞曲和電子音樂，在**人聲**中選擇**無**。這樣應用不會分離人聲也不會聽詞，所以不會有東西在合成器上編出歌詞。每首歌的歌詞就是其樂譜裡的段落標籤（沒有的話就是
   `[instrumental]`），描述會略去人聲部分，也沒有歌詞審閱：**段落**框可以編輯，編輯會被儲存。每首歌的聲音由本地模型描述（若已安裝），因為外部模型只能依據一個標題。這樣訓練出的 LoRA 可能會在方案的 Vocal 聲部寫入音符，讓渲染唱出或哼出聲來；方案的「可能會唱」警告會顯示這一點。更改已分析語料庫的人聲設定，會相應地改變它的歌詞。
2. <strong>選擇歌曲。</strong>取消勾選你想排除的歌。準備一首歌時，應用會把完整錄音的副本儲存到語料庫的內部儲存裡，所以即使原始檔夾之後被清空或移動，語料庫也會保持完整。超過 25 分鐘的錄音會被排除，因為它多半是整張專輯或一場演出被存成了一個檔案。如果旁邊有 `.cue` 檔案，**拆分為曲目**會把它切成各首歌，替代它在語料庫中的位置。這些曲目會放進應用自己的資料夾；你的資料夾不會改變。（比訓練器的 GPU 上限更長的歌，比如 15 分鐘的曲目，在匯出時會被安全地截斷，並在一個音樂段落的邊界處淡出。）
3. <strong>分析。</strong>每首歌的人聲會被分離，調性、速度和段落會被找出，歌詞會被起草並按段落標註。配置了外部 LLM 時，段落會根據聽到的詞來標註：副歌因為詞會重複，新段落則依據停頓。只傳送各行及其時間，詞和詞的順序永遠不會被改動。沒有外部 LLM，或它的回答沒有包含所有行時，標籤來自音樂分析。在一首歌的審閱中，「儲存」旁的**重新起草**會用同樣的方法重新標註段落而不重新聆聽這首歌，適用於之前起草過的歌，並會替換框中的內容。按鈕下方的一行說明正在執行什麼，進行中的分析會顯示在主螢幕的任務卡片和佇列中。**停止**會停止它。已完成的步驟會被保留，所以**分析**會從停下的地方繼續。

   <strong>重新分析。</strong>所有歌都分析完後，按鈕會顯示**已分析 ✓**。點選它會詢問你是否要用最新的提示詞和 LLM 設定重新分析所有歌曲的風格建議（在重新命名語料庫或更換提供商之後很有用）。按住 Shift 點選<strong>已分析 ✓</strong>會提供從頭開始的完整重新分析（再次進行分離、調性、速度、轉寫和風格）。每首歌也可以在它的審閱中透過**重新分析**重新確定風格。
4. **檢查**開啟一首歌，審閱它的歌詞並勾選**已檢查**，並在它的聲音與其他歌不同時加以描述。風格描述顯示訓練器將讀到的內容。
5. <strong>匯出訓練集。</strong>寫出每首歌的音訊、歌詞和描述。按鈕下方的一行顯示進度。訓練器只取每首歌的一部分，這部分由應用根據你顯示卡的空閒顯示記憶體算出（16 GB 顯示卡上大約 5½ 分鐘；日誌視窗會說明選擇了多少）。更長的歌會在這個範圍內最後一個段落的結尾處截斷、淡出，並只保留仍在演唱的詞。它那一行會顯示「first 3:12 trained」。如果訓練顯示記憶體不足，把環境變數 `TRAIN_MAX_MINUTES` 設得低一些，比如
   3.5：參見 README。
6. <strong>訓練 LoRA。</strong>這需要很長時間，在完成之前應用無法使用
   GPU。進度顯示在按鈕下方和主螢幕上，你可以在那裡停止它，訓練期間頁面頂部的語料庫徽章會閃動。重新訓練會把上一次執行的 LoRA 以帶日期的名字保留在**先前的執行**中，或者刪除它，由你選擇。使用推薦的全品質模型（BF16）訓練至少需要大約 12.5 GB 顯示記憶體（擷取 3½ 分鐘時；擷取更長則需要更多），大部分用在準備歌曲時，所以 16 GB 的顯示卡是實際的最低要求，同時還需要 32 GB 系統記憶體（ComfyUI 會把 YuE2 的完整權重和資料集快取放在主機記憶體裡；在 WSL2 中，在 `.wslconfig` 裡設定 `memory=32GB`）。8 GB 的顯示卡可以用低顯示記憶體模型（INT8）來訓練。無法訓練的顯示卡仍然可以使用在別處訓練的 LoRA（**安裝 LoRA**）。可用的顯示記憶體或系統記憶體較少時，訓練視窗會發出警告，所以先關掉其他佔用 GPU 的程式。

### 提前結束的執行 {#a-run-that-ends-early}

一次執行可能在最後一步之前就結束：**停止**、崩潰，或 GPU 顯示記憶體不足。這時按鈕下方的那一行會說明何時、為何以及在哪一步之後結束。途中訓練器每 50 步儲存一個檢查點，並按規劃器損失保留一份迄今最好的副本，所以大部分成果通常還在。**用已儲存的內容完成**會利用這些檔案，完成一次完整執行會做的事：最好的那份副本（沒有的話就是最後一個檢查點）會成為以語料庫命名、帶有它的觸發詞的 LoRA，檢查點則摺疊在風格 LoRA 列表中它的下面。這只需要幾秒鐘，也不佔用 GPU 時間。一次執行的最後幾步對 LoRA 的改變最小，所以這樣完成的 LoRA 通常接近一次完整執行；如果你想用耳朵比較，**檢查點**會在每一步各渲染一次同一首歌。要重新訓練整個執行，點選**訓練 LoRA**。

### 全部執行 {#run-all}

三個按鈕旁邊的**全部執行**會依次執行分析、匯出和訓練，適合你不想守著等的語料庫：大的語料庫要分析好幾個小時。它會先問你如何處理上一個 LoRA，然後在頁面關閉的情況下繼續。它只分析仍需要分析的部分，分析失敗的歌會被排除在訓練集之外，並在按鈕下方列出。沒有人審閱過的歌詞會按起草的樣子使用。**停止**會在當前位置停下，保留已完成的部分；在匯出時停下，會先把訓練集完成。訓練前，它會等待已在使用引擎的所有任務。重啟應用會停止它，再點**全部執行**會繼續。

### GPU 顯示記憶體用盡時 {#running-out-of-gpu-memory}

顯示記憶體不足的任務會說明這一點，並給出可以嘗試的辦法：關閉其他使用 GPU 的程式、降低時長上限，或者（對於訓練）排除最長的歌。如果引擎崩潰並重啟，正在執行的任務會丟失，這一點也會說明。

### 訓練好的 LoRA {#the-trained-lora}

訓練完成後，LoRA 會帶著它的觸發詞出現在**風格 LoRA**列表中。選擇它，風格框下方會為它學過的每首歌顯示一個標籤，點選某個標籤會把那首歌的風格放進框裡。歌曲達到十幾首時，會出現一個篩選框和一排語料庫中反覆出現的標籤（它的流派、氛圍和樂器），幫你縮小範圍；點選兩個標籤可以找到同時具備兩者的歌。列表會先顯示前十二首，點**全部顯示**才顯示其餘。初始強度請參見下文的**平衡規劃器與音色**。要分享它，在語料庫頁面點選**下載 LoRA**，或在選擇器下方點選**下載**；參見下文的**分享 LoRA**。

要新增別人分享的 LoRA，點選**新建語料庫**旁的**匯入 LoRA**並選擇它的 zip。要使用在別處用匯出的訓練集訓練出的 LoRA，點選**安裝 LoRA**並選擇該檔案。它會帶著這個語料庫的觸發詞加入風格 LoRA 列表。

**刪除語料庫**會刪除應用為它的歌曲做的副本、分離出的人聲、歌詞和樂譜。你指定的資料夾，以及用它做出的任何 LoRA，都不會被動到。

## 風格 LoRA {#style-loras}

LoRA 是一個小檔案，能讓模型偏向某種聲音。把它放進 `models/loras/`，然後點選選擇器下方的**重新掃描**，或使用**安裝**，它就會出現在**風格 LoRA**列表中。

風格 LoRA 可以有兩個半部分，選擇器會顯示一個檔案具備哪些：

- **規劃器**塑造演奏的內容——樂譜方案（結構、和聲、樂句），以及之後渲染根據這份樂譜寫出的音樂。它在兩個步驟中都起作用。
- **音色**塑造音訊——音色和製作。

檔案無法使用的強度會顯示為灰色，而這個引擎根本無法載入的檔案會被標記出來，而不是在渲染中悄無聲息地失敗。

### 在哪裡找到風格 LoRA {#where-to-find-style-loras}

最快的辦法是在安裝時：在安裝程式的元件頁面勾選**風格 LoRA**（使用 Docker 時，執行
`sh scripts/fetch-models.sh --loras`）。這會從作者那裡下載 39 個風格 LoRA，共 3.8 GB，每個都附有一段說明，給出它的觸發詞和建議強度：包括下面這些合集、atomtanstudio 的兩個（dream pop
和 old school hip-hop），以及 ntc-ai 的十六個概念滑塊，它們只塑造樂譜（音色不起作用，也不需要觸發詞）。它們原封不動地收集在
[pshields/yue2-style-loras](https://huggingface.co/pshields/yue2-style-loras) 中，其 README 註明了每位作者並連結到原始頁面。你的資料夾裡已有同名的 LoRA 會保持原樣。

Hugging Face 上還有更多。以下是收集在那裡的合集，各自位於作者的頁面上：

- [Militant reggae](https://huggingface.co/becausereasons/yue2-mltnt-militant-reggae)
- [Chanson française](https://huggingface.co/becausereasons/yue2-chnsn-chanson-francaise)
- [Canzone italiana](https://huggingface.co/becausereasons/yue2-cnzn-canzone-italiana)
- [Bulgarian voices](https://huggingface.co/becausereasons/yue2-blgr-bulgarian-voices)
- [Qawwali, sufi and tabla](https://huggingface.co/becausereasons/yue2-qwwl-qawwali-sufi-tabla)
- [J-pop](https://huggingface.co/storagejuju/yue2-jpop-t4-lora)，一個只有音色半部分的 LoRA

要新增其中一個，從倉庫的 **Files** 標籤頁下載它的 `.safetensors` 檔案，放進 `models/loras/`
並點選**重新掃描**，或者點選**安裝**並選擇該檔案。倉庫頁面給出了每個 LoRA 的觸發詞和建議強度：把它們寫進檔案旁邊的一個 `.txt`（參見下文的**說明**），選擇器就會顯示它們，並替你把觸發詞放在風格的開頭。來自別處的 LoRA
可能以這個引擎無法載入的格式儲存：選擇器會把它標記出來，它也不會造成任何損害。

每個 LoRA 都帶有作者的許可證，這些合集標明為 CC BY-NC 4.0：僅限個人、非商業用途，和 YuE2 的權重本身一樣。在使用某個 LoRA 或分享它生成的內容之前，請先在它的頁面上閱讀許可證。

### 平衡規劃器與音色 {#balancing-planner-and-sound}

- <strong>風格統一的語料庫：</strong>用單張專輯或統一的原聲音色（例如六十年代的民謠搖滾）訓練的 LoRA 可以承受更高的強度，通常在**規劃器 ~0.85 / 音色 ~0.80** 左右。
- <strong>風格多樣的語料庫：</strong>如果訓練語料庫跨越多種流派、製作風格或年代（例如原聲民謠、搖滾和合成器流行），較高的音色權重可能造成聲音上的衝突。大約到**規劃器 0.70 / 音色 0.70** 時，音訊仍保持乾淨，同時保留藝人的旋律樂句和嗓音特點。
- <strong>翻唱：</strong>你的錄音決定了旋律，所以 LoRA 要塑造的東西更少，音色半部分會被推得更用力。把音色保持在 **0.50** 左右。
- <strong>方案多樣性：</strong>使用從語料庫訓練出的 LoRA 時，**平靜**或**常規**給出的結果最容易辨認。**平靜**在搭配風格 LoRA 和簡短風格時可能陷入迴圈，方案會因此長達好幾分鐘，充滿重複的長前奏，或者完全沒有演唱。把風格描述得更詳細些（流派、樂器和感覺），或者使用**常規**。這樣的方案，或比一首歌長得多的方案，會用新種子重寫一次，如果第二次結果相同，這個版本會失敗並附上提示。
- <strong>找到好的版本：</strong>LoRA 的特點既取決於強度，也同樣取決於擲出的結果。在大約 0.3 到 0.6 之間，**音色**對人聲的改變很小，所以不必調高它。**規劃器**改變的是演奏本身，而不只是人聲，所以對某首歌合適的數值，對另一首可能是最弱的。像對待種子一樣對待它：試幾個數值（例如 0.6、0.8 和 1.0），再用**再唱一次**試幾個種子，留下你喜歡的版本。
- <strong>儲存強度：</strong>為某個 LoRA 找到合適的一對數值後，點選選擇器下方的**儲存強度**。之後選擇這個 LoRA 時就會從這組數值開始，而且你分享它時，它們也會隨之而去。

### 觸發詞 {#trigger-words}

大多數風格 LoRA 訓練時用的描述都以一個觸發詞**開頭**，沒有它就幾乎不起作用。應用會處理這件事：選擇一個 LoRA 會把它的觸發詞放在風格的開頭，換成另一個會替換它，選擇「無」會刪除它，如果它被擦掉了，渲染時也會把它放回去。你會看到這個詞出現在風格框裡——可以編輯它，也可以移動它。

### 說明 {#descriptions}

列表按合集分組。點選標題可以展開或摺疊；選擇器會記住你哪些保持展開，包含你當前選擇的那一組總會隨之展開。

把滑鼠懸停在某一項上，可以讀到它是什麼（用作者自己的話）以及建議強度。這些說明來自 LoRA 旁邊的一個文字檔案：

```
CHNSN Rive Gauche
Trigger: chnsn
Step 200, the decoder-loss minimum. The more supple of the two: acoustic
narrative, yé-yé, female leads, waltz meters.
```

第一行給出名稱，`Trigger:` 那一行成為觸發詞，其餘部分就是說明。你自己的 LoRA 只要在旁邊寫一個 `.txt` 也會有說明。同一資料夾裡的 `families.txt`
為各組提供標題，每行一個 `prefix = label`。

### 從語料庫訓練出的 LoRA {#loras-trained-from-a-corpus}

用你的某個語料庫訓練出的 LoRA 就是一個普通的風格 LoRA：它和其他 LoRA 一起出現在這個列表中，旁邊帶著它的觸發詞，同樣適用這兩種強度。

### 試用檢查點 {#trying-the-checkpoints}

一次訓練每 50 步儲存一個檢查點，並把它們放在選擇器中該 LoRA 的下面：
LoRA 名稱旁的 **▸ 9 步**會把它們展開（設定也可以改為刪除它們以節省空間）。LoRA 已被刪除的檢查點會留在**訓練檢查點**中。要刪除其中一些，在語料庫上點選**編輯**：那裡的**訓練檢查點**會列出每次執行（這次和以前的）的檢查點及其大小。勾選要刪除的，然後點選**刪除**。已完成的
LoRA 不會列在那裡；它有自己的**刪除 LoRA**。每個檢查點都是訓練進行到那一刻時的 LoRA。它們聽起來大致一樣好，但各自以自己的方式權衡所學到的東西，所以各有各的味道，同時不會丟失 LoRA 訓練所針對的風格和標誌性聲音。

要並排聽它們，選擇這個 LoRA，像為單個版本那樣設定好編輯器，然後點選**刪除 LoRA**旁邊的**檢查點**。沒有檢查點的 LoRA 這個按鈕是灰的。勾選你想要的步數，如有需要為這些版本設定時長上限，然後點選**渲染**。編輯器自己的操作會在每個檢查點上各執行一次，全部使用同一個種子，每個版本以它的步數命名：
*Night drive · step 250*、*Night drive · full*。它們會儲存在編輯器中開啟的版本里面，如果是新歌，則儲存在它們之中的最後一個裡面（參見「庫」中的**版本里的版本**）。編輯器會關閉，你會回到正在生成這些版本的庫。歌曲或純音樂會先寫方案，再直接進入渲染。

在歌曲或純音樂中，LoRA 除了塑造聲音，還會寫旋律，所以同一個種子不會得到同一首歌：每個檢查點都會寫出自己的旋律和結構。種子是在模型認為可能的選項中做選擇，而每個檢查點從第一個音符起就想得稍有不同，所以幾小節之內方案就會分道揚鑣。剩下的是聲音。若只想比較聲音，用**樂譜**載入一份方案，再依次用每個檢查點點選**渲染此樂譜**。

引擎重新檢視 `models/loras/` 之後，新檔案才會出現，它會在選項重新載入時這樣做。

### 分享 LoRA {#sharing-a-lora}

選擇一個 LoRA，點選選擇器下方的**下載**：你會得到一個包含該 LoRA 及其說明的 zip。對於從語料庫訓練出的 LoRA，說明裡帶有它學到的風格，所以標籤也會隨之而去。

要新增別人發給你的 LoRA，點選**安裝**並選擇它的 zip，或一個單獨的
`.safetensors` 檔案。它會進入 `models/loras`，歸在**已安裝**標題下，帶著名稱、觸發詞和標籤。**刪除 LoRA**會刪除所選的 LoRA、它的說明和它的分組行；**重新掃描**會在你手動新增檔案後重新讀取資料夾。

## 分軌 {#stems}

在任何版本上點選**分軌**。選擇一個模型，勾選你想要的部分——人聲、鼓、貝斯、其他，某些模型還有吉他和鋼琴——然後執行。

引擎有 Demucs 時，分離在 **GPU** 上進行，作為引擎佇列中的一個任務：它會等待正在進行的渲染，然後很快完成，排在它後面的渲染則依次等待。在此之前建置的引擎、正在訓練的 LoRA（它佔用 GPU）、設定中把**用 GPU 處理分軌和歌詞**設為「否」，或 `STEMS_ON_GPU=0`，都會讓它留在 **CPU** 上，CPU 更慢，但永遠不會拖慢渲染。*精細*會連續執行四個模型以獲得更好的分離，耗時大約是四倍。

要做伴奏軌，選擇**人聲與樂器**。它把歌曲一分為二：人聲，以及**樂器**——其餘一切合成一個分軌。取消勾選**人聲**就只保留樂器。這和四軌分離是同一個過程，只是重新加在一起，所以耗時相同，聽起來同樣乾淨。*精細*版本留下的人聲殘留最少。

分軌儲存在 `data/stems/<title>-<id>/`，可以透過卡片上的標籤播放，可以逐個下載，也可以打成
zip 下載。它們會一直保留，直到你刪除。

## 停止、刪除和重新開始 {#stopping-deleting-and-starting-again}

引擎正在做什麼，顯示在頂部欄中名稱旁邊：一個膠囊標籤，帶著任務、它的耗時、底部一條表示進度的線，以及後面還有多少任務在等待。任務開始或結束時，頁面上其他什麼都不會變。點選它可以開啟任務卡片：當前階段、**停止**，以及**接下來**（等待中的任務），每個都帶有**取消**。

排隊中或進行中的版本會在卡片上顯示**取消**，任務卡片上的**停止**會停止引擎正在做的事。任務卡片上、它的**接下來**列表中，或頁面底部播放器中的版本標題，都會帶你去到這個版本：去到它的空間，並清除任何把它隱藏的搜尋或篩選。刪除一個版本會停止它的任務並刪除它的分軌。錄音旁的**刪除**會刪除檔案及其分軌；由它做出的翻唱會保留各自的音訊和樂譜，但無法再重新渲染。

版本面板中的<strong>+ 歌曲</strong>、**+ 翻唱**和<strong>+ 純音樂</strong>，或編輯器標題旁的**新歌曲**，會從當前顯示的版本重新開始。它們會清空標題、歌詞和樂譜，並從預設值開始：空的風格（若選了 LoRA 則帶有它的觸發詞）、通常的時長上限、和聲「多樣」、常規的方案多樣性、演繹「寬廣」、製作潤色開啟、標準化關閉，以及一個新的、未鎖定的種子。已選的 LoRA 和已選的錄音保持選中。當前顯示的版本會脫離編輯器，免得「渲染」誤作用於它。

你輸入過但沒用上的詞不會被扔掉：會有一個提示條提議恢復它們。

## 庫 {#the-library}

### 空間 {#spaces}

版本存放在**空間**裡：每首歌、每張專輯一個空間，或者專門放草稿。版本上方的空間名稱就是當前顯示的那個，你所做的一切都會進入那裡。點選它可以開啟空間列表：輸入文字按名稱查詢，或用方向鍵和 Enter 選擇。你最近用過的五個排在最前，然後是所有空間，每個都顯示有多少個版本。**新建空間**、**重新命名此空間**、<strong>匯入版本…</strong>和**刪除此空間**位於列表底部。刪除空間永遠不會刪除版本——它們會轉到 Default。錄音由所有空間共享，所以同一段錄音可以在多個空間裡被翻唱。

卡片上的資料夾按鈕會把那個版本連同它包含的版本一起移到另一個空間。

### 版本里的版本 {#takes-inside-a-take}

**變奏**、**再試幾個**和**檢查點**都會為一首歌生成多個版本。它們會被儲存在它們所來自的那個版本**裡面**，這樣空間裡列出的是你的歌，而不是每首歌的每一次渲染。
Checkpoints 是在編輯器中點選的：如果那裡開啟著一個版本，它的版本就放進那個版本里；如果是還沒有版本的新歌，則由最後一個勾選的檢查點的版本（已完成的 LoRA，若它在其中）來包含其他版本。

- 當一個版本包含版本（已完成或仍在進行）時，卡片頂部的小按鈕中會出現**內部按鈕**，並**亮起橙色**。把滑鼠懸停在上面可以看到已完成多少、還剩多少。卡片本身也明顯比其他卡片更亮（在淺色主題中是一種暖色調），讓含有版本的版本在列表中一目瞭然。（旁邊的母帶處理架按鈕在版本經過母帶處理時會以同樣的方式亮起綠色。）
- **點選它**，卡片下方會開啟一個面板，列出它包含的版本，每個都有自己的卡片。版本完成後才會出現在那裡；生成期間，只顯示它所屬的那個版本。再點一次按鈕，或點選**關閉**，即可關閉。
- <strong>版本里的版本也是普通的版本。</strong>可以播放、加星標、儲存、分離成分軌、重新命名，雙擊可開啟它的歌曲和樂譜。
- <strong>只有一層。</strong>版本里的版本不再包含版本，所以它的卡片上沒有變奏和再試幾個，而它在編輯器中開啟時，**檢查點**會變灰。**移出**（從盒子裡伸出的箭頭）會讓它成為空間列表中的獨立版本，之後就可以了。
- <strong>列表工具跟隨面板。</strong>面板開啟時，**全選**、**星標**、型別按鈕、**對比**、**刪除**以及播放器的上一首和下一首都作用於面板裡的版本。面板開啟的那個版本會一直留在頁面上，不管篩選怎麼設。
- <strong>裡面在播，外面看得到。</strong>如果在面板裡某個版本播放時關閉面板，包含它的那個版本的播放按鈕會發出金光，讓你看出聲音從哪裡來。綠色仍表示正在播放的就是那個版本本身。
- **搜尋能找到它們**，和找其他版本一樣，不管它們在哪裡。搜尋期間，找到的內容會以簡單卡片顯示，位於另一個版本里的版本會註明在哪一個裡。
- <strong>刪除一個版本會刪除它包含的版本。</strong>警告中會說明有多少。想保留的，請先取出來。

在此功能出現之前做的版本留在原處，在列表中並排擺放。

### 卡片 {#cards}

每張卡片都列出塑造它的設定——和聲、演繹、方案多樣性、LoRA 及其強度、種子、渲染它的引擎以及它有多新——所以一張卡片讀起來就像做出它的配方。

**儲存**會詢問以什麼格式下載這個版本：FLAC、WAV 或 MP3。它從你上次儲存的格式開始，第一次則什麼都不選。帶圖片的版本還可以儲存為**影片**：一個顯示其卡片圖片的歌曲 MP4（H.264 影片，192 kbps 的 AAC 音訊）。像
WhatsApp 這樣的即時通訊應用會把它當作影片來傳送和播放，而音訊檔案則會作為文件傳送。母帶處理架開啟時，影片使用經過母帶處理的聲音，和其他格式一樣。旁邊的**版本**還會儲存版本的配方：一個小檔案（`<title>.yeufonic.json`），包含它的歌詞、風格和樂譜、種子和設定、按名稱記錄的 LoRA 以及母帶處理架的設定，但不包含音訊。如果同時選了格式，兩者會打成一個 zip；再點一次所選格式，就只儲存配方。這個檔案不包含你安裝環境中的任何內容（沒有路徑、ID 或金鑰），所以可以留存，也可以分享給其他 Yeufonic 使用者。

空間列表中的<strong>匯入版本…</strong>會從這樣的檔案在當前顯示的空間中新建一個版本；把檔案拖進庫也一樣。這個版本包含方案，可以直接渲染，所以你可以先審閱或修改。兩種引擎都能渲染它：同一份樂譜和同一個種子在同一個引擎上會給出非常相似的版本，在另一個引擎上則不同。它提到的、但這裡沒有安裝的 LoRA 會在匯入時被標出，方便你安裝它或在渲染前換一個。翻唱的錄音不在檔案裡，所以分享來的翻唱會以歌曲的形式到來，帶著翻唱的樂譜和歌詞，而屬於它錄音的設定（鎖定的速度、和聲、人聲提示和時長上限）會被留下：從它寫出的新方案會像從提示詞寫的歌那樣開始。

**搜尋版本**會找出那些你輸入的所有詞都出現在標題、風格、歌詞或
LoRA 名稱某處的版本，不區分大小寫。它在當前顯示的空間裡搜尋；你一開始輸入就會出現在旁邊的**所有空間**會搜尋所有空間，來自其他空間的卡片會註明來自哪個。× 或 Esc 會清除搜尋。每次開啟頁面時這個框都是空的，並會提供你最近找到過結果的搜尋：點選其中一個，或用方向鍵和 Enter 選擇。

**歌曲**、**翻唱**和**純音樂**顯示這些型別的版本：開啟一個或多個，或都不選以顯示所有型別。**星標**只顯示加了星標的版本；再點一次顯示全部。旁邊的圖示決定版本如何排列，正在使用的會亮起綠色：更寬的**寬鬆**卡片（顯示更多提示詞）或更窄的**緊湊**卡片，佔滿視窗的**全寬**或居中的一欄，以及把每個版本**摺疊**到標題行。把滑鼠懸停在圖示上可以讀到點選它會做什麼。

勾選版本後，這一行會改為提供可以對它們做的操作，取代型別和排列：已選多少個、**對比**、**刪除**以及取消勾選的**完成**。行尾的**全選**會勾選每個顯示的版本。標題總是保持在一行內，過長時以 … 結尾。把滑鼠懸停在卡片的標題、設定或風格上可以讀到完整內容。

### 每個版本的一張圖片 {#a-picture-for-each-take}

每個新版本都會得到一張這首歌的圖片，淡淡地顯示在它的卡片後面、選中它時版本面板的頂部，以及版本在編輯器中開啟時編輯器的後面。在這臺電腦上繪製時，它會等到沒有歌曲在生成時才進行，所以永遠不會拖慢方案或渲染，並在歌曲完成後不久出現；由外部 LLM 繪製時，它會在版本渲染期間完成。它分兩步完成：版本的標題、風格和開頭的詞會變成對一張圖片的**描述**，然後一個影象模型在白底上把它**畫**出來，再去掉白色，留下一張透明背景的圖片。在另一個版本里做出的版本（再試幾個、變奏、檢查點）會顯示它所在那個版本的圖片，而不是有一張自己的。

影象模型不會畫真實的樂隊或人物，所以描述中會略去名字；圖片自身的文字會保持柔和，免得和卡片上的文字搶風頭。

#### 兩種繪製方式：這臺電腦上的 FLUX.2 klein，或外部 LLM {#two-ways-to-draw-flux-2-klein-on-this-pc-or-an-external-llm}

圖片需要某個會畫畫的東西。有兩種，你可以有其中一種、兩種都有，或者都沒有。

| | 這臺電腦上的 FLUX.2 klein | 你的外部 LLM 的影象模型 |
|---|---|---|
| 是什麼 | 一個在引擎裡、與 YuE2 並排執行的小型影象模型 | 提供商自己的影象模型，比如 Gemini 的 |
| 花費 | 免費；大約 8 GB 磁碟空間 | 每張圖片都是對提供商的一次請求，可能會收費 |
| 什麼會離開電腦 | 什麼都不會：描述由這臺電腦上的 Gemma 寫，或從版本本身生成 | 版本的標題、風格和開頭的詞，以及描述 |
| 何時執行 | 在沒有歌曲生成時使用 GPU：在你的歌之後，絕不擋它的路 | 與渲染同時進行 |
| 需要設定什麼 | 一個安裝選項 | 設定中的外部 LLM，且提供商要有影象模型 |

**要在這臺電腦上繪製，請安裝 FLUX.2 klein。**

- <strong>Windows：</strong>在安裝程式的元件頁面勾選 **FLUX.2 [klein]**。除非你選擇它，否則它不會被勾選。已安裝的應用在更新時會看到同樣的頁面，或者從釋出頁面重新執行安裝程式：之後這個勾選會被記住，更新也永遠不會重複下載它。它是三個檔案，總共大約 8 GB。
- <strong>Docker：</strong>執行 `sh scripts/fetch-models.sh --pictures`，它會把三個檔案放進 `models/`
  （`diffusion_models`、`text_encoders` 和 `vae`）並逐一校驗，然後用
  `docker compose restart app` 重啟應用，讓它找到這些檔案。

<strong>FLUX.2 klein 9B，如果你的顯示卡夠用。</strong>klein 有一個更大的尺寸，品質更高的模型，能畫出更多細節以及更好的手和臉，只面向顯示記憶體更多的顯示卡。
Yeufonic 從不下載它，因為它的檔案在 Hugging Face 上需要申請訪問，並採用 Black Forest Labs 的**非商業許可證**，但只要把它們放到位，就會被使用。

- <strong>磁碟：</strong>常用的一對檔案——FP8 模型及其 FP8 文字編碼器——大約 18 GB（用 FP4 編碼器則為 16 GB），放在 4B 的檔案旁邊。它需要 4B 的 VAE（`flux2-vae.safetensors`），所以請先安裝 4B。
- <strong>顯示記憶體：</strong>能在 16 GB 顯示卡上執行，但繪製時幾乎佔滿，空閒顯示記憶體接近於零。圖片會等到沒有歌曲生成時才畫，所以不會拖慢你的歌，但同時使用顯示卡的其他程式可能會遇到困難。顯示記憶體更少時它仍然能執行，只是更慢，因為引擎要把模型換入換出；這種情況下 4B 是更好的選擇。

1. <strong>模型。</strong>登入 Hugging Face，在
   [black-forest-labs/FLUX.2-klein-9b-fp8](https://huggingface.co/black-forest-labs/FLUX.2-klein-9b-fp8)
   接受許可證，並下載 `flux-2-klein-9b-fp8.safetensors`（9.4 GB）。或者從
   [black-forest-labs/FLUX.2-klein-9B](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B) 獲取全精度的
   `flux-2-klein-9b.safetensors`，這是給 Mac 用的，大小約為兩倍，所需記憶體也是兩倍。它放在 `diffusion_models` 資料夾裡。
2. <strong>它的文字編碼器。</strong>從無需登入的
   [Comfy-Org/Flux-2-Klein-9B](https://huggingface.co/Comfy-Org/Flux-2-Klein-9B/tree/main/split_files/text_encoders)
   下載以下其中一個，放進 `text_encoders` 資料夾：
   `qwen_3_8b_fp8mixed.safetensors`（8.7 GB，NVIDIA 顯示卡上的常用選擇）、`qwen_3_8b_fp4mixed.safetensors`
   （6.8 GB，最小）或 `qwen_3_8b.safetensors`（16.4 GB，全精度，給 Mac 用）。**使用 yue2.cpp 引擎時**，圖片伺服器讀不了這些編碼器：請改為從
   [unsloth/Qwen3-8B-GGUF](https://huggingface.co/unsloth/Qwen3-8B-GGUF) 獲取 `Qwen3-8B-Q4_K_M.gguf`
   （5.0 GB）（`-Q8_0.gguf`，8.7 GB，也可以），放在同一個資料夾裡。
3. **資料夾在哪裡：** **Docker** 是 Yeufonic 資料夾中的 `models/`；**Windows** 是安裝資料夾中的 `engine\ComfyUI\models`；**Mac** 是安裝資料夾中的
   `engine/ComfyUI/models/`。
4. <strong>讓應用看到它們，並選擇它。</strong>重啟 Yeufonic（使用 Docker 時為 `docker compose restart app`），然後在設定中把**版本圖片：模型**設為 *FLUX.2 klein 9B*。在此之前由 4B 繪製，如果選了 9B 卻無法在這裡繪製，設定會提示你。選擇
   *4B* 即可退回，無需刪除任何東西。編輯器中圖片的備註會說明是哪一個畫的（*drawn by FLUX.2 klein 9B on this PC*）。

模型和它的編碼器只能以這些名稱被找到，所以請保持下載時的檔名。

<strong>FLUX 3 klein，適合畫文字，需要 12 GB 或以上的顯示卡。</strong>Black Forest Labs 的 FLUX 3 Image Klein 根據完整的場景描述來繪製，而這正是 Gemma 或外部 LLM 寫出的圖片提示詞，它寫字也寫得好，與**版本圖片：在圖片上顯示歌名**很搭。和 9B 一樣，Yeufonic 從不下載它：它的檔案在
Hugging Face 上需要申請訪問，並採用 **FLUX Kommunity License**（非商業用途，以及營收低於許可證門檻者對其所繪內容的商業使用；接受前請先閱讀）。把它的檔案放到位，就可以選擇它。

- <strong>磁碟：</strong>int8 這一對大約 11 GB，放在 4B 的檔案旁邊。它使用 4B 的 VAE（`flux2-vae.safetensors`），所以請先安裝 4B。
- <strong>顯示記憶體：</strong>繪製時大約 11 GB。它的步數是 FLUX.2 klein 的好幾倍，所以每張圖片耗時更長。
- <strong>引擎：</strong>目前只支援 ComfyUI 引擎；使用 yue2.cpp 引擎時不提供它。

1. **登入 Hugging Face**，並在
   [black-forest-labs/flux-3-image-klein-comfy](https://huggingface.co/black-forest-labs/flux-3-image-klein-comfy) 接受許可證。
2. **模型**，放進 `diffusion_models` 資料夾：`flux3-image-klein-int8-convrot.safetensors`（5.8 GB，NVIDIA 顯示卡上的常用選擇）、`flux3-image-klein-nvfp4.safetensors`（5.3 GB，給 RTX 50 顯示卡用）或
   `flux3-image-klein-bf16.safetensors`（11.1 GB，全精度，給 Mac 用）。
3. **它的文字編碼器**，放進 `text_encoders` 資料夾：`qwen3vl_4b_int8_convrot.safetensors`（4.9 GB）或
   `qwen3vl_4b_bf16.safetensors`（8.9 GB，給 Mac 用）。
4. <strong>讓應用看到它們，並選擇它：</strong>重啟 Yeufonic（使用 Docker 時為 `docker compose restart app`），然後在設定中把**版本圖片：模型**設為 *FLUX 3 klein*。編輯器中圖片的備註會寫著 *drawn by
   FLUX 3 klein on this PC*。

資料夾和 9B 的相同，檔案也只能以這些名稱被找到。

<strong>FIBO 2.0，追求照片質感，需要 16 GB 顯示卡。</strong>Bria 的 FIBO 2.0 畫出的圖片最接近這些圖片所仿效的唱片封套的真實照片：細節更銳利，景深自然，帶有底片的色彩，也更貼合描述的要求。Yeufonic 同樣從不下載它。<strong>它的授權是 CC BY-NC 4.0：僅限非商業用途。</strong>FLUX 3 的授權允許營收低於門檻的人商業使用其所繪內容；而使用 FIBO 時，任何商業用途，包括你出售的歌曲的封面，都需要與 Bria 簽訂協議。使用前請先閱讀授權。

- <strong>磁碟：</strong>約 10.4 GB，包括模型和它的 turbo 附加元件。它讀取 FLUX 3 的文字編碼器和 4B 的 VAE，所以已安裝 FLUX 3 時無需其他檔案。
- <strong>顯示記憶體：</strong>繪製時約 12.5 GB，因此需要 16 GB 顯示卡。更小的顯示卡會把一部分換出，速度會慢得多。
- <strong>時間：</strong>使用 turbo 附加元件時，與 FLUX 3 差不多。沒有它時，FIBO 按自己的設定繪製，大約要八倍的時間。
- <strong>封套：</strong>由 FIBO 繪製時，照片周圍的邊框沒有細深色線條，因為 FIBO 會把它畫成粗條，並在歌名周圍加框。
- <strong>引擎：</strong>僅限 ComfyUI 引擎。

1. <strong>模型，</strong>從 [Comfy-Org/Fibo-2.0](https://huggingface.co/Comfy-Org/Fibo-2.0)（無需登入）下載，放入 `diffusion_models` 資料夾：`fibo2_dev_int8_convrot.safetensors`（8.4 GB，NVIDIA 顯示卡的常用選擇）或 `fibo2_dev_bf16.safetensors`（16.5 GB，全精度，適用於 Mac）。
2. <strong>它的 turbo 附加元件，</strong>從同一頁面下載，放入 `loras` 資料夾：`fibo_2.0_turbo_lora_avg_rank_270_bf16.safetensors`（2 GB）。它不是風格 LoRA，也不會作為風格 LoRA 提供。
3. <strong>它的文字編碼器，</strong>如果未安裝 FLUX 3：從同一頁面下載 `qwen3vl_4b_int8_convrot.safetensors`（4.9 GB）或 `qwen3vl_4b_bf16.safetensors`（8.9 GB，適用於 Mac），放入 `text_encoders` 資料夾。
4. <strong>讓應用程式看到它們，並選擇它：</strong>重新啟動 Yeufonic（使用 Docker 時為 `docker compose restart app`），然後在設定中把<strong>版本圖片：模型</strong>設為 *FIBO 2.0*。編輯器中圖片的備註會寫著 *drawn by FIBO 2.0 on this PC*。

<strong>要用外部 LLM 繪製，</strong>開啟設定，把**用於寫歌詞和風格標籤的 LLM**設為
[外部 LLM](#external-llm)，填上它的 **API 地址**、**API 金鑰**和**模型**，和寫歌詞時一樣。提供商必須有影象模型：Gemini 有（除非你指定別的，否則使用 `gemini-3.1-flash-image`），對於相容 OpenAI 的提供商，則會請求 `gpt-image-1`。應用會在後臺向提供商查詢它的模型列表——在啟動時、這些設定改變時以及每隔幾小時——只有當列表裡有影象模型時，才會在那裡繪製。

兩者都沒有時，設定中的**版本圖片**會顯示**無圖片：預設背景**，附上一行說明如何獲得圖片，生成圖片的選項也無法選擇。設定好其中任何一個，它們就會開啟：從那以後，你新建的版本都會生成圖片。

#### 在設定中管理圖片 {#managing-pictures-in-settings}

| 設定 | 作用 |
|---|---|
| **版本圖片** | *為每個新版本生成一張*（能繪製時的預設值），或*僅在請求時*，此時版本會保留預設背景，直到你透過它的小方塊或編輯器的「圖片」按鈕生成一張。下面的設定會塑造用任何一種方式生成的圖片。只要這裡沒有東西能繪製，它就是*無圖片*。 |
| **版本圖片：繪製者** | *如果已安裝 klein 則用這臺電腦，否則用外部 LLM*（預設）、<em>這臺電腦（下面的模型）</em>或*外部 LLM 的影象模型*。這臺電腦上由哪個 klein 繪製（FLUX.2 klein 4B 或 9B，或 FLUX 3 klein）在 **模型**中選擇。FIBO 2.0 也在那裡選擇。 |
| **版本圖片：模型** | *FLUX.2 klein 4B*（預設）、*FLUX.2 klein 9B*、*FLUX 3 klein*，或*已安裝 9B 檔案時用 9B，否則用 4B*。只用於在這臺電腦上繪製的圖片。9B 和 FLUX 3 永遠不會替你安裝：參見上文的 [FLUX.2 klein 9B 和 FLUX 3 klein](#two-ways-to-draw-flux-2-klein-on-this-pc-or-an-external-llm)。如果請求的那個不在，會由另一個繪製，設定會說明是哪個。*FIBO 2.0* 同樣需手動新增，且僅限非商業用途：見上文。 |
| **版本圖片：描述者** | 由誰根據版本的標題、下面的藝術風格、它的風格和歌詞（最多 50 行）來寫圖片提示詞。*已安裝本地 Gemma 時用它，否則用版本本身*（預設），不管由誰繪製。*本地 Gemma*：在這臺電腦上寫；需要「歌詞草稿」選項。*根據版本本身*：不用 LLM；用版本的標題、風格和開頭的詞生成描述，最快，也不傳送任何內容。或者*外部 LLM*，每張圖片一次請求；它不可用時，或你在本次會話中切換到本地 LLM 時，如果已安裝 Gemma，就改由 Gemma 來寫。 |
| **版本圖片：藝術風格** | 圖片應該是什麼樣子，交給寫圖片提示詞的 LLM（版本自行描述時會變灰）。預設是七八十年代唱片封面風格的抽象超現實設計，不帶文字和人物。清空後會恢復為這個預設值。 |
| **版本圖片：你自己的提示詞** | 每張圖片的提示詞開頭的詞，例如 *salt marsh, overcast*，最多 512 個字元；LLM 寫的提示詞跟在後面。空（預設）：沒有。只在由 LLM 寫圖片提示詞時有效（版本自行描述時會變灰）。 |
| **版本圖片：在圖片上顯示歌名** | *否*（預設）或*是*：把歌名以粗體寫在封面上，大寫或小寫，照你輸入的樣子，即使它是某位藝人的名字（圖片本身仍會在不提名字的情況下描述）。大多數時候，圖片會被一條細細的深色線框起來，外面是一圈斷開的白邊，就像許多七十年代的封面，歌名居中放在上方或下方一條更寬的帶子裡。大約五張中有一張沒有邊框：歌名直接寫在圖片上，放在角落或上方、下方居中，顏色取自圖片中的一種柔和色，並會請 LLM 為它留出那部分畫面。這些都會為每張圖片隨機選擇。FLUX.2 klein 寫的時候可能會有錯字。只在由 LLM 寫圖片提示詞時有效。 |
| **版本圖片：影象模型** | 由提供商的哪個模型來繪製。只用於由外部 LLM 繪製的圖片（在**繪製者**中選擇它；否則變灰），留空則使用提供商的常用模型，這幾乎總是你想要的。 |

所以，安裝了 FLUX.2 klein 並保持預設設定時，圖片完全在這臺電腦上生成，即使由外部 LLM 寫你的歌詞也是如此：在裝有「歌詞草稿」的地方由 Gemma 寫每個圖片提示詞，沒有它時則根據版本本身生成描述，不用 LLM，幾乎不花時間。選擇*外部 LLM 的影象模型*可以讓提供商來畫，或者把**描述者**設為*根據版本本身*以獲得最快的圖片，或設為*外部 LLM*（每張圖片一次請求）。

#### 編輯器中版本的圖片 {#a-take-s-picture-in-the-editor}

編輯器視窗頂部一行、其他版本按鈕旁邊的**圖片**圖示會顯示圖片，並提供兩個選項：**生成新圖片**，在後臺重新生成；**使用預設背景**，永久去掉它：除非你請求，否則不會再為這個版本生成圖片。點選圖片可以檢視完整大圖，在視窗允許的範圍內儘量大；在任意處點選或按 Esc
會把它收起，編輯器保持原樣。完整圖片下方也有同樣的兩個選項。在那裡選擇**生成新圖片**，圖片會在新圖生成期間保持可見，按鈕之間會顯示進展，新圖準備好後再切換過去。

在版本的卡片上，把滑鼠懸停在左上角的小方塊上會顯示圖片。沒有圖片的版本會在那裡改為提供**生成新圖片**，前提是這臺電腦能生成圖片。

### 比較版本 {#comparing-takes}

勾選兩到六個版本，然後點選**對比**（勾選兩個時它會出現在「全選」旁邊，並會等待仍在渲染的版本）。這些版本會疊放在一個視窗裡，共享同一個播放位置：按 **1** 到
**6** 或點選某一個來切換，從歌曲的同一時刻繼續，無論是在播放還是暫停。**空格**播放和暫停，方向鍵前後跳 5 秒，星標標記你更喜歡的那個。**匹配響度**會把較響的版本壓低到最輕的那個，因為響一些的版本往往聽起來更好；**隱藏名稱**會打亂版本順序，並把它們稱為版本 A、B、C，以便盲聽。

### 播放器 {#the-player}

在波形上點選或拖動可以跳轉。上一首和下一首按顯示順序遍歷卡片。

| 按鍵 | 作用 |
|---|---|
| 空格 | 播放或暫停 |

### 音訊視覺化與同步歌詞 {#the-audio-visualizer-and-synced-lyrics}

點選走帶欄中的**視覺化**（或在播放曲目時按 **V**），以全屏開啟視覺化舞臺。

舞臺會顯示與播放同步的即時音訊視覺化效果：

- <strong>視覺化模式：</strong>在頂部欄中從十種視覺化效果中選擇：
  - <em>Yeufonic：</em>標誌本身在呼吸——方塊隨低音發光、隨節拍膨脹，音叉的每一臂都是顯示一半頻譜的電平表，綠點隨節拍亮起。
  - <em>波形絲帶：</em>兩條隨聲音起伏的漂浮和聲絲帶。
  - <em>北極光：</em>空靈極光的波動帷幕，隨中頻和高頻而動。
  - <em>宇宙星雲：</em>星空和由星際粒子組成的星雲，隨節奏旋轉和脈動。
  - <em>萬花筒：</em>隨速度脈動的徑向幾何對稱圖案。
  - <em>霓虹網格：</em>復古未來感的合成波線框透視平面，隨貝斯線起伏。
  - <em>液態扭曲：</em>被和聲波動扭曲的流體表面。
  - <em>粒子群：</em>受引力牽引的粒子團，隨打擊樂重音四散。
  - <em>高傳真頻譜柱：</em>帶有漂浮下落峰值的多頻段頻譜分析器。
  - <em>封面：</em>版本的圖片，放大顯示，標題在下方，背後是它自身的一份模糊副本，隨音樂而動。沒有圖片的版本會顯示 Yeufonic 場景，直到生成一張圖片。
- <strong>場景背後：</strong>封面、Yeufonic、曼陀羅、網格、液態和頻譜柱這幾個場景，會在版本有圖片時疊在那張隨音樂輕輕移動的圖片上播放。上面還可以有東西在動，用圖片的顏色：*呼吸*（只有圖片）、從中心旋轉的*光線*、隨節拍盪開的*漣漪*、*色彩漂移*、*縱深*（更多圖片副本彼此反向旋轉）或*頻譜光暈*。每個場景都從自己的那個開始（封面背後是色彩漂移，曼陀羅背後是光暈，網格背後是光線，液態背後是漣漪，Yeufonic 和頻譜柱背後只有圖片）；按 **B** 可以迴圈切換，場景會記住你的選擇。
- <strong>波形：</strong>在 Yeufonic 和封面場景下方，版本的波形會顯示歌曲已經播放了多少；點選它可以跳到那裡。
- <strong>封面與黑膠動態：</strong>以 Hipgnosis 風格把版本的封面放進一個可互動的 3D 唱片套裡，它會隨指標傾斜和轉動。一張逼真的黑膠唱片以 33⅓ 轉旋轉，隨貝斯重拍從唱片套中滑出，帶有全息光澤和隨節奏變化的衝擊波環。用**封面**按鈕切換模式：*唱片套*、*光暈*（模糊背景）或*關閉*。
- <strong>一張新圖片：</strong>每個場景右上角的圖片按鈕，會為正在播放的版本生成一張新圖片，前提是這臺電腦能生成圖片。生成期間它會脈動，新圖準備好後會接替舊圖。
- <strong>螢幕歌詞：</strong>按 **L** 或點選**歌詞**，顯示或隱藏獨立的可滾動歌詞面板。拖動它頂部的欄可以把它挪開；它會停在你放下的地方，雙擊該欄則會讓它回到原位。
- <strong>迷你播放器絲帶：</strong>完整的視覺化關閉時，一個雙波形的響應式迷你視覺化會在底部走帶欄中播放。在**設定 → 外觀**中開關。

### 播放列表與喜歡 {#playlists-liked-songs}

點選頂部欄中的**播放列表**，切換到播放列表檢視。

- <strong>雙欄佈局：</strong>左欄列出你的播放列表，以及置頂的系統播放列表**喜歡**，並顯示歌曲總數。主欄顯示當前播放列表的標題區（高畫質封面、名稱、簡介、歌曲總數和時長）以及曲目表。
- <strong>自動同步喜歡：</strong>庫中任何空間裡加了星標的版本，都會自動出現在喜歡列表中。去掉星標會把它移出。
- <strong>新增到播放列表：</strong>按 **P** 或點選任意卡片上的**播放列表**圖示，開啟播放列表選擇器，勾選或取消勾選所屬的播放列表，或新建一個。**Esc** 關閉選擇器。
- <strong>互動式排序和搜尋：</strong>點選列標題（**標題**、**時長**或**新增時間**）按該列排序並顯示方向指示，再點一次反轉順序；用搜尋框篩選曲目。
- <strong>跳到庫中的空間：</strong>點選曲目表中的歌名，會立刻切換到庫檢視，開啟這個版本所在的空間，並高亮它的卡片。
- <strong>播放列表中的快捷鍵：</strong>為避免誤改，版本自身的快捷鍵在播放列表檢視中會被忽略，但 **M**（母帶處理架）除外，它作用於正在播放或已載入的曲目；常規的走帶按鍵（**空格**、方向鍵、**?** 和 **L**）也照常可用。
- <strong>連續播放和隨機播放：</strong>點選播放列表標題區的**播放**從第 1 首開始聽，或點選**隨機播放**隨機播放。每首歌結束後，會自動播放播放列表中的下一首。

### 鍵盤快捷鍵 {#hot-keys}

在主頁面上，單個按鍵作用於**所選版本**：左側面板裡的那個。點選它的卡片即可選中它。每個按鍵都和它的按鈕作用相同，所以會刪除東西的按鍵會先詢問；版本無法執行某個按鍵的請求時（例如沒有樂譜的版本做變奏），狀態列中會留下一行說明原因。

| 按鍵 | 作用 |
|---|---|
| 空格 | 播放或暫停 |
| 左、右 | 後退或前進五秒 |
| Shift+左、Shift+右 | 上一個或下一個版本；在播放列表檢視中，是播放列表中的上一首或下一首 |
| 上、下 | 音量 |
| M | 開啟版本的母帶處理架；再按一次關閉 |
| E | 在編輯器中開啟版本 |
| I | 版本詳情：它的一切製作引數，以文字列出，並帶有**複製** |
| N | 標準化版本，若已標準化則撤銷 |
| V | 播放時開啟或關閉視覺化，空閒時則是變奏 |
| T | 再試幾個 |
| S | 給版本加或去星標 |
| P | 把版本加入播放列表 |
| D | 刪除版本，會先詢問，和它的垃圾桶按鈕一樣 |
| L | 日誌；視覺化開啟時則顯示歌詞 |
| B | 在視覺化中，切換場景背後、疊在版本圖片上移動的效果 |
| F | 全屏 |
| ? | 顯示或隱藏快捷鍵；再按一次關閉 |
| Escape | 關閉最前面的視窗：視覺化、日誌、編輯器上的母帶處理架，然後是編輯器或任何其他視窗 |

在框中輸入文字時、前面有視窗開啟時，或按住 Ctrl、Alt、Windows 鍵或 Command 鍵時，字母鍵都不起作用，這樣瀏覽器自己的快捷鍵（Ctrl+L、Ctrl+S 等）依然可用。按鈕的懸浮提示會標出它的按鍵，例如**變奏 (V)**。隨時按 **?** 可以檢視快捷鍵列表。

在編輯器視窗中，只要視窗的播放器可見——在每一步，以及母帶處理架開啟在上面時——空格和方向鍵就會控制該視窗的播放器，作用於在那裡開啟的版本。在框中輸入文字時它們從不生效，字母鍵也只在主頁面上可用。鋼琴捲簾有它自己的按鍵：參見[鋼琴捲簾](#the-piano-roll)。

## 設定 {#settings}

點選左上角的 **Yeufonic**。設定儲存在伺服器上，所以會跟著你到任何瀏覽器，重新建置後也依然保留：分軌和儲存版本時的輸出音訊格式、分離模型、分軌寫入的位置、是否保留訓練檢查點，以及如何檢查純音樂不會唱出來。

### 儲存 {#storage}

**設定 → 儲存**會顯示 Yeufonic 的磁碟空間用在哪裡，並讓你回收一部分。訓練一個語料庫會留下許多以後用不到的檔案：分析歌曲時為引擎製作的副本、訓練集（每首歌都被重寫為無損 FLAC，比原檔案更大），以及途中儲存的檢查點。視窗會列出每一項及其大小、**它是什麼**以及**刪除它的代價**，並且在最後確認之後只刪除你勾選的內容。**勾選無損失項**會勾選那些需要時會自動重新生成的副本。

從現在起分析的歌曲會把分離出的人聲存為 FLAC，同樣的音訊大約只佔一半空間。視窗可以**轉換你已有的 WAV 人聲**：每一個都會被轉換、校驗能否解碼出完全相同的音訊，然後才刪除 WAV。它在後臺執行，可以停止。

刪除訓練檢查點之前值得再看一眼：每一個都是風格 LoRA 列表中的一項，你可以為新版本選擇它，所以刪除一個語料庫的檢查點會把這些項永久移出列表。它已完成的 LoRA 會保留並照常可用。語料庫的訓練集則不同：刪除它會把 LoRA 及其檢查點留在列表中，只有重新訓練這個語料庫時才需要它。

你的版本、歌曲、已完成的 LoRA 和模型永遠不會出現在可刪除列表中。屬於正在訓練、匯出或分析的語料庫的一切，都會顯示為灰色，在完成之前無法動它。

在下面，**自動整理**選擇 Yeufonic 會替你刪除什麼：每首歌分析完成後它的工作副本（預設開啟）、LoRA 訓練完成後的訓練集（預設關閉；之後語料庫需要再做一次**匯出**才能再次訓練），以及訓練檢查點（預設保留）。

Docker 的映像和建置快取在 Yeufonic 之外，這裡不涉及；`docker system df` 會顯示它們。

### YuE2 模型 {#the-yue2-model}

YuE2 有兩種尺寸，一個安裝只有其中一種：我們推薦的**全品質**，或**低顯示記憶體**——為顯示記憶體較少的顯示卡準備的較小副本。同一選單中的**關於**會說明你用的是哪一個。它在安裝 Yeufonic 時選擇，而不是在這裡：

- **在 Windows 上**，重新執行安裝程式。它的元件頁面提供兩種尺寸，並勾選已經下載的那些。切換會在第一次時下載另一個並保留兩者，所以切回來不會再下載任何東西。
- **使用 Docker 時**，`sh scripts/fetch-models.sh` 下載全品質模型，
  `sh scripts/fetch-models.sh --int8` 下載低顯示記憶體模型。`models/checkpoints` 中兩個檔案都有時，應用使用全品質模型，除非 `.env` 中有 `YUE2_CHECKPOINT=int8`。

如果渲染非常慢，或引擎顯示記憶體不足，可以試試低顯示記憶體模型。兩種尺寸的模型都可以訓練 LoRA。**低顯示記憶體 (int8) 模型訓練**設定決定用哪一個：關閉時，訓練使用全品質模型；開啟時，使用應用渲染時用的模型。只安裝了低顯示記憶體模型時，它一開始就是開啟的。GitHub 上的 README 有一節 *Choosing a model size*，介紹了每種尺寸的預期表現。

Yeufonic 也可以使用 **yue2.cpp** 引擎代替 ComfyUI，適用於顯示記憶體更少的顯示卡，在設定時選擇：在 Windows 安裝程式的元件頁面上，或在 Docker 中透過
`sh scripts/fetch-models.sh --cpp`。**關於**會說明正在執行哪個引擎，版本的卡片則說明它由哪個引擎渲染。它能做歌曲、翻唱和純音樂，並轉寫錄音，可以用你的風格 LoRA；Gemma 可以在它旁邊起草歌詞和描述圖片（使用 Docker 時為 `--gemma`），FLUX.2 klein 則可以繪製圖片（`--pictures`）。訓練需要
ComfyUI 引擎：使用 yue2.cpp 時不提供語料庫和訓練。GitHub 上的
[Choosing an engine](https://github.com/yeufonic/yeufonic/blob/main/docs/ENGINES.md) 頁面有完整列表以及切換方法。

**檢查新版本**是這裡唯一會主動上網的東西：每四小時，應用會詢問 yeufonic.com 是否有更新的版本釋出，並在右上角版本號旁用一個膠囊標籤提示。這個標籤會給你安裝程式，或者對於 Docker 副本，給出更新它的兩條命令。這只是一次請求，此外沒有任何東西離開電腦；**不檢查**會把它關掉。選單中的**檢查更新**會立刻詢問，不管這項是否開啟，並在選單中回答：你用的是哪個版本，以及它是不是最新的。

有更新的版本時，選單會提供**獲取 x.y.z**，它會在 Windows 安裝中下載安裝程式，或者為 Docker 副本把兩條命令放進剪貼簿。

**主題**決定應用的外觀：**深色**、**淺色**、**跟隨電腦（深色或淺色）**（跟隨你係統的淺色或深色，並隨之切換）、**錄音室**（帶琥珀色的暖調深色），或**高對比度**（黑白分明、輪廓清晰）。切換會立即生效，每個瀏覽器都會記住它，讓頁面以這個樣子開啟。日誌視窗在所有主題下都保持深色，就像終端一樣。母帶處理架也會跟隨主題：在淺色主題中，它的面板是拉絲銀色，而旋鈕、電平表視窗和顯示屏仍保持深色的硬體外觀。

主題下方的**背景色**會用你選的顏色給版本背後的頁面著色：勾選**色調**，然後沿色輪移動**色相**，並把**強度**從淡淡一層調到濃郁的顏色。拖動時頁面會隨之變化，鬆開時選擇會被儲存。版本卡片、面板和視窗保持各自的顏色，高對比度主題依然是黑色。

### 外部 LLM {#external-llm}

Yeufonic 可以使用外部 LLM 代替本地 Gemma 模型來起草歌詞、轉寫錄音、標註歌曲段落，以及分析語料庫的風格。

使用外部 LLM 有兩個明顯的好處：
- <strong>節省顯示記憶體：</strong>不必把 Gemma 4 模型載入 GPU 顯示記憶體（大約節省 8 GB 顯示記憶體），讓你的顯示卡完全空出來，用於 YuE2 的規劃和音訊渲染。
- <strong>更豐富的草稿和分析：</strong>大型雲端模型往往能起草更細膩的歌詞，併為你的語料庫生成詳細的風格標籤。

<strong>推薦的提供商：</strong>如果你能用上，我們建議選擇 API 不計費的外部 LLM 提供商——**Google Gemini** 就是個好例子。Gemini API（透過 Google AI Studio）提供慷慨的免費額度且不計費，支援標準的 OpenAI 相容端點（`https://generativelanguage.googleapis.com/v1beta/openai/`），並能直接接受音訊來轉寫錄音。

如果你使用按量或按 token 計費的 API（如 OpenAI 或 Anthropic 的付費層級），分析一個包含幾十首歌的完整語料庫，或為許多版本生成描述，都可能很快耗盡 API 額度或觸及消費上限。如果外部 API 返回配額或頻率限制錯誤（HTTP 429），Yeufonic 會顯示提示，並讓你在本次會話剩餘時間裡切換到本地模型，這樣其他任務可以不中斷地繼續。選擇不計費的提供商可以避免意外的費用。

**設定方法：**
1. 開啟 **Yeufonic → 設定 → 外部 LLM 和歌詞**。
2. 把**用於寫歌詞和風格標籤的 LLM**設為**外部 LLM（OpenAI 相容 API）**。
3. 填入提供商的 **API 地址**、**API 金鑰**和**模型**（例如，模型 `gemini-2.5-flash` 或 `gemini-1.5-flash`，配合 Google Gemini 的 OpenAI 相容基礎地址 `https://generativelanguage.googleapis.com/v1beta/openai/`）。
4. 點選**測試 LLM 連線**驗證你的憑據。
5. 如果所選模型支援音訊輸入（如 Gemini），還可以把**從錄音獲取歌詞**設為**外部 LLM**，讓它聆聽分離出的人聲。

## 從 AI 智慧體使用 Yeufonic（MCP） {#using-yeufonic-from-an-ai-agent-mcp}

Yeufonic 可以作為 **MCP 伺服器**執行。這樣同一臺電腦上的 AI 智慧體（例如 Claude Code 或 Cursor）就能替你使用它：請求一首歌、一個翻唱或一段純音樂，等它完成，播放它，換種方式再試，給它配一張圖片，把它放進播放列表，整理庫，全都用你自己的話說（「在 EDM 空間裡做一段一分鐘的 EDM 純音樂，然後播放」）。智慧體做的就是頁面做的事，走的也是同樣的路徑，所以它開始的版本就是你庫中的一個普通版本。

### 設定方法 {#setting-it-up}

1. <strong>開啟它。</strong>開啟設定，把**MCP 伺服器**設為**開**。它預設關閉，因為一個請求就可能啟動 GPU 任務。
2. **把你的智慧體連線**到應用的地址，末尾加上 `/mcp`：也就是你開啟 Yeufonic 的那個地址，例如
   `http://localhost:8090/mcp`。在 Claude Code 中：

   ```
   claude mcp add --transport http yeufonic http://localhost:8090/mcp
   ```

   其他客戶端也把同樣的地址當作 HTTP 伺服器。讀取配置檔案的客戶端通常需要類似
   `{"mcpServers": {"yeufonic": {"url": "http://localhost:8090/mcp"}}}` 的內容。不需要登入或金鑰。
3. <strong>提出請求。</strong>在任意資料夾中啟動你的智慧體，描述你想要什麼。

<strong>用哪個地址？</strong>就是你開啟 Yeufonic 的那個地址，末尾加上 `/mcp`。
- **Docker：**`http://localhost:8090/mcp`。
- <strong>Windows 安裝：</strong>應用的埠寫在 `settings.ini` 裡（`app_port`，除非你改過，否則是 8090，例如為了和
  Docker 副本同時執行而改）。若 `app_port = 8091`，地址就是 `http://localhost:8091/mcp`。
- <strong>智慧體在 WSL 中、應用在 Windows 上：</strong>這樣連不上。Windows 應用只監聽 Windows 自己的迴環地址，WSL
  無法訪問（WSL 裡的 Docker 沒問題，因為它也在 WSL 中）。請從 Windows 執行智慧體（PowerShell 或你智慧體的 Windows 版本），或者開啟 WSL 的映像網路（在 `.wslconfig` 的 `[wsl2]` 下設定 `networkingMode=mirrored`，然後執行 `wsl --shutdown`），這樣兩邊的 `localhost` 就是同一個。

如果你的智慧體說伺服器**需要身份驗證**，幾乎總是因為這個設定仍是關閉的：開啟它，然後重新連線智慧體（在 Claude Code 中為 `/mcp`）。重啟 Yeufonic 之後也要重新連線，因為重啟會斷開連線。

### 你可以請求什麼 {#what-you-can-ask-for}

| 請求 | 會發生什麼 |
|---|---|
| 「列出我最新的版本」「顯示 EDM 空間裡的版本」 | 列出版本，最新的在前，附帶簡短的 id、每個的製作時間、時長和風格 |
| 「做一段一分鐘的合成波風格純音樂」 | 規劃並渲染一段純音樂。可以指定時長、空間和[風格 LoRA](#style-loras) |
| 「用這些歌詞做一首民謠風格的歌」 | 歌曲也一樣，根據你給的歌詞 |
| 「……用冒險的和聲、收斂的演繹、升 F 調、100 BPM」 | 新版本的任何設定，用頁面上的名稱：[和聲](#harmony)、[方案多樣性](#plan-variety)、[演繹](#interpretation)、鎖定調性和速度，以及歌曲的**嚴格遵循此結構**和**聲部遵循提示**。如果什麼都沒說，新版本會從頁面的起點開始：多樣和寬廣 |
| 「寫一首關於夜行列車的歌詞，用說話般的語氣」 | 應用自己的**寫歌詞**，帶有它的歌曲形式、每段行數和語氣。智慧體也可以自己寫歌詞 |
| 「用爵士風格翻唱*這段錄音*」 | 根據庫中已有的一段錄音做翻唱。需要樂譜（先在應用中轉寫）。沒有你的歌詞時，會使用在錄音中聽到的詞 |
| 「播放它」 | 在你的瀏覽器中開啟這個版本，在那裡播放 |
| 「給那個加星標」「把它改名為 Sunrise」「把它移到 Folk 空間」 | 給版本加星標、重新命名或移動 |
| 「用新種子重新渲染」「停下那個」 | 重新渲染一個版本，或取消進行中的版本 |
| 「再給我幾個那樣的」 | 用新種子重新渲染這個版本，作為幾個新版本放在一起聽 |
| 「再唱一次」「每種演繹都試試」 | **再唱一次**（同一份樂譜換新的人聲）或**變奏**（同一份樂譜和種子，用每種方式演奏）。變奏儲存在版本里面，和再試幾個一樣 |
| 「用這些歌詞唱那段旋律」 | **新歌詞**：同樣的旋律、調性和速度，配上另一份歌詞，作為新版本 |
| 「把它做成純音樂」 | 同一份樂譜，旋律交給樂器、不演唱，作為新版本 |
| 「給它寫一份新方案，更活潑些」 | 為還沒有音訊的版本（只規劃未渲染，或方案失敗的）寫一份新方案。有音訊的版本不會被動：請改為請求一個新版本 |
| 「把鬆散的那個取出來」 | **移出**：儲存在另一個版本里的版本變成獨立版本 |
| 「給它一張圖片」 | 為這個版本生成一張新圖片，和編輯器的**圖片**按鈕一樣，並給出開啟它的連結。在這臺電腦上繪製的圖片會等到沒有歌曲在生成時才畫 |
| 「把最好的三個放進一個叫 Road trip 的播放列表」 | 建立播放列表，顯示其中內容，新增或刪除版本。把版本放進**喜歡**會給它加星標 |
| 「幫我找一個合成波風格」「把這個風格儲存為 Night drive」 | 在你儲存的風格和內建風格中搜尋，並以一個名字儲存風格，供風格選單使用 |
| 「新建一個叫 Drafts 的空間」 | 新建一個存放版本的空間 |
| 「轉寫*這段錄音*」 | 把一段錄音轉寫為樂譜，以便翻唱。已有樂譜的錄音不會被動，除非你要求 |
| 「把那個分成人聲和樂器」 | 把一個完成的版本分離成各個部分（四個、六個，或只分人聲和樂器），並給出每個檔案的連結，以及整套檔案 zip 的連結 |
| 「儲存那個版本的配方」、「……連同版本一起打成 MP3 壓縮檔」 | 給出版本的配方（製作它的一切，不含音訊），可展示、修改或儲存為檔案，並附上單獨下載或與音訊一起打成一個 zip 下載的連結 |
| 「把 *Night Ferry.yeufonic.json* 匯入 Drafts 並算繪」 | 從版本檔案新建一個版本，帶有方案，在你要求時算繪。它會說明檔案中提到的哪些 LoRA 未安裝，以及翻唱何時作為歌曲匯入 |
| 「再匯入一次，換成夢幻流行風格，樂譜和種子不變」 | 在匯入前修改配方，只改你說的部分 |
| 「那個版本是哪個引擎做的？」、「現在執行的是哪個引擎？」 | 說明哪個引擎算繪了某個版本，以及 Yeufonic 現在執行的是哪個（ComfyUI 或 yue2.cpp） |
| 「Yeufonic 忙嗎？」 | 說明引擎是否就緒、正在執行什麼及其進度、什麼在等待，以及是否有 LoRA 正在訓練 |
| 「刪除那個版本」 | 先顯示會刪除什麼並徵求你的同意；見下文 |

製作一個版本需要幾分鐘。智慧體會啟動它並等待，同時報告進度，所以在此期間你可以提出下一個請求。

### 可能的過程：一個例子 {#how-it-can-work-an-example}

一次對話，從一個想法到一個播放列表。你說話；智慧體選擇工具（中間那一欄只是為了展示發生了什麼），並告訴你返回了什麼。

| 你說 | 智慧體 | 你得到 |
|---|---|---|
| 「寫一首關於燈塔看守人最後一夜的歌詞，民謠風格，敘事形式。然後在一個叫 Coast 的新空間裡用它做一首歌。」 | `write_lyrics`、`create_space`、`make_song`，然後 `wait_for_take` 直到完成 | 展示給你的歌詞，標題為 *The Last Light*；一個叫 Coast 的空間；在那裡規劃並渲染好的一首歌，過程中附帶進度 |
| 「播放它。」 | `get_take`，然後開啟它的 `listen_url` | 在你的瀏覽器中播放 |
| 「旋律不錯。試試更鬆散、更躁動的，再給我一個不唱的。」 | 用鬆散和躁動呼叫 `make_variations`，再呼叫 `instrumental_from_take` | 歌曲裡面的兩個版本，以及旁邊的一段純音樂 |
| 「看看我們都有什麼。」 | 在 Coast 中呼叫 `list_takes`，並對歌曲使用 `inside` | 一份列表，每個都有簡短的 id，所以你可以說「3f9a」而不用說標題 |
| 「把 3f9a 取出來，加星標，再給它一張圖片。」 | `take_out`、`star_take`、`make_picture` | 那個鬆散的版本成為獨立版本，加了星標（所以也進了喜歡），附帶它的圖片連結 |
| 「把那個和純音樂放進一個叫 Coast demos 的播放列表。」 | `create_playlist`、`add_to_playlist` | 一個包含這兩個的播放列表 |
| 「把這個風格儲存為 Coastal folk。」 | `save_style` | 應用風格選單中的 **Coastal folk**，下次就能用 |
| 「現在來個二重唱：這些歌詞，帶 [male voice] 和 [female voice] 提示，每段都照寫的來。」 | 帶 `follow_structure` 呼叫 `make_song`（新方案，因為段落變了） | 一首嚴格按你的段落、按順序規劃的新歌，每一行被標註的歌詞都移到了那個人聲演唱的位置 |

它做的一切都在庫裡，就像你在頁面上做的一樣：在編輯器中開啟任何版本、做母帶處理，或者從那裡繼續。當某一步做不到時，智慧體會從應用本身得到原因（「this take is an instrumental already」、「nothing here can draw a
picture」），並轉告給你，所以你聽到的回答和頁面給出的一樣。

### 使用思路 {#ideas-for-using-it}

- **先批次出點子，再挑選。**「在 EDM 空間裡做五段風格各異的一分鐘 EDM 純音樂。」它會一個接一個地啟動，並在每一個完成時告訴你。你來聽，然後說「給第二和第四個加星標，其餘刪掉」。
- **圍繞一個想法迭代。**「做一段夢幻合成器風格的純音樂並播放」，然後「現在一樣的，鼓多一點」，再「照第二個那樣再給我四個」。智慧體會記住哪個版本是哪個，所以你可以按位置或按你說過的特點來指代它們。
- **不用點來點去的翻唱。**「轉寫*這段小樣*，然後做三個翻唱：民謠、合成波和爵士。」如果錄音沒有樂譜，它會先轉寫，然後在你指定的空間裡做翻唱。
- **配合 LoRA。**「列出我的風格 LoRA，然後用爵士那個做一段純音樂。」觸發詞和儲存的強度會替你處理好，手動做很容易出錯。
- <strong>歌詞由智慧體寫，或由應用寫。</strong>智慧體可以自己寫歌詞：「寫一首關於夜行列車的歌詞，然後用它做一首民謠風格的歌。」Yeufonic 只會看到寫好的歌詞。或者請應用來寫：「用 Yeufonic 的歌詞作者，嘻哈形式，說話般的語氣」，它會像頁面上的**寫歌詞**那樣寫好，再交還給你用於一首歌。
- **同一旋律，不同歌詞。**「用這些歌詞作為第二段主歌，再把它唱一遍」：`new_words` 會保留旋律、調性和速度，而根據歌詞新寫一首歌則會寫出一段新旋律。
- **比較設定。**「同一首歌做兩遍，一遍用熟悉的和聲，一遍用冒險的和聲，用同一個種子」，然後「現在給好的那個試遍每種演繹」。設定按名稱請求，所以一句話就能搭好一個小測試。
- **根據試聽整理播放列表。**「把這周所有加星標的版本放進一個叫 Week 43 的播放列表」，或者「把純音樂從
  Road trip 裡拿出來」。喜歡就是加了星標的版本，所以星標和喜歡始終是同一份列表。
- **為一整批做分軌。**「把我最新的五個版本分成人聲和樂器，並給我連結。」它們會一個接一個排隊，排在 GPU 正在執行的任何渲染之後。
- **整理庫。**「找出標題相同的版本，告訴我哪個最新，刪掉舊的」，或者「把我今天做的所有東西移到一個叫 Drafts 的空間」。它按 id 操作，刪除之前會先詢問。
- <strong>長任務之前先看看。</strong>在排一個長渲染或一整批之前問一句「Yeufonic 忙嗎？」，免得排在訓練後面。
- <strong>更大任務的一部分。</strong>因為它是智慧體可以呼叫的工具，所以可以成為更大事情的一部分：為一段影片做一條音軌並寫好配套說明，或做一批數量與一個播放列表相當的版本，並按一個列表給它們命名。

智慧體聽不到版本，所以無法判斷它聽起來怎樣：由你來聽，它來做繁重的工作。它也不是繞過引擎的捷徑：GPU 仍然一次只做一個任務，所以一大批就是一條長隊。
- <strong>分享一個版本。</strong>「把我加星的版本連同配方儲存為 FLAC 壓縮檔」會得到一個別人能聽也能重做的檔案：對方請自己的代理「匯入這個版本檔案並算繪」。或者「用爵士 LoRA 再匯入一次，樂譜和種子不變」，用另一種方式聽同一個方案。

### 值得了解 {#things-to-know}

- <strong>版本的標題可能相同，</strong>所以智慧體用版本的 **id** 來工作，列出版本時會顯示一個簡短的 id（`short_id` 列）。你可以用 id 的開頭來指代一個版本，四個字元或更多，只要只有一個版本以它開頭。如果有兩個，它會告訴你並要求更多字元。
- <strong>刪除會問兩次。</strong>智慧體先給你看它會刪除什麼，包括任何同標題的其他版本，只有在你說是之後才會刪除。加了星標的版本需要你明確說出來。刪除的版本連同其音訊都無法恢復。
- <strong>空間和風格 LoRA 用名稱指定，</strong>而不是用編號：「在 EDM 空間裡」「用爵士 LoRA」。與任何東西都不匹配的名稱會得到現有專案的列表，不會新建任何東西。LoRA 的觸發詞會替你加進風格里，因為沒有它 LoRA 幾乎不起作用。
- <strong>新版本從頁面的起點開始：</strong>和聲為多樣、演繹為寬廣，除非你指定別的。在沒有和聲節點的引擎上，它從熟悉開始，因為那裡的和聲無法調得更高。
- <strong>圖片和歌詞會排隊等候。</strong>在這臺電腦上繪製或描述的圖片會等到沒有歌曲在生成時才處理，在這臺電腦上寫的歌詞會和其他 GPU 任務一起排隊，所以智慧體可能會說「還在生成中」，稍後再回來看。
- <strong>純音樂總是用帶時間的結構來規劃，</strong>根據你要求的時長算出（如果你什麼都沒說，大約兩分半）。沒有時間時，規劃器寫出的方案會長得沒法用。指定你自己的段落，它們就會原樣使用。
- <strong>只限這臺電腦。</strong>頁面的主機名和來源檢查同樣適用，而且沒有登入，所以不用時請關閉這個設定，也不要把埠暴露給你不信任的網路。

## 系統日誌 {#system-logs}

應用會為每個重要操作——樂譜規劃、渲染、音訊轉寫、分軌分離和 LoRA 訓練——寫一份統一的即時日誌，帶有 `INFO`、`WARN` 和 `ERROR` 字首。

- <strong>瀏覽器內控制檯：</strong>點選頂部欄中的**日誌**按鈕（或按 **L**），開啟一個可以拖動和調整大小的浮動控制檯。它保持開啟而不阻擋頁面，讓你可以把版本加入佇列，並即時跟蹤生成過程。
- <strong>獨立視窗：</strong>點選控制檯標題欄中的<strong>↗ 彈出</strong>（或直接訪問 `/logs`），開啟一個專門的日誌視窗。
- <strong>在終端中：</strong>日誌會自動輪轉到主機上的 `data/logs/yeufonic.log`，你可以在那裡即時跟蹤：
  ```bash
  tail -f data/logs/yeufonic.log
  ```

## 引擎自己的頁面 {#the-engine-s-own-page}

引擎是 ComfyUI（除非這個安裝用的是 yue2.cpp，它的頁面只是一個簡單的測試臺），它自己的介面可以訪問：Docker 為 <http://localhost:8189>，
Windows 安裝為 <http://localhost:8188>（即 `settings.ini` 中的 `engine_port`）。它只在這臺機器上響應，不需要登入。

- <strong>它和應用用的是同一個引擎、同一塊 GPU。</strong>在那裡執行的任務會作為來自外部的任務出現在應用的佇列中，應用自己的任務會等它完成。
- **它的歷史記錄顯示應用傳送的每一個圖**：方案、渲染和轉寫，以及引擎收到的每一項設定。想確切知道一個版本是由什麼做出來的，這裡是個好地方。

## 出問題時 {#when-something-is-wrong}

<strong>標題欄說缺少引擎。</strong>應用沒有它也能執行，並會這樣提示。渲染會等待。檢查引擎容器是否在執行。

<strong>一首歌停不下來。</strong>通常是規劃器強度太高。把 LoRA 的規劃器降到 0.5。時長上限無論如何都會讓它停下。

<strong>一個 LoRA 似乎沒有作用。</strong>檢查觸發詞是否在風格里，以及你調高的那個強度是不是檔案裡真的有的——選擇器會把另一個變灰。

<strong>一個版本顯示「渲染偏弱」。</strong>它從頭到尾都比正常情況輕得多。有些這樣的版本只是聲音小；另一些聽起來單薄或失真。點選提示可以對它進行標準化，這會把它提升到通常的響度，並標為 *已標準化*。如果聽起來仍然不好，換一個種子試試，並把那個 LoRA 的音色保持在 0.5 或以下。這多發生在透過在這裡訓練的風格 LoRA 做的翻唱上。

<strong>響度標準化。</strong>在編輯器中勾選它，勾選期間做的每個版本在完成時都會被調整到通常的響度，並標為 *已標準化*。沒有勾選時做的版本，之後可以用卡片頂部的揚聲器按鈕來標準化。渲染出來的原始檔案會儲存在旁邊，點選 *已標準化* 會回到它。響度的目標在設定的 *標準化到* 中設定。不勾選時，版本保持渲染時的電平。

<strong>一段純音樂唱了起來。</strong>參見上文的 *純音樂唱了起來*。這是模型的毛病；換一個新種子通常就能解決。

<strong>一個版本無法重新渲染。</strong>它的錄音可能已被刪除。翻唱會保留各自的音訊和樂譜，但無法從一段已不存在的錄音重新渲染。

<strong>沒有聲音，但波形在動。</strong>檢查音量控制，並確認沒有選中某個分軌——播放器跟隨你最後點選的東西。
