# Yeufonic 使用指南

本指南讲的是如何**使用**这个应用。安装方法，以及开始使用前需要准备的一切，都在
[README](https://github.com/yeufonic/yeufonic#readme) 里。

这个应用用 YuE2 来写歌。YuE2 分两步工作：先写一份**乐谱方案**——旋律、和弦和段落，以文本形式——然后把这份方案**渲染**成音频。下面几乎所有内容都源于这种两步分工。一份方案只要几秒钟，可以阅读、编辑，也可以丢掉；一次渲染则要几分钟。所以应用会先让你看方案。

---

## 你的第一首歌 {#your-first-song}

1. 点击左侧面板顶部的<strong>+ 歌曲</strong>。编辑器窗口随即打开。
2. <strong>写一个风格。</strong>一句话，而不是一串标签：*“warm indie rock, expressive female lead, jangly
   guitars, 96 BPM”*。它对结果的影响最大。
3. **加上歌词**，或者点击**写歌词**，让 Gemma 根据描述起草。
4. 点击**写乐谱方案**。窗口关闭，版本出现在左侧面板中。按钮旁的**方案就绪后立即渲染**默认是勾选的，此时方案会直接进入渲染。

想在渲染之前先读方案，就先取消勾选**方案就绪后立即渲染**。这样版本会停在方案这一步：打开它，在它的**乐谱**页面里，**写新方案**只需几秒钟就能为一段你不喜欢的旋律重新掷一次骰子，**渲染此乐谱**则会渲染它。还没有音频的版本会被补全；已经有音频的版本则会作为一个新版本渲染在它旁边，所以渲染永远不会覆盖你想保留的版本。

版本出现在右侧的库里，并在底部的播放栏中播放。

### 版本面板与编辑器 {#the-take-panel-and-the-editor}

**左侧面板**显示你最后点击的那个版本，只供阅读：它的风格、声音设置、歌词的前几行，以及乐谱的调性、速度、时长和每个段落的和弦。顶部的<strong>+ 歌曲</strong>、**+ 翻唱**和<strong>+ 纯音乐</strong>用来开始新的创作；与该版本类型相同的那个按钮会高亮。面板旁的箭头可以把它收起，让版本列表占满宽度，再点一次又会展开。单个按键作用于面板显示的版本（M 打开母带处理架，E 打开编辑器，等等）：参见[键盘快捷键](#hot-keys)。

创建和修改版本都在**编辑器窗口**中进行。面板中它的主按钮会显示当前合适的操作：*编辑并重新渲染*，或者在有方案等待时显示*检查方案并渲染*。卡片上的**乐谱**和**再来**按钮也能打开它，双击卡片也一样。编辑器有三栏（歌曲、歌词和声音），一览无余，乐谱则在单独的标签页里。

用**关闭**、叉号或 Esc 关闭窗口时，你写下的内容都会保留。

右上角**关闭**之后的那个按钮会让窗口占满整个浏览器窗口，再点一次则恢复常规大小。窗口会按你上次离开时的样子打开。占满窗口时，歌词栏会占据整个高度：歌词框（已有文字时）和结构会扩展到多出的空间里，播放器则留在这一栏的底部。

窗口顶部一行放着版本卡片上那些小按钮的放大版：再唱一次、变奏、再试几个、内部、取出、标准化和移动，各自位于卡片上相应的位置。版本处于标准化状态时，标准化按钮显示为绿色，此时点击会把它恢复到渲染时的电平；版本内含其他版本时，内部按钮会亮起，点击会关闭窗口，在该版本下方显示它们。

### 录制的音色 {#a-recorded-voice}

一个版本可以用由某人歌声录音训练出的音色来唱：你自己的，或者一个语料库的歌手。版本照常渲染；然后分离出人声，用该音色重新演唱，再混回其余部分。在菜单中的 <strong>音色</strong> 页面创建和管理音色。这需要可选的音色服务（README 中的 “Recorded voices”）；没有它，音色栏会被隐藏。

#### 制作音色 {#making-a-voice}

<strong>新建音色</strong> 可以用你自己的录音制作音色，或者用语料库的歌曲训练一个音色。由录音制作的音色一开始是空的，它的页面负责收集录音：

- <strong>录制…</strong> 打开录音器。你保留的每条录音都按演唱原样交给音色，绝不做自动修音。
- <strong>上传…</strong> 接受音频文件。
- <strong>从库中…</strong> 添加你已有的录音，比如为翻唱录下的人声。每条都带播放器可先试听，并以引用而不是复制的方式加入。

每条录音都会注明是单独的人声（<strong>纯人声</strong>，在此录制的会自动勾选），还是会先进行分离的一首歌。页面会计算歌声的时长：覆盖整个音域的大约十分钟就足够，而一段很短的录音就已经能得到可辨认的音色。然后按 <strong>训练</strong>。

训练会在 GPU 上排队等候，并在任务指示和日志中显示进度。<strong>重新训练</strong> 会按录音现在的样子重新训练，或者用语料库的歌曲。<strong>它学习了什么</strong> 保留每首歌分离出的人声和训练用的片段，可以试听。设置 → <em>音色训练</em> 设定音色从多少分钟的歌声中学习，以及训练多少轮。

#### 音色的设置 {#settings-for-a-voice}

这些是在音色页面上设定的默认值。一个版本也可以有自己的设置（见下文）。

| 设置 | 作用 |
|---|---|
| <strong>八度</strong> | 把音色整体升高或降低一个八度，适合音域与版本相差很远的歌手。 |
| <strong>人声音量</strong>、<strong>乐器音量</strong> | 重新混音的平衡。 |
| <strong>相似度</strong> | 音色在多大程度上保持歌手自己的声音。越高越像本人，也可能听起来处理感更重。设为 100% 时可能丢掉歌词：歌手从未唱过的词可能变得含糊，编辑器会对此给出提示。 |
| <strong>共振峰</strong> | 在音高不变的情况下改变音色的大小：<em>更低沉</em> 听起来更大，<em>更明亮</em> 更小。 |
| <strong>混合</strong> | 人声中由该音色演唱的比例；其余是它所依据的渲染人声。 |
| <strong>空间</strong> | 在转换后的人声下方加一点短暂的空间感（<em>干声</em>、<em>轻微</em> 或 <em>更多</em>），让它融入混音。 |
| <strong>明亮度</strong> | <em>自动</em> 把高频提升到与渲染人声一致；<em>关</em> 保持转换后的样子。 |
| <strong>气息与辅音</strong> | 它们在多大程度上保留渲染人声自身的声音：<em>保留</em> 清晰但带有原声的痕迹，<em>转换</em> 可能撕裂。 |
| <strong>动态</strong> | 人声每一句的响度跟随谁：渲染时的版本，还是音色自身的起伏。 |

#### 在版本中使用音色 {#using-a-voice-in-a-take}

在编辑器的 <strong>录制的音色</strong> 中选择音色。旁边的 <strong>设置</strong> 打开上面的设置，只针对这个版本；版本会保留它们，与音色的设置不同时，按钮会显示 <em>单独设置</em>。

#### 使用前试听音色 {#hearing-a-voice-before-you-use-it}

这些设置中的 <strong>试听</strong> 会让音色用当前设置反复演唱一段短循环（<em>男声演唱</em> 或 <em>女声演唱</em>），你一边改设置一边就能听到每处变化。<strong>另存为新音色…</strong> 会把你听到的保存为一个独立的音色，使用同一模型。

<strong>自己的循环。</strong> 应用自带两段循环；你也可以加入自己的：

1. 找到或录下 15 到 30 秒、只有一个人在独唱的声音：干声，没有伴奏、混响或和声。
2. 把它保存为 FLAC、WAV、MP3、M4A、OGG 或 Opus 文件，文件名就是你想在列表中看到的名字。
3. 把它放进资料库的 <em>voice-loops</em> 文件夹：Docker 中为 `data/voice-loops`；Windows 中位于安装目录的 `data` 文件夹内，除非 `settings.ini` 中的 `data_dir` 指定了别的资料库文件夹。
4. 再次打开 <strong>设置</strong>：它会以文件名列出。

#### 分享与导入音色 {#sharing-and-importing-voices}

- <strong>下载音色</strong> 把训练好的音色保存为 zip，以便分享给别人。
- <strong>导入音色…</strong> 添加一个音色：这样的 zip，或者来自别处的 RVC 模型（其 zip，或一起选择的 .pth 和 .index）。导入时没有索引的音色，之后可以用 <strong>添加索引…</strong> 补上：“相似度”依据的就是它。
- <strong>现成的音色</strong>，即他人训练的 RVC 模型，可以在 [voice-models.com](https://voice-models.com/) 等网站找到：<strong>导入音色…</strong> 可直接使用下载的 zip。
- 版本的配方会记录它的音色和该版本的音色设置，导入配方时，如果这台安装里有同名的音色，就会使用它。

#### 得到干净的音色 {#getting-a-clean-voice}

结果是在分离出的伴奏上叠加转换后的人声，因此不如模型自己演唱的人声那样浑然一体。

- 音色会连同歌手一起学到录音的混响和制作，所以主唱清晰、干净的干声演唱，比混好的歌曲组成的语料库能得到更干净的音色。
- 一首歌或一段短录音就能得到可辨认的音色，但它可能把从未听过唱出的词唱得含糊。
- 用多得多的歌声、多得多的训练轮数训练出的音色（现成的音色常常如此），即使“相似度”很高也能保住歌词。

### 高级设置 {#advanced-settings}

编辑器标题栏中的**高级**按钮会打开只针对这个版本的设置。大多数歌曲都用不到它们。这些设置随版本一起保存，所以*编辑并重新渲染*会按你离开时的样子找到它们。只要有任何设置偏离默认值，按钮就会亮起，**恢复默认**则会把它们全部恢复。

有些作用于方案，有些作用于渲染和最终文件：

- **扩散步数**（16–64，默认 32）：音频解码器走多少步。步数越多，渲染越久。
- **遵循风格**（0–100，默认 1.0）：音乐对风格和歌词的遵循程度，也就是把乐谱变成声音那一阶段的引导强度（CFG）。高于 1.0 会更贴近它们；低于则会偏离。数值较小时差别很细微，渲染会稍慢一些。可以输入引擎接受的任何数值：非常高的引导往往听起来更刺耳，而不是更贴切。引擎支持时才会显示：yue2.cpp，或最新版本的
  ComfyUI 引擎（旧的 Docker 引擎需要重新构建才能获得）。
- <strong>避免：</strong>想要避开的词，例如“drums”或“rap vocals”。它们会以“avoid: …”的形式加到风格里。这只是给规划器的提示，并非保证：渲染器没有负面提示词。
- <strong>锁定调性：</strong>规划器写完方案后，方案会被移到这个调上。规划器会忽略风格里写的调，所以这一步直接在乐谱上完成：每个音符和每个和弦都移动相同的音程，调号也会重写。小调方案依然是小调，只有主音会移动。应用无法确定读懂的方案，比如调式音乐或中途转调的方案，会保留规划器的调，日志中会说明。
- **锁定速度**（BPM）：方案会固定在这个速度上，它会取代风格里或规划器自己乐谱里的任何速度，渲染也会跟随它。
- **乐谱 token 上限**（默认 8192）：规划器最多能写多少。上限越低，短歌的方案就越不会拖长。
- **和弦停留上限**（小节，默认 8）：规划器在同一个根音上最多停留多少小节，之后必须换和弦。
- **调外和声奖励**（0–10，默认 0）：把规划器推向借用和弦以及主调之外根音的力度。这两项作用于规划器的选择，所以更多体现为方案和弦上的差异，而不是明显的听感差异。可以在乐谱窗口中比较。
- **声部遵循提示**（歌词框下方的复选框，当歌词中有像
  `[male voice]` 这样的人声提示时出现；新版本默认勾选）：每一行被标注的旋律都会按八度移动到提示所指那个人声的演唱区域。参见[歌词](#the-words)。
- **严格遵循此结构**（歌词框下方的复选框，不在“高级”里；仅限歌曲；默认关闭）：方案严格按歌词里写的段落，按顺序写，不多不少。关闭时，规划器会自己安排歌曲的形式，常常加入前奏、尾奏或间奏，或者漏掉某个段落。即便打开，方案也仍可能在列表结束前就结束。
- **段落开头各不相同**（跟随和声、总是、从不）：一个段落能否用与上一段相同的和弦开头。*跟随和声*在“多彩”及以上开启，以下关闭；*总是*和*从不*则在任何级别都为这个版本做决定，方便比较有无这条规则的两份方案。
- <strong>目标响度：</strong>版本标准化的目标电平。只在开启标准化时生效。
- **结尾淡出**（秒，默认 3）：版本在时长上限处被截断时，淡出的长度。

### 风格框里写什么 {#what-to-put-in-the-style-box}

YuE2 把它当作一段录音的描述来读，所以请描述一段录音。语言、流派、人声、乐器、氛围、速度和制作，大致按这个顺序，写成一句话。零散的标签列表效果较差，而像 `[Verse]` 这样的段落标记属于歌词，不该写在这里。

下方的**人声**标签会替你写进风格：女声、男声或二重唱，再加一种特质，比如气声或沙哑。它们只是输入的捷径，结果你也可以手动修改。

### 起草歌词 {#drafting-the-lyrics}

<strong>结构。</strong> 在歌词框上方，只要框里还没有文字，歌曲就有一个可以像纯音乐那样搭建的 <strong>结构</strong>：一个可以重新排序、删除和添加的段落列表（前奏、主歌、预副歌、副歌、桥段、间奏、尾奏）。

- <strong>从…开始</strong> 用一种常见形式填满它，每种形式的提示都说明它适合什么。
- <strong>间奏</strong> 是一段纯器乐：作者把它的标签单独放在一行，规划器用器乐声部来演奏。
- <strong>把段落放入歌词框</strong> 把标签作为空段落插入，方便你在下面手写。
- 框里一旦有了文字，唱的就是歌词，结构则让到一旁。

歌词框旁的 <strong>写歌词</strong> 会问这首歌讲什么，并为你搭好的段落写词。

- <strong>主歌或副歌的行数</strong> 设定每段的长度：一个段落里的行越多，歌就越长，因为规划器写出的音乐大致和词一样多。
- 上面的风格决定氛围。
- 同一引擎上的 Gemma 写出草稿，如果你没有起标题，草稿会带着标题进入歌词框；也可以改由在设置中配置的 [外部 LLM](#external-llm) 来写。
- 草稿一开始窗口就会关闭，进度显示在歌词框旁边。

歌词编辑器的按钮也能添加这些段落，以及人声提示（+ 男声、+ 女声、+ 双声）。

<strong>歌词的读感</strong> 设定作者追求的节奏和押韵，从 <em>自然</em>（默认）到 <em>短促有力</em> 或 <em>绵长流畅</em>：[歌词](#the-words) 列出了每个选项。

这只是初稿。各行合拍押韵，但模型偏爱熟悉的意象，也没有任何东西检查某一行是否已经属于别人。在做方案之前读一遍，把它变成你自己的。

## 从提示词写一首歌：所有选项 {#writing-a-song-from-a-prompt-every-option}

**+ 歌曲**如今有很多选项。没有哪个是必需的：一个风格加一点歌词就够了，就像
[你的第一首歌](#your-first-song)那样。本章按编辑器显示的顺序逐一介绍它们，即三栏（歌曲、歌词和声音），然后讲有了方案之后做什么。最后有一张常见需求表，比如让歌更长，或让副歌听起来和主歌不同。

### 歌曲 {#the-song}

- <strong>标题。</strong>可选。留空时使用歌词的第一行。
- <strong>风格。</strong>列表 **选择风格…** 里有 200 个起点，从 afrobeats 到 zydeco，按字母顺序排列。选择其中一个，会用完整的描述填满风格框，之后可以再编辑。下方的标签是十个快速起步的歌曲风格：warm indie rock、soulful jazz-pop、synthwave、acoustic ballad、heavy rock、modern pop、
  country、hip hop、smooth R&B 和 dance pop。参见[风格框里写什么](#what-to-put-in-the-style-box)。
- <strong>保存你自己的风格。</strong>列表旁的**保存**会把风格框里的内容以你取的名字保存。列表的第一项**保存的风格**会打开你保存的风格；旁边的垃圾桶可以删除，列表的搜索会把它们和那 200 个一起找出来。用已有的名字保存会替换那个风格。风格 LoRA 的触发词不会被保存，使用该风格时会为当前选中的 LoRA 重新填上。
- <strong>风格里的速度只是提示。</strong>规划器通常会选自己的速度。要固定速度，请用“高级”里的**锁定速度**。
- <strong>人声。</strong>这些标签会替你把人声（女声、男声、二重唱及一种特质）写进风格。
- <strong>风格 LoRA。</strong>位于声音栏底部。参见[风格 LoRA](#style-loras)。

### 歌词 {#the-words}

<strong>结构。</strong>在歌词框上方，只要框里还没有文字，就会有一个段落列表：歌曲将要遵循的顺序。每一行都可以换成另一个段落、上下移动（或拖动）或删除，列表下方的标签可以添加段落。段落有前奏、主歌、预副歌、副歌、桥段、间奏和尾奏。**间奏**是一段纯器乐：它没有歌词，规划器用器乐声部来演奏。（`solo` 不是规划器认识的段落；要独奏，就用间奏。）

**从…开始**会用一种常见形式填满列表。把鼠标悬停在某个选项上，可以看到它适合什么：

| 形式 | 段落 | 适合 |
|---|---|---|
| 主歌、副歌、桥段 | 主歌、副歌、主歌、副歌、桥段、副歌 | 经典歌曲：流行、摇滚、乡村 |
| 短小 | 主歌、副歌、主歌、副歌 | 民谣、朋克、早期摇滚乐 |
| 前奏与尾奏 | 前奏、主歌、副歌、主歌、副歌、尾奏 | 抒情歌、软摇滚、创作歌手 |
| 叙事 | 主歌、主歌、副歌、主歌、副歌、尾奏 | 叙事歌曲、民谣、乡村 |
| 带预副歌的流行 | 主歌、预副歌、副歌、主歌、预副歌、副歌、桥段、副歌 | 现代流行、舞曲流行、流行摇滚 |
| 钩子先行 | 副歌、主歌、副歌、主歌、副歌、桥段、副歌 | 流媒体时代的流行、独立流行 |
| 短而简单 | 主歌、副歌、主歌、副歌、副歌 | 朋克、车库摇滚、乡村摇滚 |
| 嘻哈 | 前奏、主歌、副歌、主歌、副歌、主歌、尾奏 | 说唱、嘻哈、陷阱、R&B |
| 双桥段 | 主歌、副歌、主歌、副歌、桥段、桥段、副歌、副歌 | 力量抒情、前卫与交响摇滚 |
| 间奏 | 主歌、副歌、间奏、主歌、副歌、桥段、副歌 | 摇滚、流行摇滚、独立 |
| 全部部分 | 前奏、主歌、预副歌、副歌、间奏、主歌、预副歌、副歌、尾奏 | 流行、舞曲流行 |

<strong>段落数量。</strong>无论歌词要求什么，规划器通常写 8 到 10 个段落，所以超过
10 个的列表会被压缩，被丢掉的段落里的词不会被唱出来。列表这么长时，搭建器会提醒你。加段落并不会让歌变长；每个段落只会变短。参见
[让歌曲更长](#making-the-song-longer)。

**把段落放入歌词框**会把段落作为空标签插入，方便你在下面手写。框里一旦有了文字，唱的就是歌词，搭建器则会让到一旁。

<strong>写歌词。</strong>描述这首歌讲什么，模型就会为你搭好的段落写词。它会问三件事：

- **主歌或副歌的行数**（4、6 或 8；默认 6）。一个段落里的行越多，歌就越长，因为规划器写出的音乐大致和词一样多。前奏、桥段或尾奏保持 2 到 4 行，间奏则没有歌词。
- <strong>歌词的读感。</strong>列表显示每一行追求的音节数。旧的作者几乎总是写出同样的八音节押韵句，而这个选项改变了这一点：

| 选项 | 追求 | 你会得到 |
|---|---|---|
| 自然（默认） | 3-13 个音节 | 长短句混合，少量押韵，没有固定节拍 |
| 规整押韵 | 6-10 个音节 | 行长相同、两两押韵：传统形式，也是作者以前的写法 |
| 口语节奏 | 5-14 个音节 | 口语化且富有节奏，像说话或说唱，带内韵 |
| 松散押韵 | 4-13 个音节 | 有的押韵，有的近似押韵，有的不押，行长不一 |
| 短促有力 | 3-6 个音节 | 短句和重复的短语 |
| 绵长流畅 | 10-14 个音节 | 如思绪般流淌的长句 |

  最后一次的选择会被记住。这些是目标而非保证：语言模型在两端（短促有力、绵长流畅）贴得很紧，在中间档则较为宽松。
- **委托内容**本身，用你自己的话写，以及上面的风格，它决定氛围。委托内容会随版本一起保存，所以打开一个版本再点**写歌词**，就能看到当初要求写什么，可以修改后重写。

草稿会进入歌词框，草稿一开始，窗口就会关闭。这只是初稿：读一遍，把它变成你自己的。

**严格遵循此结构**（歌词框下方的复选框，默认关闭）。规划器把歌词中的段落标签当作参考，自行写出自己的形式：常常加入前奏和尾奏，把桥段换成间奏和一段主歌，或压缩一个很长的列表。打开它后，方案会严格按歌词里写的段落、按那个顺序来写，不多不少。它不能加入你没写的前奏或尾奏。音乐怎么写、每个段落何时开始，仍由规划器决定。仅适用于歌曲。

<strong>谁唱哪一行：人声提示。</strong>单独一行、用方括号写出某个人声，表示接下来各行由谁来唱，直到下一个提示或下一个段落：

```
[Verse 1]
[male voice]
The ferry leaves at half past nine
I watch the harbour lights go by
[female voice]
I wait beside the ticket line

[Chorus]
[both voices]
Carry me over, carry me home
```

把提示写成 `[male voice]`、`[female voice]` 或 `[both voices]`，每个单独一行，放在方括号里。

- 展开的歌词编辑器标题栏中有 <strong>+ 男声</strong>、<strong>+ 女声</strong> 和 <strong>+ 双声</strong> 按钮，可在光标处插入。
- 这些是测试该功能时用的写法，另外也可以用 `vocal` 代替 `voice`（`[female vocal]`），以及表示两者的 `[male and female voices]`。
- 可以在逗号后加上自己的话，比如 `[female voice, soft and close]`；这不会改变由谁来唱。
- 没有提示的段落交给规划器决定。
- 为了让在别处写的歌词不被忽略，其他写法也能读懂：`[man]`、`[woman]`、`[duet]`、写在段落标签里的提示如 `[Verse 2 - female vocal]`，以及圆括号里的提示 `(female voice)`。方括号更稳妥：圆括号里的词通常是和声，可能会被唱出来。

<strong>提示本身并不决定声音。</strong> 由谁来唱主要取决于旋律写得多高：同一行高八度就会由女声来唱，而且无论提示写了谁，规划器都喜欢把一段主歌写在两个八度上，大约每四行换一次。

- <strong>声部遵循提示</strong>（歌词中有提示时出现在歌词框下方的复选框；新版本默认勾选）会让提示生效：写方案时，每段有提示的旋律都会按整八度移到该声音演唱的位置，男声低，女声高。方案的其他部分不变。
- 每次渲染前都会重新执行，所以会跟随你对歌词或乐谱的修改。
- 在乐谱页面上，<strong>声部遵循提示</strong> 会对框中的乐谱做一次同样的处理，适用于没有勾选复选框时做出的版本；保存乐谱再渲染即可。

需要知道的三件事：

- <strong>谁唱哪一行仍有几分运气。</strong>旋律到位后，大多数行会交给被提示的人声，但渲染仍可能把某一行交给另一个人声。换一个种子重新渲染，或者使用**再试几个**。
- **合唱**会把这一行放在女声演唱的位置，第二个人声则交给渲染，渲染常常会在副歌里加进一个。它是在请求二重唱，而不是制造二重唱：你能听到多少第二人声，每次渲染都不一样。目前还没有办法在不损害歌词的前提下把两位歌手写进同一行。
- 在这个复选框出现之前做的版本，乐谱保持原样；勾选它，或使用**声部对应提示**来调整。

**手写。**“展开”按钮会打开全尺寸编辑器，带有前奏、主歌、预副歌、副歌、桥段、间奏、尾奏和纯音乐按钮。一个段落是像 `[Verse]` 这样的一行，后面跟着它的各行；下面没有歌词的标签，如 `[Interlude]`，就是一段纯器乐。

### 声音 {#the-sound}

- **和声**（滑块）：和弦有多大胆。新歌从**多样**开始，演绎设在**宽广**：在我们自己的测试里，这一组合给出了音乐上最有意思的版本，所以是个不错的起点。可以随意调整其中任何一个。已有的版本保留它们当时的设置。规划器自己往往会写一个四和弦的循环，并在每个段落里使用它，而每升一级都会让它离这种写法更远一点。各级别层层叠加：

  | 级别 | 对和弦做什么 | 什么时候选 |
  |---|---|---|
  | 熟悉 | 什么都不做：YuE2 的和弦，常常整首歌只有一个循环 | 你喜欢规划器的第一想法，或想要最简单的伴奏 |
  | 多样 | 不鼓励原样重复刚用过的和弦，所以会给它们换色（先 F，再 Fmaj7），但仍留在调内 | 循环听起来太单调，而你希望歌曲保持常规 |
  | 多彩 | 同上，力度更强：主歌和副歌分开，和弦更丰富。段落也不能用与上一段相同的和弦开头，所以副歌不再像主歌那样开始 | 你希望副歌是一次推进，而不是重复。不错的第一步 |
  | 冒险 | 不鼓励最近用过的*根音*，而不只是写法，所以和声必须游走，并从调外借用和弦 | 你想要动感和惊喜，并愿意留意听起来奇怪的和弦 |
  | 调外 | 大胆，偏向调外和弦 | 实验。做好扔掉一些方案的准备 |

  从“多彩”开始，各段落之间的和弦选择差异更大：一首歌里有更多不同的和弦、更多不重复的四小节型，以及更少照搬主歌开头的副歌。方案仍然是一首正常的歌，所以在求助更狂野的方案多样性之前，值得先把和声往上调一两级试试。在**高级**里，**段落开头各不相同**可以设为*总是*或*从不*，用来测试有无副歌规则的方案；默认的*跟随和声*在“多彩”及以上生效。陷阱或氛围这类风格本质上往往建立在循环上，所以变化会比流行或摇滚小。测量数据参见[和声](#harmony)。
- <strong>方案多样性。</strong>规划器在其他所有方面写得有多自由。参见[方案多样性](#plan-variety)。
- <strong>演绎。</strong>渲染时音符如何被演奏。参见[演绎](#interpretation)。
- <strong>时长上限。</strong>歌曲最晚可以在何时结束。参见[时长](#length)。
- **模式。** *完整*保留方案的和弦；*旋律*让伴奏自由发挥。*无乐谱*（仅限歌曲）完全不写方案：参见[没有乐谱的歌](#a-song-with-no-score)。
- **种子**和**保留此种子**。参见[种子，以及重现一个版本](#seed-and-reproducing-a-take)。
- **制作润色**和<strong>响度标准化。</strong>参见[制作润色](#production-polish)。
- 窗口底部按钮旁的**方案就绪后立即渲染**会一口气完成方案和渲染，中间不停。默认勾选，编辑器会记住你的选择。取消勾选可以先读方案。
- **高级**（标题栏按钮）：扩散步数、遵循风格、避免、锁定调性、锁定速度、最长乐谱、和弦停留上限、调外和声加成、段落以不同方式开头、目标响度和结尾淡出。参见
  [高级设置](#advanced-settings)。
- <strong>母带</strong>（它左边的按钮，版本有声音时出现）会在编辑器上方打开该版本的母带处理架。处理架改变版本声音时，按钮呈绿色。处理架的模块依次为：

  1. 1073 风格均衡器
  2. 参数均衡器
  3. 压缩器
  4. 立体声扩展器
  5. <strong>3D 空间</strong>（见下文）
  6. 限制器

  每个模块都可以用左侧的箭头折叠成一条，版本会记住哪些被折叠。

  <strong>参数均衡器。</strong> 它的七个频段各是图上的一个点：

  - 左右拖动点改变频率，上下拖动改变增益。
  - 在点上滚动滚轮改变宽度；双击让它复位。
  - 图下方的条带设置所选频段的类型（低切、低架、钟形、陷波、高架、高切），并可开关它。
  - <strong>平直</strong> 把所有频段恢复到 0 dB，图角落的按钮改变图显示的分贝范围。

  <strong>按键。</strong> 处理架打开时，空格键播放和暂停版本，方向键在其中移动和调节音量，和主页面一样。Esc 关闭处理架，再按一次关闭编辑器。

- <strong>3D 空间</strong> 是处理架中位于扩展器和限制器之间的模块，为耳机把版本摆放在你周围，有两种方式：

  | 来源 | 你设置什么 |
  |---|---|
  | <strong>混音</strong> | 前方两只虚拟音箱（<strong>宽度</strong>）和后方两只（<strong>后方</strong>），<strong>环绕</strong> 决定混音的宽度和氛围有多少从后方发出；音箱也可以在圆上拖动。<strong>高度</strong> 把它们全部抬高，<strong>空间</strong> 加一点短暂的空间感。 |
  | <strong>分轨</strong> | 版本的每条分轨各自摆放：在圆下方选一条，然后沿圆拖动来放置，滚轮把它展宽。版本没有分轨时，<strong>生成分轨</strong> 会打开分轨窗口。 |

  <strong>前方</strong>、<strong>宽广</strong> 和 <strong>环绕四周</strong> 一次设好全部。你听到的是为耳机准备的，永远不会进入版本自己的文件。要保留它：

  - 耳机下的 <strong>下载</strong> 把它保存为 WAV。
  - 5.1 音箱下的 <strong>FLAC</strong> 和 <strong>AC-3</strong> 把版本保存给环绕音箱（来自分轨时，每条分轨会送到它所在位置两侧的音箱）。
  - 空间开启时，版本的保存窗口也提供同样的下载。

### 让歌曲更长 {#making-the-song-longer}

歌曲的长度由方案决定，渲染会跟随方案的长度。能改变它的是这些：

| 想要… | 这样做 |
|---|---|
| 更长的歌 | 给每个段落更多行（**主歌或副歌的行数**：6 或 8） |
| 更慢、更长的歌 | 在“高级”里设置**锁定速度**。同一份方案 BPM 越低，时长越长 |
| 通过加段落让歌更长 | 行不通：一份方案大约有 8 到 10 个段落，多出来的只会变短或被压缩 |
| 比方案允许的更多 | 写一份新方案；同样的歌词每次运行，时长差别很大 |
| 歌词结束时歌也结束 | 只在歌被截断时才提高时长上限；上限是天花板，不是目标 |

### 有了方案之后 {#after-the-plan}

- 只要打开的版本已有音频，**渲染此乐谱**就会新建一个版本，所以渲染永远不会覆盖你想拿来比较的版本。还没有音频的版本会被补全。
- **保留此旋律**（修改了某个版本的歌词之后）：用新歌词演唱该版本的乐谱，作为新版本。旋律不能增加段落或音符，所以如果你的歌词段落比旋律多，或音节比它的音符多得多或少得多（长句配给为短句写的旋律，或短句配给为长句写的旋律），这个复选框会自动取消勾选，并写一份新方案，附上一行说明原因。参见[同一旋律，新的歌词](#same-tune-new-words)。
- <strong>筛选库。</strong>筛选器旁的**歌曲**、**翻唱**和**纯音乐**开关只显示打开的空间里这些类型；可以选多个，或都不选以显示所有类型。

## 阅读和修改方案 {#reading-and-fixing-the-plan}

方案用 **ABC 记谱法**写成：音乐以纯文本表示，用字母代替五线谱上的音符。
Chris Walshaw 在九十年代初发明了它，用来通过电子邮件传送民谣旋律，此后便流传下来。

你不必会读它。应用会在编辑器下方把同一份方案显示为**和弦谱**和真正的**五线谱记谱**，**展开**会把它们全尺寸打开。但文本才是 YuE2
写下并据以渲染的东西，所以值得学会在其中找路。

### 阅读方案 {#reading-a-plan}

方案以一个标头开始，每行一个字母加一个冒号：

```
X:1
M:4/4
L:1/32
Q:1/4=120
V: Vocal clef=treble name="Vocal Melody"
V: Ins   clef=treble name="Ins Melody"
K:D#m
```

| 行 | 含义 |
|---|---|
| `X:1` | 曲目编号。每个 ABC 文件都以它开头 |
| `M:4/4` | 拍号——每小节四拍 |
| `L:1/32` | 单位时值：单独一个字母持续一个三十二分音符 |
| `Q:1/4=120` | 速度——每分钟 120 个四分音符 |
| `V:` | 声明一个声部。YuE2 写两个：一个人声线，一个器乐线 |
| `K:D#m` | 调性，升 D 小调。`K:` 总是在标头的最后 |

然后是音乐本身：

```
% intro
V: Vocal
z24z4"D#m"z4|"D#m"z32|
V: Ins
Z|d16a16-|a16g8a8|
```

- **音符是字母。**`d16` 是一个持续 16 个单位的 D。小写字母比大写字母高一个八度，
  `'` 或 `,` 会把它们移得更远。
- **`-` 把一个音符连到下一个**，让它们听起来像一个音。
- **`z` 是休止符**，和音符一样有时值。大写的 `Z` 是整小节休止。
- **和弦写在双引号里**，如 `"D#m"`，放在它开始的那个音符前面。**查找和替换**编辑的就是它们。
- **`|` 是小节线**，**`%` 开始一条注释**——段落就是这样标出的：
  `% intro`、`% verse`、`% chorus`。

所以这一段说的是：升 D 小调，四四拍，每分钟 120 拍，前奏期间人声不唱、只承载和弦，乐器则奏出连起来的 D 和 A，然后是 G 和 A。

两个实际的结论。**改和弦是安全的**，即使音符看起来晦涩——它们只是引号里的部分，其余都可以保持原样。而且**如果你修改了方案，渲染会使用你改过的内容**，所以修好一份方案往往比反复重掷直到出现一份好的更快。

### 试听 {#hearing-it}

**五线谱**标签页的五线谱上方有一个播放器。点击**播放**，就能听到框中现有的方案（包括你的修改），在为一段拿不准的旋律花掉一次渲染之前，先用耳朵判断它。播放的音符会随之高亮，它的速度控制只改变试听，不改变乐谱。开始播放会停止播放栏正在播放的内容，因为同时放两样东西对谁都没有帮助；关闭窗口——或切换到和弦或歌词——也会停止它，这样就不会有东西在没有控制按钮可用时继续播放。

<strong>乐器</strong> 用风格中提到的乐器演奏每个声部，而不是从头到尾都用钢琴：

- 写着 <em>electric guitar, drums</em> 的风格会用吉他演奏，另一把吉他弹和弦，下面配贝斯。演唱的旋律由人声代替，纯音乐的旋律则不会。
- 提到鼓的风格还会得到一个鼓声部，按乐谱自己的拍号写成：摇滚用反拍，舞曲用四四拍底鼓，爵士用叮叮镲，抒情歌则更稀疏。它从头奏到尾，因为乐谱里没有可以停下的段落。
- 播放器旁的一行说明选了什么，取消勾选则恢复你本来会听到的钢琴。

这是对风格的解读，而不是对渲染的解读：YuE2 自己决定演奏，并会加入乐谱中没有的声部，所以把它当作用合适音色演奏的方案，而不是版本本身的声音。

<strong>下载 MIDI</strong> 把乐谱保存给 DAW：

- 每个声部是单独的一轨，在自己的通道上，并设为预览所用的乐器：人声旋律、器乐旋律，以及（除非取消勾选 <strong>和弦</strong>）作为和弦声部的和弦符号，旁边配贝斯（这是和声唯一以音符写出的地方），风格要求时还有通道 10 上的鼓。
- 乐器是 General MIDI 音色编号，所以 DAW 会用它自己的声音演奏，速度和拍号也在文件里。
- 中途改变拍号的方案会以开头的拍号写出（只记录这一个），音符保留各自的时值。

点击五线谱上的音符，会把光标移到写出它的 ABC 处。

<strong>超出音域。</strong> 乐谱中有比这些乐器能演奏的更高或更低的音时，会按整八度移动直到合适，播放器旁的一行说明移了多少；五线谱、MIDI 文件和乐谱本身都不变。乐器的音域并不相同（贝斯比钢琴低得多），所以乐谱被移动时才会出现这一行。没有音符的乐谱没有东西可奏，会如实说明。

<strong>音源。</strong> 播放器需要音符采样，这些不随应用附带：每种乐器约 7 MB，在预览第一次用到它时从来源获取，并保存在资料库中，之后就能离线使用。<strong>播放</strong> 获取当前乐谱所需的内容后开始播放，<strong>获取音色</strong> 获取同样的内容但不播放，适合想提前准备好的人。

### 钢琴卷帘 {#the-piano-roll}

在乐谱窗口中点击**钢琴卷帘**，打开可视化 MIDI 编辑器。你不必编辑原始的 ABC 字母，而是直接在一个交互式的音高—时间网格上查看和塑造旋律。

编辑器同时显示乐谱的两个声部——**Vocal**（天蓝色的主唱旋律）和 **Ins**（暖琥珀色的器乐伴奏）。两个声部始终完全可用，可见、可选、可编辑。左上角的**绘制**按钮决定点击添加的新音符属于哪个声部。

#### 编辑音符 {#editing-notes}

- <strong>添加音符：</strong>点击网格中的空格，在该音高和时间处创建一个音符。音符会立即发声，让你听到音高。
- <strong>选择音符：</strong>点击一个音符即可选中。按住 <kbd>Shift</kbd> 或 <kbd>Ctrl</kbd>/<kbd>Cmd</kbd> 点击，可在人声和器乐声部中选中多个音符。在空白区域拖出一个**选框**，可选中所有声部中的一个乐句或段落。按 <kbd>Ctrl</kbd>+<kbd>A</kbd>（macOS 上为 <kbd>Cmd</kbd>+<kbd>A</kbd>）或点击**全选**选中乐谱中的所有音符。要选中从播放光标到歌曲结尾的所有音符，按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>A</kbd> 或 <kbd>Alt</kbd>+<kbd>A</kbd>（或点击工具栏中的**从光标起 ▶**）。
- <strong>移动音符：</strong>横向拖动选中的音符可提前或推后，纵向拖动可移调。选中多个音符时——无论是人声、器乐还是两者——它们会一起移动，保持相对时间、旋律和歌词不变。
- <strong>时值：</strong>拖动音符的右边缘可加长或缩短它。**吸附**选择器（1/16、1/8 或 1/4 音符）让移动和调整大小对齐到整齐的音乐细分。
- <strong>删除音符：</strong>双击音符将其删除，或选中一个或多个后按 <kbd>Delete</kbd> 或 <kbd>Backspace</kbd>。
- <strong>撤销和重做：</strong>每一次对音符的编辑、移动、调整大小、添加和删除都会记入历史。按 <kbd>Ctrl</kbd>+<kbd>Z</kbd>（<kbd>Cmd</kbd>+<kbd>Z</kbd>）撤销，按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> 或 <kbd>Ctrl</kbd>+<kbd>Y</kbd> 重做。
- <strong>试听琴键：</strong>点击左侧钢琴键盘上的琴键，听它的音高。
- <strong>最大化：</strong>点击顶部栏中的**最大化**，让钢琴卷帘撑满浏览器窗口的整个宽度。

#### 时间线、段落与和弦 {#timeline-sections-and-chords}

沿着顶部标尺，时间线显示小节号和段落边界：
- <strong>重命名段落：</strong>点击段落标记（`intro`、`verse`、`chorus` 等）可编辑名称或重新指定。
- <strong>编辑和弦：</strong>就在小节标尺下方，和弦轨显示歌曲的和声进行。点击已有和弦可重命名（例如把 `C` 改成 `Am7` 或 `G/B`），点击空小节可放置新和弦。
- <strong>为空小节配和声（填补空白）：</strong>点击工具栏中的**填补空白**，用根据和弦进行生成的音符填满器乐伴奏中的空小节。
- <strong>删除空小节（压缩空白）：</strong>点击**压缩空白**删除两个声部中都空着、无声的小节，把后面的音符和和弦向左移动，消除编曲中多余的空隙。

#### 歌词与卡拉 OK 跟随 {#lyrics-and-karaoke-tracking}

钢琴卷帘底部有一条专门的歌词轨，把每个音节对齐到人声旋律上：
- <strong>按乐句对齐：</strong>点击**匹配歌词**把歌词分配到人声旋律上。对齐会识别旋律乐句之间自然的换气和休止，把每行歌词分给它的乐句，而不会让词越过休止溢出到后面的小节。多音节的词会被干净地拆分到各个音符上。
- <strong>编辑音节：</strong>点击歌词标签（或选中一个人声音符后按 <kbd>L</kbd>）编辑其文字。如果输入用空格或连字符分隔的音节（例如 `Hel- lo world`），它们会自动分配到连续的人声音符上。
- <strong>悬停高亮：</strong>鼠标悬停在歌词标签上会高亮网格中对应的音符，悬停在人声音符上则会高亮下方的标签。
- <strong>卡拉 OK 小球：</strong>播放时，一个动画小球会在每个正在演唱的音符上跳动，当前音节和网格中的音符会实时发光。

#### 播放与和声伴奏 {#playback-and-harmony-accompaniment}

按 <kbd>Space</kbd> 或点击<strong>▶ 播放</strong>从光标处开始播放。播放线扫过网格，同时更新小节、拍和已播放时间。

- <strong>可听节拍声（节拍器）：</strong>播放默认带有可听的节拍声，每小节第一拍是加重的木鱼声，其余拍则是较轻的咔嗒声。随时按 <kbd>C</kbd> 或 <kbd>M</kbd>（或点击走带栏中的**节拍器**）开关节拍器。
- <strong>和弦和声伴奏：</strong>播放会直接根据乐谱的和弦进行合成温暖的复音和弦铺底。即使人声或器乐轨静默，和声空间仍保持音乐性和温暖，而不会陷入死寂。按 <kbd>H</kbd>（或点击走带栏中的**和弦**）开关和弦伴奏。
- <strong>逐小节移动：</strong>按 <kbd>左方向键</kbd> 和 <kbd>右方向键</kbd> 逐小节后退和前进，或按 <kbd>Home</kbd> 直接回到开头。

### 和声 {#harmony}

YuE2 自己往往会写一个四和弦循环并一直停在那里。**和声**滑块会把它从刚用过的和弦上拉开，同时不破坏歌曲的结构。

| 级别 | 你会得到 |
|---|---|
| 熟悉 | YuE2 的和弦。常常整首歌只有一个循环 |
| 多样 | 避免重复同样的和弦。留在调内 |
| 多彩 | 主歌和副歌得到不同的和弦进行，和弦更丰富。段落不能以上一段的方式开头 |
| 冒险 | 让和声保持流动，并从调外借用和弦 |
| 调外 | 大胆，离调更远 |

**写新方案**使用滑块的当前位置，所以你可以用同样的歌词和更大胆的和弦重掷一次，再比较。

这是测量出来的，而不是假设的——一份歌词、两种风格、每种三个种子：

| | 熟悉 | 多样 | 多彩 | 冒险 | 调外 |
|---|---|---|---|---|---|
| 一首歌中不同和弦的数量 | 4.7 | 6.3 | 8.7 | 9.0 | 10.3 |
| 含调外和弦的小节 | 0% | 0% | 0% | 13% | 24% |
| 不重复的四小节型 | 29% | 38% | 50% | 63% | 64% |

每个级别的每份方案都保留了有效的段落与和弦。改为在风格文本里要求大胆的和声——“jazz harmony”、“borrowed chords”——没有任何可测量的效果。

### 方案多样性 {#plan-variety}

在*高级*里，**方案多样性**决定规划器写得有多自由。和声作用于和弦，而它作用于一切：旋律、结构和长度。

- <strong>平静：</strong>最稳定。和弦少，旋律不跑远。
- <strong>常规：</strong>默认值。
- <strong>活泼：</strong>多一些和弦和转折。
- <strong>大胆：</strong>更丰富的和声，大约是常规和弦词汇的三倍，而旋律依然明显是同一类型。
- <strong>古怪：</strong>躁动不安。和弦不停变化，旋律在一个段落和下一个段落之间跳换音区。适合奇特、古怪的歌。
- <strong>狂野：</strong>最躁动的一档，还可能在中途转调。

### 没有乐谱的歌 {#a-song-with-no-score}

**无乐谱**是**模式**的第三个选项，它完全不写方案就演唱歌词：YuE2 一边唱一边写旋律和和弦，就像原来的 YuE 那样，歌曲会通过**无乐谱演唱**直接渲染。它听起来常常和有方案的歌截然不同。

引导方案的那些设置在这里无从作用，所以选中它时，**和声**、**方案多样性**、**保留此旋律**和**严格遵循此结构**都会变灰，也没有可以阅读或编辑的乐谱。在上限以内，长度由 YuE2
决定。锁定调性和锁定速度只能以风格里的文字传达给它。再唱一次、变奏、再试几个和新歌词都可以用，每次都会在没有乐谱的情况下重新演唱。**写新方案**会给这个版本一份乐谱，模式也会回到*完整*。它只适用于从提示词写的歌：翻唱就是其录音的乐谱，纯音乐则需要乐谱来把人声挡在外面。两种引擎都支持。

## 渲染 {#rendering}

### 演绎 {#interpretation}

乐谱决定音符。**演绎**决定它们怎么被演奏。

| 演绎 | 你会听到 |
|---|---|
| 标准 | YuE2 通常的诠释 |
| 紧凑 | 更收敛、更精致 |
| 松弛 | 更粗犷、更随性 |
| 沉稳 | 可以重复一个音型、停留在律动里 |
| 躁动 | 让各声部保持流动，避免重复 |
| 宽广 | 寻找不那么常见的声音 |

### 变奏 {#variations}

卡片上的闪光按钮会用其他演绎渲染**同一份乐谱和同一个种子**。因为只有演绎在变，你在它们之间听到的就是演绎本身——而不是又一次掷骰子。每一个都是独立的版本，标题为
*Night drive · Loose*，保存在它所来自的版本里面（参见“库”中的**版本里的版本**）。窗口有自己的时长上限，初始值取自编辑器的上限，只作用于这些版本。

### 再试几个 {#try-more}

卡片上的骰子按钮会把**同一份乐谱和同一份歌词再渲染成几个新版本**，方便放在一起听。变奏只改变演绎、保留种子；这个则改变掷出的结果：

- <strong>新种子：</strong>每个都用新种子，其余一切不变。
- <strong>规划器强度：</strong>对于用了带规划器半部分的风格 LoRA 的版本，使用同一个种子和其他规划器强度（跳过它自己的那个）。规划器改变的是演奏本身，而不只是人声，所以效果就像换了一个种子。

新版本的标题为 *Night drive · try 1* 或 *Night drive · planner 0.60*，保存在它们所来自的版本里面，该版本的面板会打开，随着它们完成而逐个显示。要把它们互相比较，在面板打开时点击**全选**，再点击**对比**。窗口有自己的时长上限，初始值取自该版本的上限。

### 种子，以及重现一个版本 {#seed-and-reproducing-a-take}

每个版本都会记录它的种子和塑造它的每一项设置。卡片上会列出它们，点击卡片会在版本面板中显示它们，在编辑器中打开则会把一切重新载入。**再来**会用完全相同的内容（包括种子）打开编辑器，用来重现一个你喜欢的版本，或在一个差点让你满意的版本上一次只改一项设置。

在编辑器的菜单里，把鼠标悬停在某个演绎上可以看到它的作用。

勾选**保留此种子**可在多次渲染之间保持同一个种子；不勾选时，每次渲染都会抽一个新的。

渲染使用编辑器所显示的内容：风格、风格 LoRA 及其强度、时长上限、模式、演绎和种子，即使是重新渲染某个版本自己的乐谱也一样。

### 同一旋律，新的歌词 {#same-tune-new-words}

规划器在写下第一个音符之前会读完全部歌词，所以同一个种子只有在歌词相同时才会给出相同的方案。改动一行，下一份方案就是一段新旋律：不同的曲调，常常还有不同的调性和速度，人声也会随之改变。

要保留你喜欢的旋律：

1. 打开版本并修改歌词。歌词下方会出现已勾选的 <strong>保留此旋律</strong>，主按钮变为 <strong>用新歌词演唱</strong>。
2. 先修改其他想改的内容：风格、LoRA 及其强度、时长上限、演绎。保持种子勾选，让声音尽量接近。
3. 按 <strong>用新歌词演唱</strong>。版本的乐谱会用新歌词演唱，作为一个新版本出现在原版本旁边，原版本保持不变。

取消勾选 <strong>保留此旋律</strong>，则改为为新歌词写新的方案和新的旋律。

与原来各行音节数相同的新歌词最贴合旋律。不贴合时，<strong>保留此旋律</strong> 会自动取消勾选，并有一行说明原因，然后为歌词写新的方案。仍想唱这段旋律，就再次勾选。歌词不贴合的情况：

- <strong>段落更多，或音节远多于旋律中的音符：</strong> 把长句放到为短句写的旋律上，会被重复或丢掉。
- <strong>音节少得多：</strong> 把短句放到为长句写的旋律上，会留下多余的音符，歌手会用自己的词把它们填满。

### 制作润色 {#production-polish}

**制作润色**会应用 Mothersuperior 的 Realaudio 解码器 LoRA。原版 YuE2 的中频常常听起来发闷；它能把乐器和人声分得更干净。默认开启。

### 时长 {#length}

时长上限是硬性的天花板，而不是目标。歌曲何时结束由 YuE2 决定，通常它会自己结束；上限只会叫停不肯结束的那首。它从 360 秒开始，或者从设置中**新版本的时长上限**的值开始。之后它会为音乐腾出空间，免得长歌被截断：

- 对于**从提示词写的歌或纯音乐**，写方案时如果方案更长，上限就会提高：提高到方案的时长，再留大约十秒余量。它从不会被降低。
- 选择了**录音**时（用于翻唱或纯音乐），上限跟随录音的乐谱，同样向上取整。

你自己输入的上限会保持你设定的样子，方案比它长时，乐谱页面会说明。

歌曲没有按应有的方式结束时：

- <strong>远远超出上限的方案</strong>（超出三分之一以上且长于八分钟）根本不会被当作歌曲，会被重写。
- <strong>超过乐谱仍继续的渲染</strong> 会一直持续到上限，在最后几秒淡出而不是戛然而止，卡片会说明它达到了上限。
- <strong>在乐谱最后一段开始前就结束的渲染</strong>（更少见）会在算作完成之前用新种子再渲染一次。如果那次也提前停止，卡片会说明它在最后一段之前停了：再按一次 <strong>渲染</strong> 重新尝试。

## 翻唱一段录音 {#covering-a-recording}

1. 拖入一个音频文件，最大 2 GB。它只保存一次并计算哈希，所以同一个文件永远不会保存两次。视频文件（MP4、MOV、MKV、WebM 等）也可以：只保留它的声音，存为 FLAC。
2. 点击**转录**。SheetSage2 会把旋律和和弦写进乐谱框。结果会按录音缓存，所以再翻唱同一首歌时会跳过这一步。
3. 修正它听错的地方。
4. 加上歌词，选一个风格，点击**创建翻唱**。

翻唱遵循原曲的旋律和和弦，其余一切由风格决定，这正是它成为翻唱而不是复制的原因。

### 录一段你自己的旋律 {#recording-a-tune-of-your-own}

> [!NOTE]
> 旋律能被识别得多好取决于录音，围绕它建立的方案仍可能失手或
> 跑偏：写一份新方案，或者重录这段旋律。

在**翻唱**模式下，**录制旋律**会打开录音器。在**输入**中选择你要录的内容：

- <strong>人声：</strong>对着麦克风唱或哼。**自动调音**可以把录音校准到某个调和音阶；录音上的按钮可以在校准版和原版之间切换，让你听到它做了什么。
- <strong>乐器：</strong>用乐器演奏旋律，例如接入音频接口的吉他。**一次一个音**地弹：你弹的线条会成为被演唱的旋律，扫出的和弦则不会产生可以演唱的旋律。在**设备**中选择接口，在**通道**中选择乐器接入的那一侧（接口的输入 1 通常是**左**）。乐器较轻时调高**输入增益**，同时别让电平表进入 CLIP。这里不提供自动修音：乐器本来就是准的。Yeufonic 会在这个浏览器里记住这些选择。

节拍器、倒数和耳机监听对两者都一样。**用于翻唱**会把这段录音保存为录音，在列表中标为 **MIC** 或 **INST**。像任何录音一样转写它；录下的旋律只会被转写为旋律，因为从单独一段旋律猜出的和弦会卡在用它做出的歌的每一段副歌里（在此之前转写过的录音会保留它的和弦，直到重新转写）。十到三十秒的旋律就绰绰有余。乐器录音不提供**提取歌词**，因为里面没有可听的词：请用**写歌词**。

<strong>听到自己有延迟？</strong>浏览器会在你唱或弹的声音与你在耳机里听到的声音之间加入一点延迟。如果你的音频接口有直接监听（零延迟），请使用它，并关闭录音器的**监听**，这样你会直接从接口听到自己，而且只听到一遍。请用有线耳机：蓝牙会加入它自己的延迟。

#### 扩展成整首歌 {#expand-to-full-song}

录下的旋律通常只有几小节长。**扩展为完整歌曲**会让 YuE2 规划一整首歌，把你的旋律放在里面：方案采用你旋律的调性、拍号和速度，每段副歌（如果你选择，也可以是每段主歌）都包含你的旋律，歌曲的其余部分则围绕它来写。然后它会作为你录音的翻唱进行渲染。

- <strong>演唱者：</strong>男声或女声。你的旋律会按整八度移到那个人声演唱的位置，因为旋律写在哪个八度决定了由谁来唱。如果风格没有提到歌手，就会把人声加进去。
- <strong>和弦：</strong>单独的旋律从转写器回来时常常没有和弦。这时 Yeufonic 会根据它自己的音符给它配和弦，让规划器有和声可依。你写进录音乐谱里的和弦会被保留。
- **你的旋律**始终是录音的乐谱，即使编辑器正在显示一个由它做出的版本。
- <strong>歌曲结构：</strong>歌词框为空时使用。框里有文字时，文字中的段落就是结构，并且需要一个 **[Chorus]**（或一个 **[Verse]**）来放你的旋律。
- <strong>歌词：</strong>哼唱可以不带歌词来规划。用乐器演奏的旋律需要歌词才能被唱出来，所以先写歌词：**写歌词**会替你起草。

### MIDI 文件与翻唱 {#midi-files-and-covers}

> [!NOTE]
> MIDI 文件用于为原创旋律生成不同的、常常很古怪的版本。

除了录制的音频文件，你还可以在**翻唱**模式下直接拖入或上传标准 MIDI 文件（`.mid`、`.midi`）。

上传 MIDI 文件时：
- <strong>自动转写乐谱：</strong>Yeufonic 会分析各轨和各通道，找出主唱旋律、伴奏和和弦进行，把它们转写为 ABC 记谱，并直接载入钢琴卷帘。较低音区中的合成器主音或音序人声旋律会自动移调到适合演唱的自然八度。
- <strong>内嵌歌词：</strong>MIDI 序列中内嵌的歌词或文本事件会被提取出来，并对齐到旋律的音节上。
- <strong>小节落在哪里：</strong>MIDI 文件没有自己的小节线，有些文件的第一个词落在强拍*之前*的那一拍上。Yeufonic 会读取鼓和贝斯来找到真正的小节线，当文件以这样的弱起开头时，会把开头的几个词放进一个单独的短小节里，让和弦和小节标记落在歌曲实际的位置上。没有清晰鼓与贝斯型的文件则保持原样。
- <strong>粘贴的歌词：</strong>你粘贴的词会一次性对齐到整段旋律上，每个音符一个音节，多出的音符延续前一个音节。各行在旋律休止处结束、在乐句开始处开始，所以比歌词标题更长或更短的段落不会再把后面的内容挤偏。如果词比旋律能承载的更多，最后几行会被舍去。
- <strong>用 SoundFont 完整试听：</strong>播放器使用 **FluidSynth** 和 General MIDI SoundFont（`.sf2`）把 MIDI 编曲合成为高保真音频。输出会做峰值标准化，让音量较小的多轨 MIDI 录音听起来饱满清晰而不失真。
- <strong>选择 SoundFont：</strong>在**设置**中，可以选择你偏好的当前 `.sf2` SoundFont 音色库（如 *Arachno SoundFont 1.0* 或 *JNS-GM 2.0*）。放进 `data/models/soundfonts/sf2/` 的其他 `.sf2` 文件会被自动识别。
- <strong>在钢琴卷帘中微调：</strong>打开**钢琴卷帘**检查或修改音符，选择哪一轨作为主唱旋律，用**填补空白**为伴奏中的空隙配和声，或用**匹配歌词**对齐刚粘贴的歌词。

### 翻唱语料库中的歌 {#covering-a-song-from-a-corpus}

语料库的分析已经完成了翻唱所需的工作：乐谱、在歌中听到的词，以及分离出的人声。所以在你的录音下方，列表提供了**来自你的语料库**，按语料库折叠，显示每首歌的调性和速度，大的语料库还有筛选框。选一首歌，它立刻就会变成你的录音之一，带着它的乐谱和歌词，什么都不用重新运行。词会被放到乐谱的段落下面，方式与**提取歌词**相同，除非你已经在语料库里审阅过它们，那样它们会以你留下的样子出现。它们会进入歌词框，替换来自另一段录音的词；你在那里输入或编辑过的词，只有在你同意时才会被替换。风格框会得到这首歌在语料库中学习时所用的风格，也就是用它训练的 LoRA 下它那个标签的风格。

磁盘允许时，文件会被链接而不是复制，所以不再占用额外空间，并且在语料库被删除后仍会保留。有些歌标着 *score: melody only* 或 *score: first 4 min*：它们的完整转写在分析时失败了，不过这对训练来说已经足够。点击**转录**可得到带和弦的完整乐谱。

<strong>配合 LoRA。</strong>语料库里的歌在这里最有用：一首歌和一个 LoRA 出自同一批作品，或出自不同的作品。
1. 在**翻唱**模式下，打开录音列表，在**来自你的语料库**中选择这首歌。它的乐谱决定旋律和和弦，它的歌词就在框里。
2. 选一个**风格 LoRA**。语料库自己的 LoRA 会让它的歌手翻唱自己的歌，最接近原曲。另一个语料库的 LoRA 则会用那种风格和那种人声来翻唱。
3. 像任何翻唱一样设置强度：录音已经决定了旋律，所以把**音色**保持在 **0.50** 左右，想要更多 LoRA 的人声和音色就调高它。
4. 风格框里已经是这首歌自己的风格，选择 LoRA 会把它的触发词放在最前面。这样能保留这首歌的流派和氛围；换一个标签，或用筛选框的标签，就能把它带到别处。速度和调性来自乐谱，不管风格怎么写。
5. 点击**创建翻唱**。之后**变奏**会用其他演绎来渲染它，**再唱一次**则会在同一份乐谱上换一种人声，和任何版本一样。

### 提取歌词 {#extracting-the-lyrics}

<em>转录</em> 旁的 <strong>提取歌词</strong> 会写下录音中唱的内容：分离出人声，聆听它，并把各行放到乐谱的段落下面。它按需运行，而不是每次转录都运行，因为乐谱转录只需几秒，它却要花几分钟。

- <strong>在哪里运行。</strong> 引擎有 Demucs 和 Whisper 时在 GPU 上分离人声并听出歌词，否则在 CPU 上（设置中的 <strong>分轨和歌词使用 GPU</strong>）。进度条显示处于两步中的哪一步。GPU 上的 Whisper 和 CPU 上的 Whisper 对同一段人声写出的词并不总是相同，因为两者都不精确：难的人声，比如主唱上叠着和声，可能有五分之一的词不同。
- <strong>再做一次时。</strong> 分离出的人声会被保留，所以从同一录音再次提取会直接从聆听开始，省去大部分等待。
- <strong>歌词随录音保存。</strong> 再按一次 <strong>提取歌词</strong>，歌词会立即回到框中，并询问是否重新提取，在设置中更换方法之后值得这样做。选择另一个录音会同样带入它的歌词，而选择没有歌词的录音会清除前一个的。你输入或修改过的歌词会保留，除非你同意替换。

把它当作一份好草稿，而不是逐字稿。与两首歌的真实歌词相比，Whisper 在一首中错了 <strong>1.5% 的词</strong>，在另一首中错了 <strong>25%</strong>，后者在最后一段副歌里主唱与和声重叠。它会聆听全部人声：以前它跳过人声检测器认为是静音的部分，而在演唱的人声里，那是歌曲的大部分。读一遍草稿，改正它听错的地方，尤其是声音重叠的地方。

<strong>让外部 LLM 来听。</strong> 如果你的提供商是 [外部 LLM](#external-llm)，设置中的 <em>从录音获取歌词</em> 下有一个选项。设为 <strong>外部 LLM</strong>，分离出的人声会发送给模型去听出歌词，而每行何时唱出仍由 Whisper 决定。

- 它需要能接收音频的模型，比如 Gemini。在同样的两首歌上，Gemini 得到 <strong>1.5% 和 23%</strong>，所以两者接近；在 Whisper 吃力的歌上两者都试试。
- 当模型的回答看起来像歌词时，就使用它的词，即使与 Whisper 的词差别很大：埋在混音里的人声是 Whisper 最难处理的，模型却不然。
- 如果模型拒绝音频、有所保留（截短各行，或把你引向歌词网站，模型对它认出的歌可能这样做），或几乎什么都没返回，你会得到 Whisper 的版本。
- 完成时的消息会说明是谁听出的歌词。
- 这样做时人声会离开你的电脑；Whisper 则把它留在这里。

<strong>语料库中的歌两种版本都会保留。</strong> 两者都有时，歌曲的审阅面板会显示 <strong>词来自</strong>，列出每个版本及其字数；默认使用外部模型的版本。选择另一个，它的歌词就会进入框中。第一次选择某个版本时，会为它起草歌词，并用外部模型标注段落；之后每个版本都有自己的歌词、修改和 <strong>已检查</strong> 勾选，所以切换是即时的，也不会调用模型。在 Whisper 自己的行中，任何连续重复超过八次的词，比如被写了几百次的拖长的 “la”，会被缩减为八次。

## 纯音乐 {#instrumentals}

第三种模式写没有人声的作品。它接受的不是歌词，而是一个**结构**：

| 结构 | YuE2 收到什么 | 由谁决定 |
|---|---|---|
| 让 YuE2 决定 | `[instrumental]` | YuE2 选择段落及其长度 |
| 段落 | `[intro] [verse] [chorus] …` | 你选择段落，YuE2 决定长度 |
| 定时段落 | `[intro 0:00-0:15] …` | 两者都由你选择 |

用 **+** 标签添加段落，用箭头重新排序，在定时模式下给每段设定时长。<strong>发送给 YuE2：</strong>会准确显示模型收到的内容。结构只是参考：YuE2 可能会给某个段落改名、加一段间奏，或超出你给的时间，所以时长上限才是硬性的天花板。

### 来自录音的纯音乐 {#an-instrumental-from-a-recording}

编辑器顶部的<strong>来自录音（可选）</strong>会取用你的一段录音，就像翻唱那样。它的转写就是乐谱，所以不需要写方案，渲染会用器乐 LoRA 演奏它的旋律和和弦。

段落也来自乐谱：乐谱的每个段落对应一个，并使用 LoRA 认识的名称（<em>间奏</em> 变成桥段）。渲染会把结构的每个段落与乐谱的一个段落配对，所以结构搭建器为它们让路。

<strong>重新编排歌曲。</strong> 每次改动都会重写乐谱（乐谱窗口会显示）：

- 把段落拖到新位置，或用箭头移动它。
- 在段落后紧接着添加它的 <strong>副本</strong>。
- 用 <strong>✕</strong> 删除一个段落。
- <strong>恢复原来的段落</strong> 会恢复它们，直到载入另一份乐谱为止。

<strong>跟随播放。</strong> 版本在编辑器中播放时，当前所在的段落会亮起，双击一个段落就会跳到那里。时间来自乐谱的小节和速度，渲染在版本开头以及完整渲染的版本中会紧密跟随。比乐谱早很多结束的渲染演奏的音乐比乐谱少，所以列表可能随着歌曲推进与声音错开；列表下方的一行会说明这一点，以及差多少。

<strong>歌词与时长。</strong> 翻唱在歌词下方显示同样的列表，歌词按顺序与段落配对，所以要相应修改：添加、删除或重新排列段落后，列表会说明它们需要什么。列表还会显示总时长与时长上限的对比，当更长的歌曲会被截断时，会提议提高上限。按 <strong>创建纯音乐</strong> 进行渲染。

从结构写出的纯音乐也有乐谱，规划完成后，它的段落会以同样方式列出。结构搭建器是对一份尚未写出的方案的委托，所以它会给列表让位。重新排列段落后点击**渲染此乐谱**：渲染的段落标签会跟随编辑后的乐谱。已有音频的版本会被渲染为旁边的新版本，无论你改了什么，所以原版本会保留它自己的。**写新方案**（在乐谱下方）仍会根据写出这个版本时所用的结构，请求一段不同的旋律。

<strong>带人声的歌也可以。</strong>它的乐谱把演唱的旋律写在人声声部里，那样会被唱出来，所以旋律会交给一件乐器：在没有乐器演奏的地方，演唱的音符会移到乐器上，人声声部只保留它的和弦。编辑器会在录音下方说明这一点。对一首歌来说，这往往是更好的选择：没有人声时，转写器容易丢失主歌和副歌之间的区别，把整首歌听成一个和弦循环。LoRA
会把它编成纯音乐，所以会有它自己的声部，比如多出来的吉他。

在列表中选择**无录音：写乐谱方案**，就会回到写方案。

### 纯音乐唱了起来 {#when-an-instrumental-sings}

模型偶尔会在纯音乐里塞进人声。这是模型的毛病，不是你设错了什么。渲染前，如果方案在人声声部放了音符，会弹出一个对话框，提供新方案、新种子，或照样渲染。已完成的版本不会被检查：请听一听。

### 用歌曲的乐谱做纯音乐 {#an-instrumental-from-a-song-s-score}

在编辑器的乐谱页面里，歌曲或翻唱的乐谱下方（歌曲则在**渲染此乐谱**旁边）的**生成纯音乐**，会把同一份乐谱做成纯音乐，放进一个新版本：原版本保持不变。演唱的旋律会移到一件乐器上，发给模型的只是乐谱的段落标签而不是歌词，会使用器乐 LoRA，风格里描述人声的标签（“soft male vocal”）也会被去掉。这就是得到“这段旋律，不带人声”的办法。手动清空歌曲乐谱中的 Vocal 声部是不够的：歌曲的渲染仍会唱它收到的词。

## 人声 {#voices}

**人声**标签通过写入风格来设定歌手的性别和特质，作用于整首歌。

要做二重唱，或者主歌一位歌手、副歌另一位，就在歌词里加上人声提示并勾选**声部遵循提示**：参见“从提示词写一首歌”中的[歌词](#the-words)。它也适用于翻唱的歌词。

## 语料库与训练 LoRA {#corpora-and-training-a-lora}

**语料库**是一个歌曲文件夹，被整理成风格 LoRA 的训练集：通常是一位艺人、一种流派，或几位相近的艺人。从菜单中打开**语料库**。它默认开启；为应用设置 `TRAINING_ENABLED=0`，或用
`WITH_TRAINER=0` 构建引擎，就会去掉它。

<strong>训练需要什么。</strong> 训练是应用要做的最吃资源的事：

- <strong>推荐的全质量模型（BF16）</strong> 至少需要约 12.5 GB 显存（截取 3½ 分钟时；截取更长需要更多），大部分用在准备歌曲的时候。所以 16 GB 的显卡是实际的最低要求，另加 32 GB 的系统内存：ComfyUI 会把完整的 YuE2 权重和数据集缓存放在主机内存中（在 WSL2 中，在 `.wslconfig` 里设置 `memory=32GB`）。
- <strong>低显存模型（INT8）</strong> 可以让 8 GB 的显卡进行训练。
- <strong>无法训练的显卡</strong> 仍然可以使用在别处训练的 LoRA（<strong>安装 LoRA</strong>）。
- 空闲显存或系统内存不足时，训练窗口会给出警告，所以请先关闭其他所有使用 GPU 的程序。

<strong>步骤：</strong>

1. <strong>新建语料库。</strong> 给它一个名字和一个 <strong>触发词</strong>，说明人声是男声还是女声（没有人声的歌选 <strong>无</strong>：见下文），描述所有歌曲共有的声音，并打开存放它们的文件夹。确认你有权用它们训练，然后点击 <strong>扫描文件夹</strong>。文件夹只会被读取。

   <strong>没有人声的语料库。</strong> 当歌曲是纯音乐时，比如舞曲和电子音乐，在 <strong>人声</strong> 中选择 <strong>无</strong>：

   - 应用不会分离人声也不会听词，所以不会有东西在合成器上编出歌词。
   - 每首歌的歌词就是其乐谱里的段落标签（没有的话就是 `[instrumental]`），描述会略去人声部分，也没有歌词审阅：<strong>段落</strong> 框可以编辑，编辑会被保存。
   - 每首歌的声音由本地模型描述（若已安装），因为外部模型只能依据一个标题。
   - 这样训练出的 LoRA 可能会在方案的人声声部写入音符，让渲染唱出或哼出声来；方案的“可能会唱”警告会显示这一点。
   - 更改已分析语料库的人声设置，会相应地改变它的歌词。
2. <strong>选择歌曲。</strong> 取消勾选你想排除的歌。
   - 准备一首歌时，应用会把完整录音的副本保存到语料库的内部存储里，所以即使源文件夹之后被清空或移动，语料库也会保持完整。
   - 超过 25 分钟的录音会被排除，因为它多半是整张专辑或一场演出被存成了一个文件。如果旁边有 `.cue` 文件，<strong>拆分为曲目</strong> 会把它切成各首歌，替代它在语料库中的位置。这些曲目会放进应用自己的文件夹；你的文件夹不会改变。
   - 比训练器的 GPU 上限更长的歌，比如 15 分钟的曲目，在导出时会被安全地截断，并在一个音乐段落的边界处淡出。
3. <strong>分析。</strong> 每首歌的人声会被分离，调性、速度和段落会被找出，歌词会被起草并按段落标注。
   - 设置中配置了外部 LLM 时，段落会根据听到的词来标注：副歌因为词会重复，新段落则依据停顿。只发送各行及其时间，词和词的顺序永远不会被改动。没有外部 LLM，或它的回答没有包含所有行时，标签来自音乐分析。
   - 在一首歌的审阅中，“保存”旁的 <strong>重新起草</strong> 会用同样的方法重新标注段落而不重新聆听这首歌，适用于之前起草过的歌，并会替换框中的内容。
   - 按钮下方的一行说明正在运行什么，进行中的分析会显示在主屏幕的任务卡片和队列中。<strong>停止</strong> 会停止它。已完成的步骤会被保留，所以 <strong>分析</strong> 会从停下的地方继续。
   - <strong>重新分析。</strong> 所有歌都分析完后，按钮会显示 <strong>已分析 ✓</strong>。点击它会询问你是否要用最新的提示词和 LLM 设置重新分析所有歌曲的风格建议（在重命名语料库或更换提供商之后很有用）。按住 Shift 点击 <strong>已分析 ✓</strong> 会提供从头开始的完整重新分析（再次进行分轨分离、调性、速度、转录和风格）。每首歌也可以在它的审阅中通过 <strong>重新分析</strong> 单独重做。
4. <strong>检查。</strong> 打开一首歌，审阅它的歌词并勾选 <strong>已检查</strong>，并在它的声音与其他歌不同时加以描述。风格描述显示训练器将读到的内容。
5. <strong>导出训练集。</strong> 写出每首歌的音频、歌词和描述。按钮下方的一行显示进度。
   - 训练器只取每首歌的一部分，这部分由应用根据你显卡的空闲显存算出（16 GB 显卡上大约 5½ 分钟；日志窗口会说明选择了多少）。
   - 更长的歌会在这个范围内最后一个段落的结尾处截断、淡出，并只保留仍在演唱的词。它那一行会显示“first 3:12 trained”。
   - 如果训练显存不足，把环境变量 `TRAIN_MAX_MINUTES` 设得更小，比如 3.5：见 README。
6. <strong>训练 LoRA。</strong> 这需要很长时间，训练结束前应用无法使用 GPU。
   - 进度显示在按钮下方和主屏幕上，可以在那里停止，训练期间页面顶部的语料库徽章会闪动。
   - 重新训练时，上一次运行的 LoRA 可以以带日期的名称保留在 <strong>先前的运行</strong> 中，也可以删除，由你选择。

### 提前结束的运行 {#a-run-that-ends-early}

一次运行可能在最后一步之前结束：<strong>停止</strong>、崩溃，或 GPU 显存不足。这时按钮下方的一行会说明何时、为何结束，以及在哪一步之后。工作的大部分通常都还在：训练器在过程中每 50 步保存一个检查点，并保留一份按规划器损失计算至今最好的副本。

- <strong>用已保存的内容完成</strong> 会用这些文件做完成的运行所做的事：最好的副本，没有的话就是最后一个检查点，成为带有语料库名称和触发词的 LoRA，检查点则折叠在风格 LoRA 列表中它的下面。这只需几秒，不占用 GPU 时间。
- 一次运行的最后几步对 LoRA 的改变最小，所以这样完成的 LoRA 通常接近完整运行；想用耳朵比较时，<strong>检查点</strong> 会在每一步各渲染一次这首歌。
- 要改为重新训练整个运行，按 <strong>训练 LoRA</strong>。

### 全部运行 {#run-all}

三个按钮旁边的 <strong>全部运行</strong> 依次执行分析、导出和训练，适合你不想守着的语料库：大的语料库要分析好几个小时。它会先询问如何处理以前的 LoRA，然后在页面关闭后继续。

- 只分析仍需分析的内容。分析失败的歌会被排除在训练集之外，并在按钮下方列出名字；没有人检查过的歌词按草稿使用。
- 训练前，如果已有任务在使用引擎，它会等待引擎空闲。
- <strong>停止</strong> 会在当前位置停下，保留已完成的部分；在导出时停止的话，会先完成训练集。
- 重启应用会停止它，再次点击 <strong>全部运行</strong> 会继续。

### GPU 显存用尽时 {#running-out-of-gpu-memory}

显存不足的任务会说明这一点，并给出可以尝试的办法：关闭其他使用 GPU 的程序、降低时长上限，或者（对于训练）排除最长的歌。如果引擎崩溃并重启，正在运行的任务会丢失，这一点也会说明。

### 训练好的 LoRA {#the-trained-lora}

训练完成后，LoRA 会带着它的触发词出现在 <strong>风格 LoRA</strong> 列表中。

- <strong>它的歌曲。</strong> 选中它时，风格框下方会为它学过的每首歌显示一个标签，点击会把那首歌的风格放入框中。歌曲超过十几首时，一个筛选框和一行在语料库中反复出现的标签（它的流派、情绪和乐器）可以缩小范围；点击两个标签可以找出两者都有的歌。在按 <strong>全部显示</strong> 之前，列表只显示前十二首。
- <strong>起始强度：</strong> 见下文的 <strong>平衡规划器与音色</strong>。
- <strong>分享：</strong> 按语料库页面上的 <strong>下载 LoRA</strong>，或选择器下方的 <strong>下载</strong>；见下文的 <strong>分享 LoRA</strong>。
- <strong>别人的 LoRA：</strong> 按 <strong>新建语料库</strong> 旁的 <strong>导入 LoRA</strong>，选择它的 zip。
- <strong>用导出的训练集在别处训练的 LoRA：</strong> 按 <strong>安装 LoRA</strong> 并选择文件。它会带着这个语料库的触发词加入风格 LoRA 列表。

**删除语料库**会删除应用为它的歌曲做的副本、分离出的人声、歌词和乐谱。你指定的文件夹，以及用它做出的任何 LoRA，都不会被动到。

## 风格 LoRA {#style-loras}

LoRA 是一个小文件，能让模型偏向某种声音。把它放进 `models/loras/`，然后点击选择器下方的**重新扫描**，或使用**安装**，它就会出现在**风格 LoRA**列表中。

风格 LoRA 可以有两个半部分，选择器会显示一个文件具备哪些：

- **规划器**塑造演奏的内容——乐谱方案（结构、和声、乐句），以及之后渲染根据这份乐谱写出的音乐。它在两个步骤中都起作用。
- **音色**塑造音频——音色和制作。

文件无法使用的强度会显示为灰色，而这个引擎根本无法加载的文件会被标记出来，而不是在渲染中悄无声息地失败。

### 在哪里找到风格 LoRA {#where-to-find-style-loras}

最快的办法是在安装时：在安装程序的组件页面勾选**风格 LoRA**（使用 Docker 时，运行
`sh scripts/fetch-models.sh --loras`）。这会从作者那里下载 39 个风格 LoRA，共 3.8 GB，每个都附有一段说明，给出它的触发词和建议强度：包括下面这些合集、atomtanstudio 的两个（dream pop
和 old school hip-hop），以及 ntc-ai 的十六个概念滑块，它们只塑造乐谱（音色不起作用，也不需要触发词）。它们原封不动地收集在
[pshields/yue2-style-loras](https://huggingface.co/pshields/yue2-style-loras) 中，其 README 注明了每位作者并链接到原始页面。你的文件夹里已有同名的 LoRA 会保持原样。

Hugging Face 上还有更多。以下是收集在那里的合集，各自位于作者的页面上：

- [Militant reggae](https://huggingface.co/becausereasons/yue2-mltnt-militant-reggae)
- [Chanson française](https://huggingface.co/becausereasons/yue2-chnsn-chanson-francaise)
- [Canzone italiana](https://huggingface.co/becausereasons/yue2-cnzn-canzone-italiana)
- [Bulgarian voices](https://huggingface.co/becausereasons/yue2-blgr-bulgarian-voices)
- [Qawwali, sufi and tabla](https://huggingface.co/becausereasons/yue2-qwwl-qawwali-sufi-tabla)
- [J-pop](https://huggingface.co/storagejuju/yue2-jpop-t4-lora)，一个只有音色半部分的 LoRA

要添加其中一个，从仓库的 **Files** 标签页下载它的 `.safetensors` 文件，放进 `models/loras/`
并点击**重新扫描**，或者点击**安装**并选择该文件。仓库页面给出了每个 LoRA 的触发词和建议强度：把它们写进文件旁边的一个 `.txt`（参见下文的**说明**），选择器就会显示它们，并替你把触发词放在风格的开头。来自别处的 LoRA
可能以这个引擎无法加载的格式保存：选择器会把它标记出来，它也不会造成任何损害。

每个 LoRA 都带有作者的许可证，这些合集标明为 CC BY-NC 4.0：仅限个人、非商业用途，和 YuE2 的权重本身一样。在使用某个 LoRA 或分享它生成的内容之前，请先在它的页面上阅读许可证。

### 平衡规划器与音色 {#balancing-planner-and-sound}

- <strong>风格统一的语料库：</strong>用单张专辑或统一的原声音色（例如六十年代的民谣摇滚）训练的 LoRA 可以承受更高的强度，通常在**规划器 ~0.85 / 音色 ~0.80** 左右。
- <strong>风格多样的语料库：</strong>如果训练语料库跨越多种流派、制作风格或年代（例如原声民谣、摇滚和合成器流行），较高的音色权重可能造成声音上的冲突。大约到**规划器 0.70 / 音色 0.70** 时，音频仍保持干净，同时保留艺人的旋律乐句和嗓音特点。
- <strong>翻唱：</strong>你的录音决定了旋律，所以 LoRA 要塑造的东西更少，音色半部分会被推得更用力。把音色保持在 **0.50** 左右。
- <strong>方案多样性：</strong>使用从语料库训练出的 LoRA 时，**平静**或**常规**给出的结果最容易辨认。**平静**在搭配风格 LoRA 和简短风格时可能陷入循环，方案会因此长达好几分钟，充满重复的长前奏，或者完全没有演唱。把风格描述得更详细些（流派、乐器和感觉），或者使用**常规**。这样的方案，或比一首歌长得多的方案，会用新种子重写一次，如果第二次结果相同，这个版本会失败并附上提示。
- <strong>找到好的版本：</strong>LoRA 的特点既取决于强度，也同样取决于掷出的结果。在大约 0.3 到 0.6 之间，**音色**对人声的改变很小，所以不必调高它。**规划器**改变的是演奏本身，而不只是人声，所以对某首歌合适的数值，对另一首可能是最弱的。像对待种子一样对待它：试几个数值（例如 0.6、0.8 和 1.0），再用**再唱一次**试几个种子，留下你喜欢的版本。
- <strong>保存强度：</strong>为某个 LoRA 找到合适的一对数值后，点击选择器下方的**保存强度**。之后选择这个 LoRA 时就会从这组数值开始，而且你分享它时，它们也会随之而去。

### 触发词 {#trigger-words}

大多数风格 LoRA 训练时用的描述都以一个触发词**开头**，没有它就几乎不起作用。应用会处理这件事：选择一个 LoRA 会把它的触发词放在风格的开头，换成另一个会替换它，选择“无”会删除它，如果它被擦掉了，渲染时也会把它放回去。你会看到这个词出现在风格框里——可以编辑它，也可以移动它。

### 说明 {#descriptions}

列表按合集分组。点击标题可以展开或折叠；选择器会记住你哪些保持展开，包含你当前选择的那一组总会随之展开。

把鼠标悬停在某一项上，可以读到它是什么（用作者自己的话）以及建议强度。这些说明来自 LoRA 旁边的一个文本文件：

```
CHNSN Rive Gauche
Trigger: chnsn
Step 200, the decoder-loss minimum. The more supple of the two: acoustic
narrative, yé-yé, female leads, waltz meters.
```

第一行给出名称，`Trigger:` 那一行成为触发词，其余部分就是说明。你自己的 LoRA 只要在旁边写一个 `.txt` 也会有说明。同一文件夹里的 `families.txt`
为各组提供标题，每行一个 `prefix = label`。

### 从语料库训练出的 LoRA {#loras-trained-from-a-corpus}

用你的某个语料库训练出的 LoRA 就是一个普通的风格 LoRA：它和其他 LoRA 一起出现在这个列表中，旁边带着它的触发词，同样适用这两种强度。

### 试用检查点 {#trying-the-checkpoints}

一次训练运行每 50 步保存一个检查点：每个都是训练进行到那一刻时的 LoRA。它们听起来差不多一样好，但各自对学到的东西有不同的侧重，所以在 LoRA 训练出的同一风格和标志性声音上，各有不同的韵味。

<strong>它们在哪里。</strong> 它们放在选择器中所属 LoRA 的下面：LoRA 名称旁的 <strong>▸ 9 步</strong> 会展开它们（设置也可以改为删除它们以节省空间）。LoRA 被删除的检查点会留在 <strong>训练检查点</strong> 下。

<strong>清理一些。</strong> 按语料库的 <strong>编辑</strong>：那里的 <strong>训练检查点</strong> 列出本次和以前每次运行的检查点及其大小。勾选不要的，然后按 <strong>删除</strong>。完成的 LoRA 不在列表中；它有自己的 <strong>删除 LoRA</strong>。

<strong>并排试听：</strong>

1. 选择 LoRA，像做一个版本那样设置好编辑器。
2. 按 <strong>删除 LoRA</strong> 旁的 <strong>检查点</strong>（没有检查点的 LoRA 上它是灰色的）。
3. 勾选你想要的步数，可以为这些版本设定时长上限，然后按 <strong>渲染</strong>。

编辑器自己的操作会在每个检查点上各运行一次，全部使用同一个种子，每个版本以它的步数命名：<em>Night drive · step 250</em>、<em>Night drive · full</em>。它们存放在编辑器中打开的版本里，如果是新歌，则存放在其中最后一个里（见“库”中的 <strong>版本里的版本</strong>）。编辑器会关闭，你回到正在生成版本的库。歌曲或纯音乐会先写出方案，然后直接进行渲染。

在歌曲或纯音乐中，LoRA 除了塑造声音，还会写旋律，所以同一个种子不会得到同一首歌：每个检查点都会写出自己的旋律和结构。种子是在模型认为可能的选项中做选择，而每个检查点从第一个音符起就想得稍有不同，所以几小节之内方案就会分道扬镳。剩下的是声音。若只想比较声音，用**乐谱**载入一份方案，再依次用每个检查点点击**渲染此乐谱**。

引擎重新查看 `models/loras/` 之后，新文件才会出现，它会在选项重新载入时这样做。

### 分享 LoRA {#sharing-a-lora}

选择一个 LoRA，点击选择器下方的**下载**：你会得到一个包含该 LoRA 及其说明的 zip。对于从语料库训练出的 LoRA，说明里带有它学到的风格，所以标签也会随之而去。

要添加别人发给你的 LoRA，点击**安装**并选择它的 zip，或一个单独的
`.safetensors` 文件。它会进入 `models/loras`，归在**已安装**标题下，带着名称、触发词和标签。**删除 LoRA**会删除所选的 LoRA、它的说明和它的分组行；**重新扫描**会在你手动添加文件后重新读取文件夹。

## 分轨 {#stems}

在任何版本上点击**分轨**。选择一个模型，勾选你想要的部分——人声、鼓、贝斯、其他，某些模型还有吉他和钢琴——然后运行。

引擎有 Demucs 时，分离在 **GPU** 上进行，作为引擎队列中的一个任务：它会等待正在进行的渲染，然后很快完成，排在它后面的渲染则依次等待。在此之前构建的引擎、正在训练的 LoRA（它占用 GPU）、设置中把**用 GPU 处理分轨和歌词**设为“否”，或 `STEMS_ON_GPU=0`，都会让它留在 **CPU** 上，CPU 更慢，但永远不会拖慢渲染。*精细*会连续运行四个模型以获得更好的分离，耗时大约是四倍。

要做伴奏轨，选择**人声与乐器**。它把歌曲一分为二：人声，以及**乐器**——其余一切合成一个分轨。取消勾选**人声**就只保留乐器。这和四轨分离是同一个过程，只是重新加在一起，所以耗时相同，听起来同样干净。*精细*版本留下的人声残留最少。

分轨保存在 `data/stems/<title>-<id>/`，可以通过卡片上的标签播放，可以逐个下载，也可以打成
zip 下载。它们会一直保留，直到你删除。

## 停止、删除和重新开始 {#stopping-deleting-and-starting-again}

引擎正在做什么，显示在顶部栏中名称旁边：一个胶囊标签，带着任务、它的耗时、底部一条表示进度的线，以及后面还有多少任务在等待。任务开始或结束时，页面上其他什么都不会变。点击它可以打开任务卡片：当前阶段、**停止**，以及**接下来**（等待中的任务），每个都带有**取消**。

排队中或进行中的版本会在卡片上显示**取消**，任务卡片上的**停止**会停止引擎正在做的事。任务卡片上、它的**接下来**列表中，或页面底部播放器中的版本标题，都会带你去到这个版本：去到它的空间，并清除任何把它隐藏的搜索或筛选。删除一个版本会停止它的任务并删除它的分轨。录音旁的**删除**会删除文件及其分轨；由它做出的翻唱会保留各自的音频和乐谱，但无法再重新渲染。

版本面板中的<strong>+ 歌曲</strong>、**+ 翻唱**和<strong>+ 纯音乐</strong>，或编辑器标题旁的**新歌曲**，会从当前显示的版本重新开始。它们会清空标题、歌词和乐谱，并从默认值开始：空的风格（若选了 LoRA 则带有它的触发词）、通常的时长上限、和声“多样”、常规的方案多样性、演绎“宽广”、制作润色开启、标准化关闭，以及一个新的、未锁定的种子。已选的 LoRA 和已选的录音保持选中。当前显示的版本会脱离编辑器，免得“渲染”误作用于它。

你输入过但没用上的词不会被扔掉：会有一个提示条提议恢复它们。

## 库 {#the-library}

### 空间 {#spaces}

版本存放在 <strong>空间</strong> 里：一首歌一个空间、一张专辑一个空间，或用于草稿的空间。版本上方的空间名称就是当前显示的空间，你做的一切都会进入那里。

- <strong>选择空间：</strong> 点击名称打开空间列表。输入名称的一部分来查找，或用方向键和 Enter 选择。最近用过的五个排在最前，然后是所有空间，每个都标有其中的版本数。
- <strong>新建空间</strong>、<strong>重命名此空间</strong>、<strong>导入版本</strong> 和 <strong>删除此空间</strong> 位于列表底部。删除空间永远不会删除版本，它们会移到 Default。
- <strong>移动版本：</strong> 卡片上的文件夹按钮会把这个版本连同它里面的版本移到另一个空间。
- 录音在所有空间中共享，所以一个录音可以在多个空间中翻唱。

### 版本里的版本 {#takes-inside-a-take}

**变奏**、**再试几个**和**检查点**都会为一首歌生成多个版本。它们会被保存在它们所来自的那个版本**里面**，这样空间里列出的是你的歌，而不是每首歌的每一次渲染。
Checkpoints 是在编辑器中点击的：如果那里打开着一个版本，它的版本就放进那个版本里；如果是还没有版本的新歌，则由最后一个勾选的检查点的版本（已完成的 LoRA，若它在其中）来包含其他版本。

- 当一个版本包含版本（已完成或仍在进行）时，卡片顶部的小按钮中会出现**内部按钮**，并**亮起橙色**。把鼠标悬停在上面可以看到已完成多少、还剩多少。卡片本身也明显比其他卡片更亮（在浅色主题中是一种暖色调），让含有版本的版本在列表中一目了然。（旁边的母带处理架按钮在版本经过母带处理时会以同样的方式亮起绿色。）
- **点击它**，卡片下方会打开一个面板，列出它包含的版本，每个都有自己的卡片。版本完成后才会出现在那里；生成期间，只显示它所属的那个版本。再点一次按钮，或点击**关闭**，即可关闭。
- <strong>版本里的版本也是普通的版本。</strong>可以播放、加星标、保存、分离成分轨、重命名，双击可打开它的歌曲和乐谱。
- <strong>只有一层。</strong>版本里的版本不再包含版本，所以它的卡片上没有变奏和再试几个，而它在编辑器中打开时，**检查点**会变灰。**移出**（从盒子里伸出的箭头）会让它成为空间列表中的独立版本，之后就可以了。
- <strong>列表工具跟随面板。</strong>面板打开时，**全选**、**星标**、类型按钮、**对比**、**删除**以及播放器的上一首和下一首都作用于面板里的版本。面板打开的那个版本会一直留在页面上，不管筛选怎么设。
- <strong>里面在播，外面看得到。</strong>如果在面板里某个版本播放时关闭面板，包含它的那个版本的播放按钮会发出金光，让你看出声音从哪里来。绿色仍表示正在播放的就是那个版本本身。
- **搜索能找到它们**，和找其他版本一样，不管它们在哪里。搜索期间，找到的内容会以简单卡片显示，位于另一个版本里的版本会注明在哪一个里。
- <strong>删除一个版本会删除它包含的版本。</strong>警告中会说明有多少。想保留的，请先取出来。

在此功能出现之前做的版本留在原处，在列表中并排摆放。

### 卡片 {#cards}

每张卡片都列出塑造它的设置——和声、演绎、录制的音色、方案多样性、LoRA 及其强度、种子、渲染它的引擎以及它有多新——所以一张卡片读起来就像做出它的配方。标题总是保持在一行内，过长时以 … 结尾；把鼠标悬停在卡片的标题、设置或风格上可以读到完整内容。

<strong>保存</strong> 会询问以什么格式下载这个版本。它从你上次保存的格式开始，第一次则什么都不选。

- <strong>FLAC、WAV 或 MP3：</strong> 音频。
- <strong>视频</strong>（带图片的版本）：一个显示其卡片图片的歌曲 MP4（H.264 视频，192 kbps 的 AAC 音频）。像 WhatsApp 这样的即时通讯应用会把它当作视频来发送和播放，而音频文件则会作为文档发送。
- 旁边的 <strong>版本</strong>：版本的配方，一个小文件（`<title>.yeufonic.json`），包含它的歌词、风格和乐谱、种子和设置、按名称记录的 LoRA 以及母带处理架的设置，但不包含音频。如果同时选了格式，两者会打成一个 zip；再点一次所选格式，就只保存配方。这个文件不包含你安装环境中的任何内容（没有路径、ID 或密钥），所以可以留存，也可以分享给其他 Yeufonic 用户。
- 母带处理架开启时，每种格式都使用经过母带处理的声音。

空间列表中的 <strong>导入版本</strong> 会从这样的文件在当前显示的空间中新建一个版本；把文件拖进库也一样。这个版本包含方案，可以直接渲染，所以你可以先审阅或修改。

- 两种引擎都能渲染它：同一份乐谱和同一个种子在同一个引擎上会给出非常相似的版本，在另一个引擎上则不同。
- 它提到的、但这里没有安装的 LoRA 会在导入时被标出，方便你安装它或在渲染前换一个。
- 翻唱的录音不在文件里，所以分享来的翻唱会以歌曲的形式到来，带着翻唱的乐谱和歌词，而属于它录音的设置（锁定的速度、和声、人声提示和时长上限）会被留下：从它写出的新方案会像从提示词写的歌那样开始。

<strong>搜索版本</strong> 会找出那些你输入的所有词都出现在标题、风格、歌词或 LoRA 名称某处的版本，不区分大小写。它在当前显示的空间里搜索；你一开始输入就会出现在旁边的 <strong>所有空间</strong> 会搜索所有空间，来自其他空间的卡片会注明来自哪个。× 或 Esc 会清除搜索。每次打开页面时这个框都是空的，并会提供你最近找到过结果的搜索：点击其中一个，或用方向键和 Enter 选择。

<strong>显示什么、怎样显示：</strong>

| 控件 | 作用 |
|---|---|
| <strong>歌曲</strong>、<strong>翻唱</strong>、<strong>纯音乐</strong> | 显示这些类型的版本：打开一个或多个，或都不选以显示所有类型。 |
| <strong>星标</strong> | 只显示加了星标的版本；再点一次显示全部。 |
| 布局图标 | 更宽的 <strong>宽松</strong> 卡片（显示更多提示词）或更窄的 <strong>紧凑</strong> 卡片；占满窗口的 <strong>全宽</strong> 或居中的一栏；把每个版本 <strong>折叠</strong> 到标题行。正在使用的会亮起绿色；把鼠标悬停在图标上可以读到点击它会做什么。 |

版本折叠时，卡片右上角的按钮只展开这一张卡片，点击它外面的任何地方会再次折叠。有分轨的折叠卡片会显示 <strong>分轨</strong> 标记，同样会展开它。

<strong>选择版本。</strong> 勾选版本后，这一行会改为提供可以对它们做的操作，取代类型和布局：已选多少个、<strong>对比</strong>、<strong>删除</strong> 以及取消勾选的 <strong>完成</strong>。行尾的 <strong>全选</strong> 会勾选每个显示的版本。

### 每个版本的一张图片 {#a-picture-for-each-take}

每个新版本都会得到一张这首歌的图片。

- <strong>在哪里显示：</strong> 淡淡地显示在版本卡片后面，选中它时显示在版本面板的顶部，版本在编辑器中打开时显示在编辑器后面。
- <strong>何时生成：</strong> 在这台电脑上绘制时，它会等到没有歌曲在生成时才进行，所以永远不会拖慢方案或渲染，并在歌曲完成后不久出现。由外部 LLM 绘制时，它会在版本渲染期间完成。
- <strong>如何生成</strong>，分两步：版本的标题、风格和开头的词会变成对一张图片的 <strong>描述</strong>，然后一个图像模型在白底上把它 <strong>画</strong> 出来，再去掉白色，留下一张透明背景的图片。
- <strong>在另一个版本里做出的版本</strong>（再试几个、变奏、检查点）会显示它所在那个版本的图片，而不是有一张自己的。
- 图像模型不会画真实的乐队或人物，所以描述中会略去名字；图片自身的文字会保持柔和，免得和卡片上的文字抢风头。

#### 两种绘制方式：这台电脑上的 FLUX.2 klein，或外部 LLM {#two-ways-to-draw-flux-2-klein-on-this-pc-or-an-external-llm}

图片需要某个会画画的东西。有两种，你可以有其中一种、两种都有，或者都没有。

| | 这台电脑上的 FLUX.2 klein | 你的外部 LLM 的图像模型 |
|---|---|---|
| 是什么 | 一个在引擎里、与 YuE2 并排运行的小型图像模型 | 提供商自己的图像模型，比如 Gemini 的 |
| 花费 | 免费；大约 8 GB 磁盘空间 | 每张图片都是对提供商的一次请求，可能会收费 |
| 什么会离开电脑 | 什么都不会：描述由这台电脑上的 Gemma 写，或从版本本身生成 | 版本的标题、风格和开头的词，以及描述 |
| 何时运行 | 在没有歌曲生成时使用 GPU：在你的歌之后，绝不挡它的路 | 与渲染同时进行 |
| 需要设置什么 | 一个安装选项 | 设置中的外部 LLM，且提供商要有图像模型 |

**要在这台电脑上绘制，请安装 FLUX.2 klein。**

- <strong>Windows：</strong>在安装程序的组件页面勾选 **FLUX.2 [klein]**。除非你选择它，否则它不会被勾选。已安装的应用在更新时会看到同样的页面，或者从发布页面重新运行安装程序：之后这个勾选会被记住，更新也永远不会重复下载它。它是三个文件，总共大约 8 GB。
- <strong>Docker：</strong>运行 `sh scripts/fetch-models.sh --pictures`，它会把三个文件放进 `models/`
  （`diffusion_models`、`text_encoders` 和 `vae`）并逐一校验，然后用
  `docker compose restart app` 重启应用，让它找到这些文件。

<strong>FLUX.2 klein 9B，如果你的显卡够用。</strong>klein 有一个更大的尺寸，质量更高的模型，能画出更多细节以及更好的手和脸，只面向显存更多的显卡。
Yeufonic 从不下载它，因为它的文件在 Hugging Face 上需要申请访问，并采用 Black Forest Labs 的**非商业许可证**，但只要把它们放到位，就会被使用。

- <strong>磁盘：</strong>常用的一对文件——FP8 模型及其 FP8 文本编码器——大约 18 GB（用 FP4 编码器则为 16 GB），放在 4B 的文件旁边。它需要 4B 的 VAE（`flux2-vae.safetensors`），所以请先安装 4B。
- <strong>显存：</strong>能在 16 GB 显卡上运行，但绘制时几乎占满，空闲显存接近于零。图片会等到没有歌曲生成时才画，所以不会拖慢你的歌，但同时使用显卡的其他程序可能会遇到困难。显存更少时它仍然能运行，只是更慢，因为引擎要把模型换入换出；这种情况下 4B 是更好的选择。

1. <strong>模型。</strong>登录 Hugging Face，在
   [black-forest-labs/FLUX.2-klein-9b-fp8](https://huggingface.co/black-forest-labs/FLUX.2-klein-9b-fp8)
   接受许可证，并下载 `flux-2-klein-9b-fp8.safetensors`（9.4 GB）。或者从
   [black-forest-labs/FLUX.2-klein-9B](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B) 获取全精度的
   `flux-2-klein-9b.safetensors`，这是给 Mac 用的，大小约为两倍，所需内存也是两倍。它放在 `diffusion_models` 文件夹里。
2. <strong>它的文本编码器。</strong>从无需登录的
   [Comfy-Org/Flux-2-Klein-9B](https://huggingface.co/Comfy-Org/Flux-2-Klein-9B/tree/main/split_files/text_encoders)
   下载以下其中一个，放进 `text_encoders` 文件夹：
   `qwen_3_8b_fp8mixed.safetensors`（8.7 GB，NVIDIA 显卡上的常用选择）、`qwen_3_8b_fp4mixed.safetensors`
   （6.8 GB，最小）或 `qwen_3_8b.safetensors`（16.4 GB，全精度，给 Mac 用）。**使用 yue2.cpp 引擎时**，图片服务器读不了这些编码器：请改为从
   [unsloth/Qwen3-8B-GGUF](https://huggingface.co/unsloth/Qwen3-8B-GGUF) 获取 `Qwen3-8B-Q4_K_M.gguf`
   （5.0 GB）（`-Q8_0.gguf`，8.7 GB，也可以），放在同一个文件夹里。
3. **文件夹在哪里：** **Docker** 是 Yeufonic 文件夹中的 `models/`；**Windows** 是安装文件夹中的 `engine\ComfyUI\models`；**Mac** 是安装文件夹中的
   `engine/ComfyUI/models/`。
4. <strong>让应用看到它们，并选择它。</strong>重启 Yeufonic（使用 Docker 时为 `docker compose restart app`），然后在设置中把**版本图片：模型**设为 *FLUX.2 klein 9B*。在此之前由 4B 绘制，如果选了 9B 却无法在这里绘制，设置会提示你。选择
   *4B* 即可退回，无需删除任何东西。编辑器中图片的备注会说明是哪一个画的（*drawn by FLUX.2 klein 9B on this PC*）。

模型和它的编码器只能以这些名称被找到，所以请保持下载时的文件名。

<strong>FLUX 3 klein，适合画文字，需要 12 GB 或以上的显卡。</strong>Black Forest Labs 的 FLUX 3 Image Klein 根据完整的场景描述来绘制，而这正是 Gemma 或外部 LLM 写出的图片提示词，它写字也写得好，与**版本图片：在图片上显示歌名**很搭。和 9B 一样，Yeufonic 从不下载它：它的文件在
Hugging Face 上需要申请访问，并采用 **FLUX Kommunity License**（非商业用途，以及营收低于许可证门槛者对其所绘内容的商业使用；接受前请先阅读）。把它的文件放到位，就可以选择它。

- <strong>磁盘：</strong>int8 这一对大约 11 GB，放在 4B 的文件旁边。它使用 4B 的 VAE（`flux2-vae.safetensors`），所以请先安装 4B。
- <strong>显存：</strong>绘制时大约 11 GB。它的步数是 FLUX.2 klein 的好几倍，所以每张图片耗时更长。
- <strong>引擎：</strong>目前只支持 ComfyUI 引擎；使用 yue2.cpp 引擎时不提供它。

1. **登录 Hugging Face**，并在
   [black-forest-labs/flux-3-image-klein-comfy](https://huggingface.co/black-forest-labs/flux-3-image-klein-comfy) 接受许可证。
2. **模型**，放进 `diffusion_models` 文件夹：`flux3-image-klein-int8-convrot.safetensors`（5.8 GB，NVIDIA 显卡上的常用选择）、`flux3-image-klein-nvfp4.safetensors`（5.3 GB，给 RTX 50 显卡用）或
   `flux3-image-klein-bf16.safetensors`（11.1 GB，全精度，给 Mac 用）。
3. **它的文本编码器**，放进 `text_encoders` 文件夹：`qwen3vl_4b_int8_convrot.safetensors`（4.9 GB）或
   `qwen3vl_4b_bf16.safetensors`（8.9 GB，给 Mac 用）。
4. <strong>让应用看到它们，并选择它：</strong>重启 Yeufonic（使用 Docker 时为 `docker compose restart app`），然后在设置中把**版本图片：模型**设为 *FLUX 3 klein*。编辑器中图片的备注会写着 *drawn by
   FLUX 3 klein on this PC*。

文件夹和 9B 的相同，文件也只能以这些名称被找到。

<strong>FIBO 2.0，追求照片质感，需要 16 GB 显卡。</strong>Bria 的 FIBO 2.0 画出的图片最接近这些图片所效仿的唱片封套的真实照片：细节更锐利，景深自然，带有胶片的色彩，也更贴合描述的要求。Yeufonic 同样从不下载它。<strong>它的许可证是 CC BY-NC 4.0：仅限非商业用途。</strong>FLUX 3 的许可证允许营收低于门槛的人商业使用其所绘内容；而使用 FIBO 时，任何商业用途，包括你出售的歌曲的封面，都需要与 Bria 签订协议。使用前请先阅读许可证。

- <strong>磁盘：</strong>约 10.4 GB，包括模型和它的 turbo 附加组件。它读取 FLUX 3 的文本编码器和 4B 的 VAE，所以已安装 FLUX 3 时无需其他文件。
- <strong>显存：</strong>绘制时约 12.5 GB，因此需要 16 GB 显卡。更小的显卡会把一部分换出，速度会慢得多。
- <strong>时间：</strong>使用 turbo 附加组件时，与 FLUX 3 差不多。没有它时，FIBO 按自己的设置绘制，大约要八倍的时间。
- <strong>封套：</strong>由 FIBO 绘制时，照片周围的边框没有细深色线条，因为 FIBO 会把它画成粗条，并在歌名周围加框。
- <strong>引擎：</strong>仅限 ComfyUI 引擎。

1. <strong>模型，</strong>从 [Comfy-Org/Fibo-2.0](https://huggingface.co/Comfy-Org/Fibo-2.0)（无需登录）下载，放入 `diffusion_models` 文件夹：`fibo2_dev_int8_convrot.safetensors`（8.4 GB，NVIDIA 显卡的常用选择）或 `fibo2_dev_bf16.safetensors`（16.5 GB，全精度，适用于 Mac）。
2. <strong>它的 turbo 附加组件，</strong>从同一页面下载，放入 `loras` 文件夹：`fibo_2.0_turbo_lora_avg_rank_270_bf16.safetensors`（2 GB）。它不是风格 LoRA，也不会作为风格 LoRA 提供。
3. <strong>它的文本编码器，</strong>如果未安装 FLUX 3：从同一页面下载 `qwen3vl_4b_int8_convrot.safetensors`（4.9 GB）或 `qwen3vl_4b_bf16.safetensors`（8.9 GB，适用于 Mac），放入 `text_encoders` 文件夹。
4. <strong>让应用看到它们，并选择它：</strong>重启 Yeufonic（使用 Docker 时为 `docker compose restart app`），然后在设置中把<strong>版本图片：模型</strong>设为 *FIBO 2.0*。编辑器中图片的备注会写着 *drawn by FIBO 2.0 on this PC*。

<strong>要用外部 LLM 绘制，</strong>打开设置，把**用于写歌词和风格标签的 LLM**设为
[外部 LLM](#external-llm)，填上它的 **API 地址**、**API 密钥**和**模型**，和写歌词时一样。提供商必须有图像模型：Gemini 有（除非你指定别的，否则使用 `gemini-3.1-flash-image`），对于兼容 OpenAI 的提供商，则会请求 `gpt-image-1`。应用会在后台向提供商查询它的模型列表——在启动时、这些设置改变时以及每隔几小时——只有当列表里有图像模型时，才会在那里绘制。

两者都没有时，设置中的**版本图片**会显示**无图片：默认背景**，附上一行说明如何获得图片，生成图片的选项也无法选择。设置好其中任何一个，它们就会开启：从那以后，你新建的版本都会生成图片。

#### 在设置中管理图片 {#managing-pictures-in-settings}

| 设置 | 作用 |
|---|---|
| **版本图片** | *为每个新版本生成一张*（能绘制时的默认值），或*仅在请求时*，此时版本会保留默认背景，直到你通过它的小方块或编辑器的“图片”按钮生成一张。下面的设置会塑造用任何一种方式生成的图片。只要这里没有东西能绘制，它就是*无图片*。 |
| **版本图片：绘制者** | *如果已安装 klein 则用这台电脑，否则用外部 LLM*（默认）、<em>这台电脑（下面的模型）</em>或*外部 LLM 的图像模型*。这台电脑上由哪个 klein 绘制（FLUX.2 klein 4B 或 9B，或 FLUX 3 klein）在 **模型**中选择。FIBO 2.0 也在那里选择。 |
| **版本图片：模型** | *FLUX.2 klein 4B*（默认）、*FLUX.2 klein 9B*、*FLUX 3 klein*，或*已安装 9B 文件时用 9B，否则用 4B*。只用于在这台电脑上绘制的图片。9B 和 FLUX 3 永远不会替你安装：参见上文的 [FLUX.2 klein 9B 和 FLUX 3 klein](#two-ways-to-draw-flux-2-klein-on-this-pc-or-an-external-llm)。如果请求的那个不在，会由另一个绘制，设置会说明是哪个。*FIBO 2.0* 同样需手动添加，且仅限非商业用途：见上文。 |
| **版本图片：描述者** | 由谁根据版本的标题、下面的艺术风格、它的风格和歌词（最多 50 行）来写图片提示词。*已安装本地 Gemma 时用它，否则用版本本身*（默认），不管由谁绘制。*本地 Gemma*：在这台电脑上写；需要“歌词草稿”选项。*根据版本本身*：不用 LLM；用版本的标题、风格和开头的词生成描述，最快，也不发送任何内容。或者*外部 LLM*，每张图片一次请求；它不可用时，或你在本次会话中切换到本地 LLM 时，如果已安装 Gemma，就改由 Gemma 来写。 |
| **版本图片：艺术风格** | 图片应该是什么样子，交给写图片提示词的 LLM（版本自行描述时会变灰）。默认是七八十年代唱片封面风格的抽象超现实设计，不带文字和人物。清空后会恢复为这个默认值。 |
| **版本图片：你自己的提示词** | 每张图片的提示词开头的词，例如 *salt marsh, overcast*，最多 512 个字符；LLM 写的提示词跟在后面。空（默认）：没有。只在由 LLM 写图片提示词时有效（版本自行描述时会变灰）。 |
| **版本图片：在图片上显示歌名** | *否*（默认）或*是*：把歌名以粗体写在封面上，大写或小写，照你输入的样子，即使它是某位艺人的名字（图片本身仍会在不提名字的情况下描述）。大多数时候，图片会被一条细细的深色线框起来，外面是一圈断开的白边，就像许多七十年代的封面，歌名居中放在上方或下方一条更宽的带子里。大约五张中有一张没有边框：歌名直接写在图片上，放在角落或上方、下方居中，颜色取自图片中的一种柔和色，并会请 LLM 为它留出那部分画面。这些都会为每张图片随机选择。FLUX.2 klein 写的时候可能会有错字。只在由 LLM 写图片提示词时有效。 |
| **版本图片：图像模型** | 由提供商的哪个模型来绘制。只用于由外部 LLM 绘制的图片（在**绘制者**中选择它；否则变灰），留空则使用提供商的常用模型，这几乎总是你想要的。 |

所以，安装了 FLUX.2 klein 并保持默认设置时，图片完全在这台电脑上生成，即使由外部 LLM 写你的歌词也是如此：在装有“歌词草稿”的地方由 Gemma 写每个图片提示词，没有它时则根据版本本身生成描述，不用 LLM，几乎不花时间。选择*外部 LLM 的图像模型*可以让提供商来画，或者把**描述者**设为*根据版本本身*以获得最快的图片，或设为*外部 LLM*（每张图片一次请求）。

#### 编辑器中版本的图片 {#a-take-s-picture-in-the-editor}

编辑器窗口顶行、版本其他按钮旁的 <strong>图片</strong> 图标会显示图片和两个选项：

- <strong>生成新图片</strong> 在后台重新生成。
- <strong>使用默认背景</strong> 永久移除它：除非你要求，否则不会再为这个版本生成图片。

在那里点击图片可以完整查看，窗口允许多大就显示多大；点击任意处或按 Esc 会关闭它，编辑器保持原样。完整图片下方有同样的两个选项：在那里选择 <strong>生成新图片</strong>，在新图片生成期间图片会一直显示，按钮之间会显示进度；新图片完成后会替换它。

在版本卡片上，把鼠标悬停在左上角的方块上会显示图片。没有图片的版本，如果这台电脑能生成图片，会在那里提供 <strong>生成新图片</strong>。

### 比较版本 {#comparing-takes}

勾选两到六个版本，然后按 <strong>对比</strong>（勾选两个后它会出现在“全选”旁边，并会等待仍在渲染的版本）。这些版本叠放在一个窗口里，共享同一个播放位置：

- 按 <strong>1</strong>–<strong>6</strong> 或点击一个版本来切换：它会从歌曲的同一时刻继续，播放或暂停状态不变。
- <strong>空格</strong> 播放和暂停，方向键前后移动 5 秒。
- 用星标标出你更喜欢的那个。
- <strong>匹配响度</strong> 把较响的版本调低到最安静那个的水平，因为更响的版本往往听起来更好。
- <strong>隐藏名称</strong> 打乱版本顺序，并称它们为版本 A、B、C，以便盲听。

### 音频可视化与同步歌词 {#the-audio-visualizer-and-synced-lyrics}

点击走带栏中的**可视化**（或在播放曲目时按 **V**），以全屏打开可视化舞台。

舞台会显示与播放同步的实时音频可视化效果：

- <strong>可视化模式：</strong>在顶部栏中从十一种可视化效果中选择：
  - <em>Yeufonic：</em>标志本身在呼吸——方块随低音发光、随节拍膨胀，音叉的每一臂都是显示一半频谱的电平表，绿点随节拍亮起。
  - <em>波形丝带：</em>两条随声音起伏的漂浮和声丝带。
  - <em>北极光：</em>空灵极光的波动帷幕，随中频和高频而动。
  - <em>宇宙星云：</em>星空和由星际粒子组成的星云，随节奏旋转和脉动。
  - <em>万花筒：</em>随速度脉动的径向几何对称图案。
  - <em>霓虹网格：</em>复古未来感的合成波线框透视平面，随贝斯线起伏。
  - <em>液态扭曲：</em>被和声波动扭曲的流体表面。
  - <em>粒子群：</em>受引力牵引的粒子团，随打击乐重音四散。
  - <em>高保真频谱柱：</em>带有漂浮下落峰值的多频段频谱分析器。
  - <em>封面：</em>版本的图片，放大显示，标题在下方，背后是它自身的一份模糊副本，随音乐而动。没有图片的版本会显示 Yeufonic 场景，直到生成一张图片。
  - <em>无：</em>只显示版本的图片，静止在深色背景上；没有图片时显示 Yeufonic 标志。什么都不动，适合跑不动其他场景的电脑。
- <strong>场景背后：</strong>封面、Yeufonic、曼陀罗、网格、液态和频谱柱这几个场景，会在版本有图片时叠在那张随音乐轻轻移动的图片上播放。上面还可以有东西在动，用图片的颜色：*呼吸*（只有图片）、从中心旋转的*光线*、随节拍荡开的*涟漪*、*色彩漂移*、*纵深*（更多图片副本彼此反向旋转）或*频谱光晕*。每个场景都从自己的那个开始（封面背后是色彩漂移，曼陀罗背后是光晕，网格背后是光线，液态背后是涟漪，Yeufonic 和频谱柱背后只有图片）；按 **B** 可以循环切换，场景会记住你的选择。
- <strong>波形：</strong>在 Yeufonic 和封面场景下方，版本的波形会显示歌曲已经播放了多少；点击它可以跳到那里。
- <strong>封面与黑胶动态：</strong>以 Hipgnosis 风格把版本的封面放进一个可交互的 3D 唱片套里，它会随指针倾斜和转动。一张逼真的黑胶唱片以 33⅓ 转旋转，随贝斯重拍从唱片套中滑出，带有全息光泽和随节奏变化的冲击波环。用**封面**按钮切换模式：*唱片套*、*光晕*（模糊背景）或*关闭*。
- <strong>一张新图片：</strong>每个场景右上角的图片按钮，会为正在播放的版本生成一张新图片，前提是这台电脑能生成图片。生成期间它会脉动，新图准备好后会接替旧图。
- <strong>屏幕歌词：</strong>按 **L** 或点击**歌词**，显示或隐藏独立的可滚动歌词面板。拖动它顶部的栏可以把它挪开；它会停在你放下的地方，双击该栏则会让它回到原位。
- <strong>迷你播放器丝带：</strong>完整的可视化关闭时，一个双波形的响应式迷你可视化会在底部走带栏中播放。在**设置 → 外观**中开关。

### 播放列表与喜欢 {#playlists-liked-songs}

点击顶部栏中的**播放列表**，切换到播放列表视图。

### 键盘快捷键 {#hot-keys}

在主页面上，单个按键作用于**所选版本**：左侧面板里的那个。点击它的卡片即可选中它。每个按键都和它的按钮作用相同，所以会删除东西的按键会先询问；版本无法执行某个按键的请求时（例如没有乐谱的版本做变奏），状态栏中会留下一行说明原因。

| 按键 | 作用 |
|---|---|
| 空格 | 播放或暂停 |
| 左、右 | 后退或前进五秒 |
| Shift+左、Shift+右 | 上一个或下一个版本；在播放列表视图中，是播放列表中的上一首或下一首 |
| 上、下 | 音量 |
| M | 打开版本的母带处理架；再按一次关闭 |
| E | 在编辑器中打开版本 |
| I | 版本详情：它的一切制作参数，以文字列出，并带有**复制** |
| N | 标准化版本，若已标准化则撤销 |
| V | 播放时打开或关闭可视化，空闲时则是变奏 |
| T | 再试几个 |
| S | 给版本加或去星标 |
| P | 把版本加入播放列表 |
| D | 删除版本，会先询问，和它的垃圾桶按钮一样 |
| L | 日志；可视化打开时则显示歌词 |
| B | 在可视化中，切换场景背后、叠在版本图片上移动的效果 |
| F | 全屏 |
| ? | 显示或隐藏快捷键；再按一次关闭 |
| Escape | 关闭最前面的窗口：可视化、日志、编辑器上的母带处理架，然后是编辑器或任何其他窗口 |

在框中输入文字时、前面有窗口打开时，或按住 Ctrl、Alt、Windows 键或 Command 键时，字母键都不起作用，这样浏览器自己的快捷键（Ctrl+L、Ctrl+S 等）依然可用。按钮的悬浮提示会标出它的按键，例如**变奏 (V)**。随时按 **?** 可以查看快捷键列表。

在编辑器窗口中，只要窗口的播放器可见——在每一步，以及母带处理架打开在上面时——空格和方向键就会控制该窗口的播放器，作用于在那里打开的版本。在框中输入文字时它们从不生效，字母键也只在主页面上可用。钢琴卷帘有它自己的按键：参见[钢琴卷帘](#the-piano-roll)。

## 设置 {#settings}

点击左上角的 **Yeufonic**。设置保存在服务器上，所以会跟着你到任何浏览器，重新构建后也依然保留：分轨和保存版本时的输出音频格式、分离模型、分轨写入的位置、是否保留训练检查点，以及如何检查纯音乐不会唱出来。

### 存储 {#storage}

**设置 → 存储**会显示 Yeufonic 的磁盘空间用在哪里，并让你回收一部分。训练一个语料库会留下许多以后用不到的文件：分析歌曲时为引擎制作的副本、训练集（每首歌都被重写为无损 FLAC，比原文件更大），以及途中保存的检查点。窗口会列出每一项及其大小、**它是什么**以及**删除它的代价**，并且在最后确认之后只删除你勾选的内容。**勾选无损失项**会勾选那些需要时会自动重新生成的副本。

从现在起分析的歌曲会把分离出的人声存为 FLAC，同样的音频大约只占一半空间。窗口可以**转换你已有的 WAV 人声**：每一个都会被转换、校验能否解码出完全相同的音频，然后才删除 WAV。它在后台运行，可以停止。

删除训练检查点之前值得再看一眼：每一个都是风格 LoRA 列表中的一项，你可以为新版本选择它，所以删除一个语料库的检查点会把这些项永久移出列表。它已完成的 LoRA 会保留并照常可用。语料库的训练集则不同：删除它会把 LoRA 及其检查点留在列表中，只有重新训练这个语料库时才需要它。

你的版本、歌曲、已完成的 LoRA 和模型永远不会出现在可删除列表中。属于正在训练、导出或分析的语料库的一切，都会显示为灰色，在完成之前无法动它。

在下面，**自动整理**选择 Yeufonic 会替你删除什么：每首歌分析完成后它的工作副本（默认开启）、LoRA 训练完成后的训练集（默认关闭；之后语料库需要再做一次**导出**才能再次训练），以及训练检查点（默认保留）。

Docker 的镜像和构建缓存在 Yeufonic 之外，这里不涉及；`docker system df` 会显示它们。

### YuE2 模型 {#the-yue2-model}

YuE2 有两种尺寸，一个安装只有其中一种：我们推荐的**全质量**，或**低显存**——为显存较少的显卡准备的较小副本。同一菜单中的**关于**会说明你用的是哪一个。它在安装 Yeufonic 时选择，而不是在这里：

- **在 Windows 上**，重新运行安装程序。它的组件页面提供两种尺寸，并勾选已经下载的那些。切换会在第一次时下载另一个并保留两者，所以切回来不会再下载任何东西。
- **使用 Docker 时**，`sh scripts/fetch-models.sh` 下载全质量模型，
  `sh scripts/fetch-models.sh --int8` 下载低显存模型。`models/checkpoints` 中两个文件都有时，应用使用全质量模型，除非 `.env` 中有 `YUE2_CHECKPOINT=int8`。

如果渲染非常慢，或引擎显存不足，可以试试低显存模型。两种尺寸的模型都可以训练 LoRA。**低显存 (int8) 模型训练**设置决定用哪一个：关闭时，训练使用全质量模型；开启时，使用应用渲染时用的模型。只安装了低显存模型时，它一开始就是开启的。GitHub 上的 README 有一节 *Choosing a model size*，介绍了每种尺寸的预期表现。

Yeufonic 也可以使用 **yue2.cpp** 引擎代替 ComfyUI，适用于显存更少的显卡，在设置时选择：在 Windows 安装程序的组件页面上，或在 Docker 中通过
`sh scripts/fetch-models.sh --cpp`。**关于**会说明正在运行哪个引擎，版本的卡片则说明它由哪个引擎渲染。它能做歌曲、翻唱和纯音乐，并转写录音，可以用你的风格 LoRA；Gemma 可以在它旁边起草歌词和描述图片（使用 Docker 时为 `--gemma`），FLUX.2 klein 则可以绘制图片（`--pictures`）。训练需要
ComfyUI 引擎：使用 yue2.cpp 时不提供语料库和训练。GitHub 上的
[Choosing an engine](https://github.com/yeufonic/yeufonic/blob/main/docs/ENGINES.md) 页面有完整列表以及切换方法。

**检查新版本**是这里唯一会主动上网的东西：每四小时，应用会询问 yeufonic.com 是否有更新的版本发布，并在右上角版本号旁用一个胶囊标签提示。这个标签会给你安装程序，或者对于 Docker 副本，给出更新它的两条命令。这只是一次请求，此外没有任何东西离开电脑；**不检查**会把它关掉。菜单中的**检查更新**会立刻询问，不管这项是否开启，并在菜单中回答：你用的是哪个版本，以及它是不是最新的。

有更新的版本时，菜单会提供**获取 x.y.z**，它会在 Windows 安装中下载安装程序，或者为 Docker 副本把两条命令放进剪贴板。

<strong>主题</strong> 决定应用的外观。切换会立即生效，每个浏览器都会记住它，让页面以这个样子打开。

| 主题 | 外观 |
|---|---|
| <strong>深色</strong> | 应用自己的深色外观。 |
| <strong>浅色</strong> | 浅色面板；母带处理架的面板是拉丝银色，而旋钮、电平表窗口和显示屏仍保持深色的硬件外观。 |
| <strong>跟随电脑（深色或浅色）</strong> | 跟随你系统的浅色或深色模式，并随之切换。 |
| <strong>录音棚</strong> | 带琥珀色的暖调深色。 |
| <strong>高对比度</strong> | 黑白分明，轮廓清晰。 |

日志窗口在所有主题下都保持深色，就像终端一样，母带处理架也会跟随主题。

主题下方的**背景色**会用你选的颜色给版本背后的页面着色：勾选**色调**，然后沿色轮移动**色相**，并把**强度**从淡淡一层调到浓郁的颜色。拖动时页面会随之变化，松开时选择会被保存。版本卡片、面板和窗口保持各自的颜色，高对比度主题依然是黑色。

### 外部 LLM {#external-llm}

Yeufonic 可以使用外部 LLM 代替本地 Gemma 模型来起草歌词、转写录音、标注歌曲段落，以及分析语料库的风格。

使用外部 LLM 有两个明显的好处：
- <strong>节省显存：</strong>不必把 Gemma 4 模型载入 GPU 显存（大约节省 8 GB 显存），让你的显卡完全空出来，用于 YuE2 的规划和音频渲染。
- <strong>更丰富的草稿和分析：</strong>大型云端模型往往能起草更细腻的歌词，并为你的语料库生成详细的风格标签。

<strong>推荐的提供商：</strong>如果你能用上，我们建议选择 API 不计费的外部 LLM 提供商——**Google Gemini** 就是个好例子。Gemini API（通过 Google AI Studio）提供慷慨的免费额度且不计费，支持标准的 OpenAI 兼容端点（`https://generativelanguage.googleapis.com/v1beta/openai/`），并能直接接受音频来转写录音。

如果你使用按量或按 token 计费的 API（如 OpenAI 或 Anthropic 的付费层级），分析一个包含几十首歌的完整语料库，或为许多版本生成描述，都可能很快耗尽 API 额度或触及消费上限。如果外部 API 返回配额或频率限制错误（HTTP 429），Yeufonic 会显示提示，并让你在本次会话剩余时间里切换到本地模型，这样其他任务可以不中断地继续。选择不计费的提供商可以避免意外的费用。

**设置方法：**
1. 打开 **Yeufonic → 设置 → 外部 LLM 和歌词**。
2. 把**用于写歌词和风格标签的 LLM**设为**外部 LLM（OpenAI 兼容 API）**。
3. 填入提供商的 **API 地址**、**API 密钥**和**模型**（例如，模型 `gemini-2.5-flash` 或 `gemini-1.5-flash`，配合 Google Gemini 的 OpenAI 兼容基础地址 `https://generativelanguage.googleapis.com/v1beta/openai/`）。
4. 点击**测试 LLM 连接**验证你的凭据。
5. 如果所选模型支持音频输入（如 Gemini），还可以把**从录音获取歌词**设为**外部 LLM**，让它聆听分离出的人声。

## 从 AI 智能体使用 Yeufonic（MCP） {#using-yeufonic-from-an-ai-agent-mcp}

Yeufonic 可以作为 **MCP 服务器**运行。这样同一台电脑上的 AI 智能体（例如 Claude Code 或 Cursor）就能替你使用它：请求一首歌、一个翻唱或一段纯音乐，等它完成，播放它，换种方式再试，给它配一张图片，把它放进播放列表，整理库，全都用你自己的话说（“在 EDM 空间里做一段一分钟的 EDM 纯音乐，然后播放”）。智能体做的就是页面做的事，走的也是同样的路径，所以它开始的版本就是你库中的一个普通版本。

### 设置方法 {#setting-it-up}

1. <strong>开启它。</strong>打开设置，把**MCP 服务器**设为**开**。它默认关闭，因为一个请求就可能启动 GPU 任务。
2. **把你的智能体连接**到应用的地址，末尾加上 `/mcp`：也就是你打开 Yeufonic 的那个地址，例如
   `http://localhost:8090/mcp`。在 Claude Code 中：

   ```
   claude mcp add --transport http yeufonic http://localhost:8090/mcp
   ```

   其他客户端也把同样的地址当作 HTTP 服务器。读取配置文件的客户端通常需要类似
   `{"mcpServers": {"yeufonic": {"url": "http://localhost:8090/mcp"}}}` 的内容。不需要登录或密钥。
3. <strong>提出请求。</strong>在任意文件夹中启动你的智能体，描述你想要什么。

<strong>用哪个地址？</strong>就是你打开 Yeufonic 的那个地址，末尾加上 `/mcp`。
- **Docker：**`http://localhost:8090/mcp`。
- <strong>Windows 安装：</strong>应用的端口写在 `settings.ini` 里（`app_port`，除非你改过，否则是 8090，例如为了和
  Docker 副本同时运行而改）。若 `app_port = 8091`，地址就是 `http://localhost:8091/mcp`。
- <strong>智能体在 WSL 中、应用在 Windows 上：</strong>这样连不上。Windows 应用只监听 Windows 自己的回环地址，WSL
  无法访问（WSL 里的 Docker 没问题，因为它也在 WSL 中）。请从 Windows 运行智能体（PowerShell 或你智能体的 Windows 版本），或者开启 WSL 的镜像网络（在 `.wslconfig` 的 `[wsl2]` 下设置 `networkingMode=mirrored`，然后运行 `wsl --shutdown`），这样两边的 `localhost` 就是同一个。

如果你的智能体说服务器**需要身份验证**，几乎总是因为这个设置仍是关闭的：开启它，然后重新连接智能体（在 Claude Code 中为 `/mcp`）。重启 Yeufonic 之后也要重新连接，因为重启会断开连接。

### 你可以请求什么 {#what-you-can-ask-for}

| 请求 | 会发生什么 |
|---|---|
| “列出我最新的版本”“显示 EDM 空间里的版本” | 列出版本，最新的在前，附带简短的 id、每个的制作时间、时长和风格 |
| “做一段一分钟的合成波风格纯音乐” | 规划并渲染一段纯音乐。可以指定时长、空间和[风格 LoRA](#style-loras) |
| “用这些歌词做一首民谣风格的歌” | 歌曲也一样，根据你给的歌词 |
| “……用冒险的和声、收敛的演绎、升 F 调、100 BPM” | 新版本的任何设置，用页面上的名称：[和声](#harmony)、[方案多样性](#plan-variety)、[演绎](#interpretation)、锁定调性和速度，以及歌曲的**严格遵循此结构**和**声部遵循提示**。如果什么都没说，新版本会从页面的起点开始：多样和宽广 |
| “写一首关于夜行列车的歌词，用说话般的语气” | 应用自己的**写歌词**，带有它的歌曲形式、每段行数和语气。智能体也可以自己写歌词 |
| “用爵士风格翻唱*这段录音*” | 根据库中已有的一段录音做翻唱。需要乐谱（先在应用中转写）。没有你的歌词时，会使用在录音中听到的词 |
| “我有哪些音色？”“用我的 Night Singer 音色唱，稍低沉一些” | 列出你录制的音色，用其中一个演唱歌曲或翻唱，或用它重新渲染一条录音，并可像编辑器中音色的 **设置** 那样为该录音单独设定（共振峰、混合、相似度等） |
| “播放它” | 在你的浏览器中打开这个版本，在那里播放 |
| “给那个加星标”“把它改名为 Sunrise”“把它移到 Folk 空间” | 给版本加星标、重命名或移动 |
| “用新种子重新渲染”“停下那个” | 重新渲染一个版本，或取消进行中的版本 |
| “再给我几个那样的” | 用新种子重新渲染这个版本，作为几个新版本放在一起听 |
| “再唱一次”“每种演绎都试试” | **再唱一次**（同一份乐谱换新的人声）或**变奏**（同一份乐谱和种子，用每种方式演奏）。变奏保存在版本里面，和再试几个一样 |
| “用这些歌词唱那段旋律” | **新歌词**：同样的旋律、调性和速度，配上另一份歌词，作为新版本 |
| “把它做成纯音乐” | 同一份乐谱，旋律交给乐器、不演唱，作为新版本 |
| “给它写一份新方案，更活泼些” | 为还没有音频的版本（只规划未渲染，或方案失败的）写一份新方案。有音频的版本不会被动：请改为请求一个新版本 |
| “把松散的那个取出来” | **移出**：保存在另一个版本里的版本变成独立版本 |
| “给它一张图片” | 为这个版本生成一张新图片，和编辑器的**图片**按钮一样，并给出打开它的链接。在这台电脑上绘制的图片会等到没有歌曲在生成时才画 |
| “把最好的三个放进一个叫 Road trip 的播放列表” | 创建播放列表，显示其中内容，添加或删除版本。把版本放进**喜欢**会给它加星标 |
| “帮我找一个合成波风格”“把这个风格保存为 Night drive” | 在你保存的风格和内置风格中搜索，并以一个名字保存风格，供风格菜单使用 |
| “新建一个叫 Drafts 的空间” | 新建一个存放版本的空间 |
| “转写*这段录音*” | 把一段录音转写为乐谱，以便翻唱。已有乐谱的录音不会被动，除非你要求 |
| “把那个分成人声和乐器” | 把一个完成的版本分离成各个部分（四个、六个，或只分人声和乐器），并给出每个文件的链接，以及整套文件 zip 的链接 |
| “保存那个版本的配方”，“……连同版本一起打成 MP3 压缩包” | 给出版本的配方（制作它的一切，不含音频），可展示、修改或保存为文件，并附上单独下载或与音频一起打成一个 zip 下载的链接 |
| “把 *Night Ferry.yeufonic.json* 导入 Drafts 并渲染” | 从版本文件新建一个版本，带有方案，在你要求时渲染。它会说明文件中提到的哪些 LoRA 未安装，以及翻唱何时作为歌曲导入 |
| “再导入一次，换成梦幻流行风格，乐谱和种子不变” | 在导入前修改配方，只改你说的部分 |
| “那个版本是哪个引擎做的？”，“现在运行的是哪个引擎？” | 说明哪个引擎渲染了某个版本，以及 Yeufonic 现在运行的是哪个（ComfyUI 或 yue2.cpp） |
| “Yeufonic 忙吗？” | 说明引擎是否就绪、正在运行什么及其进度、什么在等待，以及是否有 LoRA 正在训练 |
| “删除那个版本” | 先显示会删除什么并征求你的同意；见下文 |

制作一个版本需要几分钟。智能体会启动它并等待，同时报告进度，所以在此期间你可以提出下一个请求。

### 可能的过程：一个例子 {#how-it-can-work-an-example}

一次对话，从一个想法到一个播放列表。你说话；智能体选择工具（中间那一栏只是为了展示发生了什么），并告诉你返回了什么。

| 你说 | 智能体 | 你得到 |
|---|---|---|
| “写一首关于灯塔看守人最后一夜的歌词，民谣风格，叙事形式。然后在一个叫 Coast 的新空间里用它做一首歌。” | `write_lyrics`、`create_space`、`make_song`，然后 `wait_for_take` 直到完成 | 展示给你的歌词，标题为 *The Last Light*；一个叫 Coast 的空间；在那里规划并渲染好的一首歌，过程中附带进度 |
| “播放它。” | `get_take`，然后打开它的 `listen_url` | 在你的浏览器中播放 |
| “旋律不错。试试更松散、更躁动的，再给我一个不唱的。” | 用松散和躁动调用 `make_variations`，再调用 `instrumental_from_take` | 歌曲里面的两个版本，以及旁边的一段纯音乐 |
| “看看我们都有什么。” | 在 Coast 中调用 `list_takes`，并对歌曲使用 `inside` | 一份列表，每个都有简短的 id，所以你可以说“3f9a”而不用说标题 |
| “把 3f9a 取出来，加星标，再给它一张图片。” | `take_out`、`star_take`、`make_picture` | 那个松散的版本成为独立版本，加了星标（所以也进了喜欢），附带它的图片链接 |
| “把那个和纯音乐放进一个叫 Coast demos 的播放列表。” | `create_playlist`、`add_to_playlist` | 一个包含这两个的播放列表 |
| “把这个风格保存为 Coastal folk。” | `save_style` | 应用风格菜单中的 **Coastal folk**，下次就能用 |
| “现在来个二重唱：这些歌词，带 [male voice] 和 [female voice] 提示，每段都照写的来。” | 带 `follow_structure` 调用 `make_song`（新方案，因为段落变了） | 一首严格按你的段落、按顺序规划的新歌，每一行被标注的歌词都移到了那个人声演唱的位置 |

它做的一切都在库里，就像你在页面上做的一样：在编辑器中打开任何版本、做母带处理，或者从那里继续。当某一步做不到时，智能体会从应用本身得到原因（“this take is an instrumental already”、“nothing here can draw a
picture”），并转告给你，所以你听到的回答和页面给出的一样。

### 它能做的一切 {#everything-it-can-do}

你不需要这些名称：用你自己的话提出请求，智能体会自己选择。列出它们是为了让你知道都有什么，也方便你告诉智能体想用哪一个。

| 工具 | 作用 |
|---|---|
| `list_takes` | 列出版本，最新的在前，可选只列出与某些词匹配的、在指定空间里的，或加了星标的。显示简短的 id |
| `get_take` | 一个版本的全部信息：如何制作、状态、任何错误，以及有音频时一个可以播放它的链接。可以包含乐谱 |
| `wait_for_take` | 等待（每次最多大约一分钟）一个正在生成的版本，并说明它是否完成 |
| `make_instrumental` | 根据风格规划并渲染一段纯音乐，若你指定，可带时长、空间和风格 LoRA，若你给出，可带段落 |
| `make_song` | 歌曲也一样，根据歌词 |
| `make_cover` | 根据库中的一段录音做翻唱，使用它的乐谱，以及（除非你给了别的）它的词 |
| `try_more` | 从一个已有版本再生成几个，使用新种子 |
| `sing_again` | 用新种子把同一份乐谱再唱一遍：新的人声，作为新版本 |
| `make_variations` | 同一份乐谱和种子，用每种指定的演绎（或全部），保存在版本里面 |
| `new_words` | 用另一份歌词唱同一份乐谱，作为新版本 |
| `instrumental_from_take` | 把同一份乐谱做成纯音乐，作为新版本 |
| `replan_take` | 为没有音频的版本写一份新方案，可选换一种和声、方案多样性、调性或速度 |
| `take_out` | 把保存在另一个版本里的版本变成独立版本 |
| `write_lyrics` | 根据委托写歌词，带有歌曲形式和语气，写法和页面上的“写歌词”一样 |
| `render_take` | 渲染一个已规划的版本，或重新渲染一个已完成的版本（如有要求则用新种子） |
| `cancel_take` | 停止排队中或进行中的版本 |
| `make_stems`、`get_stems` | 把版本分离成各个部分，然后列出这些部分，附上每个部分以及整套 zip 的链接 |
| `list_recordings`、`transcribe_recording` | 显示库中的录音以及每段是否有乐谱；转写没有乐谱的那段 |
| `list_style_loras` | 已安装的风格 LoRA，以及它们的触发词和随之保存的强度 |
| `list_voices` | 你录制的音色、各自是否就绪及其默认设置。`make_song`、`make_cover` 和 `render_take` 可按名称指定音色，并为该录音单独设定；`get_take` 会说明录音由哪个音色演唱 |
| `list_spaces`、`move_take`、`create_space` | 各个空间及其内容；把版本移到另一个空间；新建空间 |
| `list_playlists`、`create_playlist`、`add_to_playlist`、`remove_from_playlist` | 播放列表及其中的版本；新建播放列表；放入或移出版本 |
| `make_picture` | 为版本生成一张新图片，并附上打开它的链接。`get_take` 也会给出版本图片的链接 |
| `list_styles`、`save_style` | 你保存的风格和内置风格，按词搜索；以一个名字保存风格 |
| `star_take`、`rename_take` | 给版本加或去星标；修改它的标题 |
| `delete_take` | 永久删除一个版本，先给你看并得到你的同意 |
| `save_take_recipe` | 版本的配方，附上单独下载或与音频一起打成一个 zip（按所要的格式）下载的链接 |

| `status` | 引擎是否就绪、正在运行和等待的是什么，以及是否有 LoRA 正在训练；并说明运行的引擎（ComfyUI 或 yue2.cpp） |

### 使用思路 {#ideas-for-using-it}

- **先批量出点子，再挑选。**“在 EDM 空间里做五段风格各异的一分钟 EDM 纯音乐。”它会一个接一个地启动，并在每一个完成时告诉你。你来听，然后说“给第二和第四个加星标，其余删掉”。
- **围绕一个想法迭代。**“做一段梦幻合成器风格的纯音乐并播放”，然后“现在一样的，鼓多一点”，再
  “照第二个那样再给我四个”。智能体会记住哪个版本是哪个，所以你可以按位置或按你说过的特点来指代它们。
- **不用点来点去的翻唱。**“转写*这段小样*，然后做三个翻唱：民谣、合成波和爵士。”如果录音没有乐谱，它会先转写，然后在你指定的空间里做翻唱。
- **配合 LoRA。**“列出我的风格 LoRA，然后用爵士那个做一段纯音乐。”触发词和保存的强度会替你处理好，手动做很容易出错。
- <strong>歌词由智能体写，或由应用写。</strong>智能体可以自己写歌词：“写一首关于夜行列车的歌词，然后用它做一首民谣风格的歌。”Yeufonic 只会看到写好的歌词。或者请应用来写：“用 Yeufonic 的歌词作者，嘻哈形式，说话般的语气”，它会像页面上的**写歌词**那样写好，再交还给你用于一首歌。
- **同一旋律，不同歌词。**“用这些歌词作为第二段主歌，再把它唱一遍”：`new_words` 会保留旋律、调性和速度，而根据歌词新写一首歌则会写出一段新旋律。
- **比较设置。**“同一首歌做两遍，一遍用熟悉的和声，一遍用冒险的和声，用同一个种子”，然后
  “现在给好的那个试遍每种演绎”。设置按名称请求，所以一句话就能搭好一个小测试。
- **根据试听整理播放列表。**“把这周所有加星标的版本放进一个叫 Week 43 的播放列表”，或者“把纯音乐从
  Road trip 里拿出来”。喜欢就是加了星标的版本，所以星标和喜欢始终是同一份列表。
- **为一整批做分轨。**“把我最新的五个版本分成人声和乐器，并给我链接。”它们会一个接一个排队，排在 GPU 正在运行的任何渲染之后。
- **整理库。**“找出标题相同的版本，告诉我哪个最新，删掉旧的”，或者“把我今天做的所有东西移到一个叫 Drafts 的空间”。它按 id 操作，删除之前会先询问。
- <strong>长任务之前先看看。</strong>在排一个长渲染或一整批之前问一句“Yeufonic 忙吗？”，免得排在训练后面。
- <strong>更大任务的一部分。</strong>因为它是智能体可以调用的工具，所以可以成为更大事情的一部分：为一段视频做一条音轨并写好配套说明，或做一批数量与一个播放列表相当的版本，并按一个列表给它们命名。

智能体听不到版本，所以无法判断它听起来怎样：由你来听，它来做繁重的工作。它也不是绕过引擎的捷径：GPU 仍然一次只做一个任务，所以一大批就是一条长队。
- <strong>分享一个版本。</strong>“把我加星的版本连同配方保存为 FLAC 压缩包”会得到一个别人能听也能重做的文件：对方请自己的代理“导入这个版本文件并渲染”。或者“用爵士 LoRA 再导入一次，乐谱和种子不变”，用另一种方式听同一个方案。

### 值得了解 {#things-to-know}

- <strong>版本的标题可能相同，</strong>所以智能体用版本的 **id** 来工作，列出版本时会显示一个简短的 id（`short_id` 列）。你可以用 id 的开头来指代一个版本，四个字符或更多，只要只有一个版本以它开头。如果有两个，它会告诉你并要求更多字符。
- <strong>删除会问两次。</strong>智能体先给你看它会删除什么，包括任何同标题的其他版本，只有在你说是之后才会删除。加了星标的版本需要你明确说出来。删除的版本连同其音频都无法恢复。
- <strong>空间和风格 LoRA 用名称指定，</strong>而不是用编号：“在 EDM 空间里”“用爵士 LoRA”。与任何东西都不匹配的名称会得到现有项目的列表，不会新建任何东西。LoRA 的触发词会替你加进风格里，因为没有它 LoRA 几乎不起作用。
- <strong>新版本从页面的起点开始：</strong>和声为多样、演绎为宽广，除非你指定别的。在没有和声节点的引擎上，它从熟悉开始，因为那里的和声无法调得更高。
- <strong>图片和歌词会排队等候。</strong>在这台电脑上绘制或描述的图片会等到没有歌曲在生成时才处理，在这台电脑上写的歌词会和其他 GPU 任务一起排队，所以智能体可能会说“还在生成中”，稍后再回来看。
- <strong>纯音乐总是用带时间的结构来规划，</strong>根据你要求的时长算出（如果你什么都没说，大约两分半）。没有时间时，规划器写出的方案会长得没法用。指定你自己的段落，它们就会原样使用。
- <strong>只限这台电脑。</strong>页面的主机名和来源检查同样适用，而且没有登录，所以不用时请关闭这个设置，也不要把端口暴露给你不信任的网络。

## 系统日志 {#system-logs}

应用会为每个重要操作——乐谱规划、渲染、音频转写、分轨分离和 LoRA 训练——写一份统一的实时日志，带有 `INFO`、`WARN` 和 `ERROR` 前缀。

- <strong>浏览器内控制台：</strong>点击顶部栏中的**日志**按钮（或按 **L**），打开一个可以拖动和调整大小的浮动控制台。它保持打开而不阻挡页面，让你可以把版本加入队列，并实时跟踪生成过程。
- <strong>独立窗口：</strong>点击控制台标题栏中的<strong>↗ 弹出</strong>（或直接访问 `/logs`），打开一个专门的日志窗口。
- <strong>在终端中：</strong>日志会自动轮转到主机上的 `data/logs/yeufonic.log`，你可以在那里实时跟踪：
  ```bash
  tail -f data/logs/yeufonic.log
  ```

## 引擎自己的页面 {#the-engine-s-own-page}

引擎是 ComfyUI（除非这个安装用的是 yue2.cpp，它的页面只是一个简单的测试台），它自己的界面可以访问：Docker 为 <http://localhost:8189>，
Windows 安装为 <http://localhost:8188>（即 `settings.ini` 中的 `engine_port`）。它只在这台机器上响应，不需要登录。

- <strong>它和应用用的是同一个引擎、同一块 GPU。</strong>在那里运行的任务会作为来自外部的任务出现在应用的队列中，应用自己的任务会等它完成。
- **它的历史记录显示应用发送的每一个图**：方案、渲染和转写，以及引擎收到的每一项设置。想确切知道一个版本是由什么做出来的，这里是个好地方。

## 出问题时 {#when-something-is-wrong}

<strong>标题栏说缺少引擎。</strong>应用没有它也能运行，并会这样提示。渲染会等待。检查引擎容器是否在运行。

<strong>一首歌停不下来。</strong>通常是规划器强度太高。把 LoRA 的规划器降到 0.5。时长上限无论如何都会让它停下。

<strong>一个 LoRA 似乎没有作用。</strong>检查触发词是否在风格里，以及你调高的那个强度是不是文件里真的有的——选择器会把另一个变灰。

<strong>一个版本显示“渲染偏弱”。</strong>它从头到尾都比正常情况轻得多。有些这样的版本只是声音小；另一些听起来单薄或失真。点击提示可以对它进行标准化，这会把它提升到通常的响度，并标为 *已标准化*。如果听起来仍然不好，换一个种子试试，并把那个 LoRA 的音色保持在 0.5 或以下。这多发生在通过在这里训练的风格 LoRA 做的翻唱上。

<strong>响度标准化。</strong>在编辑器中勾选它，勾选期间做的每个版本在完成时都会被调整到通常的响度，并标为 *已标准化*。没有勾选时做的版本，之后可以用卡片顶部的扬声器按钮来标准化。渲染出来的原始文件会保存在旁边，点击 *已标准化* 会回到它。响度的目标在设置的 *标准化到* 中设定。不勾选时，版本保持渲染时的电平。

<strong>一段纯音乐唱了起来。</strong>参见上文的 *纯音乐唱了起来*。这是模型的毛病；换一个新种子通常就能解决。

<strong>一个版本无法重新渲染。</strong>它的录音可能已被删除。翻唱会保留各自的音频和乐谱，但无法从一段已不存在的录音重新渲染。

<strong>没有声音，但波形在动。</strong>检查音量控制，并确认没有选中某个分轨——播放器跟随你最后点击的东西。
